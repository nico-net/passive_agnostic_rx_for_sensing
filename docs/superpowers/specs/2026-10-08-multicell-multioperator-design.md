# Multi-PCI and multi-operator passive sensing on GB10 + X410

2026-10-08. **Design only.** Target: at least two PCIs and two operators observed **at the same time**, with coherent antenna pairs per carrier and capacity to add cells within a carrier. The receiver stays passive and agnostic: PLMN comes from decoded broadcast information, never from a configured operator label. `PROJECT_MEMORY.md` §§12,14,17–20 defines G12–G14 and the intended pipeline. Evidence labels below distinguish current measurements, source inspection, calculations, and questions.

## Evidence and hard constraints

- [MEASURED, DGX GB10 + X410 34B2AF1, 2026-10-08] CG_400, UHD 4.11, DPDK, one 100 GbE path and four 122.88 MS/s sc16 RX streams have run. RX channel 2 is about 20 dB weak in live RF measurements; inspect cable/antenna before assigning it to a two-branch AoA pair. The one-cell PCI-415 chain with about 20–35 UEs has PDCCH scan p99 2–4 ms in replay and live PDSCH saturation around 400 grants/s. The appended §T26b/§T26c evidence is in `git show csd/t26b:docs/superpowers/reports/csd/T26.md` (current branch has the [T26 base report](../reports/csd/T26.md)); reread the integrated report at implementation time. The nID-10163 population has real repeatable DCI but no PDSCH CRC under the tried scrambling IDs; neighbour PCI is a **hypothesis**, not an identification.
- [CALCULATED] sc16 is 4 bytes/complex sample, so 122.88 MS/s costs **0.49152 GB/s per RX**, four streams **1.96608 GB/s** of ingress (15.73 Gb/s before framing). RXR removes one ring staging read and write: **3.93216 GB/s** of memory traffic at this rate, calculated rather than measured OTA. The stated additional CPU-coherent memory headroom is roughly **2 GB/s** before DPDK drops; any channelizer, duplicated IQ, or extra ring cursor must be accounted for against it. Source: `git show csd/rxr:docs/superpowers/reports/csd/RXR.md` and `PROJECT_MEMORY.md` 2026-10-08 RXR updates.
- [CODE-READ] The current `radio/USRP/usrp_lib.cpp:2825-2890,3061-3063` sets rates/frequencies by channel but creates one RX streamer over a contiguous channel list; `:2141-2159` retunes all channels to one frequency on reconfiguration. This is **not** a multi-frequency control plane. [T23](../reports/csd/T23.md) reserves DPDK/control/reader cores but plans one RU; it has no runtime multi-carrier replan. [T24](../reports/csd/T24.md) and [T24b](../reports/csd/T24b.md) define one shared GPU discovery budget; 30%/rolling second and a 250 µs RT deadline are settings awaiting GB10 contention validation, not a per-cell entitlement.

## Channel allocation and runtime switching

Profiles assign **physical RX channels**, antenna locations, RF centres, gain, DDC settings, and stream routes. A carrier can hold several co-channel PCIs; each consumes cell compute but no extra RF stream. The minimum steady profile is **2×A + 2×B**, with A and B chosen from different operators after SIB1 evidence. One operator may have multiple cells on A/B. A third separated carrier/operator needs the 1× profile or a proven channelizer; the 1× profile loses array sensing.

| Profile | Example mapping and sc16 ingress | Sensing / decoding trade-off | Admission |
|---|---|---|---|
| `4×A` | All four at A, 122.88 MS/s: 1.966 GB/s | Best array aperture/MRC and AoA baseline; many co-channel PCIs, one carrier/operator unless another operator shares the same captured band. | Calibration and 4-RX baseline; no simultaneous separated second operator. |
| `2×A + 2×B` | ch 0/1 at A, ch 2/3 at B, same aggregate 1.966 GB/s; remap after channel-2 repair | Two simultaneous operators with two complex branches each; lower diversity and AoA aperture than four; poor channel 2 can make B effectively one-branch. Same-carrier channels must sample the same RF epoch and be phase calibrated. | **Default target** for G13/G14. Compare per-carrier PBCH, SNR, CFR and AoA to 2-RX single-carrier baselines. |
| `1×{A,B,C,D}` | One channel each, 122.88 MS/s: 1.966 GB/s | Up to four separated carriers/operators but no multi-antenna AoA on any carrier; useful traffic inventory/health only. Do not claim the user's sensing minimum from this profile. | Opt-in coverage mode; label AoA unavailable. |
| Wideband + GPU channelizer | Example 2×245.76 MS/s: 1.966 GB/s, or 4×491.52: 7.864 GB/s before derived channels | Can keep two spatial branches across several carriers within their common analog passband; FFT/polyphase channelization, filtering and per-output phase delay must be validated. A single RF path split digitally does not increase physical antenna count. | Experimental; admit only after RF passband, host traffic, CUDA latency and phase gates. Prefer FPGA DDC where possible. |

Switching is a **coordinated RF configuration transaction**: DiscoveryManager proposes a profile from observed SSB inventory and sensing priorities; admission checks physical channels, both operators' continuous coverage, calibration validity, link/CPU/GPU budgets; stream quiesces at an epoch boundary; hardware retunes/sets DDC/gain; actual settings and channel map are read back; a fresh common sample-time origin is published; affected cell tasks reject old tickets and revalidate SSB/PBCH before use. Profile changes create observation gaps and invalidate AoA calibration until checked. They are exceptional reconfiguration, **not** an alternating operator dwell schedule. When two target operators cannot each retain two RX channels in one steady profile, report unsatisfied sensing coverage instead of hiding a time-share behind G14. Operator selection may prioritize an observed PLMN, never seed a PCI or decoder parameter.

## Pipeline and state ownership

`DiscoveryManager → CarrierContext → CellContext → UeContext`. The manager keeps a bounded SSB/PCI inventory, RF profile, per-carrier admission and event scheduler. A carrier owns its channel subset, common timestamp/ring and read cursors, RF epoch, band/grid and **shared FFT/FEP only when numerology, sample grid, symbol boundary and residual CFO are compatible within the CP**. Otherwise share raw IQ but compute separate FFTs; a shared FFT must not silently force the strong cell's timing/CFO on the weak one. Each cell owns independent PSS/SSS/PBCH, SFN unwrap, timing/CFO servo, MIB/SIB1 or NSA fallback, TDD, CORESET/SearchSpace, CSI-RS/ZP, nID discovery, PDCCH/PD(S/ U)SCH hypotheses, health and configuration epoch. A cell key is `(carrier RF identity, PCI, SSB frequency, physical cell identity evidence)`; PLMN/cell identity may refine it after SIB1, and PCI alone is insufficient across carriers. The UE key is `(carrier_id, cell_track_id, RNTI, reuse_generation)`; a numeric RNTI never crosses cells. A DCI on a configured nID is **not** proof its PDSCH belongs to the serving PCI.

Migration first wraps the legacy singleton into exactly one context behind a default-off multi-cell feature, preserving single-cell behavior. A temporary one-process-per-cell prototype may test isolation, but two full RF streamers cannot own the same X410 capture independently; production uses one RF reader and shared immutable IQ windows with cell-specific cursors. Reference-counted windows and per-job `(rf_epoch, cell_config_generation, RNTI_generation, sample range)` prevent stale reads. RXR restart increments the RF epoch; the cell's cheap reacquisition follows it. The existing acquisition module is a reporter, so a controller is new work, not a rename.

## Compute, scheduling and persistence

At 30 kHz SCS there is a 500 µs slot. **Budget is an admission inequality, not an assumed speedup:** per-carrier fixed cost `C_RF + C_channelize + C_shared_FEP`, plus each cell's periodic `C_PBCH + C_PDCCH + C_RS`, plus per-grant `C_DL/UL`, plus discovery duty must fit measured X925, GPU and memory service with p99 deadline margin. Record CPU time, queue lag and memory traffic per component and per `(carrier,cell)` at 2 RX and 4 RX; extrapolate only after simultaneous runs. One cell's observed 2–4 ms PDCCH p99 already exceeds a 500 µs slot and proves that duplicating the present worker per cell is inadmissible. The T26c big-core placement (X925 5–9,15–19; DPDK 17–19 in the current arrangement) and T23 core planner are starting points; reserve RF reader/DPDK/control first, then PDCCH and FEP, then PDSCH/UL and discovery. GPU RT work gets first admission; the T24/T24b discovery 30% rolling budget is **global**, divided fairly among active cells and paused for confirmed banks. Measure actual CUDA occupancy, fallback, RT waits and CPU copies on GB10; unified memory does not eliminate all host traffic.

Provisional admission ledger for the **2×A+2×B, one busy cell per carrier** case (targets to measure, not demonstrated capacity):

|---|---|---|

Profile is invalid regardless of decode success. |

| Shared GPU discovery | T24 setting: ≤30% CUDA event time in any rolling second; with two equally active cells, initial fair shares ≤15% each, lent to the other when idle. The X925 reservations are a **capacity test**, not hard pin numbers: only seven X925 cores remain outside current DPDK cores 17–19, and one busy single-cell chain already occupies several. The ledger therefore forces an efficiency decision before a third carrier or busy cell is admitted; average CPU utilization alone cannot certify the p99 slot path.

The scheduler is event driven. Every cell gets nonstarving SSB/PBCH, known SearchSpace occasions, configured CSI-RS and low-cost health probes. Expensive SSB sweep, nID search, CORESET geometry, anonymous RNTI and Technique D probes run on **new SSB/PCI**, first entry, bank/config/RNTI change, health degradation or long RF gap; discovery tokens are bounded per carrier and cell and charged against the one global GPU/CPU budget. Known UE grants and sensing pilots outrank speculative hypotheses. When overloaded, shed diagnostic logging and probes, then lower-value PDSCH decode jobs while preserving RF drain, cell sync and calibrated CFR; publish gaps/drops per cell. Never silently starve one operator. A runtime increase in cell count must pass admission using measured 1-cell and 2-cell costs; “more the better” cannot mean unbounded workers.

Persistence follows `PROJECT_MEMORY.md` §19: SEARCH → SSB_LOCK → MIB_LOCK → COMMON_CONFIG/NSA → TRAFFIC_DISCOVERY → TRACKING → DEGRADED → LOCAL_REACQUIRE → GLOBAL_SEARCH. Keep validated cell/UE evidence across RF epochs as a **hint**, with source, confidence, signal-time expiry and config generation; revalidate PBCH/CORESET and fresh CRC before returning to TRACKING. Cell loss never purges another cell. RNTI reuse, SIB1/TDD changes and strong/weak cell handoffs invalidate only affected hypotheses. Log each transition and bounded rediscovery time. RXR may provide timed stream restart and direct ring read, but its corrected OTA fault recovery is still a separate gate.

## Interference and sensing output

For co-channel PCIs, detect multiple SSB peaks in one immutable capture and track their timing/CFO separately. Evaluate weak-cell PBCH/CSI-RS/CFR and grant CRC at a stated SIR against its single-cell capture; no strong-cell timing capture is allowed (G12). First use cell-specific RE masks and robust estimators. Optional strongest-cell RS reconstruction/subtraction is admitted only when a replay demonstrates weak-cell gain without strong-cell damage; subtraction must carry channel/phase estimate uncertainty and never subtract unknown PDSCH data as truth. Co-channel UE ownership is inferred from cell-linked CORESET/DM-RS/PDSCH-CRC evidence; nID-10163 alone cannot assign one.

Export each observation with `(carrier_id, cell_track_id, PCI, PLMN if decoded, cell identity if decoded, RNTI + reuse epoch if UE-linked, rf_epoch, cell_config_generation, sample timestamp, antenna map, calibration id/age, uncertainty)`. Per-cell products: SSB/CSI-RS CFR, RSRP/SINR, delay/Doppler and beam history; per-UE products: grant-linked DL/UL DM-RS CFR, AoA and uncertainty when at least two **calibrated physical antennas on that carrier** exist, plus quality/CRC/association confidence. Preserve complex per-antenna CFR before combining. Existing Sensing API v2 (`PROJECT_MEMORY.md` §21) carries single-PCI records and NRCF frames; add versioned carrier/cell/UE identity and calibration metadata to records **and** CFR linkage, then compute AoA downstream from those coherent CFRs. Test old-reader compatibility or publish an explicit schema version bump. `1×` profiles mark AoA unavailable; `2×` AoA has limited aperture/ambiguity, and the weak RX 2 must not be concealed by an “antenna count 2” label. Unknown PLMN stays unknown, especially for NSA/SIB1-less cells.

## First risks to measure

1. [HYPOTHESIS] nID-10163 grants belong to a neighbour PCI. Correlate independently detected PSS/SSS/PBCH and test that PCI's PDSCH DM-RS/data scrambling on the **same grants**; CRC/RS consistency and cell-timing alignment decide. Do not count a second PCI from an nID alone.
2. [QUESTION] Distinct-frequency channel pairs on both ZBX boards, actual DDC settings, lock stability and calibrated inter-channel phase across boards. This decides whether `2×A+2×B` meets sensing rather than merely decoding.
3. [MEASUREMENT REQUIRED] 2-operator simultaneous DPDK stream and RF reader/GB10 memory headroom; 300/600 s zero-drop captures at 2+2 before any decoder claim. Second QSFP link is optional only if measured necessary and physically available.
4. [MEASUREMENT REQUIRED] Real-time two-cell and two-carrier PDCCH/PDSCH/CSI-RS CPU/GPU tails after T26c efficiency merges. Replay speed below real time and one 120 s clean RXR run are insufficient for G12–G14.
5. [MEASUREMENT REQUIRED] AoA calibration and strong/weak-cell tolerance, particularly RX channel 2 and possible inter-board frequency offset. Publish uncertainty or suppress AoA when calibration fails.

# K35 — GPU FEP hygiene

## Change

`[CODE-READ]` The existing CPU post-FEP lifetime check already rejected stale GPU results as `UNSUPPORTED`. K35 prevents those expired requests from wasting the single GPU lane and makes the self-check compare the correct slot and enforce a health decision.

- `[CODE-READ]` `nr_pdsch_passive_queue.c` passes the source absolute slot to the single GPU worker. It checks the producer's slot before FEP and after the synchronous FEP copy, rejecting expired requests before LLR generation. A rejected request falls back to the existing CPU decode path, whose lifetime check returns `UNSUPPORTED` for expired IQ.
- `[CODE-READ]` The worker snapshots the resident GPU `rxdataF` into the requesting consumer's buffer before servicing another slot. The snapshot is an optional operation in the same FEP request: a separately queued read could observe a later resident slot. A CPU rerun returning `UNSUPPORTED` is skipped; a CPU rerun returning `ERROR` fails the health gate.
- `[CODE-READ]` `nr_gpu_fep_hygiene.h` applies the health thresholds: FEP correlation >= 0.9999, FEP scale 0.99–1.01, LLR sign agreement >= 0.999, CRC agreement. The first 32 valid GPU jobs are checked by default; `ISAC_GPU_SELFCHECK=0` disables the check. A failing job's GPU result is discarded. Two failures set `g_gpu=NULL` for the run and emit one error log. `NR_GPU_FEP` remains opt-in.
- `[CODE-READ]` `nr_passive_metrics.{h,c}`, `nr_passive_metrics_json.c`, and the queue stats expose `gpu_fep_stale_pre`, `gpu_fep_stale_post`, `gpu_fep_selfcheck_fail`, and `gpu_fep_disabled` in `ISAC_METRICS`. `PROJECT_MEMORY.md` updates only K35 and its §11 log/metric entries.
- `[OFFLINE VERIFIED, DGX aarch64]` `nr_gpu_fep_hygiene_test.cc` covers a request expiring while waiting, expiry during FEP, and tolerance boundaries without CUDA.

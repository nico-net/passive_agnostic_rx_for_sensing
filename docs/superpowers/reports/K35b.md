# K35b — GPU FEP health gate review fixes

## Changes

- `[CODE-READ]` The self-check now counts a GPU job as `gpu_fep_selfcheck_skipped` when the CPU rerun is unsupported or errors, has no current LLRs, has no comparable LLRs, lacks a valid same-slot GPU FEP snapshot, or the source IQ has expired by the time the CPU reference finishes. Skips consume no checked-job budget and cannot trip the health gate. `nr_pdsch_passive_decode()` already resets its thread-local `t_last_llr` and `t_last_G` at the start of every decode body; the self-check requires a non-null LLR pointer and nonzero count from that rerun.
- `[CODE-READ]` Sign agreement uses only CPU LLRs with `|LLR_cpu| > 8` in the decoder's int16 units. If none qualify, the check is skipped. The per-bit diagnostic log still covers all bits; the gate's `sign_agree` field covers only qualified bits. The correlation and scale thresholds remain uncalibrated on live 4-RX hardware.
- `[CODE-READ]` `ISAC_GPU_SELFCHECK` still defaults to 32 comparable jobs. With `NR_GPU_FEP=1`, self-check is now **OBSERVE** by default: comparable failures are logged and counted, but do not discard a GPU decode or disable FEP. `ISAC_GPU_SELFCHECK_ENFORCE=1` opts into discarding failing decodes and disabling GPU FEP after two failures. The disabled metric flag is set before the GPU API pointer is cleared; both are atomic.
- `[CODE-READ]` `gpu_fep_selfcheck_skipped` is exported in queue stats and `ISAC_METRICS` JSON. `NR_GPU_FEP` remains off by default.

## Findings and decisions

1. **Persistent VERIFY — fixed.** [CODE-READ] `nr_pdsch_config_sweep.c` no longer clears `verify_left` during CB0/prune evidence resets. Rebuild carries the budget and content-valued hint alongside configuration flags; new/recycled contexts explicitly initialise both. The existing selector matches the hint by geometry, MCS table and DM-RS mask, so catalogue indices are not a hint identity. [OFFLINE VERIFIED] `VerifySurvivesPruneAndRebuild` exercises a destructive prune and template rebuild, then checks all remaining selections: 24 preferred slots in the 32-selection budget, without synthetic acceptance evidence.

2. **Class/cause scope and eager copies — fixed.** [CODE-READ] Scope is documented in `nr_passive_cfg_epoch.h` and the table below. The authority retains the latest broad dedicated-state invalidation epoch, including in queued snapshots, so a later narrow SOFT cannot hide a HARD_REVERIFY from lazy consumers. Sweep listeners update small context metadata and mark pending VERIFY; `find_context` rebuilds only the context next selected. Pending contexts cannot report settled/evidence or accept stale tickets. Tickets now explicitly carry the central epoch, preserving stale-feedback rejection on narrow SOFT while retaining the context's evidence and generation. [OFFLINE VERIFIED] Short-gap/BWP/CSI-RS tests cover sweep, lengths, pins and bank; dedicated-change tests cover all four; copy-count and hard-then-soft lazy-lookup tests cover the delayed paths. Sixteen settled contexts cause zero template copies during drain, one on first lookup, and no second copy on repeated lookup.

3. **Idle epoch-STALE removal — fixed.** [CODE-READ] `nr_pdcch_coreset_bank.c` starts the sentinel removal timer only when `elsewhere` is true, including accepted traffic in another bank entry. The existing timer policy after traffic has supplied absence evidence is unchanged. [OFFLINE VERIFIED] `IdleCellEpochStaleNeverRemoved` stays STALE through idle ticks at slots 100/1000/10000, starts the timer on traffic elsewhere, and removes only at its deadline.

4. **UL relock reopening DL — fixed.** [CODE-READ] `nr_pdcch_blind_monitor_rt.c` passes direction to the relock helper and `nr_pdsch_config_sweep_relock_length`; the latter returns immediately for UL. DL third-length replacement also passes the replacement length. [OFFLINE VERIFIED] `UlRelockLeavesDlAloneAndDlCarriesHintToNewKey` keeps the DL winner and generation across UL relock, then checks the DL transition.

5. **New DL length loses the hint — confirmed and fixed.** [CODE-READ] The auto configuration key appends DCI length with one invertible FNV step. Targeted DL relock records the corresponding new key on the old context. Creation of that exact geometry/layout/RNTI/TDA/type-A key consumes only its ordering hint, with a fresh 32-selection VERIFY budget and zero CRC evidence. Transfer is bounded by the existing context LRU and identity scope; the source is not copied as trusted state. Hint lookup runs only while installing a context, not on every grant. [OFFLINE VERIFIED] The direction/transfer test selects the new key and observes the old winner first, `verify_left=31`, and all-zero CRC successes.

6. **Hot-path snapshots/subscription — confirmed and fixed.** [CODE-READ] Sweep selection, length-store lookup and bank dispatch compare the atomic current epoch before taking a snapshot. Sweep subscription is once per sweep lifetime (reset re-subscribes for a new authority lifetime). No drain is introduced under receiver locks; the authority still releases its lock before callbacks. [OFFLINE VERIFIED] Pending-drain, selection-straddle, concurrent bank and shuffle fixtures remain covered. No latency measurement is claimed.

7. **HARD_RESET removal hook — not a bug in the present consumers.** [CODE-READ] The sole production hook, `bank_reopen_geometry` in `nr_pdcch_blind_monitor_rt.c`, clears matching DL/UL length banks and resets all TD contexts. Length stores already key banks by `identity_gen`; sweep selection/feedback already reject old identities. Both retain old records dormant, as allowed by §4.4. Calling this hook during identity archival would discard dormant records and could reset newly created new-identity contexts. Keep lease-drained archival without the hook; the bank comment records this rationale. [OFFLINE VERIFIED] Existing bank/length/sweep HARD_RESET isolation tests pass.

8. **Reopen timestamp — confirmed and fixed.** [CODE-READ] The authority exposes the current tick slot; health-driven sweep reopen uses it instead of the last bound DCI slot (which can be zero or old). [OFFLINE VERIFIED] `ReopenUsesCurrentSlotWithoutLengthBinding` rejects a false cell-wide trigger for reopens 9900 slots apart and accepts two distinct reopens at slot 10000.

## Class/cause → consumer mapping

[CODE-READ] This table implements the requested affected-context interpretation of SPEC_CURRENT §4.4–4.5. A BWP geometry change additionally changes the pre-existing geometry/configuration keys; a SOFT signal alone does not assert every UE changed its dedicated configuration.

| Class / cause | Published cell lengths / shared TD prior | Per-RNTI lengths | Technique D contexts | Layout pins | CORESET bank | CellFieldBook / queued work |
|---|---|---|---|---|---|---|
| SOFT CONTINUITY_LOSS (<10 ms by default) | Withdraw publication | Keep LOCKED and evidence | Keep winner, evidence and generation | Keep if geometry matches | Keep geometry proof | R11 mirror, drop field trust/bonus; reject old work/tickets |
| SOFT CSIRS_MAP_CHANGE | Withdraw publication | Keep | Keep | Keep if geometry matches | Keep | Same R11 / stale-work actions |
| SOFT BWP_CHANGE | Withdraw publication | Keep under existing geometry key | Keep under existing configuration key | Existing geometry mismatch still invalidates | Keep | Same R11 / stale-work actions |
| SOFT DEDICATED_CHANGE_SUSPECTED | Withdraw; clear broad TD observations/certifications | LOCKED → SUSPECT; old primary/secondary ordering hints | Pending VERIFY, applied on next lookup; old winner hint | Invalidate | STALE; removal clock waits for traffic elsewhere | Same R11 / stale-work actions |
| HARD_REVERIFY (MIB/SIB1/SI boundary/hard continuity) | Same broad invalidation | Same SUSPECT action | Same lazy VERIFY | Invalidate | Same STALE action | Same R11 / stale-work actions; broadcast re-derivation remains with its existing owners |
| HARD_RESET / identity change | Clear new-identity shared state | Old banks dormant by identity | Old contexts dormant by identity; no hint transfer | Invalidate | Archive after dispatcher leases drain | R11 clears old fields; reject old work/tickets |

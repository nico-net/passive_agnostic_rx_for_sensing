## Changes and decisions

- [IMPLEMENTED, NOT VALIDATED on live traffic] The accepted DCI 0_1 path in `nr_pdcch_blind_monitor_rt.c` sends a nonzero CSI-request, its DCI absolute slot and any coincident confirmed NZP CSI-RS resource to R17's bounded UeContext event queue. Duplicates and rejected candidates do not enter this hook. `ISAC_RECONF=1` and `ISAC_UECTX_PATH` are required to open the writer; with either absent the path remains inactive.
- [IMPLEMENTED, NOT VALIDATED on live traffic] `nr_csirs_blind_rt.{c,h}` reads the first confirmed NZP resource due in the trigger slot with `pthread_mutex_trylock`. A busy search lock, disabled blind search or no due resource yields JSON null. It does not update CSI-RS search statistics. This is a coincident observed resource, not a claim about the CSI configuration selected by the DCI request; that linkage is unavailable to the passive receiver.
- [IMPLEMENTED, NOT VALIDATED on live traffic] `nr_passive_ue_ctx.{c,h}` serializes `ue_change` param `APERIODIC_CSI`: `new` is the CSI-request value, `abs_slot` is the triggering DCI slot and `evidence` is null or an object with row, frequency bitmap, RB range, first symbol and scrambling ID. It never emits `ue_reconfig`. The producer packs the small resource into the existing bounded queue event and performs no I/O or blocking lock operation.

# R5 — CORESET bank life cycle

Host: DGX aarch64 (`spark-74c3`). Branch: `rr/reconfig-robustness`.

## Changes and decisions

- [OFFLINE VERIFIED] `nr_pdcch_coreset_bank.{h,c}` adds VERIFIED, STALE and REMOVED health, the three plan APIs (`remove`, `note_accept`, `tick`), fresh DCI re-verification using two later slots with the same RNTI and different payload hashes, and removal with compaction. A bank mutex protects updates and lookups. A dispatcher lease preserves borrowed cfg/AL1 pointers until all readers finish; pending compaction stops new dispatchers until the last reader leaves.
- [IMPLEMENTED, NOT VALIDATED on live reconfiguration] `nr_pdcch_blind_monitor_rt.c` enables tick, acceptance bookkeeping and removal only with `ISAC_RECONF=1`. Defaults are 5 s to STALE and 30 s from STALE to REMOVED, converted to slots using the current numerology. Unique CORESET#0-USS accepts and accepts on other bank entries are the current elsewhere-traffic sources. STALE entries continue to be searched. `ISAC_RECONF` unset/0 keeps the previous dispatcher path.
- [IMPLEMENTED, NOT VALIDATED on live reconfiguration] The remove hook clears matching DL/UL length banks and reopens Technique D. Technique D has only a global reset API, so this also reopens other geometries; this is the same R3/R4 limitation. `verified_epoch` is reserved for the later unified epoch owner and remains zero in R5.
- [OFFLINE VERIFIED] `tests/nr_pdcch_coreset_bank_test.cc` and `CMakeLists.txt` add the five named tests plus concurrent note/tick and deferred-compaction tests. Re-verification requires a changed payload; an identical repeat leaves the entry STALE.

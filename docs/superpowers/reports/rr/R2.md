# R2 — DCI lengths through 140 bits

Host: DGX, aarch64. Baseline: `26a217bbf2aa6a1d9e76158645380a3b255bc851` (R1).
CPU decoder commit: `088163a80c`. The following R2 commit contains the migration,
search order, GPU source/test changes, and this report. Scope is R2 only.

## Changes and decisions

- [OFFLINE VERIFIED] CPU polar now encodes/decodes A through 140, K through 164.
  `nr_polar_encoder.c` expands the interleaving lookup to three words and packs
  wide CRC input explicitly. `nr_polar_decoder.c` extracts all payload words.
  `nr_polar_defs.h` expands lookup tables, decoder-tree storage and operation
  storage: the former tree allocation also proved too small for wider DCI.
  The existing A <= 64 CRC/extraction branches remain unchanged. The table
  construction preserves their bit mapping; the byte loop stops at ceil(K/8).
- [OFFLINE VERIFIED] `nr_pdcch_blind_monitor.{c,h}`, runtime, UL discovery,
  layout sweep, BWP tracking, passive queue, grant deduplication and replay
  storage carry `nr_dci_bits_t`. `dci_nr.c` allocates three decoder words.
  Indicator/field reads cross word boundaries; re-encoding uses all words.
  Wide 1_0/0_0 padding checks cover every padding bit. Existing narrow fixture
  inputs and expectations retain their values through explicit type adapters.
- [OFFLINE VERIFIED] Sweep arrays and CPU/GPU caches index 0..140; default
  length range is 30..140. The final grep also found UL field-generation and
  UL discovery guards and the UL supported-length count; these now use the
  wider bound/range. Invalid A+24 > 108*AL candidates are rejected before
  constructing polar parameters (notably A > 84 at AL1).
- [OFFLINE VERIFIED] Seen lengths are shared atomic ordering hints across
  RNTIs/geometries. A sweep snapshots distance order for a complete rotation,
  including budget suspensions. Equal distances use increasing length; no
  hints means increasing length. Existing significance/recurrence gates are
  unchanged. Tests check 47,46,48,45,49,44,50,43,51,42, complete coverage,
  budget resume, and hints shared by independent contexts. Narrow sweep
  payload hashes retain the previous low-word XOR calculation; wide hashes
  include all declared bits. Capacity needs no `ISAC_RECONF` flag.
- [OFFLINE VERIFIED] **Joint-solver decision: retain the opt-in <=64 guard.**
  `nr_pdcch_joint_solve.c` has two-word GF(2) vectors, JMAX_K=96, and scalar
  payload construction (A + 16 RNTI + 16 n_ID). Public payload interfaces now
  use the vector, but extending those matrices is unnecessary for the normal
  polar path. `ISAC_PDCCH_JOINT=1` rejects wider calls before solving and logs
  once using an atomic flag. `nr_pdcch_gf2_rnti.c` solves scrambling identity,
  not a payload-sized matrix; it needs no change. Wide polar decoding and
  the opt-in rejection have separate passing tests.
- [IMPLEMENTED, NOT VALIDATED] GPU host extraction and both batch APIs carry
  three words; the parameter cache grows to 704 (140 lengths x five ALs).
  Existing kernel N=512/E=2048/op limits already cover DCI. Lane/sweep caches
  retain per-item CPU fallback for `ok=0`. The loader uses
  `nr_gpu_polar_api_v2` so an old one-word plugin cannot silently corrupt the
  new output stride. `nr_polar_sc_cuda_test` compares all words against CPU
  at A=80,128,129,140, plus prior shapes and the shared-vector sweep. CMake
  registers its quick correctness mode only with ENABLE_LDPC_CUDA and
  ENABLE_TESTS. No CUDA configuration, build, test or benchmark was run.
- [IMPLEMENTED, NOT VALIDATED with captured IQ] Discovery replay is same-build
  ABI v3 (incompatible with v1/v2). Passive replay embeds larger records and
  rejects old files via header/job size checks. DISCOVERY_EVIDENCE JSON prints
  all payload words; older human-readable diagnostic lines still show the
  low word. Use JSON or new binary captures for wide payload reconciliation.

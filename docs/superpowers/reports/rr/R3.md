# R3 — per-RNTI DCI length re-lock

Host: DGX aarch64. Branch: `rr/reconfig-robustness`. Scope: R3 only.

## Changes and decisions

- [OFFLINE VERIFIED] `nr_pdcch_dci_length_sweep.{h,c}` now provides `SEARCHING`, `LOCKED`, and `SUSPECT` context state, a default 200-occasion threshold (`ISAC_RECONF_N_SUSPECT` override), the requested `note_occasion` and `relock_order` interfaces, and a lock transition. A miss counts only when the locked length's candidate set was searched. Inactivity cannot by itself cause SUSPECT. A SUSPECT context retains the old length as its first hypothesis; other cell-seen lengths follow, then the full 30..140 range. The existing significance gate still decides the re-lock.
- [IMPLEMENTED, NOT VALIDATED on live reconfiguration] `nr_pdcch_blind_monitor_rt.c` enables the transitions only with `ISAC_RECONF=1`. DL and UL accepted lengths update the corresponding per-RNTI context under its existing lock. Recent persistence/CFRA-RAR sightings and accepts from other geometries supply activity without CORESET#0. When a locked DL length has 200 misses but no fresh external activity, a bounded one-candidate scout runs every twentieth occasion; its repeated exact-RNTI evidence can make the context SUSPECT. SUSPECT sweeps reuse R2's `sweep_gpu_prefill` batch and per-item CPU fallback. No GPU run was made.
- [IMPLEMENTED, NOT VALIDATED on live reconfiguration] A significant same-length result restores LOCKED. A different result replaces the old length and logs `DCI length RELOCK rnti=… old=… new=…`. On re-lock the existing `nr_pdsch_config_sweep_reset_all()` entry point reopens Technique D and the existing `nr_dci11_pin_select()` configuration-mismatch path invalidates that RNTI's pin. This Technique D API is global, so one RNTI's re-lock also clears other Technique D contexts; a targeted reopen API does not exist in the header, and `nr_pdsch_config_sweep.c` was not changed. R4's per-length pin is still pending.
- [OFFLINE VERIFIED] `nr_pdcch_blind_rnti_bootstrap.c` adds a lock-protected fresh-RNTI query. `nr_pdcch_blind_monitor.h` declares it. Default `ISAC_RECONF` unset/0 retains the previous sweep, acceptance, and pin paths; the added secondary exclusion is used only by the enabled scout.
- [OFFLINE VERIFIED] `tests/nr_pdcch_dci_length_sweep_test.cc` adds all six named tests: `LockedToSuspectAfterNMisses`, `InactiveRntiNeverSuspect`, `SuspectWithoutCoreset0Evidence`, `RelockSameLengthReturnsLocked`, `RelockDifferentLengthReplaces`, and `RelockOrderOldFirst`. The two re-lock tests feed the existing significance engine before calling the transition.

# R8 — epoch trigger sources

Host: DGX Spark (`spark-74c3`, aarch64). Branch: `rr/reconfig-robustness`.

## Changes and decisions

- [OFFLINE VERIFIED] `nr_passive_cfg_sources.{c,h}` supplies canonical integer/bit hashing, MIB hashing without SFN, half-frame or SSB index, P-RNTI short-message parsing, SI modification-period calculation, the five-second SIB1 request cadence, and the `(PCI, semantic hash)` cache filename. `nr_passive_cfg_epoch.{c,h}` adds the source-facing Point A refinement, SI period and monotonic SFN/slot helpers. CMake links one epoch authority into the receiver and MAC tests.
- [IMPLEMENTED, NOT VALIDATED on live traffic] `config_ue.c` hashes decoded SIB1 fields in a fixed order: PLMN, cell identity, TAC, DL/UL carriers and initial BWPs, common PDSCH/PUSCH TDRA, PDCCH common CORESET/search spaces, TDD patterns, and RACH fields. Bit-string padding is ignored; omitted MCC inherits the preceding decoded MCC; optional default values used by the receiver are normalized. A SIB1 decoded on any cell feeds the epoch authority without an SA/NSA flag. The existing common-facts cache uses `(PCI, semantic hash)` with `ISAC_RECONF=1`; it waits for a live semantic hash before loading a cache entry. Flag-off cache filenames and behavior remain unchanged.
- [IMPLEMENTED, NOT VALIDATED on live traffic] `nr_ue_procedures.c` feeds the MIB hash and decoded P-RNTI DCI. The blind monitor feeds both accepted paging-plus-short-message DCI and short-message-only DCI; the latter remains rejected as a PDSCH grant. The first short-message bit is `systemInfoModification` ([ETSI TS 38.331 §6.5](https://www.etsi.org/deliver/etsi_ts/138300_138399/138331/16.05.00_60/ts_138331v160500p.pdf)); indicator 10/11 contains a short message ([ETSI TS 38.212 §7.3.1.2.1](https://www.etsi.org/deliver/etsi_ts/138200_138299/138212/17.10.00_60/ts_138212v171000p.pdf)). The period is `modificationPeriodCoeff × defaultPagingCycle × slotsPerFrame`, read from decoded SIB1. Duplicate observations for one boundary coalesce.
- [IMPLEMENTED, NOT VALIDATED on live traffic] `nr_ue_dci_configuration.c` requests a fresh SIB1 every five seconds when CORESET#0 exists and immediately after an SI-modification announcement, and advances the pending boundary. Passive P-RNTI monitoring with UE_ID=0 is enabled only under `ISAC_RECONF=1` so short messages can be observed. The blind scan advances the boundary when MAC monitoring is absent. `nr-ue.c` feeds acquired PCI/SSB frequency, numerology, and receive-stream continuity loss. The blind RT path feeds confirmed BWP switches and R3 LOCKED→SUSPECT transitions for DL and UL with `was_converged=true` and monotonic slots. All source calls are gated by `ISAC_RECONF=1`; no SA/NSA mode flag was added.
- [OFFLINE VERIFIED, source inspection] Passive MAC did **not** request periodic SIB1 re-decode: `nr_ue_decode_BCCH_DL_SCH()` clears `mac->get_sib1` after a successful decode, and the pre-existing setter `nr_rrc_mac_sched_sib()` runs only when RRC schedules SIB1. The new periodic request hook is therefore needed. It is gated by `ISAC_RECONF=1` and by the presence of CORESET#0; SIB1 remains optional on every network mode.
- [PLANNED] Technique D's `reopen_context()` and its sole recovery call are inside `nr_pdsch_config_sweep.c`. Adding the note there would change that file's internals, which are reserved for R10 after the levers merge. R10 must wire `nr_cfg_epoch_note_rnti_reopened(..., true, slot)` at that call and review listener lock order. No Technique D internals were changed here.

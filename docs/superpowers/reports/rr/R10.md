## Changes and decisions

- [CODE-READ] `nr_pdcch_blind_monitor_rt.c` subscribes the DL/UL length stores before the R8b drain, outside receiver locks. Stores also synchronise on lookup to cover another consumer already draining. `nr_pdcch_dci_length_sweep.{c,h}` demotes LOCKED to SUSPECT, clears accumulated evidence and published cell priors, and tries the old primary first. The old secondary becomes an ordering-only hint; confirming the primary does not re-trust the secondary. Successful locks stamp the central epoch. Hard resets retain dormant, identity-generation-keyed banks in the bounded LRU.
- [CODE-READ] `nr_dci11_pin.{c,h}` adds the central epoch to the pin's configuration identity, preserving the complete geometry key. Stale pins fail validity and selection until reseeded.
- [CODE-READ] `nr_pdcch_coreset_bank.c` subscribes on use and synchronises before dispatch. Epoch changes make entries STALE and clear re-verification proof; the existing same-RNTI, later-slot, different-payload rule restores VERIFIED and stamps its epoch. The removal timer starts at the next producer tick. HARD_RESET archives one dormant bank with its identity generation; geometry storage is cleared only after dispatcher leases drain, without invoking the unrelated geometry-removal reset hook.
- [CODE-READ] `nr_pdsch_config_sweep.{c,h}` keeps old identities dormant in the context LRU. Selection, tickets, settled counts and context statistics reject stale identity/epoch records, including the interval before callbacks drain. SOFT/HARD_REVERIFY rebuild legal catalogues, clear old CRC/CB0/observation/certification/dormancy evidence, and enter bounded VERIFY: the previous winner is preferred on 24 of the first 32 selections, with eight ordinary exploration picks. Hints contribute no acceptance evidence; existing TB-CRC separation still elects the winner. Consecutive bumps preserve a pending hint. HARD_RESET clears shared priors/observations and fieldbook contents; R11 owns central fieldbook mirroring.
- [CODE-READ] Actual health-driven `reopen_context()` now calls `nr_cfg_epoch_note_rnti_reopened(rnti, true, slot)`. The new binding API records each context's source DCI length and monotonic DCI slot. Epoch-induced VERIFY does not call this source hook, preventing a feedback-trigger loop.
- [CODE-READ] Genuine changed-length RELOCK and third-length replacement call `nr_pdsch_config_sweep_reopen_length(rnti, old_length)`. Other RNTIs and other lengths retain their context generations/evidence. Automatic layout configuration keys include the DCI length to avoid aliasing the same layout index across lengths. Existing geometry-removal reset scope is outside this deferred RELOCK fix.
- [CODE-READ] New behavior is gated by `ISAC_RECONF=1`. The flag-unset selection, backend, fieldbook=2, GrantWork, CB0 elimination and acquiring-TB CPU defaults remain selected as before.

# S2 — sensing engine removal and receiver export adapter

## Changes and scope

[CODE-READ, DGX aarch64] `nr_isac.cc` now only reads configuration, opens/closes the Task 1 exporter, converts the receiver's RE indices, and submits CFR frames. All seven legacy source enums map explicitly to the six export sources; both PDSCH DM-RS enums map to PDSCH DM-RS. Each multi-antenna submission makes one antenna-major frame, preserving its stride, slot, fraction and noise variance. No sensing algorithm runs.

[CODE-READ, DGX aarch64] Removed every D1 algorithm source/header/test and the replay executable, including the old algorithm configuration header. Retained `nr_isac_ssb_axis.{c,h}`, the receiver portions of `test_nr_isac_ssb_source`, and `test_dlsch_fixed_point`. CMake links the adapter in ON mode and `nr_isac_stub.c` in OFF mode; the standalone Task 1 export core remains independently testable in both modes, as in S1.

[CODE-READ, DGX aarch64] Removed the D1 offline consumers: `tests/sensing_sim/`, `tests/passive_rx/monitor/`, the named detection/track scripts in `tests/passive_rx/`, and `tests/ota_sync_bench/{grid_dump,process_capture}.py`. These deletions overlap the later Task 5 file list but are explicitly required by D1 and this task's prompt. No Task 3–6 record integration, gating redesign, reader, run-script rewrite, operational-document rewrite, live measurement, PRACH or SRS implementation was undertaken. Remaining launcher references to retired consumers belong to Task 5.

[CODE-READ, DGX aarch64] Dropped `nr_isac_aoa_antennas` from the header/stub and replaced its four callers in `phy_procedures_nr_ue.c`, `csi_rx.c`, `nr_pdsch_data_aided.c`, and `nr_pdcch_blind_monitor_rt.c` with frame-parameter antenna counts, retaining local buffer bounds. Receiver CFO/SFO/DM-RS corrections, UL/DL data-aided reconstruction, receiver defaults and `ISAC_RECONF` default-off policy are unchanged.

## Decisions

- [CODE-READ, DGX aarch64] Kept `enable`, `sources`, `cfr_path`, `records_path`, `endpoint`, `cfr_ring_frames`, `cfr_max_re`, and metadata-only `rx_id`/`rx_array`. All **133** other descriptors from the old adapter are accepted through the existing OAI config helpers and ignored; explicitly supplied keys produce one `LOG_W` per initialization, naming them. Receiver monitor keys sharing the section are not labelled ignored. The legacy single `source` is ignored, per D3.
- [CODE-READ, DGX aarch64] `sources` defaults to `all`. `csirs` and legacy `csi_rs` are aliases; `pdsch_dmrs` enables both old DL DM-RS enums, while `pdsch_dmrs_blind` selects that legacy enum alone. `subslot_config` returns zeros: retired grouping/SNR settings no longer affect export. `nr_isac_source` remains for compatibility.
- [CODE-READ, DGX aarch64] Initialization copies strings before the config module can free them. Start emits the Task 2 session metadata (`schema`, `type`, `reconf`, epoch/identity and receiver ID/layout). RF session fields and per-grant/per-RS records remain Task 3. Empty paths mean no file sink; at least one new file path or endpoint must be configured for the exporter to open. Old output paths/endpoints are never used.
- [CODE-READ, DGX aarch64] Defaults are 64 CFR ring frames, 46,200 maximum RE (275 PRB × 12 × 14), and 1024 record slots. Configured CFR limits accept 1–46,200 RE and 1–65,536 frames. Producer index conversion uses fixed thread-local arrays, preserves original `n_re` so Task 1 counts truncation, and rejects unrepresentable indices. No producer allocation, I/O, or mutex wait was introduced. Lifecycle init/start/stop is serialized, and producers must stop before reinitialization.
- [CODE-READ, DGX aarch64] Plan adjustment required by D6: `nr_cfg_epoch_snapshot()` takes a blocking mutex. It is used at session start, but cannot be used on the CFR producer. Added `nr_cfg_epoch_cfr_stamp()`, a single atomic epoch/identity pair published from the same authoritative state on every bump/reset. It preserves pair coherence without a mutex or retry loop and does not depend on deferred listener dispatch. The full snapshot and all existing epoch consumers are unchanged. A concurrent unit test verifies hard/soft bumps, snapshot agreement before drain, and reset.
- [CODE-READ, DGX aarch64] K45 scan-queue capacity, rank > 1 acceleration limitations and the deferred levers remain outside this change. All existing merged-main acceleration defaults stay unchanged; `ISAC_RX_BRANCH_FO` was never enabled.

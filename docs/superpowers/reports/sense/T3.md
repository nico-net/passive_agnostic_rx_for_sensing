# T3 — schema-2 sensing records

## Changes

- [CODE-READ, DGX aarch64] Added `nr_sense_emit_session`, `nr_sense_emit_grant`, and `nr_sense_emit_rs` with the Task 3 RS metadata prefix, plus optional PRACH/SRS fields for Task 6. PRACH and SRS source IDs follow the six existing IDs, preserving CFR v1 source values. Session, grant, and RS records carry schema 2, common timing and configuration provenance, and JSON null for unknown values.
- [CODE-READ, DGX aarch64] Schema-2 grants copy the schema-1 JSON field/value sequence verbatim before adding `type`, epoch, identity, dedicated epoch, RF timestamp, DCI verification, DL coverage, and UL fields. The legacy `ISAC_OBS_PATH` writer still uses schema 1. Queue admission captures epoch provenance before deferred decode; the adapter stamps RS provenance with the CFR submission. The context lookup for `verif` uses a nonblocking try-lock and emits null when unavailable.
- [CODE-READ, DGX aarch64] Queued DL, inline DL, and decoded UL paths emit grant records. Every existing CFR tap emits an RS record with the returned `cfr_frame_id`, or null on a dropped frame. The SSB tap reads the MIB-derived k_SSB from MAC and normalizes it for the PHY grid; CSI-RS, PDSCH, and PUSCH taps pass known source metadata. UL timing advance is positive when the receiver advances its FFT window relative to the DL frame; `ul_timing_ref` is `dl_frame`.
- [CODE-READ, DGX aarch64] The adapter emits a session at exporter open; startup, synchronization, and RX gain changes emit sessions with the known RF metadata. The `build` field uses the generated OAI package version. RF sample timestamps and per-UE UL CFO remain null where the receiver has no capture-aligned value or estimate.

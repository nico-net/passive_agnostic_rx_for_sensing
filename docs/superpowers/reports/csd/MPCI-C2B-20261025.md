# MPCI C2b — CPU channelizer on k derived worker threads (2026-10-25)

Branch `mpci/c-c2b` (from `mpci-main` c426b5aeb9). Host for every number: DGX GB10 aarch64, shared with other sessions (load average 3-14 during the runs), `nice -n 19`, no receiver, no GPU, no radio. No exclusive `td_measure.lock` was obtainable (other sessions held shared locks for long periods), so these are logic-grade numbers, not clean benchmarks.

## What changed (radio/COMMON/iq_chan.{c,h}, tests/test_iq_chan.c)
- **Independent units.** Filter state is per (cell, channel): one `iq_ddc_t` holds the halfband histories and the mixer phase; the input block is read-only; each job writes its own output buffer. A job = (cell slot, channel). [CODE-READ + tests below]
- **Parallel backend.** `iq_chan_backend_t.set_workers(ctx, k, cpus, ncpus)` (optional member; NULL = single thread). CPU backend: the channelizer thread is worker 0, k-1 extra threads. Per block the caller writes the job list, then publishes one 64-bit word `generation<<20 | njobs<<10 | next_index` with a release store; workers claim jobs with `fetch_add`, a claim is valid only against the njobs carried in the same word (a late worker can never run a job of another block); the caller waits only for jobs that were actually claimed (`pending`), never for an unscheduled worker. Job list double-buffered by generation parity. Nothing is allocated per block. Idle workers yield, then sleep 50 us.
- **k = 1 is the old path** (no extra thread; the caller drains all jobs in the same order as before); output is bit-identical (tests below).
- **k is derived, not configured.** Pure `iq_chan_threads_needed(load, per_thread_msps_measured, margin)` = `ceil(margin x in_rate / rate)` clamped to [1, cells x channels]. `iq_chan_start(c, cpus, ncpus)` measures the one-thread capacity of the actual load (`iq_chan_cpu_bench`), takes the formula's k capped by the cpus it was given, then measures the capacity with k threads and adds threads while it is below the 1.25 margin (scaling is not linear), up to cpus/jobs. `cpus[0]` pins the channelizer thread, the others pin the workers. `iq_chan_start_k()` / `iq_chan_set_threads()` take an explicit k (tests, benches); they are API functions, not flags.
- **Shortfall is published, never silent.** `iq_chan_stats()` gives `threads`, `threads_needed`, `capacity_sps` (measured capacity of the load with `threads` threads, samples/s per channel: the admission input); a stderr line `IQ_CHAN_SHORTFALL threads_needed=.. threads=.. capacity=..` when `threads < threads_needed`.
- Also: narrow rings are pre-faulted at `iq_chan_cell_add` (page faults belong to start-up), `iq_chan_pos()` is atomic (TSAN finding in C2 code), new stats `run_ns`, `lag_max`, `step_gap_max_ns`.
- NO FLAGS: no env var, no option, no -D in product code.

## Tests [OFFLINE VERIFIED, DGX GB10 aarch64 unit]
- `test_iq_chan` now runs the equivalence, live add/remove/retune, ring-epoch, overrun/discontinuity and live-thread cases twice, with k = 1 and k = 3 backend threads; every comparison is against an independent fresh `iq_ddc` (= the frozen reference to 0 LSB), so k=3 output is bit-identical to k=1 (0 differing samples, 12 entries x 3 geometries, decim 1/2/4/8, shifts 0 / -19.81 / +7.3 MHz, 122.88 and 245.76 MS/s, blocks 65536 / 6160 / 20496). `test_threads_needed`: formula steps, clamping, bad input, and a one-cpu start that publishes the shortfall.
- ThreadSanitizer (gcc -fsanitize=thread, `setarch -R`, direct compile): 0 warnings over the whole suite incl. k=3 (the first TSAN pass found two real races in the first barrier design: a straggler worker reading the job list while the caller rewrote it, which could also run a job twice; replaced by the generation word above).
- ASAN+UBSAN: 0 reports, no leaks. ctest `test_iq_chan`, `test_shm_iq`, `test_iq_ddc_equiv` pass.

## Bench: free-run real-time factor, one channelizer block loop with k threads, 4 RX
`test_iq_chan --bench --reps 3 --secs 2`, [Bench, DGX GB10 aarch64, shared host, n=3], unpinned threads. Cells: 106 PRB (decim 4 at 245.76 / decim 2 at 122.88) and 51 PRB (decim 8 / decim 4); 4 cells = the two repeated.

| input | cells | k=1 | k=2 | k=3 | k=4 |
|---|---|---|---|---|---|
| 245.76 MS/s | 2 | 0.510x | 0.719x | 1.019x | 1.014x |
| 245.76 MS/s | 4 | 0.241x | 0.321x | 0.541x | 0.467x |
| 122.88 MS/s | 2 | 1.094x | 1.978x | - | - |

Two earlier runs of the same bench on the same host (different load): 245.76 x 2 cells k=1..4 = 0.541 / 1.074 / 1.324 / 1.568 and 0.529 / 0.930 / 0.903 / 1.212; 4 cells k=1..4 = 0.258 / 0.519 / 0.556 / 0.606 and 0.251 / 0.511 / 0.640 / 0.673. So 2 cells at 245.76 reach real time with k = 2-4 depending on what else the host runs; 4 cells at 245.76 do not reach real time with k <= 4 here. Scaling is sub-linear (memory bandwidth, shared host).

Finding: GB10 is a hybrid CPU (slow and fast cores). The same load was 2-2.6x slower per block when the threads landed on the slow cores (backend run 0.7-1.2 ms/block vs 0.28 ms on fast ones at 122.88 MS/s, 2 cells, k=2). The core plan (`nr_core_layout`) must hand the channelizer the fast cpus; the test harness picks idle cpus within 75 % of the fastest measured one.

## 60 s soak, 2 cells x 245.76 MS/s x 4 RX, derived k
`test_iq_chan --soak 60 --rate 245.76e6`: generated input, two cells (106 PRB decim 4, 51 PRB decim 8), channelizer started with `iq_chan_start(cpus)` (cpus = idle fast cpus found at that moment), one consumer thread per cell records a hash of every (block, channel) and checks continuity during the run; afterwards one thread per (cell, channel) recomputes the stream with an independent `iq_ddc` and compares every block (verification is as expensive as the channelizer, so it is not run during the real-time part).

Results [Bench, DGX GB10 aarch64, shared host]:
- **2 cells x 245.76 MS/s x 4 RX, derived k, 60 s (the one clean run, n=1):** `IQ_CHAN_SHORTFALL threads_needed=4 threads=3 capacity=214.4 MS/s` (idle fast cpus at that moment: 14 10 13, i.e. only 3 of the 4 threads the load needs were available). 116977/116977 blocks seen without gap and then verified bit-exact on every channel of both cells (0 mismatches, 0 gaps, timestamps continuous), 0 overruns, 0 discontinuities, lag max 101.6 ms. The test paced at 60 % of the measured capacity (127.8 MS/s per channel = 0.52x real time), because the capacity with 3 threads (214 MS/s = 0.87x) is below real time. So: continuity, bit-exactness and the shortfall report are shown; **real time at 245.76 x 4 RX with 2 cells was NOT shown on this host**, because the host did not offer enough idle fast cpus. In the free-run bench real time (1.0-1.6x) is reached with k = 3-4 when the cores are free.
- **122.88 MS/s x 4 RX, 2 cells:** free-run 1.09-1.18x with k=1 and 1.98-2.36x with k=2 (table above). A 60 s soak at real time was not obtained: the runs that completed had only 1 idle fast cpu (k=1, shortfall published, overruns because the test was paced at real time anyway in that older test version), the later ones were frozen (below).
- **Environment limit.** From about 12:20 the orchestrator's `rr-orchestration/ota/agents_freeze.sh guard` froze (SIGSTOP) this session's processes for minutes (state T, ShdPnd SIGSTOP); two soaks ended with a 309-310 s process-wide stall and later runs never finished. The soak now prints `SOAK INVALID` when the producer or a channelizer step stalls more than 1 s, so such runs cannot be mistaken for results. The sanitizer runs of the last source state: TSAN clean (0 warnings, ALL OK); ASAN+UBSAN was clean on the state before the last edits (prefault, run_ns, soak harness) and could not be repeated before the freeze.

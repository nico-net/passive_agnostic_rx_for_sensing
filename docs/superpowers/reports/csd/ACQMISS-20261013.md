### Root cause of ab_L1 `[MEASURED, OTA log; mechanism INFERRED]`
Not a missing dedicated CORESET and not an empty cell: the probe sees 212k ungranted PDSCH-like RB-slots and 85 lit control RBs per slot.
L1 differs from every other 415 run of that morning in the front end, which starves the DM-RS-correlation sweep:
1. **Time sync wandered all run.** `TIMEMUT shiftForNextFrame(pbch)` first delta -57 samples, then +-20..58 samples every frame for ~100 frames (median |delta| 3, tail 57);
   siblings (K2, K3, L2, L3, J1) have median 1 and max 9. `TSYNC_OBS` e_win_frac 0.55-0.68 (siblings 0.97), `max_pos_acc` swings +226 .. -162.
   The nID sweep correlates the PDCCH DM-RS over 6-RB windows (18 pilots, 2.16 MHz): 50-150 samples of timing error (0.4-1.2 us) is ~1 cycle of phase slope
   across the window and cancels the coherent sum. The DM-RS CFO tracker agrees: 2 accepted estimates in L1 vs 62 (L2), 122 (K3).
2. **Carrier verdict at 29.3 s instead of 1-7 s** (CSI-RS discovery needed 17 TRS bursts; the CRB-indexed reference also decorrelated), so the sweep got ~100 s of a 133 s run.
3. **Capture starved**: only 3000 of 99630 offered symbols were taken (3 %), while L2/L3/K3 take 27-44 %; 28997 skipped_empty. With dur=3 each pass costs 540 ms of GPU
   and pass 11 took 26.2 s (GPU shared with CSI-RS discovery); the producer drops symbols when no staging batch is free. The incremental window never filled with coherent snapshots.
   Noise floor 46.3 dB (siblings 30-53, so not the cause).
4. Context: it was the second start after the post-reboot RX_START failure (K1, 11:04); its log also has "RFNoC blocks timed out during flush". `[INFERRED]` the radio/clock was
   still settling (see task B). Next run (L2, 3 min later) was fine with the same binary and env, so this is not a code regression and not cell-dependent.

Why 1 in 5-6: the sweep needs (a) a stable sync, (b) a verified carrier early, (c) traffic. Failures in (a)/(b) are what the data shows; (c) is the J3/J4 night case.

## 2. Awareness and recovery (ISAC_CORESET_DISC_WATCH=1, default off)

New in `nr_dl_traffic_probe.[ch]` (pure `nr_cdisc_step`, unit tested) and `nr_dl_traffic_probe_rt.c` (evaluated on every TRAFFIC line = every 256 probed slots).
Criterion (receiver-side only, no gNB data): UE-specific traffic = PDSCH-like occupancy (>= 3 consecutive lit data symbols per RB, chi-square 1e-4 cell test) that no decoded
grant explains, **outside CORESET#0** (SIB1/SI PDSCH is not registered as a grant and was the reason the old verdict read PRESENT on dark cells), counted since the carrier verdict.
- `LOCKED`: >= 1 dedicated CORESET banked. `SEARCHING`: carrier not verified (`reason=carrier_pending`), traffic undecided, or inside the grace.
- `NO_TRAFFIC`: >= 100 probed slots and < 8 ungranted PDSCH-like RB-slots.
- `MISSED`: >= 64 RB-slots at >= 0.5 per probed slot (sustained; 8x the probe's leakage bound) and `ISAC_CORESET_DISC_MISS_S` (default 12 s) after arming, bank still empty.
Log line (every 256 probed slots, ~2 s of air at 1-in-16 probing):
`SENSING: CORESET_DISC state=MISSED reason=traffic_present_no_dedicated_coreset armed_for_s=22.5 window_probed=256 window_ungranted_pdsch_like_rbslots=24994 (excl. CORESET#0) bank=0 nid_passes=0 capture offered/taken/empty=0/0/0 recoveries=1 -> RECOVER`.
Recovery (at most `ISAC_CORESET_DISC_RECOVER_MAX`=3 times, linear back-off k x MISS_S): `nr_pdcch_nid_gpu_rearm()` (new cfg epoch: forgets the stale incremental window and published records,
restarts the ACQUIRE duty which already has GPU priority) and `nr_pdcch_coreset_map_idsweep_gate_bypass(1)` (capture every offered symbol: the occupancy gate and the 3 %-style
starvation of L1 cannot hold it back). The bypass is lifted when LOCKED. Without a verified carrier (Vb1 class) no recovery is possible here; the line says `carrier_pending`
and the existing CSI-RS/Point-A paths remain the only way (flag `ISAC_POINTA_SWEEP` is already in t26b).
Setting `ISAC_CORESET_DISC_WATCH=1` also turns the traffic probe on at 1 in 16 if `ISAC_DL_TRAFFIC_PROBE` is unset.
Flags off: no code path runs; the only always-on edits are `rearm=0` (cfg epoch unchanged) and `nid_gate_bypass=0` (atomic load), so behaviour is identical `[CODE-READ]`.

## 3. Task B: first start after a reboot gets 0 samples `[MEASURED, OTA logs; cause INFERRED]`

no packet ever arrived. The "flush timeout" warning also appears in most healthy runs (benign); the RPC timeout is mildly enriched (7/58 = 12 % vs 31/740 = 4 % without), and the
longest idle gaps stall more (gs2_38 after 9.5 h idle, K1 after the reboot). `[INFERRED]` the first timed START after a cold/idle device is lost or ignored (X410 MPM/clocking
not settled; the lcore sees "No link entry in rx table" during init).

Code `[CODE-READ]` (`radio/USRP/usrp_lib.cpp`): the consumer (`trx_usrp_read`, first buffer) gives up after 3 s, but the ring producer only treats silence as a fault after
`start_deadline` = **5 s**. So the existing recovery (`ISAC_RX_RECOVER=1`: STOP, drain, back-off, timed START re-issue, in `usrp_ring_producer`) never runs for a START that produces
no packet: the receiver is already shut down at 3 s. Fix: `ISAC_USRP_START_TIMEOUT_MS` (default 5000 = unchanged; accepts >= 1200). With e.g. 2200 the producer faults at 2.2 s
(start latency 1 s + margin), sets `ring_restarting` (which extends the consumer's deadline by 3 s per wait) and re-arms with a fresh timed START (`get_time_now()+20 ms`,
no local reference yet), up to `ISAC_RX_RECOVER_MAX` (20) attempts with back-off. Built (`liboai_usrpdevif.so` compiles); the logic is the already-exercised recovery path, the new
part is only the earlier trigger. `[NOT VALIDATED]` on air: whether a re-issued START wakes a cold X410.

## A. Correction of section 1 (L1 root cause) `[MEASURED, OTA log]`
Section 1 said the time sync "wandered all run". That was wrong: `TIMEMUT`/`TSYNC_OBS` are capped (200 / 60 events), so they only cover the first ~100 PBCH steps (~2 s).
L1's PBCH steps are, in order: -57 -58 14 -27 27 -21 -28 34 ... (first ~38 steps, <= 1 s), then 1..4 samples for the rest of the log, exactly like healthy runs.
The carrier verdict came at 29 s and the 35 sweep passes ran after that, with a stable sync. So **the early timing wander cannot explain a miss from 30 s to 133 s**; the
"2 vs 62 DMRSFO estimates" is a consequence (no banked CORESET -> no C-RNTI PDSCH to estimate from), not a cause. What is measured and still unexplained in L1:
carrier verdict 29 s (CSI-RS discovery lag), 35 passes in ~104 s (3 s/pass average; one pass 26.2 s) against 96 passes in 130 s for healthy dur=3 runs, capture taken 3 % of offered.
Open hypothesis: GPU starvation of the sweep by CSI-RS discovery (pass 11 = 26 s) after a device (re)start; not tested. Population check: runs with a large early wander
(te_1, rx2_3, rx3_3, td_3/4: median |step| 26-66 in the first 100 steps) all locked, later (6-16 s) than healthy runs (1-5 s). Timing instability delays, it did not by itself cause a permanent miss.

## B. What was built (default off; flags off byte-identical `[CODE-READ]`)
- Metric `nr_syncq_*` (`nr_dl_traffic_probe.[ch]`): magnitude of every PBCH-based timing step (fed from `nr-ue.c` where `shiftForNextFrame(pbch)` is set), window of 32 steps, median and p90.
  Levels: GOOD; DEGRADED (median > 8, log only); POOR (median > 20 or p90 > 64, release at median <= 10 and p90 <= 32). Thresholds derive from the 636-run OTA population
  (worst-window median: p50 1, p90 1, p99 21.6; worst-window p90: p95 8, p99 54) and the replay injection below (a +-20..60 wander, step median 11, still banks; +-60..150, median 25-29, does not
  verify the carrier). Not tuned on 415/L1. DMRS-CFO accept rate and `e_win_frac` were NOT used: both depend on a banked CORESET or are capped (see A).
- `ISAC_CORESET_DISC_SYNCQ=1`: `CORESET_DISC` line gets `sync_q=GOOD|DEGRADED|POOR sync_step_med=.. sync_step_p90=.. reacquires=..`; POOR with an empty bank reports `state=SYNC_POOR reason=sync_poor_timing_unstable`
  (also while the carrier is still pending), never MISSED, never counted in the recovery budget; the grace timer excludes the poor time. Recovery `-> REACQUIRE_SYNC` (every `MISS_S`): reset
  of the time-tracker integrator (`UE->max_pos_acc = 0`) and a PBCH-step clamp of +-16 samples (above the 6 samples/frame true drift, below the +-50 jumps) until sync is good; on POOR -> not POOR
  `-> REARM` (sweep re-arm over fresh symbols, clamp released). Needs `ISAC_CORESET_DISC_WATCH=1`.
- `ISAC_CORESET_DISC_SYNCQ=2`: additionally pauses the nID capture while POOR (`nr_pdcch_coreset_map_idsweep_want`). **Not recommended**, see C.
- Test injection (replay only): `ISAC_RAW_IQ_WANDER=lo:hi` in `radio/COMMON/raw_iq.c` -- a new random content offset of +-[lo,hi] samples every 10 ms frame, timestamps kept continuous;
  `ISAC_RAW_IQ_WANDER_UNTIL_S` ends it. Not a radio path.

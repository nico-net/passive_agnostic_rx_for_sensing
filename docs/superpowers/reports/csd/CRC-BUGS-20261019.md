# CRC-BUGS 2026-10-19: rv != 0 never decodes; large grants fail at high DM-RS SNR

Branch `csd/int16-merge19`, base d79b8b7bc5. Logs are the 2026-10-19 on-air runs `ab_jj*`, `ab_kk*`, `ab_ll*` and `ab_uu*` (DGX, X410, TIM PCI 923 and Vodafone PCI 415).
The EVMGRANT rows used have probe=0 and are not SI. TIM and Vodafone are never pooled. Parser: one-off scratch scripts over EVMGRANT, with `goal_metrics.py`'s `required_snr_db` / `true_snr_db`.

| | cause | status |

Measured on the EVM SNR, large grants decode at 75-90 %, and CRC falls with C as (1-p)^C. ## Bug 2: rv != 0

### Evidence

**B1. rv != 0 CRC per build/config** `[MEASURED, DGX OTA 2026-10-19]`. "comb" = the run log has a HARQC line (DL combining on).

| runs | rv 0 CRC | rv != 0 CRC | ndi = 0 among rv != 0 | clean rv != 0: MCS 0-2, EVM SNR >= 10 dB | same (rnti, pid, ndi) pairs with equal TBS |
|---|---|---|---|---|---|
| jj, combining off | 198197/296754 | 2/22152 | 92 % | 0/180 | 4334/19631 (22 %) |
| jj, combining on | 56791/80643 | 1/392 | 77 % | 0/26 | 96/237 |
| kk, combining off | 46705/77595 | 0/3855 | 80 % | 0/41 | 386/2633 |
| kk, combining on | 51428/129449 | 1/22258 | 91 % | 0/46 | 2196/17441 |
| ll, combining off | 66236/127313 | 1/13852 | 78 % | 0/99 | 1272/9240 |
| ll, combining on | 52483/96581 | 0/10135 | 81 % | 0/52 | 1075/6554 |
| uu (merged build, combining on) | 98604/180536 | 0/16216 | 74 % | 0/92 | 2214/10439 (21 %) |

- rv != 0 is about 0 % **with and without combining**. So the failure is in "rv != 0 decode", not in "combining" `[MEASURED]`.
- Among rv 0 rows, NDI is 50/50 in every run (example: uuVU2 14151/14333). Among rv != 0 rows it is 74-92 % zero (uuVU2 rv 3: 367 zero, 8 one). Real retransmissions inherit their initial NDI, which would make them 50/50 too. `[MEASURED]` distribution, `[INFERRED]` reading: the (ndi, rv) bits of these rows are not the HARQ fields.
- Only 21-22 % of same-NDI rv != 0 grants carry the TBS of the previous grant on that (rnti, pid). TS 38.214 5.1.3.2 makes a retransmission carry its initial TBS `[MEASURED]`.
- Vodafone RNTI 0x7019 (uuVU2) shows the same pattern. Its rv 0 rows are Nl 2, port 0x3, rb = k*16 + 16, 11 symbols. Its rv != 0 rows are mostly Nl 1, ports 0x2 / 0x4, rb starting at 0, 13-14 symbols, and often a DM-RS margin below 0 `[MEASURED]`.
- The receiver's HARQC counters (uuVU2): `retx_combined=11/1306`, `tbs_from_first=1521`. Almost every combined retransmission was decoded with the stored TBS, not its own. uuTM1: 78/2429 and 2491. kkVM1: 31/16553 and 19667 `[MEASURED]`.
- TIM MCS 0-2 at EVM SNR >= 10 dB: rv 0 passes 16814/16989, rv != 0 passes 0/16 (uuTM1) `[MEASURED]`. The unit test below shows every rv is self-decodable at R 0.12. A clean low-rate rv != 0 grant can therefore fail only if a parameter handed to the decoder (rv, TBS/MCS, or the combined buffer) is not the transmitter's `[INFERRED]`.

### Code review (every path)

- `nr_rate_matching_ldpc_rx` uses k0 = floor(rv_num * Ncb / N) * Z with numerators {0,17,33,56} for BG1 and {0,13,25,43} for BG2, N = 66Z / 50Z over d (the 2Z punctured columns removed), and Ncb = min(N, floor(3 * TBS_LBRM / (2C))). This is TS 38.212 5.4.2.1, and the TX (`nr_rate_matching_ldpc`) is identical. Filler skip and wrap match `[CODE-READ]`.
- Decoder R: `nr_get_R_ldpc_decoder(rv, E, ...)` sizes the parity rows from k0 + E, so rv != 0 uses enough rows `[CODE-READ]`.
- GPU pass `k_rdm`, hq_mode 1/2 is bit-identical to the CPU combine (existing `GpuPassPost.RateDematchHarqCombineMatchesCpu`, rv 0..3, LBRM) `[CODE-READ]`.
- LBRM only moves rv != 0 k0 when Ncb < N. With n_L = 4 (cell 217 PRB, table 1, TBS_LBRM 1277992), N_ref binds only for C > 75. The receiver's n_L = 1 retry ran 119 / 1618 / 154 times and rescued 0 (HARQC `lbrm` field) `[MEASURED]`.
- HARQ store (`harq_retx_decide`): retransmission = same NDI and (rv != 0 or rv-0 admitted). **When the TBS differed, it decoded with the stored TBS into the stored sum.** Per TS 38.214 5.1.3.2 / 38.212 5.2.2, such a grant is not that TB's retransmission (or one of the two DCIs was misread), so this decode cannot pass. A reserved MCS already takes its TBS from `nr_harq_init_tx`, so it is unaffected `[CODE-READ]`.
- Missed initial transmission: with no stored entry, the grant decodes alone at its own rv. rv 0 and 3 (and every rv at low rate) are self-decodable, and the test shows the decoder does it `[MEASURED unit test]`.

### Fix

`nr_hq_retry.h: nr_hq_retx_rule()` returns 1 (combine), 0 (first transmission) or -1 (decode alone, entry untouched). It returns -1 for the same NDI with a different TBS (stored TBS != 0).
`harq_retx_decide` uses the rule on both paths:
- CPU: -1 releases the entry and decodes via `passive_ldpc_decode_core`.
- GPU pass: -1 releases the entry, so hq_mode = 0.

The stored sum is kept for its own retransmission. HARQC `tbs_from_first` now counts these -1 decisions. SI combining is unchanged.

**This fix does not by itself make rv != 0 decode on air.** The combining-off runs are also at 0 %, so the remaining cause is the field reading `[INFERRED]`.

## Bug 1: large grants at high DM-RS margin

### Note on the `cb=` field

EVMGRANT `cb=` is `t_seg_C`, a thread-local value of the last LDPC decode on that thread. It is stale on some rows: `cb=41` on TBS 1128, `cb=38` on TBS 984 `[MEASURED]`. The tables below use C computed from TBS, MCS and the table (TS 38.212 5.2.2, BG per 7.2.2).

### Evidence (uu runs, rv 0, DM-RS margin >= 10 dB) `[MEASURED, DGX OTA 2026-10-19]`

Large grants are C >= 8:
- TIM: 570/3675 (16 %); small: 34884/43267 (81 %).
- Vodafone: 2527/3563 (71 %); small: 43546/50744 (86 %).

DM-RS comb SNR minus post-equalisation EVM SNR (median, Qm >= 4):

| cell | Nl | rb < 64 | rb 64-191 | rb >= 192 | CRC (rb >= 192) |
|---|---|---|---|---|---|
| Vodafone | 1 | 2.1 dB | 1.9 dB | 2.7 dB | 89 % |
| Vodafone | 2 | 5.4 dB | 5.5 dB | 6.8 dB | 60 % |
| Vodafone | 3 | 11.9 dB | 12.7 dB | - | - |
| TIM | 2 | 9.2 dB | 10.1 dB | 11.6 dB | 24 % |
| TIM | 3 | 18.7 dB | - | - | - |

CRC by **EVM** margin (`goal_metrics.py` true SNR minus required SNR), large grants with DM-RS margin >= 10:
- TIM: < 0 dB: 9/740; 0-5 dB: 157/1482; 5-10 dB: 378/543 (70 %); >= 10 dB: 13/18.
- Vodafone: 0-5 dB: 39 %; 5-10 dB: 80 %; >= 10 dB: 830/898 (92 %).

At EVM margin >= 5 dB (pass rates):

| shape | Vodafone | TIM |
|---|---|---|
| Qm6 C >= 8 Nl 1 | 883/990 (89 %) | no such grants |
| Qm6 C >= 8 Nl 2 | 56/75 | 113/251 (45 %) |
| Qm6 C 2-7 Nl 2 | - | 498/599 (83 %) |

TIM's Qm6 C >= 8 Nl 2 result is consistent with a per-CB failure of about 4 % at C of about 15 (0.96^15 = 54 %) `[INFERRED]`.

Properties of large grants at the same margin:
- Frame parity does not separate them (TIM 13/17 %, Vodafone 70/72 %).
- Slot index is flat, except TIM even-frame slots 8/18: 0/4 at EVM >= 5. This is the known CSI-RS rate-match set of FIXB-CSIRS-RMSET-20261016; `ISAC_CSIRS_FULL_VALID` is off. n is too small to rank it.
- `ndmrs`, `tbl` and position are flat at equal Nl.

### Candidate ranking

1. **Post-equalisation SINR loss on multi-layer and wide grants** (inter-layer / co-scheduled interference, channel estimate on wide bands; the known NL2 LLR resolution issue, PROJECT_MEMORY 10-12 §5). Supported by the gap table and the EVM-margin CRC `[MEASURED]`. Mechanism within the equaliser `[NOT PROVEN]`.
2. **CSI-RS rate-match set on TIM even-frame slots 8/18**: known, small n here `[MEASURED, n=4]`.
3. **PT-RS**: unlikely `[INFERRED]`. Vodafone Nl 1 Qm6 C >= 8 passes 89 %, and TIM Qm6 Nl 2 C 2-7 passes 83 %. An unhandled PT-RS shifts every later RE and would give about 0 %. The PT-RS sweep made 0 trials (PTRS_SWEEP line), so PT-RS is assumed absent.
4. **LBRM: excluded for rv 0** `[INFERRED + MEASURED]`. With n_L >= rank, G <= 1.5 TBS_LBRM, so E <= N_ref and rv 0 never wraps. The n_L = 1 retries rescued 0.
5. **TBS / xOverhead / segmentation: excluded for the coding chain** `[MEASURED unit test]`. Vodafone Nl 1 large passes at the small-grant rate, and the unit test below decodes the failing shapes clean.

### Test

`Cb0.LargeOnAirShapesDecodeClean` (new) uses the on-air failing shapes:
- 217/201/160 PRB, 11-13 symbols, 1-2 CDM groups;
- Nl 1-4, Qm 4/6/8, code rate 0.48-0.85;
- C >= 8 on 12 of the 16 cases (as the test enforces);
- TBS_LBRM for n_L 4 and 1.

These shapes are encoded with the OAI chain at the receiver's own TBS and LBRM and decode bit-exact. It passes and reproduces no failure: the failure is not in TBS, segmentation, LBRM or LDPC rate matching `[MEASURED unit test]`. It does not cover RE mapping (PT-RS, CSI-RS, DM-RS RE set).

### Logging that would prove the cause

1. **Per-CB pattern:** a run per cell with the existing per-CB diagnostic `ISAC_PDSCH_DECODE_DIAG=1` (per-CB `E:ok` list) on the grants with C >= 8. It tells constant per-CB failure (SINR) from failure after an index (RE shift).
2. **Per-layer SINR and equaliser:** per-layer `snr_l` and `nvar_db` / `alpha` / `rho` are already in EVMGRANT. Add an A/B on TIM with the default MMSE vs `ISAC_L2MAXH_DELTA_NL2=-3` (NL2, existing). If CRC at the same EVM margin moves, it is the equaliser.
3. **CSI-RS:** a TIM run with `ISAC_CSIRS_FULL_VALID=1` (existing, FIXB) for slots 8/18 in even frames.

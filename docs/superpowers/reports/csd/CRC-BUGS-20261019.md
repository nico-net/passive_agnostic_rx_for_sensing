## Bug 2: rv != 0

### Evidence

| runs | rv 0 CRC | rv != 0 CRC | ndi = 0 among rv != 0 | clean rv != 0: MCS 0-2, EVM SNR >= 10 dB | same (rnti, pid, ndi) pairs with equal TBS |
|---|---|---|---|---|---|

| jj, combining on | 56791/80643 | 1/392 | 77 % | 0/26 | 96/237 |
| kk, combining off | 46705/77595 | 0/3855 | 80 % | 0/41 | 386/2633 |

- rv != 0 is about 0 % **with and without combining**. So the failure is in "rv != 0 decode", not in "combining" `[MEASURED]`.
- Among rv 0 rows, NDI is 50/50 in every run (example: uuVU2 14151/14333). Among rv != 0 rows it is 74-92 % zero (uuVU2 rv 3: 367 zero, 8 one). Real retransmissions inherit their initial NDI, which would make them 50/50 too. `[MEASURED]` distribution, `[INFERRED]` reading: the (ndi, rv) bits of these rows are not the HARQ fields.
- Only 21-22 % of same-NDI rv != 0 grants carry the TBS of the previous grant on that (rnti, pid). TS 38.214 5.1.3.2 makes a retransmission carry its initial TBS `[MEASURED]`.
- Vodafone RNTI 0x7019 (uuVU2) shows the same pattern. Its rv 0 rows are Nl 2, port 0x3, rb = k*16 + 16, 11 symbols. Its rv != 0 rows are mostly Nl 1, ports 0x2 / 0x4, rb starting at 0, 13-14 symbols, and often a DM-RS margin below 0 `[MEASURED]`.
- The receiver's HARQC counters (uuVU2): `retx_combined=11/1306`, `tbs_from_first=1521`. Almost every combined retransmission was decoded with the stored TBS, not its own. uuTM1: 78/2429 and 2491. kkVM1: 31/16553 and 19667 `[MEASURED]`.
- TIM MCS 0-2 at EVM SNR >= 10 dB: rv 0 passes 16814/16989, rv != 0 passes 0/16 (uuTM1) `[MEASURED]`. The unit test below shows every rv is self-decodable at R 0.12. A clean low-rate rv != 0 grant can therefore fail only if a parameter handed to the decoder (rv, TBS/MCS, or the combined buffer) is not the transmitter's `[INFERRED]`.

### Code review (every path)

- `nr_rate_matching_ldpc_rx` uses k0 = floor(rv_num * Ncb / N) * Z with numerators {0,17,33,56} for BG1 and {0,13,25,43} for BG2, N = 66Z / 50Z over d (the 2Z punctured columns removed), and Ncb = min(N, floor(3 * TBS_LBRM / (2C))). This is TS 38.212 5.4.2.1, and the TX (`nr_rate_matching_ldpc`) is identical. Filler skip and wrap match `[CODE-READ]`.
- Decoder R: `nr_get_R_ldpc_decoder(rv, E, ...)` sizes the parity rows from k0 + E, so rv != 0 uses enough rows `[CODE-READ]`.
- GPU pass `k_rdm`, hq_mode 1/2 is bit-identical to the CPU combine (existing `GpuPassPost.RateDematchHarqCombineMatchesCpu`, rv 0..3, LBRM) `[CODE-READ]`.
- LBRM only moves rv != 0 k0 when Ncb < N. With n_L = 4 (cell 217 PRB, table 1, TBS_LBRM 1277992), N_ref binds only for C > 75. The receiver's n_L = 1 retry ran 119 / 1618 / 154 times and rescued 0 (HARQC `lbrm` field) `[MEASURED]`.
- HARQ store (`harq_retx_decide`): retransmission = same NDI and (rv != 0 or rv-0 admitted). **When the TBS differed, it decoded with the stored TBS into the stored sum.** Per TS 38.214 5.1.3.2 / 38.212 5.2.2, such a grant is not that TB's retransmission (or one of the two DCIs was misread), so this decode cannot pass. A reserved MCS already takes its TBS from `nr_harq_init_tx`, so it is unaffected `[CODE-READ]`.
- Missed initial transmission: with no stored entry, the grant decodes alone at its own rv. rv 0 and 3 (and every rv at low rate) are self-decodable, and the test shows the decoder does it `[MEASURED unit test]`.

### Fix

`nr_hq_retry.h: nr_hq_retx_rule()` returns 1 (combine), 0 (first transmission) or -1 (decode alone, entry untouched). It returns -1 for the same NDI with a different TBS (stored TBS != 0).
`harq_retx_decide` uses the rule on both paths:
- CPU: -1 releases the entry and decodes via `passive_ldpc_decode_core`.
- GPU pass: -1 releases the entry, so hq_mode = 0.

The stored sum is kept for its own retransmission. HARQC `tbs_from_first` now counts these -1 decisions. SI combining is unchanged.

**This fix does not by itself make rv != 0 decode on air.** The combining-off runs are also at 0 %, so the remaining cause is the field reading `[INFERRED]`.

### Candidate ranking

1. **Post-equalisation SINR loss on multi-layer and wide grants** (inter-layer / co-scheduled interference, channel estimate on wide bands; the known NL2 LLR resolution issue, PROJECT_MEMORY 10-12 §5). Supported by the gap table and the EVM-margin CRC `[MEASURED]`. Mechanism within the equaliser `[NOT PROVEN]`.
2. **CSI-RS rate-match set on TIM even-frame slots 8/18**: known, small n here `[MEASURED, n=4]`.
3. **PT-RS**: unlikely `[INFERRED]`. Vodafone Nl 1 Qm6 C >= 8 passes 89 %, and TIM Qm6 Nl 2 C 2-7 passes 83 %. An unhandled PT-RS shifts every later RE and would give about 0 %. The PT-RS sweep made 0 trials (PTRS_SWEEP line), so PT-RS is assumed absent.
4. **LBRM: excluded for rv 0** `[INFERRED + MEASURED]`. With n_L >= rank, G <= 1.5 TBS_LBRM, so E <= N_ref and rv 0 never wraps. The n_L = 1 retries rescued 0.
5. **TBS / xOverhead / segmentation: excluded for the coding chain** `[MEASURED unit test]`. Vodafone Nl 1 large passes at the small-grant rate, and the unit test below decodes the failing shapes clean.

### Bug 2 cause: proven. The rv != 0 DCIs are read with the wrong DCI 1_1 layout

**Runs:** RMDCI (`ISAC_PDSCH_RM_GENIE=1`) in `ab_dgTG1_1_145921` (TIM) and `ab_dgVG1_1_150231` (Vodafone): 6000 rows each, with the raw DCI bits MSB-first. Field offsets come from SOLVEDLAYOUT. `[MEASURED, DGX OTA]`

**Rows and the solved layout:**
- The logged rv != 0 rows: TIM 148, Vodafone 630.
- Read with the solved layout (TIM: MCS at bit 18, pre_mcs 2; Vodafone: MCS at bit 20), every one of them reads **rv = 0**. NDI is mixed: TIM 115 ones / 33 zeros, Vodafone 341 / 289.
- Over all 6000 rows, the solved layout reads rv = 0 on every DCI.

**HARQ rules per (rnti, pid):** a new TB (NDI toggled) has rv 0; a retransmission follows 0, 2, 3, 1.

| layout | TIM | Vodafone |
|---|---|---|
| solved | 0/5699 violations | 0/5299 violations |
| fields read 2 bits early (TIM) | 2593/5921 | - |
| fields read 4 or 5 bits early (Vodafone) | - | 864/5681 and 1380/5810 |

**Which layout produced the logged fields:**
- Searching the raw bits for the offset that reproduces each logged (mcs, ndi, rv, pid):
  - TIM rv != 0: MCS at bit 16 for 136 of 148 rows.
  - Vodafone rv != 0: MCS at bit 15 for 477 rows, bit 16 for 136.
- TIM RV_RETRY run (`ab_dgTR1_1_150538`): 91 RVRESCUE lines, all MCS 0, `dci_rv=1 ok_rv=0`. The TB decodes at rv 0, the rv the solved layout reads.

**Where the wrong layout comes from (two mechanisms):**

1. **The representative is the lowest-id layout among CRC-equivalent ones** (TIM). `[MEASURED + CODE-READ]`
   - With `ISAC_DCI11_RV_CONSISTENCY` off, `choose_rep()` (nr_pdsch_solver.c) returns the first layout in id order that is consistent with the CRC-passed evidence.
   - Layouts whose MCS sits 2 bits early read the same fields on MCS-0, NDI-0 DCIs, which is the bulk of the evidence. So the solve picks the earlier one (ids 834/851/861, MCS at bit 16) until a distinguishing CRC pass narrows the set. Example: RNTI 0x4c22 solved on layout 834, moved to 861, then to 905 two evidence passes later.
   - The representative active when each RMDCI row was logged, rebuilt from the solver log:

| active representative | rv != 0 rows | rv 0 CRC |
|---|---|---|
| MCS at bit 16 | **147** | 48/89 |
| MCS at bit 18 | **1** | 4729/5763 |

2. **The representative is missing from the DCI's readings** (Vodafone). `[MEASURED + CODE-READ]`
   - With representative 1664 (MCS at bit 20) active, 787 of 5282 DCIs were fully decoded with another reading's fields: 1 CRC pass, 484 of them rv != 0. In those rows the antenna-ports value is 3-4 layers more often (ap 9/10: 471/787, against 1028/4495).
   - In `nr_pdsch_solver_plan_slot()`, a solved RNTI decodes reading `ri`, which **defaulted to 0 when no reading contains the representative**. Reading 0 is the lowest-id layout's reading. That is the only non-probe path that decodes a non-representative reading, and probes are excluded from RMDCI.
   - The monitor can leave the representative without a reading: grouping parses one layout per offset key, and an earlier same-key layout that fails to parse leaves the key's group empty. Which branch dropped it on these DCIs is `[NOT PROVEN]`: it would need the resolver state.

**Fix (general, no cell values):**
- **Representative choice:** `ISAC_DCI11_RV_CONSISTENCY` (DCIRV, existing code and tests) is now **default on** (`=0` turns it off). `choose_rep()` scores the CRC-equivalent layouts by TS 38.214 / 38.321 HARQ rules on the RNTI's last 64 DCIs and drops refuted ones. `hq_score` allows retransmissions at rv 0, so a cell that retransmits at rv 0 is not penalised. The solved layout scored 0 violations on both cells.
- **Missing representative:** a solved RNTI whose representative is in no reading of the DCI gets **no full decode**, only refinement probes (new solver why-counter `norep`).
- **Monitor:** when the representative has no group, it is parsed on its own, under the same admission rules, and given its reading.

**Tests:**
- `PdschSolver.SolvedRntiNeverFullDecodesAReadingWithoutItsRepresentative`: fails on the old `ri = 0` code by construction, passes now.
- `PdschSolverRvc.OnByDefault`.
- The existing `PdschSolverRvc.*` tests (shifted layout loses the representative, reselect, seeding) now pin the env explicitly.
- test_nr_pdsch_solver: 31/31 pass.

**Risks:** not measured on air yet.
- With DCIRV on, an MCS-0-only solution seeds the cell / other RNTIs only after HARQ verification, about 12 DCIs (`seed_ok`). This may delay the first solve of other RNTIs.
- The 2026-10-12 replay showed no CRC regression on Vodafone (n = 2).
- An OTA A/B is needed: rv != 0 rows, CRC, and the solve-time metric `ttc`.

### Bug 1: the per-CB pattern is censored

DECODEDIAG runs: `ab_dgTD1_1_150954` (TIM) and `ab_dgVD1_1_151304` (Vodafone).

- Failed CBs are never scattered: every TB is all-fail, a contiguous failing tail, or all-pass (0 scattered in both runs).
- This is OAI's decode abort, not the channel. `nrLDPC_decoder.c:75 set_abort()`: the first CB that fails stops every CB still running. So the per-CB verdicts after the first failure carry no information, and with the thread pool even CB 0 can be aborted.
- **The cause stays unproven from these logs.** `[CODE-READ]` for the abort mechanism.

TB CRC for C >= 8 by layers and EVM margin (`goal_metrics` true SNR minus required):

| cell | Nl | EVM margin >= 5 dB | 0-5 dB | < 0 dB or at the EVM floor |
|---|---|---|---|---|
| TIM | 2 | 84 % (n 189) | 16 % | 0 % |
| TIM | 3 | - | 79 % (n 14) | 4 % (228 at the floor) |
| Vodafone | 1 | 83 % | 38 % | 9-10 % |
| Vodafone | 2 | 76 % | 33 % | 0-1 % |
| Vodafone | 3 | 11/11 | 52 % | 8-19 % |

The failures sit where the post-equalisation SINR is low. This is consistent with the first report's DM-RS-to-EVM gap.

**What would prove it:** per-CB verdicts without the abort. The receiver's `abort_decode` would need a diagnostic mode that keeps decoding the other CBs. That is not an existing flag, so it is a code change for a separate decision. With it, look at which CB index, OFDM symbols and RB range fail first.

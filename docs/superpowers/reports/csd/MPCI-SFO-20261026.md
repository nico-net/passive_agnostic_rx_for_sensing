# MPCI-SFO 2026-10-26: per-cell SFO state

Branch `mpci/c-sfo` from `mpci-main` @ 86a3f902e2. Host: DGX GB10 aarch64, shared. No receiver run, no replay.

## What changed
- `nr_sfo_state.c`: the whole `nr_sfo_state_t` is `NR_CELL_STATIC_INIT(..., g_st, {.mu = PTHREAD_MUTEX_INITIALIZER})`, aliased through `NR_CELL_REF`.
  `t_pin` stays thread-local (a value, not cell state). Window, eps, DM-RS term, counters, mutex are per cell.
- Readers (`nr_sfo_eps_q`, `nr_sfo_eps`, `nr_sfo_eps_q_for_fep`) and writers (`nr_sfo_note_frame_read`, `nr_sfo_note_dmrs_residual`,
  `nr_sfo_resync`, `nr_sfo_reset`) resolve the cell with `nr_cell_idx()`. No reader file was edited: slot_fep_nr.c, nr_gpu_pass_dl.c,
  nr_pdsch_gpu_exact.c, nr_pusch_passive_decode.c, nr_pdsch_passive_decode.c (`gp_sfo_same()` = `nr_sfo_eps_q()` of the decode thread's
  bound cell vs `t_gp_sfo_q` recorded on the same thread, so it compares the same cell's eps). [CODE-READ]
- New API: `nr_sfo_resync_cell(cell, reason)` and `nr_sfo_resync_all(reason)` (all `nr_cell_count()` cells).
- Log text: own cell, N=1 identical ("SENSING: SFO reset (%s); previous eps ..."; D2 adds `[c<k>] ` only when count > 1). When a thread resets
  another cell the line says "of cell <k>". `SFO eps=` lines come from the cell's own thread, so they get the D2 tag.
- `nr-ue.c`: "initial sync" and "MAC sync request" use `nr_sfo_resync_cell(UE->Mod_id, ...)` (the sync actor thread may not be bound);
  "stream discontinuity" and "RF stall / PBCH lock lost" also use `nr_sfo_resync_cell(UE->Mod_id, ...)` (each cell detects loss on its own ring; coordinator decision). `nr_sfo_resync_all` stays in the API, unused. Frame-read note
  stays in UE_thread (bound by A8, `nr_cell_bind(UE->Mod_id)`).

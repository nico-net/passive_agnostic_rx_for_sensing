## Implementation

- [CODE-READ] `executables/nr-uesoftmodem.c:472` calls `nr_dl_gpu_warmup()` immediately before the discovery pipeline initialization, before `nrue_init_openair0()` and RX start. `nr_pdcch_blind_monitor_rt.c:7563` prepares CB0, polar, PDCCH FEP, PDSCH FEP and the configured passive PDSCH queue. Runtime loader getters do not call `dlopen`. Failed initialization is not retried during reception.
- [CODE-READ] `nr_td_grantwork.c:82` reserves and faults an ordinary host LLR pool, then seals it. Capacity is clamped consumers × configured queue depth × 16 signature entries; each entry fits the started grid's full-slot, rank-four, 256-QAM LLR maximum. At 217 PRB, three consumers and depth 20, this reserves 960 size-class buffers of 4 MiB (3.75 GiB). Exhaustion returns an error and releases the publishing owner correctly; main CPU decoding remains available. `ISAC_TD_GW_UNIFIED` remains accepted but never selects managed memory. FEP buffers are ordinary host memory, never mapped for GPU IQ access.
- [CODE-READ] `nrLDPC_cuda/ldpc_cb0.cu:816` initializes configured item/slot/chunk workspaces, streams/events, all legal BG/Z tables, common iteration graphs, and a small decode that exercises copy/prep/finish/callback machinery before sealing. Graph misses after warm-up use direct launches. The CB0 default memory strategy is explicit copies on both integrated and discrete GPUs. Historical mapped mode remains only in the offline test API.
- [CODE-READ] `nr_td_cb0_batch.cu:118` stages each distinct LLR pointer once, copying only the largest CB0 span requested for that pointer. Dematched inputs stay in device memory through LDPC; no host round trip of the expanded batch. Eight device output buffers are reserved in advance: a timeout/error retires an output permanently, and exhaustion falls back to CPU rather than growing or reusing memory still referenced by a pending decode. Busy/capacity/admission refusals rerun the same batch on CPU; decoder-dominance and failed-batch rules remain intact.
- [CODE-READ] `nr_pdsch_passive_queue.c:1701` initializes PDSCH FEP and its worker before RX. FEP scratch covers the queue's nine-job slot group, including preallocated self-check staging. FEP initialization is idempotent for the original geometry and refuses a different geometry without allocating. PDCCH FEP is also eagerly prepared; its existing module is not newly wired into a live PDCCH search by this task.
- [CODE-READ] `nr_polar_sc_cuda_host.c:206` reserves the 131072-item batch maximum, pinned staging, device buffers and all supported DCI length/aggregation parameters, then executes a warm decode. Runtime parameter lookup and decoding cannot grow those pools.
- [IMPLEMENTED, NOT VALIDATED ON RADIO] Four DL transfer paths have conservative admission accounting at 100 MB/s each, counting staging reads/writes as well as transfers. This prevents sustained whole-slot FEP transfers at the incoming IQ rate. Refused work takes the existing CPU path. This is admission accounting, **not a measured hardware bandwidth guarantee**; individual DMA bursts, achievable offload rate, and stale-drop improvement require OTA measurement.
- [CODE-READ] `nr_dl_gpu_memory.h` provides the CUDA allocation/free/registration/stream fence and per-module counting hooks. `ISAC_METRICS` adds `dl_gpu_allocs`, `dl_gpu_late_alloc_denied`, `dl_gpu_transfer_bytes`, `dl_gpu_transfer_refused`, and `gw_pool_refused`. CB0 refusal also increments the existing GPU-skipped counter. After the warm-up baseline, allocation counts must stay flat and late-allocation denials must stay zero. Counters cover the changed DL module call sites, not driver-internal allocation or the separate legacy TB decoder implementation.

The task's DL safety requirements apply with discovery off; they intentionally override the older brief's CSI-RS-only feature gate. Existing GPU enable flags, CPU fallbacks, iteration policy, CRC/LLR self-checks and enforcement defaults are retained. The discovery contract is unchanged. No changes to `radio/USRP/*`, `nr_csirs_disc_td.c`, or frozen sens6 data.

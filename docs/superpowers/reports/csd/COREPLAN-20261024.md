# COREPLAN-20261024: receiver core plan from the host topology (sens6)

Branch `sens6/coreplan` (base `sens6/integ` @ `1d497f7b3a`), code commit `54fa4d5435`. Host sens6 (x86_64 Intel Core Ultra 5 235, 14 CPUs, 14.8 GB RAM, RTX 4060 Ti, CUDA 12.4, gcc 15), build dir `build_cp` (`-DOAI_USRP=OFF`).

Evidence labels: `[MEASURED, sens6 rfsim 106 PRB 4 RX, 180 s, n=1]`, `[OFFLINE VERIFIED, sens6 unit test]`, `[MEASURED, sens6 ctest]`, `[MEASURED, sens6 /sys]`, `[CODE-READ]`, `[INFERRED]`. Nothing here is a DGX or OTA measurement; the DGX statements are unit tests on a reconstructed GB10 fixture.

Run extracts: `docs/superpowers/reports/csd/coreplan_20261024/{plan_on,plan_off}/` (plan lines, scorer JSON, `taskset -pc` per thread at 60 s and 150 s, `ps -L` placement of UEthread_0 every 15 s, pidstat and mpstat averages, `/usr/bin/time`).

## Headline

- The passive receiver builds its core plan from `/sys` at start-up and logs one `SENSING: CORE_PLAN` line, plus one `exported:` line and one warning line when it has no CAP_SYS_NICE. The planned values are exported for every `ISAC_*` core key that is unset, so the existing readers use them instead of the DGX numbers (15, 10-14, CPU 2, 13). Explicit `ISAC_*` values stay overrides. `ISAC_CORE_PLAN=0` restores the old defaults.
- On sens6 (rfsim): RT reader (UEthread_0) on CPU 3 (a P core), pool 4,5,6,7,8,9, float lane 10-13, housekeeping and dashboard on CPU 0, USS 12, nID 13, GPU worker 10. On air, the plan adds UHD control on CPU 1 and the USRP ring on CPU 2 (the isolated CPUs).
- Without CAP_SYS_NICE the affinity is now applied; before, it was dropped. Measured: UEthread_0 stayed on CPU 3 in 11/11 samples (94 % of that CPU). With the plan off, the same binary left it floating on the E-core lane (CPU 10 in 8 samples, CPU 12 in 3) `[MEASURED, sens6 rfsim 106 PRB 4 RX, 180 s, n=1 per arm]`.
- DGX: unit tests show that the GB10 fixture gives exactly today's assignment, both as layout and as exported keys (RT 5, UHD 15, ring 16, pool 6,7,8,9,3,4, lane 10-14, housekeeping 0-2, dashboard 2, GPU worker 10, USS 12, nID 13, check 10-14, recovery 11,13,14) `[OFFLINE VERIFIED, sens6 unit test]`. One behaviour change on the DGX: without CAP_SYS_NICE (rfsim, not sudo), threads are now pinned (UEthread_0 on 5) instead of floating; see section 5.
- Decoding is unchanged within one run each. post-solve CRC was 99.90 % with the plan and 99.88 % without; sections 3 and 4 give all numbers.

## 1. What the plan reads and decides

Code: `common/utils/nr_core_layout.{c,h}` (pure solver `nr_cl_build`, probe `nr_cl_topo_read`, process-wide `nr_core_layout_init`). It is wired in at the top of `main()` in `executables/nr-uesoftmodem.c`, before the float lane changes any affinity. It is active only with `--passive-rx`.

Inputs `[CODE-READ]`:
- online CPUs, and the process affinity as inherited (taskset or cgroup);
- `isolated` and `nohz_full`;
- `cpu_capacity`, else the Intel hybrid PMU lists (`/sys/devices/cpu_core|cpu_atom/cpus`), else `cpufreq` max;
- SMT siblings, L3 domain, NUMA node, and the NVIDIA GPU's NUMA node;
- CAP_SYS_NICE or RLIMIT_RTPRIO;
- hardware radio or not (`--rfsim` and offline replay count as no radio);
- UHD DPDK lcores, from `uhd.conf`.

Rules (header comment in `nr_core_layout.h`):

| W = usable CPUs minus RT/IO | mode | lane | housekeeping | pool |
|---|---|---|---|---|
| >= 14 | SEP | 5 far CPUs | 3 (anchor + leftovers) | rest, max 32 |
| 6..13 | COMPACT | 4 (W >= 10), 3 (W 8..9), 2 (W 6..7) far CPUs | the anchor (lowest CPU) | rest |
| <= 5 | SMALL | the anchor | = lane | rest (none when W <= 1) |

- **RT reader:** highest capacity bucket (10 %), then the GPU's NUMA node, then the lowest number. It is never the housekeeping anchor, and its SMT sibling stays idle.
- **Radio IO** (UHD control, then the ring): isolated CPUs when the mask is the kernel default, else the next big CPUs in the other L3 domain. DPDK lcores are never used.
- **Fixed-CPU workers:** GPU worker, USS and nID take lane CPUs 0, 2 and 3. Check workers use the lane. Recovery uses the lane minus the GPU worker and USS CPUs. The dashboard uses the last housekeeping CPU.
- **Removed design:** the previous agent's draft had "MERGED" modes, in which background work leases DISC/HOUSE tokens and idles on 1-2 home CPUs. That needs the background-lane leasing that `nr_bg_lane.c` does not implement (`nr_bg_lane_on() == 0`). COMPACT keeps a dedicated lane instead `[CODE-READ]`.

Other changes:

| file | change |
|---|---|
| `nr-uesoftmodem.c` | `nr_core_layout_init(true, radio)`; the hardcoded `ISAC_UHD_CTRL_CORES=15` and `ISAC_FLOAT_CORES=10-14` are set only when the plan is off |
| `system.c` `threadCreate` | the CPU passes through `nr_core_layout_filter_cpu`: a CPU this host cannot use is left unpinned, with one log line. Without CAP_SYS_NICE the affinity is kept (SCHED_OTHER) unless `ISAC_CORE_PIN_NOCAP=0`. A failed `pthread_setaffinity_np` with the plan active is a warning, not an assert |
| `nr_dashboard.c` | core from `ISAC_DASHBOARD_CORE`; still 2 when the variable is unset |
| `nr_pdcch_nid_gpu.c` | `ISAC_PDCCH_NID_GPU_CORE=-1` accepted, meaning the highest CPU of the thread's mask (used on hosts whose lane is shorter than 4 CPUs) |
| `nr_pdsch_recovery.c` | default CPUs = the plan's recovery mask; the old 10-14 when no plan is active (weak reference, so the unit test links without utils) |

Without CAP_SYS_NICE, the receiver logs one warning line at start-up: `SENSING: CORE_PLAN warning: no CAP_SYS_NICE and RLIMIT_RTPRIO=0: every thread runs SCHED_OTHER (no RT priority); the plan is applied as CPU affinity only`.

Reading:
- The plan does what it states. The reader sits alone on a P core, and the lane load drops from 71 % on CPU 10 to about 8 % per lane CPU, because the reader is no longer on the lane `[MEASURED]`.
- The decode counts differ mostly because the first C-RNTI came 4.4 s earlier, which leaves more time in the 180 s arm `[INFERRED]`. With n=1 that gap is within what one run can swing; no speed-up is claimed.
- drop_full went from 2 to 33 events. That is still 0.012 %, well under the 2.5 % gate limit, and within the 0.006-0.21 % range of the earlier sens6 arms (SENS6-SIM section 4, PORTABILITY section 4.1) `[MEASURED]`.

Comparison with the SENS6 reports (`[MEASURED, sens6 rfsim]`, other commits and boots, not pooled):

The UEthread_0 hotspot remains: it is the single-thread slot loop. Pinning moves it to a P core on its own; it does not split it (item 7 stays open).

## 5. DGX behaviour

- **Same assignment:** with isolcpus 15-19 and DPDK lcores 17-19, the planned and exported values equal what the DGX uses today. These are the `nr_env_core` defaults, the `--passive-rx` float lane, the `nr_bgq_start` check cores, dashboard CPU 2, and RT 5 / ring 16 from the POOL_20261021 launcher `[OFFLINE VERIFIED, sens6 unit test on a reconstructed GB10 fixture]`.
  - The fixture's L3 split and big/little split come from `env_dgx.txt` `lscpu -e`. The `cpu_capacity` values 1017/997/460 are assumed; only the 10 % bucket split matters.
  - **Owed:** one DGX start to compare the real CORE_PLAN line with the fixture.
- **Changed — no-capability runs:** without CAP_SYS_NICE (DGX rfsim gate runs, not sudo), threads used to float; now they are pinned. UEthread_0 goes to 5 even when `ISAC_UE_RT_CORE` is unset.
  - DGX OTA runs under sudo, so they already applied affinity and do not change.
  - To get the old rfsim behaviour, set `ISAC_CORE_PIN_NOCAP=0` (affinity off) or `ISAC_CORE_PLAN=0` (whole plan off).
- **Changed — RT core default:** `ISAC_UE_RT_CORE` is now exported as 5 when unset. The DGX launchers already set it to 5 `[CODE-READ, run_rx_dgx.sh / p99 replays]`.

## 6. Tonight's X410 OTA on sens6

- **Planned cores** `[OFFLINE VERIFIED, sens6 unit test]` for `--passive-rx` without `--rfsim` on the current boot (isolcpus 1-2, inherited mask unchanged):

  | role | CPU |
  |---|---|
  | UHD control (`uhd_ctrl*`) | 1 |
  | USRP ring producer | 2 |
  | UEthread_0 | 3 |
  | pool | 4-9 |
  | float lane | 10-13 |
  | housekeeping / dashboard | 0 |

  - Under sudo, the RT priorities apply as on the DGX.
  - `/etc/uhd/uhd.conf` is absent on sens6, so there are no DPDK lcores to avoid `[MEASURED, sens6 /sys]`.
- **Frozen `run_arm.sh` launcher:**
  - It sets `ISAC_UE_RT_CORE=${RTCORE:-2}` and runs under `taskset 0-7`. With the current boot, CPU 2 is isolated, so the reader keeps 2, UHD control goes to 1 and the ring to 3.
  - The narrowed mask leaves W = 5 (SMALL: lane 0, pool 4-7).
  - **Recommendation:** run without `taskset 0-7`, or use the in-tree plan as it is.
- **IRQs:** the plan does not set NIC IRQ affinity (that needs root and stays in the launcher). `run_arm.sh` pins NIC IRQs to 8-13. On this layout, 8-9 are pool CPUs and 10-13 the lane.
  - **Recommendation:** move the X410 NIC IRQs to lane CPUs 10-13, or to 0, and keep them off 1-3 `[INFERRED]`.
- **Build:** `build_cp` is configured with `-DOAI_USRP=OFF`. The OTA binary needs a build with `oai_usrpdevif` (UHD 4.9 is installed). `usrp_lib.cpp` was not changed; it reads the exported `ISAC_UHD_CTRL_CORES` / `ISAC_USRP_RING_CORE` `[CODE-READ]`.
- **RAM:** RSS reached 7.0 GB at 106 PRB 4 RX in rfsim. Check MemAvailable before the OTA run (SENS6-SIM item 6).

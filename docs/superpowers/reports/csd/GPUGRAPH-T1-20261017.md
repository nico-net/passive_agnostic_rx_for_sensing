# GPUGRAPH Task 1 (2026-10-17): v2 mode, LLR stats on the device, prewarmed pool for late threads

Branch `csd/int16-gpupath`, binary build_t26 (`CMAKE_CUDA_ARCHITECTURES=89;121`, libpdsch_gpu.so carries sm_89 + sm_121 ELF [MEASURED cuobjdump]). Plan `docs/superpowers/plans/2026-10-17-dl-gpu-datapath.md` Task 1, spec section 10.

## What changed [CODE-READ, this commit]
- `ISAC_PDSCH_GPU_GRAPH=1` brings the DL graph pass up in v2 mode (`nr_gpu_graph_on()`); with `ISAC_GPU_PASS=1` also set it logs one line and v1 runs. Census lines are prefixed `GPUGRAPH pool[sets claimed empty]`; disable lines say `GPUGRAPH DISABLED`. `nr_gpu_graph_flag(sub)` reads `ISAC_PDSCH_GPU_GRAPH_<sub>`.
- `k_llr_stats` (nr_gpu_pass_graph.cu): the 11 LLR statistics of the body's demod_ok block (magnitudes, signs, posbit/nbit) as one kernel after `k_unscr` (descrambling only flips signs and |-v| == |v| for every int16, so the pre/post halves of the plan fold into one pass). Integer sums: bit-equal. In v2 the body takes them from the result instead of the host loops and counts pass-taken grants in the `g_llr_*` census (v1 unchanged).
- `nr_gpu_graph_pool.h`: 8 host buffer sets (out + job + LLR + shadow), allocated and prefaulted pre-fence, lock-free claim. `gp_thread_prewarm` claims one when v2 is on and the fence is up, before the nomem gate. Header-only so `test_nr_gpu_pass` tests the same code without a CMake change.
- Tools: `tests/passive_rx/gpugraph_ab.sh`, `gpugraph_tail.py` (+ `test_gpugraph_tail.py`). gpugraph_tail.py on the spec's v1 run reproduces spec 10.0 (b: 29/45 tail grants stage path, 12.9 % share).

- The pool is claimed by exactly one thread, `pdschRecov` (the async recovery worker); its bodies run outside tot, so removing nomem does not move tot p99. The tail grants still on the stage path are first bodies gated by probe (2949-6729 per run), seg > 16 (~400 on b), unseen class (210-226 on tim), old_first/shadow: Task 2 territory.

## Deviations
1. ON arm carries ISAC_GPU_PASS_RETRY_OLD=1 + ISAC_GPU_PASS_POLL_SLEEP_US=600 (plan: the master flag alone) so the tail split compares with spec 10.0.
2. One `k_llr_stats` kernel after `k_unscr` instead of `_pre`/`_post` halves (same values, one launch fewer).
3. Pool code in a new header `nr_gpu_graph_pool.h`; the test exercises its pool directly (no `nr_gpu_graph_pool_init_for_test` / fence hook: the module has no reversible fence and nr_gpu_pass_dl.c is not linked into test_nr_gpu_pass). The pool test was green before the implementation was wired (header-only); its red step is by construction.
4. A `GPUGRAPH pool claim by thread <name>` log line per claim (at most 8 per run).

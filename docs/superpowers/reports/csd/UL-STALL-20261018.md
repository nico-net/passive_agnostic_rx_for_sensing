## 1. Mechanism [CODE-READ unless stated]
1. UL FEP and LDPC run in the real-time partition at the least stream priority (ISAC_UL_GPU_PART=rt, nr_pusch_gpu_diag.h).
   - Stream priority orders PENDING blocks only.
   - So a UL launch waits for every higher-priority block that is pending or running in the partition.
   - [MEASURED, test_nr_pusch_gpu_fep Bench with the injector] A UL launch waits about one running kernel length.
     With 4 ms spin kernels: p99 8.1 ms, against 37 us idle.
2. nr_pusch_gpu_fep_run waits for its kernel with no deadline ("a late kernel is waited for, never abandoned"), because the
   kernel writes the caller's rows directly.
3. The wall time of the call, including the time queued behind DL, is added to the 30 % duty window.
   One 26 ms call nearly empties it, and the rest of the 100 ms window goes to the CPU FEP (VL2 over_cap=166).
4. UL LDPC: 4 ms deadline, but no hold afterwards. Every TB in a starved stretch pays the 4 ms again (VL2 ldpc-deadline 5;
   replay below 70-130 per run).
5. The UL queue had no age limit for a job that holds a shared snapshot (ISAC_UL_SNAP_POOL=1). Only the no-snapshot path
   was policed (nr_pusch_queue_snapshot_fresh), so a backlog was drained in full (VL2 queue wait 44 ms median, 60 ms max).

## 2. Reproduction
- **Cross-process GPU load** (scratchpad ulst/burst.cu: back-to-back spin kernels from a second CUDA process; replay b,
  n=3 per arm) does NOT reproduce VL2.
  - Time slicing between the two contexts blocks host CUDA calls instead of queueing UL blocks: ULSTALL gpu_us is about
    50 us and wake_us 3-16 ms (one blocking cudaStreamQuery, nvcsw=1).
  - over_cap reached 58-326 and fep max 17-23 ms, but the UL queue wait stayed below 17 ms. A FEP deadline cannot bound a
    blocking API call.
  - These runs (rpC, table in section 5) are not used for the decision.
  - Host hygiene incident: 11:30-11:46 the burst process outlived its replay and loaded the core agent's runs.
    Those runs and mine are discarded. wrap.sh now ties the burst to the receiver.
- **In-partition load** (new, TEST ONLY, default off): `ISAC_UL_TEST_RT_LOAD=delay_s:burst_ms:gap_ms:blocks[:kern_us]`.
  - A thread keeps 3-4 spin kernels pending in UL context 0's real-time green context, at the GREATEST priority.
  - With 5:600:1400:1024:1000 on replay b, the off arm shows the VL2 signature [MEASURED, b, n=4]:
    - FEP ULSTALL gpu_us up to 14.7-19.4 ms, launch and wake small;
    - FEP over_cap 317-1129;
    - UL queue wait max 14-24 ms (4-48 real grants above 10 ms);
    - UL p99 14.5-18.4 ms;
    - DL p99 19-26 ms: the DL is starved by the same load, as in VL2.
  - Not reproduced: the 40-60 ms backlog and queue-full drops. The replay's UL rate (about 250 real grants/s plus probes)
    is below VL2's 400-700/s.

## 3. Changes (all default off)
| flag | what | file |
|---|---|---|
| `ISAC_UL_GPU_FEP_DEADLINE=1` | The kernel writes per-context staging rows (allocated and written at warm-up), copied to the caller's rows on success.<br>Deadline = one slot (1000 / slots_per_subframe us, 500 us at 30 kHz).<br>On a miss the call is abandoned: the context stays reserved until its stream drains, nothing of the caller's is touched, and the caller runs the CPU FEP (-4).<br>Hysteresis with no constant: CPU while the abandoned call is on the GPU, then for as long again as it took (launch to reclaim).<br>Counters deadline/hold/reclaimed on the UL_GPU_FEP line. | nr_pusch_gpu_fep.cuh/.h, nr_pusch_passive_decode.c |
| `ISAC_UL_GPU_FEP_KCHARGE=1` | Duty cap charged with the kernel span (%globaltimer per block: first start to last end), not wall time. An abandoned call's span is charged at reclaim. | nr_pusch_gpu_fep.cuh |
| `ISAC_UL_STALE_DROP=1` | A job holding a shared snapshot is dropped at dequeue by the existing UL age rule (one frame minus 5 slots = 7.5 ms at 30 kHz), counted in slots AND in wall time from the slot's arrival.<br>The producer's slot counter lags when the host stalls: with the slot rule only, grants still waited 11-14 ms.<br>Real-grant stale drops: PUSCHQ2 `real_stale=`, scored as UL drops by goal_metrics.py. | nr_pusch_passive_queue.c, goal_metrics.py |
| `ISAC_UL_GPU_LDPC_HOLD=1` | The FEP hysteresis applied to the UL LDPC deadline: CPU decoder while an abandoned call is on the GPU and for as long again after it drains. | nr_pdsch_gpu_ldpc.cu |
| `ISAC_UL_TEST_RT_LOAD=...` | TEST ONLY injector (section 2). Never on air. | nr_pusch_gpu_fep.cuh |

## Risks / open
- The deadline path is the one that bounds the starved FEP call itself; it waits for a cheaper copy-back:
  - Options: GPU writes straight to the caller rows plus a per-call cancel flag and a CPU FEP into a second row set; or
    pinning the consumer read to the GPU-written lines.
  - Without it, under a VL2-like burst the FEP calls still wait 15-20 ms each, and the queue age limit turns that into
    stale drops (0.9-3.7 % in the synthetic stall; a real 0.6 s burst at about 1 grant/slot would drop about 1000 grants).
- The wall-time age needs the arrival ring of ISAC_E2E_TRACE=1 (on in t26uL). Without it only the slot-count rule applies.
- The UL LDPC deadline (4 ms, ISAC_UL_GPU_LDPC_DEADLINE_US) is an existing constant, not derived from slot timing; not
  changed here.
- Not reproduced: queue-full drops and the 40-60 ms backlog (replay UL rate too low); the CSI-RS discovery share of the
  VL2 GPU load.
- The injector models DL as spin kernels at the greatest priority; the real DL mix (LDPC/demod kernels of 12-22 CBs) is
  not measured per kernel.
- Process: one early build (11:26) was started while another agent's receiver ran (it waited on heavy.lock, no overlap).
  Every later build checks pgrep inside heavy.sh.

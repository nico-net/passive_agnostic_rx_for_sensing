## 0. Conditions of every run (read first)

- **Shared host.** Other agents' ctests, replays and rfsim receivers ran on sens6 during my arms. Host-level MemAvailable minima are therefore **not idle-host numbers**. In one arm (`od273_gpu`) a second, foreign `nr-uesoftmodem` (pid 171611, not from `build_od`) was alive for part of the run.
- **What counts.** The numbers that count are each arm's own scope numbers (`memory.current`/`memory.peak`, swap, `oom_kill`) and the receiver's `/proc/<pid>/status` (VmRSS, VmHWM, VmLck, VmSwap), sampled every 3 s.
- **Launch (coordinator rule 2026-10-24).** Every arm was launched as follows:
  - under `flock -x /tmp/td_measure.lock`;
  - inside its own transient scope: `systemd-run --user --scope -p MemoryMax=<cap> -p MemorySwapMax=1G choom -n 1000 -- tests/passive_rx/dgx/rfsim_arm.sh`;
  - with `cap = min(7G, MemAvailable - 0.5G)` read at start;
  - only when MemAvailable was >= 7 GB at start.
- **Scope contents.** The gNB and the receiver share the scope, so the receiver's budget sees the cgroup v2 headroom (`limited_by=cgroup_v2`).
- **Other settings.**
  - `ISAC_RX_BRANCH_FO` was unset.
  - Receivers stop at the arm timeout with SIGINT (`timeout -s INT`).
  - Builds ran with `flock -x /tmp/sens6_build.lock` + scope `MemoryMax=5G` + `nice -n 19 ninja -j3`.
  - ctest ran with `-j2` in a 4G scope under the measurement lock.
- **mlockall in rfsim.** It fails in every rfsim arm (`mlockall() failed: 12`), because the user `sens` has `ulimit -l` = 8 MB and no CAP_IPC_LOCK. So VmLck = 0 in rfsim. The lock *plan* is still computed and logged. On air the receiver runs under `sudo`, so the lock applies there (see §4).
- **Hugepages.** The 4 GiB hugepage pool was reserved during the rfsim arms (`hugetlb_mb=4096/free=4096`). By 19:39 UTC someone had released it (`hugetlb_mb=0`, MemAvailable 11 GB). Check `/proc/meminfo` before the OTA if the X410 / DPDK path needs it.

## 1. Root cause recap and what was still open after item 7

- **Earlier host death** [MEASURED, sens6 273 PRB, previous agent]. The GrantWork LLR pool was 4096 x 2,935,296 B, about 12 GB, pre-faulted and locked. The result was a swap storm and then the OOM killer.
- **HEAD `ccbd74d36c` crashes at every start** [MEASURED, sens6 rfsim 273 PRB 4 RX, run `base273_gpu`]. The process dies after 7.4 s with `ISAC_SEGV_BT signal 11` at a stack address in `libpdcch_nid_gpu.so resize+0x1d`.
  - [CODE-READ] `resize()` kept a by-value copy of `Device`, which holds the CHUNK/CELLS tables (tens of MB), so the stack probe faulted on the 8 MB main-thread stack.
  - The unit test uses a fake module, so it never exercised this.
  - Fixed in `8d0f935f41`: the copy is now on the heap.
- **The gaps listed in the task.** All were confirmed by [CODE-READ] and are closed in `6a76e1b2f3` (§2):
  - queue bytes were committed after the GrantWork share was computed;
  - only the queue and GrantWork reached the budget;
  - mlockall was unconditional;
  - there was no launcher check.
- **GrantWork buffer size was undercounted** [CODE-READ]. Each buffer is a power-of-two class plus a 64 B header: 4 MiB + 64 B at 273 PRB, not 2.9 MB. The old budget undercounted by 43 %, and under `mlockall(MCL_CURRENT)` the whole 4 MiB is faulted in.

## 2. What changed (`6a76e1b2f3`)

Every module that takes a lot of host memory now commits its real bytes to `nr_host_membudget` and appears on the `SENSING: HOST_MEM` line. Order of sizing at start (`executables/nr-uesoftmodem.c`):

| # | module | kind | rule | log |
|---|---|---|---|---|
| 1 | USRP RX ring (`usrp_ring`) | shrinkable, **reserved first**, OTA only (not rfsim/replay) | `ISAC_USRP_RING_MS` x nb_rx x samples/ms x 4 B. Fits in 50 % of the headroom, floor 100 ms. **Below the floor the receiver refuses to start, exit 7.** usrp_lib reads the planned ms through `dlsym(RTLD_DEFAULT,"nr_host_membudget_usrp_ring_ms")` and commits the bytes it allocated | `HOST_MEM USRP ring 500 ms reserved (937 MB)` / `500 -> N ms` |
| 2 | GPU pass pinned mirrors (`pinned`) | fixed | `pinned_host_mb` of the pass census (cudaHostAlloc) | on the HOST_MEM line |
| 3 | PDSCH queue arenas (`queue`) | fixed | rxdataF + owned IQ per consumer, committed **before** anything is sized | on the line |
| 4 | async-recovery IQ snapshot holders (`snap`) | shrinkable | 8 x 37 MB at 273/4RX. Fits in 10 % of the headroom, floor 2. Below the floor: recovery stays inline | `recovery snapshot holders 8 -> N` |
| 5 | CSI-RS discovery ring (`csirs`) | shrinkable | host grid (+ snapshot ring when used). Fits in 30 %, floor 160 slots. Becomes the elastic base. Run-time growth also needs the whole new grid inside the host headroom (it is allocated before the old one is freed) | `CSIRS_DISC ring A -> B slots (host-RAM budget)` |
| 6 | CSI-RS time-domain slot queue (`td`) | shrinkable | 1024 slots x 1.04 MB + 100 batch slots + FFT buffers (1.3 GB at 273/4RX). Fits in 60 %, floor 256 slots. Below the floor: discovery off (logged), receiver continues | `time-domain queue 1024 -> N slots` |
| 7 | GrantWork LLR pool (`gw_pool`) | scalable, **last** (`nr_dl_gw_pool_warmup`) | share = min(accounted 60 % of B minus everything committed, live re-probe share). Unit = the real allocation. Below a floor of 8 sets per consumer: no pool, CPU path without LLR sharing | `GrantWork pool A -> B buffers ... (share: accounted X, live Y)` |
| - | hugetlb pool | info | reported `hugetlb_mb=T/free=F(outside_MemAvailable)`. It is already outside MemAvailable and not charged to memcg, so it is **not** deducted again [CODE-READ kernel semantics] | on the line |

Budget definitions (`openair1/PHY/TOOLS/nr_host_membudget.h`):
- `avail = min(MemAvailable, cgroup v2/v1 headroom)`, probed once at the first planning call. Swap is never counted.
- `B = 0.8 * avail - 1.5 GiB`. This is the budget that shrinkable and scalable modules are sized from.
- Hard limit `H = avail - 512 MB`. If the committed bytes exceed H after everything is sized, the receiver logs `SENSING: HOST_MEM REFUSE: ...` with the per-module list and refuses before the radio is touched (exit 7).
- Live re-probe at GrantWork time: `0.9 * MemAvailable_now - 512 MB - reservations not yet allocated`. It covers whatever the accounting does not list: CUDA host allocations, other processes.
- `NR_HOST_MEM_BUDGET_MB` still emulates a host.

mlockall (`common/utils/system.c`, receiver only, through weak symbols; the gNB and the tools keep upstream behaviour):
- It runs after the budget plan.
- It sums `Size - Rss` over the accessible mappings in `/proc/self/smaps`. PROT_NONE reservations (CUDA VA), `/dev/*`, VM_IO/VM_PFNMAP and hugetlb mappings are skipped.
- If that sum fits `calc(MemAvailable_now)`, it uses `MCL_CURRENT|MCL_FUTURE`. This is unchanged on the DGX: 128 GB unified, always `full`.
- Otherwise it uses `MCL_CURRENT|MCL_FUTURE|MCL_ONFAULT`. The pools are pre-faulted by their owners, so they are resident and locked either way; mappings that are never touched no longer get faulted in.
- Log lines: `SENSING: HOST_MEM mlock plan=full|onfault unfaulted_mb= live_avail_mb= ...` and `mlock done flags= vmlck_mb=`.

Launcher check (task item 4):
- **There is no 48 GB guard in this repo.** [CODE-READ, `git grep`] The `MemAvailable >= 48 GB` check is in the DGX's `rr-orchestration/ota/ota.sh` (PROJECT_MEMORY header and §25 notes). It does not exist on sens6, and no file under `tests/passive_rx/` checks free memory.
- The sens6 OTA launcher `tests/passive_rx/captures/run_arm.sh` is frozen and has no memory check. It was not edited.
- New file: `tests/passive_rx/hostmem_preflight.sh <nr-uesoftmodem> <receiver args>`. It runs the receiver itself with `ISAC_HOST_MEM_PLAN_ONLY=1`, which does the complete real sizing (ring reservation included) and exits before `nrue_init_openair0`. No X410 claim is made.
- It prints `SENSING: HOST_MEM PLAN verdict=OK|REFUSE ...` and exits 0 when the plan fits, 7 when it is refused (the DGX guard's code), 3 when there is no verdict.

## 6. What is not done / open

- **Not run on the X410.**
  - Not run: the USRP ring plan in the driver (`usrp_ring_ms()` override and commit), and `mlock plan=full|onfault` with `sudo`, where mlockall succeeds and VmLck > 0.
  - Expected [CODE-READ]: on air under sudo with MemAvailable about 7-11 GB, the plan is `onfault`, so VmLck = the touched pages only, not the 1.6-2 GB of untouched mappings.

- **GrantWork pool shares are small on sens6** (159-524 buffers, or 0). The pool only gives throughput: a miss decodes on the CPU path without LLR sharing. The power-of-two class wastes 30 % at 273 PRB (4 MiB per 2.9 MB set). Exact-size classes would give about 40 % more buffers. Not done.
- PROJECT_MEMORY.md is not updated. This report is the record.
- The frozen `captures/run_arm.sh` still does `sudo pkill -9` on timeout. **For tonight, use a launcher that sends SIGINT**, per CLAUDE.md.

Decision for tonight: **`NR_GPU_PATH_FEP=cpu`**. In the clean arms CPU FEP has the lowest tot p50 and dec p50, at rank 1 and at rank 4. p99 and CRC are equal within noise. n = 1 per arm per round, so this is a small-sample decision. C equals B functionally: `SELECT=off` already gives `choice=gpu` for pass_dl and ldpc_dl (`reason=select_off` vs `reason=env`).

Does CPU FEP add host↔device copies? No, not on the pass path `[CODE-READ, nr_gpu_pass_dl.c:606-623; nr_pdsch_passive_decode.c:3008-3017]`.
- GPUPASS takes the time-domain IQ ring (`nr_pdsch_passive_iq_for_slot`) and runs its own FEP on the device. In DISCRETE mode it copies back only the grant's symbols (`copy_mask`).
- A grant the pass decodes (`gp_ok`) runs no CPU FEP.
- `NR_GPU_PATH_FEP` chooses only the FEP of grants outside the pass (`GPU_EXACT_FEP`: ~4000 calls per 200 s, mean ~0.66 ms when GPU).
- Pass coverage `[MEASURED]`: launches = graph_hits = 9925 / 9893 / 9939 (rank 1) and 5687 / 4710 / ~5.3k (rank 4), with fallback 0 and need_cpu 0 in every arm.

- SOLVERTDDEND: `slot phase {special} learnt ... failed k of n` with k < 8.

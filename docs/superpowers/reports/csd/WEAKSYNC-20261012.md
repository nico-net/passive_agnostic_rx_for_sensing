# WEAKSYNC 2026-10-12: cheap + sensitive initial sync, multi-PCI, SIB1 for the new cells

Evidence labels: [MEASURED, replay] = nr-uesoftmodem replay on the DGX (worktree rr-csd-wsy, branch csd/weak-sync, 4 RX, env t26u, SPEED 0.25),
[MEASURED, unit] = test_nr_pss_decim, [INFERRED] = reasoning. NO OTA was run. Single host (DGX), single capture per cell.
All flags default OFF; nothing is tuned per cell. Fully blind: the PSS centre bin comes from the grid geometry (first_carrier_offset +
ssb_start_subcarrier), not from a cell constant.

## OTA env delta (t26u -> t26w)
`ISAC_PSS_DECIM=1 ISAC_PSS_ACC=8 ISAC_SSS_MULTI=2.5 ISAC_KSSB_ALIGN=1 ISAC_SI_RV_ANY=1` (all new, all default off; ISAC_SSS_REL_RATIO=2.5 stays).
Operator-chosen target: `ISAC_TARGET_PCI` is unchanged in meaning (N_ID_2 pin); with ISAC_SSS_MULTI it pins the full PCI.

## 1. Why one failed sync attempt costs ~20 s [MEASURED, replay; INFERRED for the OTA factor]
Stock pss_search_time_nr: 4096-tap int16 dot products at every 4th sample, 2 frames x 3 N_ID_2 x 4 RX ~ 30 G MAC. Replay (isolated, 1 GSCN, 4 RX,
217 PRB): SYNC_SCAN 6.2 s per attempt; OTA ~20 s is the same work under RT-thread/GPU contention [INFERRED]. New ISAC_PSS_DECIM path (mix PSS centre
to DC, CIC-3, decimate by N/256=16, float correlate, full-rate float refine +-2D): SYNC_SCAN 0.50-0.54 s (12x), 0.29 s when the first frame hits.
It also removes dot_product()'s floor-shift bias on weak input: stock peak/avg on c3550 was 10 dB, decimated float is 24 dB on the same capture.
Bug found+fixed on the way: the int16 IDFT reference carries a DC bias and a stray component near DC, so a spectrum-derived centre followed them
(TIM 923 ssb 233: never synced). The reference is now bandlimited to its 127 PSS bins around the geometric centre.
Not done: shorter retry cadence (the loop is capture-bound: each attempt needs 2 fresh frames, ~20 ms of data); with 0.5 s attempts the attempt rate is set by capture + the ~1 s catch-up, not compute. [INFERRED]

## 2. Multi-burst non-coherent accumulation (ISAC_PSS_ACC=K) [MEASURED, unit + replay]
Fold of the decimated per-position PSS profile over successive attempts on the absolute 20 ms grid, acc = acc(1-1/K) + new; SSS/PBCH CRC24 still decide
on the newest capture. Unit test (synthetic PSS, 4 RX, 0.5 ms window, 90 % detection): K=1 -28.5 dB, K=8 -35.0 dB per-sample SNR = **6.5 dB gain**
(theory for 8 non-coherent sums of 4-RX profiles: ~5-6 dB). Replay c3430 (PCI 675, no sync before): syncs on the first attempt with the float correlator alone.
The fold needs the capture start (UE_synch passes capture_end - 2 frames); it resets on a lock or a backwards time step.

## 3. All PCIs at one SSB frequency (ISAC_SSS_MULTI=R) [MEASURED, replay]
Top-3 N_ID_1 per N_ID_2 are each PBCH-CRC-tested; line `SSB_MULTI_PCI cand(pci:sss:pbch)`. c3550: `508:41571:crc_ok 4:18708:crc_ok 691:crc_fail`
-> **both 508 and 4 decode** (two cells on one SSB frequency, confirms the earlier sweep). Chosen = strongest SSS that decodes (508). c3610: 403 only;
c3430: 675 only; raw_pci415: 415 only; TIM 923: 923 only.

## 4. SIB1 [MEASURED, replay]
- Root cause A (receiver): the CSS0 grid is offset from the CRB grid by (ssb_sc - k_SSB/2) mod 12 subcarriers (c3550: 6, c3610: 1, c3430: -4), so no
  SI-RNTI PDSCH decodes. ISAC_KSSB_ALIGN=1 moves --ssb/-C like an operator would (UE_synch now re-reads the carrier). Result: c3610 PCI 403 SIB1 decoded
  (barred cell still broadcasts), c3430 PCI 675 SIB1 decoded: PLMN 222-01, cell_identity 0x5ba6041e1.
- Root cause B (receiver): SI-RNTI grants with rv!=0 and "autodiscover-unverified" were dropped (SIB1 repeats RV 0,2,3,1; DCI 1_0 size is fixed by CORESET#0).
  ISAC_SI_RV_ANY=1 exempts RNTI 0xffff. c3550 PCI 508: DCIs now reach PDSCH, but per-branch SNR is +1..2 dB on RX0 and -13 dB on RX1-3 (the survey
  capture has the antenna on one channel only): TB CRC fails, acq_sib1_decodes 0. [INFERRED: link budget, not receiver logic] PCI 4 not tried (same SSB, needs ISAC_TARGET_PCI=4).

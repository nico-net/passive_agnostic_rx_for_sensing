## What A8 wires

Cells come only from `<run dir>/cells.json` (D1 parser/watcher; run dir = directory of stdout when it is a regular file, the uectx rule) and the
admission plan (B3 via the D1 manager). No option, no env var. New module `common/utils/nr_cell_life.{h,c}`: order (the started cell is always
slot 0, merged with the inventory entry at the same centre within 1 kHz) -> `nr_cell_mgr_plan` (MPCI_ADMIT line) -> **admit** (slots known) ->
**prepare** (prealloc hook of each cell, bound to it; fence hook; `nr_cell_set_count`) -> **start** (start hook, bound) -> run time poll
(retire after the manager's hysteresis, re-activation of a slot prepared before the fence, retune event; a slot never prepared is not started).

Receiver main (`executables/nr-uesoftmodem.c`), only when more than one cell is admitted:
- before the core plan: `mpci_plan_cells()` (inventory, host caps from the device: `nr_host_probe_at`, `nr_cl_max_cells`, pool size), then
  `nr_core_layout_init_n(.., N)` (CORE_PLAN with `cells= rt_cells=`). `NB_UE_INST = N`.
- cell k > 0: `nrue_add_cell_ru()` (new in `nr-ue-ru.c`): cell params from the slot (centre, n_rb, numerology, SSB start derived from
  `ssb_hz`/centre/n_rb), own RU = shm_iq consumer of ring `nrcell_<inventory id>` (loaded directly whatever the configured device);
  `initial_fo` = inventory CFO; actors bound with a first job (`nr_ue_bind_actor`). Line `MPCI_CELL_SLOT cell=k ...`.
- prealloc hook (bound to k, before `nr_cell_alloc_fence()`): `nr_passive_reconf_rules_cell_prealloc`, `nr_passive_ue_ctx_cell_prealloc`,
  `nr_pdcch_cell_prealloc`, `nr_pdsch_cell_prealloc`, `nr_ul_cell_prealloc_all`; k > 0: `nr_pdcch_blind_monitor_init()` and uectx with
  `nr_cell_path(k, ..)`; `nr_csirs_disc_pipeline_init` + `nr_csirs_disc_cell_prealloc(k, fp, nant)`; PUSCH queue start.
- `nr_cell_alloc_fence()` right after `nr_gpu_rx_started()`. Start hook: `init_NR_UE_threads` per cell (bound). Control thread polls cells.json 1/s.
- shutdown: queue stops, csirs release, obs/uectx close per cell (bound); N=1: one iteration on cell 0 = the old sequence.
- input check: N > 1 needs published rings (configured device `shm_iq`). With a radio device, rfsim or the offline replay env, the receiver
  logs `MPCI_INPUT ... serving the started cell only` and runs N=1.

Slot threads / binding (`executables/nr-ue.c`, `openair2/RRC/NR_UE/rrc_UE.c`):
- `UE_thread` and the stats thread `nr_cell_bind(UE->Mod_id)`; RRC task binds to the message instance (instance k = cell k), so the MAC config
  sites of A4 (`config_ue.c:1801/2345`, `nr_passive_rrc_harvest.c` on the bound PDSCH consumer, `nr_ue_dci_configuration.c` on the bound actors)
  resolve to their cell `[CODE-READ]`. `phy_procedures_nr_ue.c` callers (`td_push`, traffic probe) run on the bound slot thread / actors: no edit.
- Decision F2 (a): one RT slot thread per cell; cell 0 keeps `ISAC_UE_RT_CORE` (= rt_cell[0]), cell k > 0 takes `nr_core_layout()->rt_cell[k]`,
  logged `SENSING: MPCI_RT cell=k slot thread core=c` (the P3 per-cell RT core). Pool / lane / housekeeping stay shared (CORE_PLAN line).
- Per-cell slot clock (new `nr_ue_cell_clock.h`): producer absolute slot / wall ns, rebase delta/valid, signal-absent; early-start banks,
  progress, done, slot gate (`nr_early_start.h`) — all were process globals read by the scan/PDSCH/PUSCH consumers (age, freshness, credit):
  two cells have different SFNs, sharing them would mis-age every job of the other cell. Names unchanged at call sites (macro over
  `name_cells[nr_cell_idx()]`); the `extern` lines in 8 consumer files and the definitions in 3 test stubs + 3 physims were replaced.
- `nr_adjust_synch_ue.c` `s_gr_cnt` per cell; `nr-ue-ru.c` `s_radio_fo` per cell.
- Scan producer `gNB_id`: **not changed** (deliberate): `proc.gNB_id` indexes OAI per-gNB arrays (RRC `perNB[]`); the pool cell is already the
  bound consumer's `nr_cell_idx()` (A4), which is the alignment the plan asked for.

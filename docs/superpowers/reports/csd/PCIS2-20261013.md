## 1. Interference measurement (offline, no receiver)  [MEASURED, DGX offline, c3610 and c3550 survey captures]

Method (`cochannel.py`, no per-cell constant: PCIs, Point A, CFO are arguments): frame timing from the SSB burst (PSS fold, PBCH DM-RS of the cell picks the SSB index), per slot/symbol FFT on the exact 162-PRB grid (Point A 3560.850 MHz from SIB1 of 508; CORESET#0 lowest RB 2, 48 RB), joint least squares of the type-1 PDSCH DM-RS sequences of all listed PCIs (nSCID 0, scrambling id = PCI = SIB1 case) in blocks of 16 RB (flat channel) with a per-cell timing slope. Output: channel vector per cell/block/symbol (4 RX) and the residual. Noise floor 72.0 dB (sum over 4 RX per RE, measured in UL slots 4/5/14/15).
The list of candidates was not hand-picked: a scan of all 1008 scrambling ids over the SIB1 slots gives 508 (+7.3 dB over the median), **688 (+6.7 dB)**, 614 (+3.8), then noise (<= 2.6 dB); c3550 the same (7.4 / 7.1 / 3.8) (`pdsch_dmrs_pci_scan_*.txt`). The SSB census over all 1008 PCIs and 8 SSB indices finds 508 (indices 1,0,6,3,2), 4 (index 0, 8.6 dB) and 614 (indices 5,6), **never 688** (`pbch_census_*.txt`): 688 is a fourth co-channel transmitter whose SSB is not in the window or uses another SSB position [INFERRED].

### 1.4 Spatial rank
Mean |correlation| of the normalised 4-RX channel vectors between cells 0.60-0.83; smallest/largest singular-value power ratio of the 3-cell signature set median -10.6 ... -18.5 dB (c3610), -14.9 ... -16.2 dB (c3550): the interferers are near collinear with the wanted cell, the covariance has effective rank ~2 (`sinr_mrc_irc_sic.py`, inline SVD). Four RX cannot separate 4 equal-power co-channel sources.

## 2. Implemented  [IMPLEMENTED; OFFLINE VERIFIED test_nr_passive_acq_state 17/17 incl. the new CellState test; MEASURED replays below]
Commit d42a6915ed (+ follow-ups on csd/pcis2). Every behaviour change is default off.

### 2.1 `ISAC_SI_SOFTCOMBINE=1`: SIB1/SI soft combining across repetitions (generic, per cell)
`nr_pdsch_passive_decode.c`, reuses the HARQC soft-buffer cache (LDPC into the stored buffer of the previous undecoded TB; the GPU LDPC refuses `d_to_be_cleared=false` and falls back to the CPU decoder, as for HARQC). Differences from the existing HARQC path: armed for **SI-RNTI grants only** (rnti 0xffff), **no layout bootstrap** (the old path needed 100 prior CRC passes, a cell that decodes nothing never gets there), **no NDI/RV evidence** (SI DCIs carry no meaningful NDI; SIB1 repeats with rv 0,2,3,1), key = (rnti, harq pid, **Nid_cell**), at most 8 consecutive combines (one 160 ms SIB1 window), stored TBS must equal the grant TBS. Log: `SENSING: SI_SOFTCOMBINE cell N: TB CRC ok after k combined repetitions (rv r)` and every 64 decodes `SI_SOFTCOMBINE stats first=a ok=b | combined=c ok=d`.
Lines touched (for the tim34 merge), all in `nr_pdsch_passive_decode.c` (no demod/MMSE line): new `si_combine_on()` after `harq_combine_on()` (~l.137-145); `harqc_entry_t` fields `cell`, `ncomb` + `#define NR_SI_COMB_MAX` (~l.1476-1483); `t_hq` gains `cell`,`si` (l.1489); `harqc_acquire(...,cell)` (l.1716, 1722, 1733); in `passive_ldpc_decode`: acquire call (l.2024), `retx` rule (l.2052-2055), counters/log block (l.2078-2088); arming in the decode body (l.4884-4890 `if (si_combine_on() && grant->rnti == 0xffff ...) {...} else if (...)`, existing branch otherwise unchanged) and `t_hq.si = false` (l.4894). Flag off: `cell`=0 for all entries, `t_hq.si` false: identical logic [CODE-READ].

### 2.2 `ISAC_CELL_STATE=1|2`: barred / idle report, bounded search (generic, per cell)
New pure struct `nr_cell_state_t` + `nr_cell_state_update()` in `nr_passive_acq_state.[ch]` (one instance per cell context; the process-wide instance is used by the single-cell receiver). Inputs: MIB cellBarred (hook `nr_ue_procedures.c` l.220-221), every accepted C/TC-class RNTI (hook `nr_pdcch_blind_monitor_rt.c` l.9088-9091, 3 lines), the absolute slot. Verdict after `ISAC_CELL_STATE_SECS` (default 30 s of signal time, replay-speed independent) with no recurring UE RNTI (>= 3 accepts of one RNTI): `BARRED_IDLE` (MIB barred) or `IDLE`; a recurring RNTI sets `ACTIVE` at any time. Level 1 logs `SENSING: CELL_STATE <verdict> barred=.. sib1_decodes=.. nid_capture offered/taken/skipped_empty -> ...`; level 2 additionally stops the nID sweep capture (`nr_pdcch_coreset_map_idsweep_want`, hook l.444-445 = one block, 2 lines) until ACTIVE. Resets on a sync loss. Unit test `CellState.*` (window, single RNTIs are not recurrence, ACTIVE overrides, two contexts share nothing, uint32 slot wrap) [OFFLINE VERIFIED].

## 6. Observations that matter for the next step
- RAR: in 9 OTA logs the RA-RNTI (0x63, 0x1d) PDSCH grants show `crc=0` in every one of 1 100+ cases (PCI 4: 247/149/94, 614: 100, 508: 9-357), mean EVM-snr 1.9-3.8 dB. The history says RAR decoding worked (Swisscom, 100 % CRC), and a cell that issues RARs has UEs trying to attach, so for 4 / 614 the route to a dedicated CORESET is RAR -> TC-RNTI -> Msg4 -> C-RNTI, not the nID sweep. RAR is one-shot (no repetition to combine); interference-limited like SIB1 [HYPOTHESIS]; the RAR decode path itself is not investigated here [NOT RUN].
- 508 had a real C-RNTI in the OTA run ab_B508a (RNTI 0xa70a x12 574): "no UE traffic on this site" does not hold in general.
- A SIB1 of one cell is a known-payload interferer for the others (same TB every repetition): a cell-keyed SIC that re-encodes 508's decoded SIB1 could cancel it in repetitions where 508 itself fails. Measured upper bound with one cell removed is only +0.4-2 dB because 688/614 remain, so it is not implemented [NOT RUN].

## 7. Implications for multi-PCI (csd/mpci-*: one process per cell, shm ring, M2 per-cell paths)
- All new state is process-private (per cell by construction) or a pure struct (`nr_cell_state_t`, soft buffers keyed (rnti,pid,Nid_cell)); nothing is shared between processes except the existing sibling file `/tmp/passive_rx/sib1_sibling_<kHz>.bin` (fixed path, not touched by M2's ISAC_CELL_INSTANCE tagging) which is the desired cross-process channel. Start the SIB1-decoding cell first or keep the file (PCIS report).
- Co-sited sectors on one carrier (here 4 cells) are mutually interfering on all common channels: a multi-PCI deployment must not assume independent cells; the cell-state verdict lets a supervisor stop sweeping cells that are idle/barred and give the GPU to the others (ISAC_CELL_STATE=2, N processes).
- Each process pays one extra CPU LDPC decode per SI-RNTI grant that is combined (a few per second).

## 9. Not done / limits
- IRC/SIC numbers are oracle estimates from DM-RS LS channels in two 1 s captures (c3610, c3550), blocks of 16 RB, 4 transmitters modelled; real decoders lose 1-2 dB more. No IRC/SIC demodulator was implemented because the bound is below what 614/4 need.
- No receiver-side IRC hook, so the demod/MMSE files of csd/tim34 are untouched.
- Combining A/B is replay-tiled (n = 2 pairs); an OTA window with a continuous SIB1 stream is the real test.
- 688 is inferred from PDSCH DM-RS correlation alone (no SSB, no PDCCH decoded): do not treat as a confirmed PCI.
- PCI 4 is below the detection floor in the 1 s captures; its SI DCIs (7 in 8 s) cannot be combined.
- The cell-state window was exercised with 3 s on the 8 s replays; the 30 s default needs a longer OTA run.

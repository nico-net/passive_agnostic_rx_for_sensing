# MPCI M3: cross-cell GPU discovery arbiter (2026-10-13)

Status: implemented, default OFF. Evidence: [OFFLINE VERIFIED, cloud x86 4c, no GPU] unit tests only. All GPU/OTA behaviour [NOT RUN].

## Design
One receiver process per cell (M1) shares the GB10 and host CPUs. `nr_gpu_budget.c` stays process-local; with `ISAC_MPCI_SCHED=<segment>` it also consults
`openair1/PHY/TOOLS/nr_mpci_sched.{h,c}` (compiled into `nr_gpu_platform`, plain C, no CUDA). Segment `/dev/shm/<segment>`: up to 16 cell slots, each
{tag, pid, share, acquire flag, rt_inflight, heartbeat, last discovery request, 1 s rolling discovery GPU-us (100 x 10 ms buckets), total us, yields, rt_jobs,
7 published drop counters}.

Lock-free atomics, not a robust mutex: a SIGKILLed process can never wedge the others (no lock to be held), every field is single-writer or CAS-claimed, and
a torn aggregate only perturbs one admission decision. Dead cells: pid check (`kill(pid,0)`) frees the slot (also at attach and snapshot); a cell whose
heartbeat is >2 s old has its `rt_inflight` ignored (hung cell cannot block discovery forever).

## Policy (`nr_mpci_discovery_admit`, called from `nr_gpu_budget_discovery_begin` after the local checks)
- Global discovery budget G = `ISAC_MPCI_GPU_DISCOVERY_PCT` % of wall time over 1 s (default = local `ISAC_GPU_DISCOVERY_BUDGET_PCT`; segment creator's value wins). A slice reserves 5 ms like the local policy.
- Entitlement of a cell = G * share / sum(shares of demanding cells); demanding = asked for discovery in the last 200 ms. A cell may exceed its entitlement only while total + 5 ms + (unused entitlement of other demanding cells) <= G: work-conserving borrowing, an idle cell's share is free.
- Any other live cell with RT in flight => yield (RT blocks new discovery in every cell). RT admission is never throttled by the arbiter (`rt_begin/rt_end` only publish).
- ACQUIRE (= `nr_gpu_budget_discovery_prefer(1)`, the nID sweep): does not hold back for MAINTAIN cells' unused share; a MAINTAIN cell is confined to 1/4 of its entitlement (no borrowing) while another demanding cell is in ACQUIRE. The 1/4 is a compile-time constant (`MAINTAIN_DIV`), a policy choice not tuned on air.
- Local budget and arbiter are ANDed; the arbiter only adds yields (counted in `discovery_yields`).

## Per-cell drops / visibility
`nr_passive_metrics.c` (ISAC_METRICS emission) publishes scanq full/stale/epoch and pdschq full/stale/epoch/narrow into the slot (no-op unless env set).
Reader: `mpci_sched_stat <segment> [period_s]` (built with tests) prints one `MPCI_CELL tag=.. disc_used_pct= yields= rt_inflight= rt_jobs= scanq_drop=f/s/e pdschq_drop=f/s/e/n` line per live cell. No in-process reporter role (kept simple).

## Parameters
| env | default | meaning |
|---|---|---|
| ISAC_MPCI_SCHED | unset (OFF) | segment name; also needs ISAC_GPU_BUDGET=1 for gating (drop publishing needs only this) |
| ISAC_MPCI_GPU_SHARE_PCT | 100 | relative weight of this cell (1..1000) |
| ISAC_MPCI_GPU_DISCOVERY_PCT | ISAC_GPU_DISCOVERY_BUDGET_PCT (30) | global discovery % of wall time (creator wins) |
| ISAC_CELL_INSTANCE / ISAC_SHM_IQ_CELL | pid | slot tag |

## Verified [OFFLINE VERIFIED, cloud x86 4c, ctest]
`test_nr_mpci_sched` (6 tests, fake clock, fork for cross-process): 3:1 share split within +-8 %, total <= budget; borrowing when peer idle; foreign RT blocks both MAINTAIN and ACQUIRE discovery, hung-cell expiry; SIGKILLed child's slot and stuck RT reclaimed; ACQUIRE >2x MAINTAIN at equal share; NULL handle / unset env = no-ops; `nr_gpu_budget.c` hook yields on foreign RT in a fresh process. Existing `test_nr_gpu_budget` (10 tests) passes; `nr_gpu_platform`, `nr_pdcch_blind_monitor` build.
Byte-identical when unset: `mpci` pointer is NULL, every hook is a NULL-checked no-op [CODE-READ].

## Not measured / open risks [NOT RUN]
- GPU time-slicing across separate CUDA contexts without MPS: kernels from different processes are time-sliced, not concurrent; a context switch costs and the arbiter only paces discovery, it cannot preempt a running kernel. RT latency across processes is the key number.
- Green contexts are intra-process; per-process partition would need MPS or per-process green ctx sized from share.
- CPU: not scheduled here; use `taskset`/cpuset per cell (core plan is identical across processes).
- Arbiter RT-in-flight only gates discovery; it does not cap RT-vs-RT contention between cells.
- Rolling window of an ACQUIRE cell is not guaranteed a floor if MAINTAIN cells already consumed G.

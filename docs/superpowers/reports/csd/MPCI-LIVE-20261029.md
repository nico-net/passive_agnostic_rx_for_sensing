## What was built

When the front end rewrites `cells.json` (atomic rename, polled 1/s by the control thread), the manager's events (retire after the 10 s hysteresis, add, retune)
are now APPLIED, through the new `radio/COMMON/iq_live.{h,c}` (decisions and order, pure, hook driven) and these supporting pieces:

1. **Quiesce without a blocked read (`radio/COMMON/ru_park.{h,c}`, `shm_iq.c`, `nr-ue-ru.c`).** `iq_chan` marks a paused ring away until `SHM_IQ_AWAY_PAUSED`; the
   `shm_iq` device now returns `SHM_IQ_READ_PAUSED` (-2) for such a ring (a time-shared dwell still waits). `nrue_ru_read` of a ring RU goes through `ru_park_read`: the
   read is retried OUTSIDE the radio lifetime gate every 20 ms (`RU_PARK_POLL_MS`, woken at once by `ru_park_wake`), so `nrue_ru_restart_rx / reinit / stop`
   never wait for a paused cell (the G6 open item). The slot thread is quiescent while parked (no gate, ~50 wake-ups/s, no ring polling). Backlog written before the
   pause is still read first, then PAUSED (nothing is lost, the park starts when the consumer has caught up).
2. **Slot lifecycle (`iq_live`).** States EMPTY (spare, prepared before the fence), SERVED, UNSERVED (admitted, outside the capture; ring paused; retried after every
   removal), PARKED (retired; per-cell state kept, same slot on return). Transitions:
   - remove: `chan_pause` -> PARKED. add into a prepared slot: grid check (N_RB, SCS, RX count; else `unserved reason=geometry`), inside the capture: `chan_retune` (paused
     entry) -> `ue_retune` -> `chan_resume` -> wake; outside: **re-plan** at the RUNNING rate (LO to the middle of the new span; accepted only when every served cell and
     the new one fit the flat band) -> ONE `radio_recentre` (bounded radio retune; the wideband ring starts a new run, every cell resyncs once) -> serve; refused ->
     `unserved reason=capture_rate_change` (another rate would carry them) / `out_of_span` / `radio_retune_failed`, radio untouched. retune of a served cell: pause, channelizer
     retune if the centre moved, UE tuning, resume (the resume is the forward gap that makes only THIS cell's timing loop re-acquire; its SFO is reset via
     `nr_sfo_resync_cell`).
   - every transition logs `MPCI_LIFE cell=k id=.. event=park|add|retune|retry ..` (+ `MPCI_SPAN radio recentre ..`, `MPCI_FEED cell=.. paused|resumed`).
3. **UE side (`nr-ue.c`, `ru_tune_*` mailbox).** The control thread posts (centre, SSB, CFO) while the slot thread is parked; the slot thread takes it at the loop top, outside any
   acquisition, flushes its actors, sets `dl/ul_CarrierFreq`, `ssb_start_subcarrier`, `initial_fo`, `init_symbol_rotation`, cleans HARQ, drops the sync state and
   re-acquires with `target_Nid_cell = -1` (the slot may now serve another PCI; `nr_cfg_epoch_note_identity` starts the new epoch [CODE-READ]). `nrue_ru_ring_set_centre`
   retunes the ring RU (shared gate; the slot thread is parked: the hook waits for `ru_park_parked`, 3 s bound). `nrue_feed_recentre` moves the capture LO.
4. **Spare slots (`nr_cell_life`, `nr_cell_mgr`).** With a radio and >= 2 cells in the first inventory, `NR_CELL_LIFE_SPARE_DEFAULT` = 1 placeholder (`spare1`, the started
   cell's grid, admitted LAST) is admitted with them, prepared before the fence (UE instance, RU on its paused ring `nrcell_spare1`, threads), then released from the manager:
   a cell added at run time takes it with no allocation (`MPCI_LIFE .. event=activate_spare`). B3 is re-run on every run-time add (`nr_cell_admit_plan` over the
   cell set as it would be, line `MPCI_ADMIT .. live=add`; refused -> `not_started reason=admission:<limit>`). The manager picks the free slot that FITS the cell
   (`slot_fit`) preferring the slot that last held the same id; free slots but none fits -> `refuse cause=no_slot_fits`. A retire re-applies the last inventory so cells refused for lack of a slot get the freed one.
   Published-ring input (`shm_iq` device) cannot have a spare (nobody publishes its ring): `mpci_check_input` drops them.
5. **CHAN demand recomputed (`iq_chan.c`).** `iq_chan_demand_for(k0, n0, running, threads)` = ceil(k0 x running / n0), >= 1 while an entry runs, 0 when all are paused,
   <= threads; applied after every add/remove/pause/resume of the CPU backend (`IQ_CHAN_DEMAND` line, `chan_demand=` in `MPCI_LIVE`). Pool tokens go back to the other classes.
6. **Per-cell quiesce/resume registry for other modules (coordinator request, c-cellfeat).** `ru_cell_hook_register({name, quiesce, resume, ctx})` in `radio/COMMON/ru_park.h`.
   The receiver calls `ru_cell_quiesce(cell)` right after a cell is parked/retired (hooks run on the control thread, bound to the cell, must not allocate, return quickly; the
   session is KEPT, closing stays in the per-cell shutdown loop) and `ru_cell_resume(cell)` after the slot took a cell again (reverse registration order). PRACH, SRS, the
   sense-API session and the dashboard sense view register once in their per-cell prealloc (before the fence). The orchestrator wires them when merging with c-cellfeat.
7. Test fixtures: `mpci_file_pub watch=<cells.json>` (pauses/resumes the ring of an id that left/returned), `tests/passive_rx/mpci/run_live_replay.sh`.

## OTA procedure for live add / remove / retune (orchestrator, not run)

Preconditions as G6/FEEDSTART OTA: X410 enabled by the user, no other heavy job, MemAvailable >= 48 GB, daytime. Build this branch (`ninja -k 0 -j8 nr-uesoftmodem oai_usrpdevif shm_iq params_libconfig`, `liboai_device.so` symlink). Start as G6 step 2 with `R/cells.json` = 415 + 923 (245.76 MS/s pair) or 415 + 403 (122.88 MS/s pair); expected `MPCI_ADMIT cells=3 of 3` (the third is the spare), `MPCI_LIFE cell=2 id=spare1 spare slot prepared`, `MPCI_LIFE activated cells=2 prepared=3 .. spare=1`. Rewrite `R/cells.json` ATOMICALLY (write tmp + rename) at each step; SIGINT to stop. All 4 RX.
1. Remove: write the file without cell 1. After 10 s: `event=park`, `MPCI_FEED cell=1 paused (radio not stopped)`, `IQ_CHAN_DEMAND tokens=..`, `slot thread PARKED`. Pass: cell 0 keeps decoding, no `USRP_RING_RECOVER|RESTART`, `chan_overruns` unchanged, `MPCI_LIVE served=1/..`.
2. Re-add (same entry): `event=add served`, `resumed`, one `SHMIQ_DISCONT` + `RXDISCONT` of cell 1 only, `CORESET`/MIB again, grants decoded. Pass: cell 1 syncs again within ~2 s of acquisition; cell 0 has no new RXDISCONT.
3. Add into the spare: write a third cell with cell 0's grid (e.g. same N_RB/SCS) inside the span: `activate_spare`, `MPCI_ADMIT .. live=add`, ring `nrcell_spare1` retuned (`IQ_CHAN_TUNE .. retune`), the new cell syncs on its PCI (A10 not yet in: check the locked PCI matches).
4. Retune: change `centre_hz`/`ssb_hz`/`cfo_hz` of a served cell: `event=retune served` (CFO/SSB only: no `IQ_CHAN_TUNE`), `live tune:` line from the slot thread, re-acquisition. Pass: other cells unaffected.
5. Out of span: add a cell outside the capture: `unserved reason=capture_rate_change|out_of_span`, radio untouched. Then (only if the set fits the flat band at the SAME rate) a cell that needs the LO to move: `span_replan` + `MPCI_SPAN radio recentre .. done`: EVERY cell resyncs once (`RXDISCONT`), then decodes; record the time to recover and `USRP_RING` events. `[HYPOTHESIS]` the usrp decoupled ring may still hold up to `ISAC_USRP_RING_MS` of old-LO samples after the tune: the first resync can fail once; if so the drop of that backlog is the follow-up (usrp_lib is not touched here).
6. Abort rules and labels as G6. Record one row per cell, never pooled.

## Open items / decisions
- A radio RATE change at run time is refused (`capture_rate_change`): rings, channelizer entries and the host-RAM plan are sized at start. The spare slot only carries a cell of the started grid (N_RB/SCS/RX); other grids stay unserved until a restart (a bigger spare would cost ~13 GB per 217-PRB cell).
- `MPCI_ADMIT cells=N of N` now counts the spare (3 of 3 for a 2-cell start with a radio): scripts that grep `cells=2 of 2` for that case need `cells=3`.
- Radio recentre is untested on air (hook-level tested); published-ring input has no channelizer: retire/add there only wakes/logs, the publisher owns the ring.
- `nrue_ru_restart_rx` stops all ring RUs (pre-existing): their blocked reads return -1 = receiver exit; unchanged here.
- The parked-window drain: a cell that lags its ring reads its backlog before it parks.
- c-cellfeat per-cell sessions: register into `ru_cell_hook_register` (item 6); not wired here.

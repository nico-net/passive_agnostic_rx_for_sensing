## Choice: (b) shared-memory ring + one receiver process per cell

| criterion | (a) one process, N cell contexts | (b) shm ring, N receiver processes |
|---|---|---|
| state isolation | every global/static/TLS on the receive path must become per-cell first (PROJECT_MEMORY §18 lists > 15 modules of process-global state; blind monitor alone is ~10 kLOC of statics) | free: process boundary; only cross-process resources need keying (M2) |
| GPU sharing | one CUDA context, shared streams, green contexts already in-process | one context per process (GB10 time-slices between contexts); needs a cross-process budget (M3) |
| failure isolation | one assert kills every cell | a cell's crash/restart leaves the radio and the other cells running; producer loss is detected (heartbeat) |
| effort / risk to the single-cell path | months, touches the avoided files | ~600 lines in `radio/COMMON`, one default-off hook; single-cell binary unchanged |
| memory/CPU overhead | lowest | N copies of the receiver's fixed buffers; one ring copy per consumer read; DDC per consumer |

(b) is taken: it delivers multi-cell now without touching the receive path, and keeps (a) open as a later
optimisation (shared FFT across co-numerology cells, PROJECT_MEMORY §20). Not reused: `common/utils/shm_iq_channel`
(OAI vrtsim point-to-point server/client with TX, one reader) [CODE-READ].

## Design [IMPLEMENTED]
- **Producer** (`radio/COMMON/shm_iq_pub.c`, hook in `openair0_device_load`): `ISAC_SHM_IQ_PUB=<ring>` wraps the loaded
  device's `trx_read_func` and `trx_set_freq_func`. Works for any device (USRP, raw_iq, rfsim); the process that owns
  the X410 claim is an ordinary `nr-uesoftmodem` tuned to the window centre at the full rate (it may decode a cell of its
  own). Retune or device reload (`nrue_ru_reinit`) bumps `rf_epoch` and starts a new contiguous run.
- **Ring** (`shm_iq_ring.{h,c}`, `/dev/shm/<ring>`): header page + per-channel sc16 ring of `capacity` samples
  (power of two, default 2^23 = 68 ms at 122.88 MS/s; 128 MB at 4 channels; `ISAC_SHM_IQ_CAPACITY`). Seqlock-style:
  producer raises `reserve`, writes, raises `head`; a consumer copies, then re-checks `reserve` and `valid_from`.
  The producer never waits for consumers (never blocks the RF reader, §20 overload policy). Radio gaps keep the tick
  mapping and advance the index; `valid_from` marks the start of the current contiguous run.
- **Consumer** (`shm_iq.c` → `libshm_iq.so`, `device = { name = "shm_iq"; }`): attaches (waits up to
  `ISAC_SHM_IQ_ATTACH_S`), checks `ring_rate / cell_rate ∈ {1,2,4}`, starts at the newest sample, and per read:
  copy → DDC → cell stream. Timestamps = `(base_tick + ring_index) / D`: one common sample-time base for every cell on
  the ring (cross-cell alignment for sensing for free). Overrun (fell behind > capacity) or gap → skip forward, reset the
  DDC, log `SHMIQ_OVERRUN|SHMIQ_DISCONT`; the receiver's own continuity logic sees a timestamp jump, exactly like
  `ISAC_RAW_IQ_GAP`. Producer heartbeat older than `ISAC_SHM_IQ_TIMEOUT_MS` (2000) → `SHMIQ_PRODUCER_LOST`, clean exit.
  Gain changes are ignored (the analog gain belongs to the shared radio). TX asserts (passive).
- **DDC** (`iq_ddc.{h,c}`): mixer (block phasor table × exact block-start phasor, float) then 0, 1 or 2 Kaiser halfband
  stages (polyphase: every tap is a contiguous vector op; 32 outputs held in registers across taps, GCC vector
  extensions → SSE/AVX/NEON). Each stage is designed at start from the cell's channel bandwidth (`rx_bw`, or 95 % of
  its sample rate) for 70 dB (`ISAC_SHM_IQ_ATTEN_DB`): 106-PRB class = 27 taps, 51-PRB class (D=4) = 15+27 taps,
  162-PRB class = 175 taps (58 MHz in a 61.44 MS/s grid has a 1.2 % transition band). Group delay (c input samples per
  stage) is constant and not compensated (the receiver's sync absorbs it, as with the replay decimator).
  D=1 with zero shift is a plain copy (bit-exact). The replay decimator in `raw_iq.c` is untouched.

## Open risks
1. **DDC CPU on the DGX** [NOT RUN on aarch64]: per-cell DDC runs in the consumer's RF read thread (`UEthread_0`, the
   hottest thread, PROJECT_MEMORY K27). 162-PRB cells at D=2 cost ~0.4 core per channel on x86. Mitigations, in order:
   run such cells at D=1 on a wider grid (`-r 217/273` + `ISAC_CARRIER_FROM_SIB1=1`, GRIDCARRIER) — only for cells
   with servingCellConfigCommon in SIB1; split the per-channel DDC over threads; move the DDC to the GPU.
2. **Publisher = critical process**: its RF reader feeds every cell. Its own decode load can stall the reader
   (RFSTALL) for all. Run it on the window centre with its own cell or none, pinned per the core map, and watch
   `RFSTALL` / `SHMIQ_OVERRUN` in every consumer.
3. **Shared analog gain**: the publisher's gain control (if any) changes the level for every cell; consumers ignore
   gain calls. Pick one gain for the window (as the survey does: RX1 gain 38).
4. **Polling consumers**: 20 µs `nanosleep` polling; fine for ≤ 5 consumers, futex wake if many share a core.
5. **Consumer channel subset**: a cell takes ring channels 0..N-1; no per-cell channel map yet.
6. **Window geometry**: a cell's band must lie inside the ring's ±61.44 MHz with margin; `SHMIQ_WARN` is logged
   otherwise (not fatal). Cells outside one window are M4.
7. Memory: 128 MB ring (tmpfs) + N receivers' locked buffers (`mlockall`); check `/dev/shm` size and `ulimit -l`.

## Review round (independent concurrency review, same day) [OFFLINE VERIFIED, cloud x86 4c]
Fixed in `radio/COMMON` (commit after 53354e0):
1. HIGH: a device reload (clock restart) was invisible to a caught-up consumer: the ring index continued, so
   timestamps stayed continuous across a radio hole and the receiver's RXDISCONT never fired. Now a backward tick
   advances the index by the wall-clock gap (>= 1 sample); a retune on a continuous clock starts a new run without a
   jump. The INT64_MIN sentinel is replaced by a producer-local `new_run` flag (no lost update from set_freq).
2. MEDIUM: consumers exited after 2 s without producer writes, but the producer's own RFSTALL reinit retries for
   ~40 s. Now `SHMIQ_PRODUCER_LOST` only when the heartbeat is stale AND the producer pid is gone, or after 60 s.
3. MEDIUM: header `magic` published/read with release/acquire (the fence was on the wrong side).
4. MEDIUM: a consumer that inherited `ISAC_SHM_IQ_PUB` would re-create (destroy) the producer's ring: unset in
   `device_init`.
5. MEDIUM: with two radio devices the second one took over the wrapper: only the first device publishes
   (`SHMIQ_PUB_SKIP`). Plus: a read larger than half the ring asserts instead of skipping forever.
Tests: `test_ring` extended (retune/reload), new `test_ring_stress` (writer races a reader at the overwrite edge):
20000 valid copies, 0 bad, also under ASAN/UBSAN and TSAN; with the after-copy re-check removed it lets 4613 bad
copies through (the test catches it). Seqlock ordering on ARM [CODE-READ] correct.

Additional open risks from the review:
8. Publisher memcpy ~2 GB/s at 4 ch x 122.88 MS/s in the radio process -- the same order as the headroom
   `usrp_lib.cpp` warns about: watch overflows/RFSTALL on the DGX [NOT RUN].
9. The DDC adds a fixed group delay to timestamps (c1 + 2 c2 input samples, <= ~185 at 122.88 MS/s ~ 1.5 us):
   irrelevant for decoding, a bias for absolute sensing timing (compensate in the sensing export if needed).
10. After a retune, up to one read of old-tuned samples gets the new shift (epoch bumped before the first new write).

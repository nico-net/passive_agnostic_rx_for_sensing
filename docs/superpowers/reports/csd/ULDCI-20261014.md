# ULDCI-20261014: why the UL DCI fields of one HARQ process jump, and the fix

Branch `csd/uldci` (from `csd/otatest` c23cc9e213), DGX Spark aarch64, build `build_t26`. Cells never pooled: Vodafone PCI 415 (capture `raw_pci415_12s_b`,
OTA T*/S4*/UA-UC) and TIM PCI 923 (`raw_pci923_tim_12s_tile3`, OTA U*/Q*/X*/UT*). Labels: `[MEASURED, DGX replay <capture>]` = reference binary
`rr-csd-b/build_t26` (c3ceb2f472) vs this branch, `default.env` (t26z) + `ISAC_UL_DBG_LOG=1` (raw payload per UL DCI), 12 s, speed 1, n = 1 per arm;
`[MEASURED, OTA log]` = re-read `~/NICOLA/ota_runs/ab_*` of 2026-10-14; `[INFERENCE]` otherwise. gNB logs/configs not used.

## 1. Root cause

The DCI 0_1 field layout is NOT wrong in the lock/fit code: the bank fit (`nr_ul_layout_fit_mcs/prefix/tail`) finds the right MCS/NDI/RV/HARQ block
(`mcs_off` 21 on Vodafone, 20 on TIM, stable across UEs and lengths 42/44: per-RNTI fit on replay b, 18 of 18 RNTIs at 21; first-8-sample fit on 2400 TIM/Vodafone
RNTIs: 20 or 21 with >= 90 % per cell) `[MEASURED]`. Three defects around it produce the random jumps:

1. **Grants of a fitted-but-not-locked length are read by the width sweeps, not by the fit.** The sweep default has no BWP indicator. Vodafone sends a constant
   `1` after the identifier (bit profile of 2779 len-44 DCIs, replay b: idx1 = 1.00, RIV idx 2..16, TDRA idx 17..20 = 0000, MCS idx 21..25, NDI 26, RV 27-28, HARQ
   29-32, DAI 33-34, TPC 35-36 = "01", ULSCH last) so the default reads MCS/NDI/RV/HARQ **one bit early**
   (rx mcs 3 where the payload says 6; pid 4 where it says 2). Replay b, reference: **only 904 of 3370 ULDCI lines (26.8 %) carry the real MCS/NDI/RV/pid**,
   HARQ pid steps of 1..3 between consecutive grants of one RNTI 37 %, NDI-same retx candidates 62 %. Since the BWP lock never completes (or completes on a
   look-alike) this is the state of almost every grant of an OTA run; the fit is available after ~260 DCIs (< 1 s) `[MEASURED, DGX replay b]`.
2. **Prefix split ambiguity ranked wrong.** `nr_ul_layout_fit_prefix` keeps every split whose RIV window is "valid" and orders by RIV width ascending.
   A RIV window one bit too short (top 14 bits of a 15-bit RIV, value always < N(N+1)/2 for N <= 162) is always valid, and it parks the RIV LSB in the TDRA
   field. TIM tile3 FIT: `[{riv=14 tda=4 N<=162},{riv=15 tda=3 N<=217},{riv=13 tda=4 fh=1 N<=107}]` -> pre[0] is the false one; the true split
   has TDRA entropy 0.78 bit (rows 1 and 5, `x01`), the false 1.78 bit. TDRA/RIV/k2 are misread and, worse, **the false widths seed the BWP hypotheses**
   (107@x, 162@x, 135@x, 178@39: widths 13/14): ref TIM replay locked **107@2** (false) at 3 s; the garbage locks of the OTA tallies in ULBWP-20261014
   (178@39, 107@5, 106@1, 135@5) are exactly these widths `[MEASURED, replay + OTA log; the link to the OTA locks is INFERENCE]`.
3. HARQ identity: with (1) the pid/NDI/MCS/RV of one process cannot line up, so retx are never matched.

TIM tile3 is the benign case for (1): its default reading sits at 20 by coincidence (BWP ind 1 + RIV 15 + TDRA 3 = the default's RIV 15 + TDRA 4), reference truth
match 84.8 %, retx NDI match 100 % already, so the ULQ `retx_try = 0` on TIM is not a DCI-field problem (it is the TBS / RIV side, see risks).

## 2. Fix (both default off)

- `ISAC_UL_FIT_READ=1` (needs `ISAC_UL_LAYOUT_LOCK=1`): `nr_ul_layout_read_fitted()`; a grant of a length that is fitted and not locked is read with the fitted
  prefix/tail/k2 rows (RIV provisional: widest candidate at the SIB1 UL start when it matches, else PRB 0), `hyp_generation = 1` (explicit-layout sentinel, like
  `ISAC_UL_FORCE_OPTS`). Hook in `nr_pdcch_blind_monitor_rt.c` before the config-discovery branch.
- `ISAC_UL_PREFIX_ENT=1`: prefix splits ranked by the entropy of the TDRA + hopping bits they leave (sum of per-bit binary entropies), splits more than 0.5 bit above the
  best dropped, equal entropy -> wider RIV (a RIV MSB that is 0 in a short bank is not a constant BWP-indicator bit).
- Tests `UlLayoutFit.EntropyRankedPrefixAndFitReadAreCoherent` (TIM-shaped synthetic bank: old order has riv=14 first, new order keeps only {1,15,3}; fitted but unlocked
  read returns exact MCS/NDI/RV/pid on 200 DCIs; flag off -> false), `UlLayoutLock.*` 9/9 and `UlReadyDci01.*` still pass `[OFFLINE VERIFIED]`.

## 4. Risks / not done

- Pre-fit window unchanged; `FIT_READ` grants carry a provisional RIV (PRB 0 or SIB1 start): booked PUSCH jobs are wrong exactly as before until the lock; do not read UL CRC off them.
- `PREFIX_ENT` could prefer a wider RIV when a cell's real TDRA field is high entropy and a w+1 window also validates (needs a cell with all RIV < 2^(w-1)); it never drops below the best and only cuts splits > 0.5 bit worse.
  Not seen on the 8 OTA cells/days reviewed. Needs an OTA check of the lock outcome (replay only, n = 1 each).
- The `MCS_STAT` accept in t26z rejects the fit in many OTA runs (`mcs_off=-1`, 163 evals B5, 55 NT): no fit -> no layout read. Not changed here.
- Left as is: ULBWP look-alikes (216@1/216@0) and RIV/TDRA -> PRB/symbol mapping (TDRA row table is still the inferred k2 only).
- Env line for the next OTA: add `ISAC_UL_PREFIX_ENT=1 ISAC_UL_FIT_READ=1` to t26z (with the lock/CRC-first flags already there).

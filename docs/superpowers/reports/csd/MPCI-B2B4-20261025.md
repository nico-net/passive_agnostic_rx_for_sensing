Rules [CODE-READ]:
- `build_core(topo, over, n_cells, L)` is the old body. Cell 0's reader and the radio IO are computed exactly as before; readers 1..N-1 are taken afterwards by the same chain and `best_rt` ranking (isolated RT set first, else general CPUs minus the anchor, the radio IO and the chosen readers; capacity bucket, GPU NUMA node on multi-node hosts, lowest number). With |C| >= 8 a CPU whose SMT sibling is already a reader is used only when nothing else is left. A reader is never the housekeeping anchor and never a DPDK lcore.
- All readers join the RT set `R`, so W, the SMT-sibling idling, SEP/COMPACT/SMALL, pool, lane and housekeeping follow the existing rules on the reduced W (no new rule).
- Floor: `NR_CL_MIN_POOL = 2` tokens. Derived from the pool rules (B.4): the DL cap is N-1 and the scan reserve token needs a second one; in SMALL mode pool = W-1, so the floor is W >= 3, the same as the B.5 "W < 3 refuses" rule.
- `max_cells` = largest k (1..16) for which k readers exist and pool >= 2 (0 when not even one cell fits: 1-2 cpu hosts). `nr_cl_max_cells()` is the same value as a pure helper. `nr_cl_build_n` returns 0 when the request is hostable, 1 otherwise (layout still filled best effort, missing readers are -1).
- CORE_PLAN line: unchanged for N=1; for N>1 the suffix ` cells=N rt_cells=a,b,c max_cells=M` is appended after `src=`.
- `nr_core_layout_init_n(passive, radio, n_cells)` added (init = init_n(...,1)); nothing in main() calls it yet (orchestrator/G2).
- `NR_CL_MAX_CELLS = 16`, static-asserted equal to `NR_POOL_MAX_CELLS`.

## B4 (R6): `openair1/PHY/TOOLS/nr_gpu_sm_plan.h`

Pure, header-only, includes only `nr_gpu_platform.h` (no CUDA; it declares prototypes only, the test does not link them). Test `openair1/PHY/TOOLS/tests/test_nr_gpu_sm_plan.cpp`, target `test_nr_gpu_sm_plan` in `cmake_targets/mpci_cloud.cmake` block `# ---- B2B4 ----`.

Rule [CODE-READ of nr_gpu_green.h:40-120, reproduced]: disc = round_up(max(1, SM/6), gran); rt = SM - disc (rt <= 0 -> "no_rt_sms", no green). Groups: all SMs cut with minCount 4 into groups of round_up(4, gran) (raised only to keep <= 15 full groups, the `g < 16` bound of the code); disc_groups = ceil(disc/group_sz); next group = probe and first UL group; rest = DL; UL = probe + DL (overlapping). GB10: group 8, 6 groups, disc 8, rt 40, DL 32, UL 40, probe 8.
New split-2 rule replacing `rt >= 32`: DL >= dl_instances(4) x w and DL >= 60 % of rt, with w = round_up(8, gran). Justification: on the GB10 the literal is 4 DL pass instances x the 8-SM granule [INFERRED: the 8-SM instance width is the one calibrated point (DlSmShare bench, P99-UL Task 3), a HYPOTHESIS on other devices]; 60 % keeps the probe group below 40 % of rt (20 % today). The 60 % clause is implied by the first for equal groups; kept as an explicit guard.
Behaviour [OFFLINE VERIFIED, DGX GB10 aarch64 unit], 9 tests: 48/gran 8 equals the literal oracle (8/40, DL 32, UL 40, probe 8, group_req 4); 34 (RTX 4060 Ti [INFERRED]) gran 1/2/4/8: disc 5/6/8/8, rt 29/28/26/26, one RT context; 24, 16, 12 unsplit; 8/gran 8 -> no green ("no_rt_sms"); `green=false` -> "no_green", tier NONE -> "no_gpu"; 132 (H100 [INFERRED]) splits with group_sz 16 (the old code, g == 16, would stay unsplit); granularity sweep on 48; exhaustive invariants over SM 1..200 x gran {0,1,2,3,4,8,16}.
Differences from the literal off the GB10: stricter on devices with rt >= 32 but DL < 32 (e.g. 42 SMs gran 8); looser on very large devices (>= 16 full groups). When gran < 8 and disc is not a multiple of group_sz (e.g. 34/gran 2) `idle_sms` > 0: SMs in no context if it did split.

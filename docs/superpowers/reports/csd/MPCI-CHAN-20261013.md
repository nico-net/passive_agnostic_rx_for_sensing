# MPCI-CHAN 2026-10-13: shared channelizer (one process mixes + decimates the wideband ring for all cells)

Branch `claude/wonderful-edison-jkt5ut`, uncommitted at time of writing. Host for every measurement: cloud x86 (Xeon, 4 cores, no GPU, nvcc 12.0 for the compile check only).
Labels: [OFFLINE VERIFIED, cloud x86], [MEASURED, cloud x86 4c], [COMPILE ONLY, nvcc 12.0 sm_80], [NOT RUN]. No DGX / GPU / OTA claim anywhere.

## Why
Wideband mode publishes ONE ring (4 antennas, 245.76 MS/s, 491.52 later). A cell process attached directly mixes and decimates all its antennas
itself (M1 report: ~0.5 core per antenna-cell at D=4 on x86). The channelizer does that work once, in one process, and writes one NARROW ring per
cell; the cell process then attaches with decim 1 (the memcpy path of `libshm_iq.so`, `D=1` + zero shift is bit-exact copy).

## Design [OFFLINE VERIFIED, cloud x86 for CPU path]
- `radio/COMMON/shm_iq_chan.c` (executable `shm_iq_chan`; links `shm_iq_ring.c`, `iq_ddc.c` only). Input: read-only consumer with the rules of `shm_iq.c`
  (duplicated, ~25 lines; `shm_iq.c` untouched): start at the newest sample rounded to the largest decimation; `shm_iq_ring_copy` of one block;
  `-1` below `valid_from` = DISCONT (skip to `valid_from`), otherwise OVERRUN (skip to head); both reset the DDC state; producer lost = heartbeat
  stale AND pid gone (or > 60 s), honouring `away`/`dwell_until`; the log line is `SHMIQ_CHAN_PRODUCER_LOST`, exit code 0.
- Output ring `<ring>_<tag>` per cell: same channel count, `rate = ring_rate / decim`, `centre = cell centre`, v2 `radio_id`/`time_source` copied,
  capacity = max(`--out-ms` of samples, 8 blocks) rounded up to a power of two. Written with `shm_iq_ring_write(tick = (base_tick + pos) / decim)`:
  exactly the timestamp formula of `shm_iq.c`, so the output ring's own `base_tick + index` equals what a direct consumer would stamp. An input gap
  becomes a forward tick jump, hence `valid_from` + `gaps` in EVERY output ring; the cell's `libshm_iq.so` then logs `SHMIQ_DISCONT` as with any gap.
- Retune: input `rf_epoch` change -> shifts recomputed from the new ring centre (`cell centre - ring centre`), `shm_iq_ring_new_epoch` on every output
  ring (epoch bumped, new run, `valid_from` moved). Like M1 risk 10, up to one block of old-tuned data can carry the new shift into the new run.
- `away` (time-shared window) is mirrored to the output rings so cell consumers extend their timeout; it clears on the next write.
- Filters: the `iq_ddc` design itself (same halfband cascade, 70 dB, passband = half the cell BW or 95 % of its rate, as `shm_iq.c` computes it).
  Block size `--block` (default 65536 = 0.267 ms at 245.76 MS/s; multiple of 4096, >= 16384) is the latency/efficiency knob.
- Backends. CPU: one `iq_ddc` per (cell, antenna), jobs on a pthread pool (`--threads N`, workers pinned round-robin to `--cores 2,3,4-6`; the
  main thread only waits). GPU (`--gpu`): `libshm_iq_chan_gpu.so` (`shm_iq_chan_gpu.cu`), dlopen'd from next to the executable
  (`ISAC_SHM_IQ_CHAN_GPU_LIB` overrides), built only with `-DENABLE_LDPC_CUDA=ON` (same option/arch machinery as `td_cb0_gpu`: `CMAKE_CUDA_ARCHITECTURES`,
  default `89;121`); the default build has no CUDA dependency. Kernels: int16 -> float mixer (block-start phasor from double, host side, identical
  recurrence to iq_ddc), halfband stage on `[history | block]` float buffers (thread per output, grid.y = antenna, one launch per cell and stage),
  history copy kernel, round-to-nearest-even + clip to int16. Pinned host staging + `cudaMemcpyAsync`, one stream, `cudaEvent` timing per block.
  The per-element arithmetic is in `shm_iq_chan_kern.h`, compiled by nvcc and by the host compiler, so `--selftest` runs the GPU data flow
  (indexing, history, phasors) on the CPU against iq_ddc without a GPU.
  Expected GPU-vs-CPU difference: float FMA contraction only; <= 1 LSB on isolated samples (test tolerance: max 2 LSB, < 0.1 % of samples differ).
- Not done (shortcuts): no per-cell antenna subset (all ring channels), no clipped-sample counter on the GPU, no double buffering between H2D/compute/D2H,
  futex wake instead of 20 us polling, decimations limited to 1,2,4,8,16 like `iq_ddc`.

## CLI
```
shm_iq_chan --ring R --cell TAG:CENTRE_HZ:RATE[:BW_HZ] [--cell ...]      (or --cells-json plan.json: plan.ring, cells[].tag/C_hz/decim|r/bw_hz)
            [--threads N --cores L] [--gpu] [--block 65536] [--out-ms 100] [--timeout-ms 2000] [--attach-s 30] [--stat-s 5] [--atten-db 70]
shm_iq_chan --selftest [--gpu] [--threads N]
shm_iq_chan --bench SEC --nch 4 --in-rate 245.76e6 --cell ... [--threads 3 | --gpu]
```
Log lines: `SHMIQ_CHAN_READY/CELL/TUNE/WARN/STAT/DISCONT/OVERRUN/PRODUCER_LOST/END`. `SHMIQ_CHAN_STAT` every `--stat-s`: per-block processing ms (avg/max),
`gpu_ms_avg`, input backlog max in ms (queueing + the block itself = added latency bound), overruns, discontinuities. SIGINT/SIGTERM stop cleanly and
unlink the output rings (mapped consumers keep their mapping and see the heartbeat stop).

## How it plugs into the supervisor (not edited)
`mpci_auto.py plan --wideband` already writes `plan.json` with `ring`, `cells[].tag/C_hz/decim/r/bw_hz`: start `shm_iq_chan --cells-json plan.json
--threads 3 --cores <cores>` (or `--gpu`) after the publisher. Each cell process then gets `ISAC_SHM_IQ_NAME=<ring>_<tag>`, the shm_iq device
as today, and its own `-C <C_hz>` (= its ring's centre, so the device's shift is 0) and `-r <grid>` whose sample rate equals the narrow ring's rate
(decim 1, 0 Hz shift: bit-exact memcpy). Tag charset is `[A-Za-z0-9_]` (the supervisor's `p<pci>_<gscn>` fits). The supervisor must restart the
channelizer if it dies (cells then see PRODUCER_LOST on their narrow ring after the 2 s/60 s rule) and start it BEFORE the cells (they wait up to
`ISAC_SHM_IQ_ATTACH_S` for the ring). Cell bandwidth in the plan is the channel BW (`bw_hz`), used for the filter passband.

## Tests (ctest, CPU only) [OFFLINE VERIFIED, cloud x86]
- `test_shm_iq_chan`: producer process, 4 antennas x 245.76 MS/s, cell A decim 4 (-45 MHz, 40 MHz BW) and cell B decim 8 (+70 MHz, 20 MHz BW), one distinct
  tone per antenna per cell; real `shm_iq_chan --cells-json` (2 threads) -> `<ring>_A`, `<ring>_B` read with `shm_iq_ring_copy`:
  own tone 0.000 .. -0.003 dB on the right antenna; the other three antennas' tones <= -77 dB; the other cell's tone (folded) <= -65 dB; header (channels, rate,
  centre, radio_id, time_source) copied; 0 gaps before the discontinuity; a +1000003-tick input jump becomes a gap in both rings and the first sample
  after it has ts = (base_tick + align8(valid_from_in)) / decim, unambiguously the direct-consumer value (base tick deliberately unaligned); a producer
  `new_epoch` to centre +10 MHz bumps both rings' `rf_epoch`, tones stay at 0 dB (new shifts correct); producer killed -> channelizer exits 0 with
  `SHMIQ_CHAN_PRODUCER_LOST`, output writer pid gone and heartbeat stale (the cell consumers' PRODUCER_LOST condition). 5 consecutive runs passed, ~1 s each.
  It reads the rings directly, not through `libshm_iq.so` (decim 1 path is covered by M1's test and `shm_iq_ring_copy` is the same call).
- `test_shm_iq_chan_selftest` (`shm_iq_chan --selftest`): 2 cells x 2 antennas, gain <= 0.001 dB, other-antenna <= -110 dB, other-cell <= -70 dB;
  host emulation of the GPU kernel bodies vs `iq_ddc`: max diff 0 LSB over 786432 values.

| 1 | D=2, 100 MHz BW | 0.88 | 2.20 |

Reading: ~0.5 core per antenna-cell regardless of D (the 245.76 MS/s mixer + first stage dominate), so the CPU backend keeps up with real time
for at most ONE cell on 3 threads of this host (0.98x, i.e. not reliably), and 2 cells need ~3.6 cores. 4 cells at 245.76 and everything at 491.52
need the GPU path. (Bench uses noise input, no ring, no output writes; the live pipeline adds the ring copy and writes.)

## GPU compile status [COMPILE ONLY]
`nvcc 12.0 -arch=sm_80 -shared -Xcompiler -fPIC shm_iq_chan_gpu.cu` compiles without warnings and exports `chan_gpu_*`. sm_121 is unsupported by nvcc 12.0
(the DGX toolkit must build it). `shm_iq_chan --selftest --gpu` on this host reaches the module and fails cleanly at `cudaStreamCreate`
(`gpu setup FAIL`). Everything GPU-numeric is [NOT RUN]; the indexing/history/phase logic is [OFFLINE VERIFIED] only through the host emulation above.

## DGX validation steps (never build while a receiver runs; SIGINT only)
1. Build: `cmake -DENABLE_LDPC_CUDA=ON -DCMAKE_CUDA_ARCHITECTURES=121 ...` (existing DGX configuration), `ninja shm_iq_chan shm_iq_chan_gpu test_shm_iq_chan`;
   `ctest -R shm_iq_chan` (CPU tests, expect pass on aarch64).
2. `./shm_iq_chan --selftest --gpu`: expect `gpu vs cpu: max_abs_diff<=2`, `PASS`; record `gpu_ms/block` (a 65536-sample block is 0.267 ms of signal at 245.76 MS/s).
   If the max diff is > 2 LSB, suspect the phasor/rot handling first (set `--fmad=false` in the .cu to separate FMA effects).
3. `./shm_iq_chan --bench 10 --gpu --nch 4 --cell ...` for 1, 2, 4 cells (+ 491.52 with `--in-rate 491.52e6`): need x realtime >= 1.5 with margin.
4. Live: `shm_iq_uhd_pub` at 245.76 MS/s x 4 (the user-verified UHD command), `shm_iq_chan --cells-json plan.json --gpu`, watch `SHMIQ_CHAN_STAT`:
   `gpu_ms_avg`, `proc_ms` max, `backlog_ms_max` (= end-to-end latency added, should stay ~ 1-2 blocks), `overruns=0`, `discont=0` over >= 10 min.
5. Then N cell receivers with `ISAC_SHM_IQ_NAME=<ring>_<tag>` and decim 1: `SHMIQ_READY ... decim=1`, `SHMIQ_END overruns=0`, and compare decode statistics with a
   direct-DDC consumer of the same cell the same day (A/B alternation per PROJECT_MEMORY §12).
6. GPU contention: run the receivers' GPU work (PDSCH/LDPC/PDCCH) at full load and watch `gpu_ms` max and overruns of the channelizer; repeat with the M3
   arbiter on.

## Risks
- GPU contention: the channelizer is one more CUDA context (GB10 time-slices contexts); a long receiver kernel can delay a block. Budget: per block the GPU
  must finish within the block duration x the share the M3 arbiter leaves; the channelizer is RT-class work and should be accounted like the receivers'
  `nr_gpu_budget_rt_*` (a cross-process arbiter has to know it, M3 follow-up). Mitigation: bigger `--block` (cost: latency), higher stream priority (not done).
- Latency vs ring capacity: added latency ~ block + processing + one poll; the receivers' narrow rings hold `--out-ms` (default 100 ms; 128 MB at 61.44 MS/s x 4 ch
  -> use 40 ms or less if tmpfs is tight). The wideband ring (default 2^23 at 122.88 = 68 ms; at 245.76 only 34 ms) must be bigger than a worst-case GPU stall:
  raise `ISAC_SHM_IQ_CAPACITY` to >= 2^24 at 245.76 and 2^25 at 491.52.
- Single point of failure: a channelizer crash/overrun interrupts all cells; one restart policy in the supervisor, `SHMIQ_CHAN_END` counters in its log.
- Memory traffic: host staging copy of 4 ch x 245.76 MS/s x 4 B = 3.9 GB/s in, plus outputs; negligible on LPDDR5X unified memory, but pinned staging
  buffers are allocated up front (`block x 4 ch x 4 B` in, `sum(block / D) x 4 ch x 4 B` out).
- UHD publisher at 491.52 MS/s x 4 = 7.9 GB/s into the ring plus the channelizer's read: memory-bandwidth bound, untested.
- First GPU kernels are naive (global-memory taps); expected cost is small (< 1 Gtap/s per 245.76 MS/s stream at D=4), but unmeasured.

## 1. Root cause 1: the held channel estimate and the residual CFO [CODE-READ, MEASURED]

`[CODE-READ]` `nr_rx_pdsch()` equalises data symbol m with the estimate of `get_valid_dmrs_idx_for_channel_est()` = the PREVIOUS
DM-RS symbol (`nr_dlsch_demodulation.c` 436-441, `dmrs_nr.c` 217). On both cells almost every grant has 2 DM-RS symbols (2 and 11,
`dmrs=0x804`, EVMGRANT `ndmrs=2`), so symbols 3-10 use symbol 2's estimate, up to 8 symbols (285 us) later. Any phase drift
between DM-RS symbols becomes a per-symbol phase error that grows across the slot. `ISAC_RX_MRC_ALIGN=2` re-phases each branch onto the
strongest branch per symbol (decision-free) but cannot remove the reference branch's own (common) drift; at Nl >= 2 nothing does.

`[MEASURED, DGX replay]` residual common CFO (DMRSFO, DM-RS sym 2 -> 11, coherence > 0.8): **tim +122 Hz**, b +14 Hz, old +31 Hz;
per-branch FO vs branch 0 (BRANCHFO): tim [0 60 19 -22], b [0 65 134 92], old [0 -41 119 110] Hz.
`[MEASURED, OTA logs]` Vodafone M2a/b/c (2026-10-13): mean |cfo| 46-54 Hz, BRANCHFO up to 92-102 Hz (branches 2/3: second X410
board LO); TIM TmA/TmB (2026-10-12): mean |cfo| 61-77 Hz (sd 142-221), BRANCHFO up to -207 Hz. 120 Hz over 8 symbols = 0.24 rad:
an EVM floor near -12..-18 dB on the late symbols. `highmcs2_data/ota_analysis.txt`.

`[MEASURED, OTA logs Vodafone M2+S0, Nl=1, DD snr >= 20]` the per-symbol complex-gain fit (`snr_cpe - snr`, a per-symbol
phase/amplitude error) gains 1.5 / 2.3 / 3.0 dB on 16QAM (wide / 32-99 RB / narrow) and 0.6-1.2 dB on 64QAM: on air the floor is
present on Vodafone too. The b capture shows 0.12-0.16 dB at the same SNR (its residual CFO is 14 Hz), tim 0.9-1.3 dB on 64QAM.

### 1.1 The fix: `ISAC_CHEST_TINTERP=1` (existing flag, linear complex interpolation between the bracketing DM-RS symbols)
It existed (lab 2026-09-14: 256QAM MCS 25 at 80 %) but was only ever A/B'd on MCS 0-4 grants (DECODERES item 1: 0 CRC changes) and
on the b capture, where there is almost no drift. It was never in the OTA env.

`[CODE-READ, MEASURED]` `passive_decode_retry()` reset `t_tinterp_override = -1` inside and after its recovery-arm loop, so the alt arm's
recovery arms ran with the global setting. With `ISAC_CHEST_TINTERP=1` global, the "off" arm then recovered with interpolation on and

restores the caller's override (`saved_tint`); with no A/B active the value is -1 exactly as before (byte-identical default path).

## 3. What is SNR-limited and cannot be fixed in the receiver [MEASURED, OTA logs, Vodafone S0/M0/M1/M2/H0/H1]

- **256QAM**: comb=3 (MRC) grants at DD snr >= 19: Nl=1 Qm8 4/51, Nl=2 Qm8 1/142, while Qm4 99-100 % and Qm6 87-96 % at the same DD snr
  (`ota_analysis.txt`). Against the ideal-MRC bound of the four per-branch LS SNRs (`br_snr`), **51 of the 70 Nl=1 MRC 256QAM grants
  sit < 2 dB above Shannon for their MCS**, 15 at 2-10 dB (0 pass; 64QAM there: 0 / 2 / 29 / 73 % per 2-dB bin) and 8 at 10-14 dB
  (4 pass; 64QAM 83-92 %) (`ota_vodafone_margin_nl1_comb3.txt`, `margin.py`); Qm4 / Qm6 grants need 7-8 dB of such margin for 50 % and
  ~11-12 dB for 90 %. 256QAM grants are scheduled for the target UE's channel, not ours: at our antennas they are SNR-limited. Their DD
  snr (23-25 dB) is inflated by the 256QAM decision floor (14.4 dB for noise, MRCBUG §2.1) and by the same-symbol fit.
- **Nl=2 64QAM** (`snr_l` weak layer, M0/M1/M2): MCS 11-16 0 % at weak-layer DD 9-12, 38 % at 15-18, 86 % at 18-21 -- the same DD SNR
  Nl=1 64QAM needs (95 % at 18-21 dB on comb=3). MCS 17-19 1.5 % at 15-18, 11 % (9) at 18-21. Weak-layer SNR-limited (HIGHMCS §2).
- **Vodafone rank 4**: every grant at DD < 9 dB (HIGHMCS §5).
- Constant ~7-8 dB margin for 50 % on Qm4/Qm6 (Vodafone): decomposition `[INFERRED]` ~1.5 dB LDPC (8 iterations, min-sum) + 1.3 dB ALIGN'd
  MRC vs ideal (HIGHMCS) + 0.5 dB equal-noise MRC weighting (computed from `br_snr`/`nvar_db`, `mrcloss`: mean 0.58 dB, p90 1.2 dB) +
  the per-symbol drift floor of §1 on air + frequency-selective fading (Jensen) that the DD mean hides. Only the drift part is addressed here.

## 4. Root cause 2: short TIM allocations read as 13 symbols [MEASURED, DGX replay tim, `ISAC_PDSCH_CDM_DIAG=1`]

New diagnostic CDMDIAG (default off): per OFDM symbol of the allocation, 10 log10(energy on the other CDM group's subcarriers / energy on
our group's), type 1. With 2 CDM groups without data a DM-RS symbol reads << 0 dB (other group empty), a data symbol 0 dB.

`[MEASURED, DGX replay tim]` RNTI 0x4624: 152 one-CDM-group grants CRC-OK (S=1 L=13, DM-RS {2,11}); its two-CDM-group grants read
the other CDM group of symbol 2 at -20..-24 dB (DM-RS, 2 groups without data) and **every symbol from 6 to 13 at -22..-38 dB in total
power** (CDMDIAG `pow_db`): the PDSCH is S=1 **L=5** (type A, ld = 6, hence no additional DM-RS), not S=1 L=13. Same on 0x5264 (MCS 14-18),
0x5214, 0x516a, 0x5954, 0x5a94. One tim run (`enddet.py`): cdm=2 grants short 26 (all S=1 L=5, 0 CRC-OK), full-length 10 (4 OK); cdm=1
grants 209, none short. The DCI's TDRA value was resolved to the 13-symbol row; the receiver then reads 8 empty symbols as data and takes
symbol 11 as DM-RS. That is the on-air TIM cdm=2 picture `[MEASURED, OTA TIM TmA/TmB/TmL]`: Nl=1 cdm1 6-10 dB 85.7 % vs cdm2 4.5 %; Nl=2
cdm1 87.4 % vs cdm2 28.7 % (`ota_analysis.txt`).

A first candidate that only corrected the DM-RS symbols (S/L kept, and a mapping-type-B S shift) recovered 0 of 73 (tim) -- the length is
what matters.

**Fix `ISAC_PDSCH_SIGNAL_GEOM_RETRY=1`** (default off; `signal_geom_detect()`, `dmrs_mask_type_a()` in `nr_pdsch_passive_decode.c`). On a
CRC-failed full dedicated DCI 1_1 grant (type 1, contiguous PRBs): allocation end = first symbol after the first DM-RS symbol from which
every symbol to the assumed end is >= 15 dB below the DM-RS symbol's power; DM-RS symbols = the 2-CDM-group signature (other/own <= -6 dB)
when all ports are in one CDM group, else the assumed additional-position count re-applied to the new duration (38.211 table
7.4.1.1.2-3). Only a SHORTER allocation is retried (a full-length DM-RS-only correction never passed: b 26 tries per run, tim 0/73), once,
accepted on a full TB CRC only (`config_recovered`), one SIGGEOM line per try. No latch (the TDRA is per DCI).

`[MEASURED, DGX replay, + TINTERP]` (SIGGEOM, same grants, failed -> retried):
| run | Nl=1 short grants recovered | Nl=2 | Nl=3/4 | spurious retries |
|---|---|---|---|---|
| tim G1 | 39 / 56 | 25 / 31 | 0 / 12 | -- |
| tim G2 | 42 / 47 | 20 / 26 | 0 / 1 | -- |
| tim G4 (final rule) | 42 / 49 | 22 / 27 | 0 / 1 | -- |
| b G4 (final rule) | -- | -- | -- | 0 |
`GPU_EXACT_DEMOD check_bad=0` in all. Cost: the energy scan runs only on CRC-failed grants; the retry decodes 5 symbols. MCS of the
recovered grants spans 0-18 (0x5264: MCS 14-18, 64QAM). The real cure is a correct TDRA row for that DCI value in the solver
(`nr_pdsch_solver.c`, not touched here): this retry pays one failed decode per such grant.

## 5. TIM rank 3/4 [MEASURED, DGX replay tim]
- Fixed-point stock MMSE vs float ZF for QPSK at rank 3-4 (`ISAC_PDSCH_MMSE2_NL34_QPSK=1`, run tim_Q4, + TINTERP): rank-3 QPSK 0/126
  (T4) vs 0/41 (Q4), DD snr 3.9 vs 3.8 dB; 16QAM 0/27 vs 0/11 (8.1 / 8.4 dB). The float path gives the same noise-floor output: the
  HIGHMCS hypothesis (fixed-point adjugate MMSE defect) is **not supported** on this capture.
- CDMDIAG: rank-3 grants (ports 0-2) read the CDM-group-1 subcarriers of the DM-RS symbols at -9..-12 dB (expected about -3 dB for one
  port vs two): port 1002's DM-RS arrives ~7-9 dB below ports 1000/1001, or is absent; 11 of the rank-3/4 grants also lack DM-RS on
  symbol 11. `[HYPOTHESIS]` the third/fourth layer is not received at our position (precoder of another UE's channel) or the port set is
  misread (e.g. double-symbol / maxLength 2 ports 4-7 in CDM group 0). Not resolved here; tile3 rank-3 grants all sit at DD < 12 dB.

# PCI 675 restart at 51 PRB fails: root cause and fix (2026-10-24)

Branch csd/narrow51 from main e9c874c308. All numbers are for the DGX X410 4-RX runs/replays named below; cells are never pooled.

## Failure [MEASURED, DGX OTA 2026-10-23, ab_pci675_1_214900 vs ab_pci675_1_214600]
- Pass 1 (217 PRB, -C 3426570000 --ssb 1171): 0 "Error decoding PBCH", acq stays locked for the whole run.
- Restart (51 PRB, -C 3425010000 --ssb 227): sync + MIB ok (rsrp 17 dB/RE, adjust_rxgain 33 dB), then every sync runs clean for 3-4 s and then PBCH collapses (RFCENSUS pbch_ok 50 -> 16 -> 0, 2196 "Error decoding PBCH", 2629 polar failures), `max_pos_acc` ramps about +20/s, then "RFSTALL PBCH lock lost (timing runaway)" -> exit(3) (nr-ue.c:2132) after 5 syncs. Exit code 3 is that RFSTALL watchdog, not a crash.

## Root cause [MEASURED + CODE-READ]
The PBCH channel estimator is fixed point (int16 LS product + filt16a). phy_procedures_nr_ue.c already carries a fix for this ("FIXED-POINT HEADROOM FOR THE SSB REs BEFORE THE ESTIMATOR": scale the 240 SSB REs by 2^shift to a 2^13 working point) but it was gated `Nsym > 1024` on the premise that the 20 MHz path is healthy. That premise fails for a WEAK 20 MHz cell. PCI 675 at 51 PRB:
- rf_pow 4.4 (403 at 51 PRB: 24-35; 415/923: 40-110); the SSB REs reaching the estimator are rawmean 0.2 / rawmax 1-2 (PBCHFAIL dump), and the estimate is |H| mean 8.7-9.1 / max 28 against hundreds-thousands on a healthy cell (about 5 bits).
- That reproduces exactly the documented symptom of the unscaled estimator: CIR peak/median collapse, the +-CP timing search chases noise, the PI loop integrates it (max_pos_acc ramp), PBCH lock lost, RFSTALL.
- The 217-PRB run of the same cell takes the scaling (Nsym 4096 > 1024), which is why it tracked clean. It is not geometry: Point A / --ssb 227 / -C 3425010000 are correct (SSB start = 36*12 + 22 = 454 SCS15 sub-carriers = 227 SCS30; centre 3415.83 + 51*6*0.03 = 3425.01 MHz), the FO seed is the same, SIB1/MIB were read. 403 at 51 PRB worked because it is 15-20 dB stronger.
- Hypotheses refuted: SSB placement/k_SSB (fits, MIB decoded), FO seed (same, CFO 130 Hz measured), exit(3) path (watchdog), wrong -C.

## Fix
`Nsym > 1024` -> `Nsym >= 1024` in the estimator-input scaling (openair1/SCHED_NR_UE/phy_procedures_nr_ue.c). The shift is 13 - log2(max|RE|) clamped at 0, so it is derived from the measured level, no per-cell parameter, no flag. Sizes below 1024 are unchanged. Cost: one 240-RE copy per PBCH symbol on 1024-FFT cells only.

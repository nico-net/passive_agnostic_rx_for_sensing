# MPCI M2: per-cell context isolation (2026-10-13)

Evidence labels: [CODE-READ], [MEASURED, cloud x86 4c, ...], [OFFLINE VERIFIED, cloud x86 ...], [NOT RUN]. No DGX/OTA result is claimed here.

## Design
M1 chose one receiver PROCESS per cell, fed by the shm IQ ring. Process-private globals, statics and TLS are therefore isolated by construction [CODE-READ]. M2 makes every cross-process / host-global resource per-cell, proves it with tests, and records the in-process singleton audit for a possible future in-process option.

Mechanism: `common/utils/nr_cell_instance.h` (header-only, stateless: getenv per call, so nothing to leak across fork()).
- `ISAC_CELL_INSTANCE=<tag>`, `[A-Za-z0-9_-]`, 1..32 chars. Unset or empty: every path is returned unchanged (byte-identical). Invalid tag: FATAL (`exit(2)` with a message). Silently ignoring it would make two cells share files.
- `nr_cell_path(default, out, n)`: `/tmp/a.txt` -> `/tmp/a.<tag>.txt`; `/tmp/passive_rx` -> `/tmp/passive_rx/<tag>`.
- `nr_cell_mkdirs(dir)`: mkdir -p.
- Explicit env overrides (ISAC_PDCCH_DISCOVERED_FILE, ISAC_PBCH_CAPTURE_PATH, ISAC_SIB1_CACHE_DIR, ISAC_METRICS_PATH, ...) are never tagged and keep winning.

## Process-private (isolated by process) vs cross-process
Everything not in the table above is a file-scope static/global/TLS inside one nr-uesoftmodem: acquisition state, CORESET bank, solver tables, SIB1/UL-lock state, CSI-RS discovery, metrics counters, drop counters, GPU budget state, thread pools [CODE-READ].

## Remaining risks (not fixed here)
- Core plan (common/utils/nr_core_plan.c) is identical in every process: N processes pick the same cores. Mitigation: the launcher `taskset -c <cell cores>`; the plan reads sched_getaffinity, so it should stay inside the mask [CODE-READ, NOT RUN with 2 cells]. ISAC_GPU_WORKER_CORE default 3 and the ISAC_*_CORE pins and config scan/pdsch/ul pins must be set per cell if they fall outside the mask.
- GPU: one CUDA context per process on device 0; green contexts and nr_gpu_budget are intra-process, so budgets do not see each other (M3).
- mlockall (system.c): each process locks its own pages; with 2+ cells check RLIMIT_MEMLOCK/RAM (ISAC_MLOCK=0 skips).
- captures/run_arm.sh (frozen) does `pkill -x nr-uesoftmodem` and `rm -rf /var/run/dpdk/* /dev/hugepages/*`: never use it with sibling cells running; mpci_launch.sh kills only its own PIDs, with SIGINT.
- DPDK/hugepages: only the radio (publisher) process should own them; consumers use the shm_iq device.
- ZMQ endpoint: must differ per cell (launcher does it for tcp://*:PORT only; ipc:// endpoints are not rewritten).
- Mod_id is 0 in every process, hence the stats-log tag.

1. Idle host, no nr-uesoftmodem running, then build the DGX variant (ninja nr-uesoftmodem oai_usrpdevif rfsimulator params_libconfig nr-softmodem tests && ctest -j4). Only the known ARM failures are allowed.

3. `DRY=1 OUT=/tmp/mpci RING=isac_iq BASE_CFG=<.cfg> tests/passive_rx/mpci/mpci_launch.sh A:<C>:<R>:<SSB>:-:<cores> B:...` and check the printed lines; pick disjoint core lists (X925 map from coremap_dgx.env).
4. Start for real with PUB_CMD of the X410 radio process; confirm per-tag files in /tmp/passive_rx/<tag>, `$OUT/<tag>/metrics.jsonl` has `"cell":"<tag>"`, no shared file in `ls -l /tmp/passive_rx /tmp/coresets_discovered*`.
5. `mpci_launch.sh stop` (SIGINT); verify X410 claim is released (no SIGKILL).

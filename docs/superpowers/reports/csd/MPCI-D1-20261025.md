## Decisions / open items
1. Pass 2 for 415 (k_ssb 14 -> `--ssb 1171`): equals pass 1, so `pass2_from_log` returns 0 with `*ssb_out = 1171` and emits no event (a no-op retune is not emitted); 923 (k_ssb 10 -> 1169, `-C 3731910000`) emits RETUNE (cause `pass2`).
2. A cell with non-null `n_rb_hint` is treated as already refined by the front end: pass 2 does not override its `centre_hz` (otherwise it would undo the live aligned-grid tunings such as 923 `-C 3759990000 --ssb 233`). Assumption, to confirm with the front-end agent.
3. The `--ssb` in force is receiver-side state (starts at 1171), not an inventory key; an inventory retune keeps it.
4. N_max is the number served for the `wanted` set given at plan time; later inventory growth beyond it is refused with `max` (or the plan's binding reason). A8 should pass the whole expected inventory (or a representative set) to the plan.
5. The retire hysteresis default (10 s) is a policy constant overridable by the caller; to be tuned with the front end's lost detection.
6. The receiver already logs `ISAC_ACQ_RETUNE {"centre_hz":..,"n_rb":..}` on a carrier mismatch (seen in pcis_data/r508); not consumed here (out of D1 scope), a natural next input of the manager.
7. The fixtures' PCI 380 tuning and CFO are `[INFERRED]` (never tuned); the log excerpts are synthetic in the receiver's format.
8. The existing front-end tools still write the bare list (rejected by the reader); the writer change is the front-end agent's.

## Cause

[CODE-READ] `nr_passive_samples_valid(producer, source, slots_per_frame)` requires
`source >= 0`, `producer >= source`, and `producer - source < slots_per_frame - 2`.
The actual producer publishes after a successful `nrue_ru_read()` (`executables/nr-ue.c:1596`,
also true at `e3349dcd96`). Older lifetime/queue comments saying "before" are stale; the queue
comment is corrected here. The unchanged two-slot safety margin covers overwrite/prefetch.
At mu=1 this is **18 slots / 9 ms from the source slot**, not 20 queued jobs and not elapsed time
since enqueue. The `/20` printed by PDSCHQ is `fp->slots_per_frame`, coincidentally also the depth
in this configuration. `NR_PDSCH_PASSIVE_QUEUE_MARGIN_SLOTS` is not used by this predicate.
`max_lag_slots` is sampled once before GPU submission, not at the later rejection.

The old checks are:

1. Consumer admission after its bounded future-k0 wait. Both an expired slot and a not-yet-ready
   slot increment `dropped_stale`; a rejected group previously counted only its head.
2. GPU worker before/after `fep_slot` (the latter includes its CUDA stream synchronization).
   These are `gpu_fep_stale_pre/post`; rejection falls back to CPU.
3. Decoder before/after SSB PSS/SSS FEP (`UNSUP@ssb-fep-before/after`) and after the main FEP
   (`UNSUP@1625`). The last check also runs when GPU LLRs have already replaced the CPU FEP.
   The queue counts an UNSUPPORTED outcome as stale if the live ring has expired by then;
   this can also mislabel an unrelated unsupported configuration.
4. After decode and self-check, K33 suppresses learning credit through `stale_after_decode`.
   Thus even a good CRC from already-owned LLRs loses credit when the unrelated live ring advances.

## Implementation

[IMPLEMENTED, NOT VALIDATED on device/OTA]

- `nr_pdsch_passive_queue.c`: flush admitted grants immediately, retaining consumer coalescing of
  already-queued siblings. Keep bounded depth, narrow-grant admission and per-RNTI fair eviction.
  Copy the target slot's time-domain IQ on all RX branches **before any GPU wait or oracle work**,
  with the existing lifetime predicate before and after the copy. Include the early FFT prefix,
  CPs and final-symbol slack. Reject a copy straddling expiry. Count rejected group members individually.
- Each consumer has a reusable CPU arena with the original ring address layout. Only the needed
  slot window is copied; preserving original indices preserves CFO phase, wrap and existing FEP
  addressing. At 122.88 MS/s, 4 RX, 3 consumers the arenas reserve/clear **112.5 MiB total**;
  each slot copy is about 1 MiB. Allocation happens during queue preparation, never per grant,
  with no CUDA registration. The arenas live through GPU completion, decoder, fallback, self-check,
  feedback and data-aided submission, then are reused. Queue shutdown frees them.
- `nr_pdsch_passive_decode.c`: consumer-local owned-IQ access for early SSB FEP, normal FEP, and
  explicitly captured pointers in thread-pool FEP tasks. CPU fallback and self-check use the same
  snapshot. Future-slot oracles still use the live ring and their existing guards. No FEP/kernel
  arithmetic changes. Ownership ends the ring deadline; epoch checks remain independent.
  The optional XANT wide-lag diagnostic retains its existing live-ring source (it is not decoder input).
- GPU requests now publish completion individually. GPU processing of an owned snapshot does not
  recheck the live ring. Valid snapshot CRCs retain learning credit even if LDPC/self-check ends later.
- **Minimal edits in T18-owned files:** only stream initialization in `nr_pdsch_gpu_fep.cu` and
  `nrLDPC_cuda/ldpc_decoder.cu` selects the device's highest supported priority with
  `cudaStreamNonBlocking`. Buffer allocation, registration, budgets and kernel code are untouched.
  FEP and the LDPC pool retain separate streams; there is no added device-wide synchronization or
  dependency on PDCCH/polar/discovery streams. CUDA priority is scheduling preference, not a hard
  preemption/latency guarantee. LDPC/CB0 internals otherwise remain T18's domain.
- Queue timestamps are sidecars, so `nr_pdsch_passive_job_t` and the job-replay binary format are unchanged.

## Metrics

[IMPLEMENTED] `ISAC_METRICS` gains these fields only with the T21 gate enabled:

- `pdschq_latency_us_bounds`: `[100,250,500,1000,2000,4000,8000,16000]`.
- `pdschq_latency`: nine non-overlapping, cumulative-count bins per stage, last bin >16000 us.
  `enqueue_dequeue`, `enqueue_fep`, `fep_ldpc`, `enqueue_ldpc`, `gpu_wait`.
  All clocks are CLOCK_MONOTONIC. Enqueue starts at queue admission; FEP completion is the GPU
  FEP return or actual CPU FEP completion on fallback. `fep_ldpc` includes chest/demod and LDPC;
  its endpoint is the primary decoder return, before CB0 follow-up and self-check reruns.
  Layout probes are included. GPU wait is one sample per GPU request, other stages per grant.
  Unsupported work contributes only to the stages it reached; no invented successful decode latency.
- `pdschq_reasons`: `queue_expired`, `future_unready`, `copy_expired`, `unsupported`, `decode_error`,
  `gpu_fallback`. GPU fallback is a diagnostic event, not necessarily a dropped grant.
- `pdschq_drop_narrow`; existing full/epoch/stale/late-credit and GPU health counters remain.
  Owned-IQ stale drops are the sum of queue-expired, future-unready and copy-expired. Late ring
  movement alone no longer relabels UNSUPPORTED as stale.

Flag-off JSON is unchanged. All counters are bounded-size atomics, without a per-grant log.

  one serial GPU lane, 500 us slots, admission at source age 9 slots, 100 us copy, 4 ms GPU,
  1 ms CPU tail. At 20/50/100/200 grants/s, every offered job decodes with zero stale/full drops.

  SSB-forced CPU fallback uses the snapshot. LDPC is the fixture's recorder, not a device decoder.

## Limitations

[IMPLEMENTED, NOT VALIDATED] Live near-zero stale at light load and real hundreds-of-grants/s
GPU capacity require the deferred runs. The fix cannot recover a grant already expired before
consumer admission, compensate for sustained offered load beyond service capacity, or preempt a
long-running foreign GPU kernel. GrantWork/CB0 has its own conservative lifetime policy and can
still skip auxiliary hypothesis work; this patch does not change T18-owned scheduling internals.
The fixed arena trades roughly 112.5 MiB on this configuration for unchanged FEP indexing and no
hot-path allocation. A compact per-symbol snapshot would require broader modulation API changes.

## Implementation

[IMPLEMENTED, NOT GPU/OTA VALIDATED]

- `nr_csirs_disc_feed.c:343,393`: one application worker, explicit `SCHED_OTHER`, default unpinned, optional
  `ISAC_CSIRS_DISC_CORE`. The same worker drains confirmation, FEP, detection, and sequence work.
  `nr_csirs_disc_fp.c:566` no longer creates normalization/fold/cluster helper threads, including CPU fallback.
  Four **period groups** remain, preserving T14's detection/admission order.
- `nr_csirs_disc_confirm_internal.h:145,181,248`, included by the RT state owner: actors read an atomic 640-slot
  due-symbol schedule and reserve an owned queue entry with CAS. No actor takes `g_csirs_state_lock`
  for discovery confirmation. Entries own their IQ and CFO/rotation descriptors; there are 128 ordinary
  entries plus 128 reserved for pending resources/unfinished phases. Already transformed symbols are
  copied; missing symbols on the GPU path use a copied CP-bearing TD span and worker-side GPU FEP.
  No actor pointer to mutable RX storage survives publication. FD symbols cross H2D once per queued slot
  and are reused for all due resource scores. Epoch and admission tickets reject
  obsolete queued work. Proper-divisor ZP probes are included in the published schedule.
- The worker uses the original T14 phase rotation, hit inference, admission/readmission, observer,
  monitor export, and ZP lifecycle. CUDA confirmation computes sequence correlation, EPR, and full
  occupancy-union ZP evidence; legacy CPU scoring remains the offline reference. Published immutable
  rate-match snapshots also prevent decode readers from blocking on worker scoring. The observed-NZP accessor uses the same immutable publication.
- `nr_csirs_disc_gpu_cluster.cuh:233`: local Q12 normalization and exact integer sufficient statistics
  stay on the device, followed by lattice screening, per-symbol RB segmentation, candidate ranking,
  harmonic suppression and footprint merging. Only the bounded footprint list returns to the CPU.
  Hypothesis construction remains CPU work; its mapping table is initialized before RX.
- `nr_csirs_disc_gpu_sweep.cu:196,446,471,491`: persistent workspace and stream; gather REs from the resident device
  ring, then sweep, refine extent, verify, and score confirmation on the GPU. Reference mapping has a
  caller-provided-buffer API and allocation-free in-place sorting. Existing allocating map API is retained.
  CUDA refinement preserves the CPU arithmetic/decision order; its serial device reduction still needs timing.
- `nr_csirs_disc_gpu.cu:178,346,524`: host staging is pinned by default. `ISAC_CSIRS_DISC_MANAGED=1` is the only
  managed-memory opt-in. Production FD IQ, normalization, histories, FFT work, and sequence workspaces
  are device allocations. TD staging crosses H2D once; repeated computation uses device traffic.
  Dedicated nonblocking streams use blocking completion events so GPU waits do not spin a CPU core.
- `nr_csirs_disc.c:125` (`nr_csirs_disc_pipeline_init`) prepares CUDA capacities, plans, kernel paths, confirmation storage,
  and the hypothesis table before RX; `nr_csirs_disc_start` allocates the resident ring before starting
  the worker. Initialization failure disables discovery. Resident GPU failures do not fall back to
  stale host IQ or trigger heavy CPU FEP. Host-backed offline/legacy APIs retain their CPU fallback.
- Acquisition remains **5120 slots at 50%**, then **640-slot windows, 1/7 duty**. No feed-duty constants
  changed. The only TD-file change prevents CPU fallback from corrupting a resident ring after GPU failure.
  No `nr_pdcch_*`, `nr_td_*`, `nrLDPC_cuda`, `nr_pdsch_gpu*`, or `radio/USRP/*` source was edited.

The shared discovery contract has **additive fields/functions only**. Rebuild core and both CUDA modules
from the same commit. Feature-off paths do not allocate the queue or CUDA workspace.

## Limits

[IMPLEMENTED, NOT VALIDATED ON DEVICE]

- GPU parity, absence of post-start CUDA allocations, GPU/CPU time, live actor latency, and X410 startup
  stability remain device gates. Do not treat CPU dump success or a successful CUDA compile as those gates.
- Confirmation storage is bounded. Pending work never uses trylock-and-drop on the state mutex;
  reserve exhaustion is still counted in `csirs_disc_confirm_drops`. A stalled worker can exhaust any
  finite queue; the live gate must check this counter and the TD backlog.
- Workspace dimensions are prepared for the started carrier; changing FFT/RB/RX geometry requires
  reinitialization. Buffers are retained for process lifetime. Diagnostic stateless CUDA primitives may
  allocate per call; the production resident path does not use them.
- The CPU fallback and synchronous dump bridge retain their reference allocations. The no-runtime-allocation
  contract applies to the warmed production GPU path. Receiver-output byte identity requires a host run;
  the isolated feature-off byte-comparison regression checks local behavior.

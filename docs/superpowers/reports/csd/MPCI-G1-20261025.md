# MPCI G1 (code part): GPU / pinned-host memory ledger and per-cell sizing

Branch `mpci/g-g1` from `mpci-main` @ a19d5f24de, DGX GB10 (aarch64). Labels: `[OFFLINE VERIFIED, DGX GB10 unit]` = unit test run here; `[CODE-READ]`; `[HYPOTHESIS]`.
STOP (code part): ledger booking every receiver GPU allocation, `GPUMEM` line, `nr_gpu_cell_bytes` equal to the real allocations for every exact PER_CELL kind, admission using it. Replay measurement (STOP of the plan task) is for the orchestrator: commands at the end.

## 1. Design
* Ledger lives in `nr_gpu_memstat.{h,c}` inside `libnr_gpu_platform.so` (not in nr_gpu_mem): one process-wide table shared by the core and the dlopen'd GPU modules (they cannot link `nr_cell.c`). Tag = (module, scope, cell); kinds dev / pin / mgd; current, peak, count. All relaxed atomics, no lock.
* Booking: the wrappers book by themselves under the thread scope (`nr_gpu_alloc`, `nr_gpu_register_host`, `nr_gpu_buf_alloc[_dev]`, and their frees; the tag is stored with the allocation so a free releases against the allocating tag). Raw `cudaMalloc/cudaHostAlloc` sites use `nr_ms_*` helpers (`nr_gpu_memstat_cuda.cuh`). Scope = `NrMsScope` RAII (C++) or enter/leave (C). A booking outside any scope shows as `untagged=` (must be 0).
* PER_CELL scope without a cell takes `nr_cell_idx()` of the calling thread, looked up by name (the modules do not link nr_cell.c). N=1: cell 0. Inits must therefore run on the cell's thread (A8) or pass the cell.
* GPUMEM line (header grammar): `SENSING: GPUMEM at=<fence|exit> dev= pin= mgd= peak_dev= peak_pin= peak_mgd= allocs= untagged= rss_anon_kb= cells= shared=[mod:dev/pin/mgd/n[+kg] ...] cellK=[...]`. Fence: logger; exit: stderr from an `atexit` (so SIGINT shutdown through main prints it). On the GB10 `nr_gpu_buf` DIRECT buffers are unified memory counted as `pin`; RssAnon is printed too.

## 3. nr_gpu_cell_bytes (seam)
`nr_gpu_cell.h` (pure C) with `nr_gpu_cell_params_t {n_rb, n_rx, scs_khz, max_layers (reserved), nid_dur, nid_window}`, kinds, `nr_gpu_cell_mem()` = {dev, pin}, `nr_gpu_cell_bytes()` = dev + pin. The allocators call the same inline functions (`nr_gpu_cell_fep_rx_bytes`, `..._fft_bytes`, `..._pdcch_rxf_bytes`, `..._nid_window_dev_bytes`, `..._nid_fixed_bytes`); the constants a module still owns are `static_assert`ed against the header (sizeof(st2_snap_t), sizeof(Device) = 8425776, HARQ block counts, PASS_SLOTS, MAX_SYM). No separate stub file: the function has no CUDA dependency and is linked into the no-GPU builds as is (`nr_cell_admit` library), which is more than a stub.

## 5. Admission hand-over (B3)
`nr_cell_admit.c`: HARQ and the nID window/fixed model call `nr_gpu_cell_mem`; removed `G_NID_CENSUS_MIB`, `G_NID_BATCH`, `G_NID_DUR` ([HYPOTHESIS, G1]), `G_NID_STAT`. The nID model now includes the st2 snapshot term the old one dropped and the exact fixed part (8 425 776 B Device etc.) instead of 776 MiB minus ten windows: total at 273 PRB window 10 is 767 MiB (was 776 census). Effect: sens6 profile nID window 6 -> 7 of 10 (`test_nr_cell_admit` expectation updated); `admit_model.py` mirrors the formulas. Still [HYPOTHESIS]: `G_GRAPH_FLOOR_MIB` (needs graph executables of real classes: read the `pass_graph` row of GPUMEM on a replay) and the CSI-RS model (kept, within 5 % above the measurement).

## 6. Orchestrator: measure the real per-cell numbers on replay
Run each replay normally with the unchanged command line (no new flag) and read the lines:
`grep -E "SENSING: GPUMEM" <log>` : fields `at=fence` (steady state) and `at=exit`; per cell: the `cellK=[..]` group (dev/pin/mgd per module) and `shared=[..]`; process: `rss_anon_kb`. Runs: 1 cell (c3610 PCI pair separately, then 217-PRB b), then 2 cells in one process; per-cell increment of the second cell = `cell1=` group sums (dev, pin) and the delta of `rss_anon_kb`. Check `untagged=0` and compare `cell0` with `nr_gpu_cell_bytes` of the same N_RB / RX (the csirs group against the model). Pin-ledger bytes (`pdsch_fep` mgd) keep growing after the fence (decoder-thread buffers); `at=exit` is the final figure.

## 7. Open items
* G3: HARQ store, FEP/PDCCH buffers and CSI-RS workspaces are still one instance per process (booked to the creating cell); they become per cell with G3/G4. LLR out buffers (2 x 64 MiB) and pass instances stay SHARED, class-sized (the Stage-4 "size from N_RB" is not done: no algorithmic change here).
* `NR_GPU_CELL_PASS_SLOTS` is a compile-time 8; when G2/G3 derive pool counts at run time the constant becomes a parameter (the static_assert will say so).
* `test_nr_gpu_isa_twin` needed `nr_gpu_platform` in its link line (the exact-FEP header books its self-test scratch).

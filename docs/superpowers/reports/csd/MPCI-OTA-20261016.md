Single-PCI direct, same morning (P99-BOTTLENECK): first body p50 ~0.6-0.8 ms, tot p99 8-15 ms (T), 13-24 ms (V).

Findings:
1. The radio side is fine at 245.76 MS/s on one QSFP link: publisher 0 overflows / 0 timeouts / 0 resyncs.
2. The GPU channelizer keeps up for ONE cell (ST 0 overruns, SV 2) but not for two: with both receivers running it needs 5.9-6.1 ms per 4.27 ms block (GPU 3.0-3.4 ms vs 1.3-1.5 ms with one cell) -> overruns, every M run aborted after ~140 s.
3. Every GPU context added multiplies the decode body: T first-body p50 0.79 ms direct -> 1.77 ms with the channelizer process -> 4.3-6.8 ms with channelizer + second cell; p99 up to 100 ms. Same direction for V. This is the multi-context GPU time slicing already found in Stage 4 (MC1PROC: second active CUDA context = 4-9x p99), now on air, and it also hits the channelizer.
4. Consequence: multi-PCI cannot work with separate CUDA contexts (cells + channelizer) on the GB10. It needs all GPU work in ONE context (GPU service process or single process), and the single-cell body cost (P99-BOTTLENECK) fixed first.

## 2. Root causes

### RC1 — the anonymous search could never decode a USS DCI on a configured-nID CORESET [CODE-READ, confirmed by replay]
TS 38.211 7.3.2.3: a USS PDCCH in a CORESET with `pdcch-DMRS-ScramblingID` uses c_init = (C-RNTI·2^16 + n_ID).
Before any C-RNTI is known, `nr_pdcch_autodiscover_length_scorer` descrambled with n_RNTI = 0 (or a confirmed RNTI
from the rotation), so the polar CRC could never pass for a USS DCI. The GF(2) joint (RNTI, payload) solver
(`ISAC_PDCCH_JOINT`) was reachable only from per-RNTI candidate tasks, which do not exist in full-auto mode until a
C-RNTI is known — hence zero `JOINT_RNTI_HIT` in every OTA run (m7/m10). Fix: `ISAC_PDCCH_JOINT_ANON=1`.

### RC2 — the dedicated CORESET was only searched on SS#0 slots [CODE-READ + replay]
Without a dedicated search-space periodicity the occasion gate is CSS0's (2 slots in 20 ms), so the dedicated
CORESET saw only slots 11–13 (the j1 hits are all at slot 12). `ISAC_PDCCH_SCAN_EVERY_SLOT=1` (pre-existing,
diagnostic) is required: with it the 36-CCE dwell sees every slot.

### RC3 — two candidates per AL on the dedicated CORESET [replay j1 dump]
The per-AL candidate split uses the process-wide `g_al_accepts`, which before any dedicated decode holds only CSS0
SI-RNTI accepts (AL4/AL8). The dwell ladder became AL1=2 AL2=2 AL4=9 AL8=4 of 64; the dump of 500 anonymous
occasions held 8 candidates per occasion. The UEs here are scheduled at AL2 (18 positions). With JOINT_ANON the
ladder now fills AL2/AL4/AL8 completely and gives AL1 the rest (18+9+4+33 = 64).

### RC4 — the anonymous search stopped forever [CODE-READ]
`anonymous_exhausted` after 500 occasions was never cleared, and `n_known_dl > 0` (an RNTI known from another
CORESET) disabled the anonymous search on every later discovered CORESET (j5: nid 62922 "rejected, no fresh CRC
evidence in 4000 occasions" after an RNTI locked on nid 10163). With JOINT_ANON the budget is the 4000-occasion
dwell, restarted on every dwell, and the search keeps running while every known RNTI's own context is settled.

### RC5 — alias RNTIs on a ghost geometry [replay j5]
The nID pass also publishes nid 10163 at grid_rb 1 (5/6 CCE overlap with the real grid_rb 0 CORESET). There the
joint solver turns real DCIs into a stable alias RNTI (0xb876 at median 8 mismatched bits, 4/319 ≤ 1) which locked
with mm 7..32 evidence. Fix: JOINT_ANON accepts need mismatched_bits ≤ max(1, ISAC_PDCCH_JOINT_ANON_MM·E/216)
(default 1 per 216 coded bits). On the correct grid_rb 0 geometry 0xb876 decodes with mm ≤ 1 in 308/361 DCIs and
is a genuine UE (hash test below).

### RC6 — RA type 0 was never armed for the DCI 1_1 layout [replay j3/j4 + unit test]
403 DCI 1_1 payloads of 0x8f5a fit exactly one field layout (bit statistics; HARQ PID increments by 1 mod 16 in
368/402 consecutive DCIs): id 1 | BWP ind 1 (always 1) | **RA type 0 bitmap, 14 RBGs (P=16)** | 4 bits (TDRA…) |
MCS 5 | NDI | RV 2 | HARQ 4 | DAI 2 | TPC 2 | PRI 3 | K1 3 | AP 4 | SRS 2 | DMRS 1. 13 % carry the full-band bitmap
0x3fff, which every type-1 layout reads as RIV 0x7fff > 217·218/2 — impossible — yet the soft stage-1 rule (drop
below 75 % plausible) kept type 1 alive, and RA type 0 waited for a TB-CRC refutation that 12 s cannot supply.
Also the resolver is used for PDSCH only with `ISAC_DCI11_STAGE2=1` (or V2); without it 3 hand-written type-1
layouts were decoded (DCIGT showed `prb=0+68` for full-band grants). Fixes: `ISAC_DCI11_HARD_REFUTE=1`,
`ISAC_DCI11_HARQ_SEQ=1` (see §3), use with `ISAC_DCI11_STAGE2=1`.

### RC7 — heap corruption [replay gdb backtraces j1, j4]
Every crash happened at `RAW_IQ_EOF` (the orchestrator's r415a run included: its log has `RAW_IQ_EOF` right before
`malloc(): unsorted double linked list corrupted`). gdb: `exit()` → static `Workspace::~Workspace` →
`Device<double>::~Device` → `cudaFree` → libcuda `free(): corrupted unsorted chunks` (nr_csirs_disc_gpu_sweep.cu),
i.e. CUDA calls from a static destructor after the runtime's own atexit teardown while other threads still used
CUDA. Fix: no CUDA calls in the static destructors of `nr_csirs_disc_gpu_sweep.cu` (`Device`) and
`nr_csirs_disc_gpu.cu` (`Buffer`). Replays j7–j10 (with the fix) end without the abort. Not an RT-path corruption.

### What the receiver does (all opt-in, own flags)
* **`ISAC_PDSCH_SOLVER=1`** (`nr_pdsch_solver.c`): a C-RNTI DCI 1_1 goes to the solver instead of Technique D. The
  live DCI 1_1 layouts are grouped by what they READ from this payload (PRB set, DM-RS ports/CDM groups, MCS); layouts
  reading identically decode identically, so a DCI offers tens of readings, not hundreds of layouts. On small grants
  (≤ 48 PRB) the solver probes (reading, S 0..3 with L = 14 − S, DM-RS add-pos 1/2/0/3, MCS table where (Qm, R)
  differ) with code-block-0 probes, `ISAC_PDSCH_SOLVER_BUDGET` per grant (24 used). One CRC pass = candidate; a second
  pass on another DCI among the candidate's layouts = SOLVED. Then every grant is one full decode with the
  representative layout chosen consistent with all CRC-passed (payload, S) pairs (S learnt per TDA index, MCS table on
  the first discriminating grant). The first solution is offered first to other RNTIs (prior, never assumed). Starts
  only once stage 1 has ≤ `ISAC_PDSCH_SOLVER_MAX_LIVE` (512) live layouts.
* REFINEMENT (after SOLVED): each other reading the solution's layouts give for a DCI gets one probe with the solved
  physical parameters; any CRC pass narrows the layout set to the layouts reading the DCI that way and the
  representative is re-chosen (k18 lesson).
* **`ISAC_PDSCH_PROBE_C1`** (implied by the solver): a probe of a one-code-block TB now reports its CRC — before, every
  single-CB probe read "fail" by construction [CODE-READ + OFFLINE VERIFIED: k8 probes that decode offline at LDPC
  iteration 1 were reported failed].
* Solver CRC passes are credited even when the IQ expired meanwhile (a pass cannot come from overwritten samples
  other than by the same chance as any hypothesis); failures on expired IQ are not.
* **CSI-RS (strictly blind)**: only resources the blind CSI-RS search confirmed at run time
  (`nr_csirs_blind_rt_rate_match_all`); nothing configured or hard-coded. TS 38.214 5.1.4 rate matching applies only to
  resources configured for that UE, so "rate-match the discovered resources" is a **per-RNTI hypothesis selected by TB
  CRC** (probe with and without; `PDSCH_SOLVER … CSI-RS rate matching APPLIED/NOT applied`), and the search never
  probes a CSI-RS slot (a missing rate match must not count against the true layout) [IMPLEMENTED, unit-tested;
  not exercised in k17: no grant with a solved RNTI fell on a confirmed CSI-RS slot (csirs_rm=0 on every full decode)].
  CSI-RS-derived IDs/spans/port counts as ranking hints: [PLANNED], not implemented.
* **`ISAC_PDCCH_JOINT_ANON_ASYNC=1`**: the anonymous (unknown-RNTI) search never runs on the PDCCH scan path. The scan
  path copies the top `ISAC_PDCCH_JOINT_ANON_TOPK` (6) prescreen-passing candidates to a bounded queue
  (`ISAC_PDCCH_JOINT_ANON_Q`, 64 items, drops counted); one SCHED_OTHER worker runs n_RNTI=0 polar + the GF(2) joint
  solve; hits are fed to the unchanged anonymous lock rule on the next occasion of that CORESET. The synchronous joint
  fallback in the candidate worker is off in this mode. The search keeps running on banked CORESETs for the next UE
  (after k17). `ISAC_PDCCH_JOINT_ANON_BUDGET_US` bounds the synchronous variant if used.
* **`ISAC_PDCCH_DED_EVERY_SLOT=1`**: every slot reaches the scan consumer once a dedicated CORESET is banked or may be
  dwelt on, but a non-SS#0 slot runs only ALL banked + the discovered CORESET passes; **`ISAC_PDCCH_C0_OCC_GATE=1`** adds
  CORESET#0 (USS + CSS passes) there only when its symbols carry PDCCH-like energy (per 6-RB group power on antenna 0
  vs an EMA floor of the quietest group, `ISAC_PDCCH_C0_OCC_DB` 6 dB): 26 % of non-SS#0 slots in k17.
* **`ISAC_PDCCH_KNOWN_PRESCREEN=1`**: skip known-RNTI polar decodes of candidates whose amplitude-consistency score is
  below `ISAC_PDCCH_KNOWN_PRESCREEN_MIN` (0.66; noise mean 2/π). The first, strict threshold (3.09 σ) lost DCIs (k15:
  48 DCIs of 0x8f5a vs 338 in k11); the loose one keeps them (k17: 430).
* **`ISAC_PDCCH_SCAN_TIMING=1`**: `SCANTIME` p50/p99/max per occasion (log2 buckets).
* Exit-time abort fixed in T26; T26b replays j7–k18 end cleanly.

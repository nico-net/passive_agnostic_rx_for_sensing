# MPCI supervisor (2026-10-13)

Evidence: [OFFLINE VERIFIED, cloud x86 4c] = `test_mpci_auto`, `test_mpci_launch` (python, ctest); [CODE-READ]; [NOT RUN] = anything live. No DGX/OTA result is claimed.

## What it is
`tests/passive_rx/mpci/mpci_auto.py` (python3 stdlib): one blind scan -> N live cell receivers in ONE radio window. All per-cell values come from the scanner (`cells.json`) or from the receiver's own log (pass 2); nothing is operator-entered except host resources (`--cores`, `--pub-cores`, `--base-cfg`, `--pub-cmd`).

| Command | Does |
|---|---|
| `plan CELLS.json --cores 4-19 [--max-span-hz 110e6] [--rate 122.88e6] [--pub-cores 0-1]` | `plan_window()` (separate function, one window) picks the centre covering the most cells; others -> `unserved` (M4 input). Per cell: tag `p<PCI>_<gscn>`, -C/-r/--ssb/--initial-fo (autofront `tune()`), `ISAC_TARGET_PCI=<pci>` + `ISAC_SSS_MULTI=2.5` only when `n_cells>1` or two served cells share a GSCN, cores = host list split evenly. |
| `launch PLAN.json --out DIR [--pub-cmd] [--base-cfg] [--build]` | builds 6-/7-field specs and calls `mpci_launch.sh start` (`DRY=1` prints). |
| `pass2 PLAN.json --out DIR [--wait 180]` | per cell, once `ue.log` has `Initial sync successful` + `MIB fields` + SIB1: `autofront.apply_refine` into cells.json; if the log has `ACQ carrier MISMATCH`, `retune_args.py auto` gives -C/-r/--ssb, and ONLY that cell is restarted (SIGINT, 60 s wait, old log kept as `ue.log.<ts>`), plus `ISAC_CARRIER_FROM_SIB1=1` when grid > carrier (GRIDCARRIER). A retune target outside the window is not restarted (`outside_window`, `wanted` stored). plan.json updated. |
| `watch PLAN.json --out DIR [--period 10 --lost-s 30 --max-restarts 5 --backoff-s 10 --rescan CAPDIR...]` | polls pid (/proc), last `metrics.jsonl` line (`acq_state`, `pdschq_crc_ok/decoded`), `SHMIQ_OVERRUN`/`SHMIQ_PRODUCER_LOST` in `ue.log`. Restart (SIGINT + relaunch) when the process exited or `acq_state==LOST` longer than `--lost-s`; at most `--max-restarts`, wait `backoff_s*2^n` between restarts. One status line per cell per period. `--rescan` runs `live_chain.sh discover` on fresh capture dirs every 300 s and prints NEW (fits / outside window) / VANISHED. |
| `auto (--cells F \| --capdirs D...) --out DIR --cores ...` | discover (live_chain.sh) -> plan -> launch -> pass2 -> watch. |

Launcher change: `mpci_launch.sh` accepts an optional 7th spec field `K=V,K=V` (per-cell env) and `APPEND=1` (keep `OUT/pids`, single-cell restart; the supervisor passes `BASE_PORT=base+index`). 6-field form unchanged [OFFLINE VERIFIED].

## Window rule (no operator constants)
Cell interval = C +- BW/2. BW = SIB1 carrier width (`sib1_nrb`, pass-2 data in cells.json) else the pass-1 grid: the smallest receiver-supported 30 kHz grid whose half width reaches `autofront.RB_GRID_SC` (the first-pass `--ssb 1171` rule) = 217 PRB = 78 MHz. On the FRONTLIVE table only 508+4 (co-located, identical -C, PCI pins) fit one 110 MHz window in pass 1; 675/403/415/923 are `unserved`. With pass-2 widths (508 and 4: 162, 403: 51) 508+4+403 fit [OFFLINE VERIFIED, synthetic widths in the test]. Pass-1 over-reserves on purpose: pass 2 can only shrink a grid, so a served cell never leaves the window.

## Limits
- One window only; rescan reports but does not launch (needs a fresh capture by the radio orchestrator); pass-2 interval uses the carrier width, the restarted grid is the next supported size and is checked against the window.
- Loss detection = `acq_state==LOST` / process exit only; no repeated-`synch Failed` heuristic. `PRODUCER_LOST` is reported, not acted on (restarting a consumer cannot help).
- 30 kHz SCS, python/CPU, supported-grid list copied from retune_args.py. Cores: even split, all cells get the same count; no per-cell ISAC_*_CORE pins (see M2 risks).
- Restarting a co-located cell relies on the SIGINT-only path; the old process is never SIGKILLed.

## Multi-window (M4 planner, 2026-10-13)
Evidence: [OFFLINE VERIFIED, cloud x86 4c] = `test_mpci_auto` (13 tests), `test_mpci_launch` (4); [CODE-READ] = publisher parser; [NOT RUN] = any radio/X410.
Inputs stay blind: cells.json + host inventory (`--cores`, `--channels N` radio RX channels, default 4). Default `plan`/`auto` is now multi-window; `--single-window` = the old behaviour (one window, rest `unserved`).

Commands: `mpci_auto.py plan CELLS.json --cores 4-19 --channels 4 [--min-ch-per-window 1] [--dwell-min-ms 40 --dwell-max-ms 200] [--max-span-hz 110e6]`, then `launch/pass2/watch PLAN.json --out DIR` as before.

Rules (`cover_windows`, `assign_channels`):
1. Windows = greedy interval cover of ALL cells (sort by left edge, open at the leftmost uncovered edge, width `--max-span-hz`): optimal. A cell wider than the span gets its own window. FRONTLIVE fixture pass 1 (217 PRB = 78 MHz per cell, 110 MHz span) -> 5 windows: [675] [508,4] [403] [415] [923] [OFFLINE VERIFIED].
2. D = channels // min_ch. Windows <= D: all dedicated, channels split evenly, remainder one each to windows with more cells (tie: lower frequency); 4 ch / 3 windows -> 2+1+1, the 2 to the window with most cells. Windows > D: the D-1 windows with most cells (tie: lower) get `min_ch` channels each, ALL others time-share the remaining channels (>= min_ch) via `ISAC_SHM_IQ_DWELL`; dwell = `dwell-min-ms` x cells in the window, clamped to [min, max]. 40 ms = 2 SSB periods of 20 ms, so each visit can see an SSB; the cap bounds the absence of any window. Fixture, 4 ch: 508+4, 675, 403 dedicated (1 ch each), 415+923 share ch 3 at 40 ms each (50 % duty each) [OFFLINE VERIFIED].
3. Receiver RX count = its window's channel subset size, passed as `--ue-nb-ant-rx` (the shm_iq device takes ring channels 0..N-1 of `rx_num_channels`, which is the CLI/cfg value [CODE-READ shm_iq.c]). A single-window plan thus also gets `--ue-nb-ant-rx <channels>` (v1 had the default 1); use `--channels 1` for the old 1-RX form.
4. Co-channel pin (`ISAC_TARGET_PCI` + `ISAC_SSS_MULTI=2.5`) is decided per window (n_cells>1 or same GSCN inside one window).

plan.json v2: `radio{channels,min_ch_per_window,pub_env{ISAC_SHM_IQ_PUB[,_PUB_FREQ,_DWELL]}}`, `windows[{ring (<ring>_w<k>; plain <ring> for one window), centre_hz, channels, mode dedicated|dwell, dwell_ms, cells}]`, cells gain `ring`, `nrx`, `window`. Env strings follow `shm_iq_pub.c`: `PUB=ringA:0-1,ringB:2+3`, `PUB_FREQ=ring=hz` (dedicated windows only), `DWELL=ring@hz:ms` (dwell windows; the parser requires one shared subset). A single dedicated window keeps the v1 form `ISAC_SHM_IQ_PUB=<ring>`. The tests extract the real `parse_env/parse_freq_dwell` from `shm_iq_pub.c` (file untouched), compile them with gcc and check names, channels, frequencies, dwell and `nd` [OFFLINE VERIFIED].

Launch: ONE publisher with `PUB_ENV` (new launcher env, replaces the default `ISAC_SHM_IQ_PUB=$RING`); one `mpci_launch.sh` call for all cells; per-cell ring via the existing 7th env field `ISAC_SHM_IQ_NAME=<ring>` (appended after the global one, so it wins); new pseudo-key `UE_NB_ANT_RX=n` in that field becomes `--ue-nb-ant-rx n`. 6-field specs unchanged. A restart (`restart_cell`, `APPEND=1`) rebuilds the same spec so the cell keeps its ring and RX count.

pass2/watch: pass-2 checks the refined carrier against the cell's OWN window centre; if it leaves, the cell is NOT restarted, `pass2=outside_window`, `wanted` stored, message suggests re-plan with the refined cells.json (re-plan restarts everything: the publisher env changes). `watch` adds one line per window (skipped for a single dedicated window): mode, channels, dwell, `SHMIQ_PUB_DWELL` switches seen in `OUT/pub.log` and ON/AWAY from the last one, `SHMIQ_DISCONT` returns and `SHMIQ_OVERRUN` summed over its cells. Away state is read from logs only, not from the ring header.

Limits: planner uses pass-1 widths (217 PRB per cell) until pass 2; pass 2 does not re-plan windows or channels automatically. All channels of a dwell group share one LO schedule; a dwell window is blind between visits (no continuous tracking); cores are split evenly over all cells; per-window rate is the one `--rate`. `rescan` NEW cells are reported against all windows. Interaction of dedicated windows with X410 LO sharing is unknown.

DGX steps [NOT RUN]: (1) `plan ... --channels 4 --pub-cores 0-1`, read printed env; (2) `DRY=1 launch` and compare with the M4-DESIGN steps 1 and 3; (3) run the publisher with the printed env (`ISAC_SHM_IQ_RADIO_ID` optional) and check `SHMIQ_PUB_READY` per ring, UHD `Actual RX frequency` per channel (LO sharing, M4-DESIGN step 2); (4) real launch + `pass2`; (5) `watch`: window lines, `SHMIQ_DISCONT` once per return, no PRODUCER_LOST, per-cell outage and CRC vs single-cell baselines.

## Wideband mode (2026-10-13)
**Update 2026-10-13: wideband is the DEFAULT and the primary architecture; M4 multi-window is the fallback.** `plan`/`auto` with `--uhd-args` (+ `--gain`) plan ONE wideband window on all antennas, default `--rate 245.76e6` (the user-verified X410 CG_400 rate: 4 ch x 245.76 MS/s clean for 300 s with benchmark_rate multi_streamer, priority high [USER-VERIFIED, DGX Spark/X410]). `--wideband` stays as a no-op alias. `--multi-window` (with or without `--uhd-args`) requests the M4 plan (default `--rate 122.88e6`); without `--uhd-args` and without `--multi-window` the M4 plan is made as before and a one-line hint says wideband needs `--uhd-args`. `--wideband` together with `--multi-window` is an error.
Commands: wideband `mpci_auto.py plan CELLS.json --cores 4-19 --uhd-args "type=x4xx,addr=192.168.10.2,mgmt_addr=10.79.1.235,use_dpdk=1" --gain G --pub-cores 0-1` (same flags for `auto`); fallback `mpci_auto.py plan CELLS.json --cores 4-19 --multi-window [--channels 4 ...]`. The publisher command shape is unchanged (`shm_iq_uhd_pub --args .. --rate 245760000 --freq .. --gain .. --channels 4 --antenna RX1 --ring ..`; multi-streamer and high priority are the tool's own defaults).
Cells outside the wideband window stay in `unserved` (FRONTLIVE: 675, 923 at 245.76 MS/s, pass-1 widths [OFFLINE VERIFIED, cloud x86 4c]). `--fallback-dwell [--radio-channels 4]` is REFUSED with an explanation: all antennas share one LO, a dwell visit would retune them away from the wideband window. With `--channels` < `--radio-channels` the spare channels could host an M4 window for the unserved cells (cover_windows/assign_channels); that is NOT implemented, the message says so. To serve those cells run a separate `--multi-window` plan. Tests: `test_wideband_default_cli_and_fallback_dwell` [OFFLINE VERIFIED, cloud x86 4c]; any radio run [NOT RUN].

Evidence: [OFFLINE VERIFIED, cloud x86 4c] = `test_mpci_auto` (3 new tests) on the FRONTLIVE cells.json; [NOT RUN] = any X410/UHD publisher run.
`mpci_auto.py plan CELLS.json --cores 4-19 --wideband --rate 245.76e6 --uhd-args <uhd args> --gain <dB> [--channels 4 --antenna RX1 --ibw-hz HZ]`: ONE window on ALL channels, standalone publisher `shm_iq_uhd_pub --args .. --rate .. --freq <centre> --gain .. --channels N --antenna RX1 --ring <ring>` (printed, stored in `plan.radio.pub_cmd`, started by `launch` unless `--pub-cmd` overrides; not re-started on a single-cell restart). `--uhd-args` and `--gain` have no defaults.
Rules: usable span = the radio's instantaneous bandwidth `--ibw-hz`, default rate x 200/245.76 (X410 datasheet: 200 MHz at 245.76 MS/s, 400 MHz at 491.52 MS/s; beyond it the radio's own filter rolls off) [ANALYTICAL, datasheet, not measured on this unit]; a cell needs its whole interval C +- BW/2 (same blind widths as before) inside it; the window serves the most cells (plan_window), centre = middle of the served extent. Every served cell gets `--ue-nb-ant-rx <channels>` and `decim = rate / cell rate` (cell rate from its grid: 51 -> 30.72, 106/133/162 -> 61.44, 189/217/273 -> 122.88 MS/s); a cell whose decim is not a power of two in 1..16 is `unserved` (reason `decim`). Unserved cells carry an M4 fallback note only (a dwell window cannot coexist with a window on all channels).
FRONTLIVE: 245.76 MS/s -> usable 200 MHz, centre 3625.29 MHz, serves 508, 4, 403, 415; 675 and 923 unserved with pass-1 (217 PRB) widths [OFFLINE VERIFIED] (whether 923 joins once SIB1 widths are known depends on its carrier width); 491.52 MS/s -> all 6 in one window. Pass-1 grids (217 PRB) give decim 2 / 4; with pass-2 widths the decim is 8/16 for 51 PRB cells. Pass 2 recomputes `decim` on a retune. Consumers decimate by 1/2/4/8/16 (iq_ddc, 4 halfband stages).

## Wideband + shared channelizer (2026-10-13)
Evidence: [OFFLINE VERIFIED, cloud x86 4c] = `test_mpci_auto` (23 tests), `test_mpci_launch` (5), including the REAL `shm_iq_chan --bench --cells-json` parsing the generated file and a fake-process restart test (no X410, no GPU, no real channelizer data path); [CODE-READ] = `shm_iq_chan.c` `load_plan`; [NOT RUN] = any live radio, GPU, or real publisher -> channelizer -> cell chain.

**Default for wideband plans.** `plan`/`auto` with `--uhd-args` now add the channelizer stage (`shm_iq_chan`, MPCI-CHAN): it mixes + decimates the wideband ring once and writes one narrow ring `<ring>_<tag>` per served cell; every receiver attaches with decim 1 (`-C` = the ring centre, `-r` grid = the ring rate, `--ue-nb-ant-rx` = channels). `--no-chan` keeps the previous behaviour (each receiver decimates the wideband ring itself, `decim` = 2..16). Multi-window (M4) plans are unaffected.
Flags: `--chan-backend gpu|cpu` (default gpu), `--chan-cores L` (REQUIRED with chan, no site default; must be disjoint from `--cores` and `--pub-cores`, else the plan is refused). `cpu` prints a WARNING and stores `radio.chan_warn`: real-time for about one cell only [MEASURED in MPCI-CHAN, cloud x86 4c: 0.98x for 1 cell, 0.66x for 2, 3 threads].
plan.json: `radio.chan_cmd = shm_iq_chan --ring <ring> --cells-json <dir of plan>/chan_cells.json --attach-s 120 (--gpu | --threads <#chan cores>) --cores <chan cores>`, `radio.chan_backend/chan_cores/chan_cells`; per cell `ring=<ring>_<tag>`, `decim=1`, `chan_decim=<ring rate / cell rate>`. `--attach-s 120` because UHD/DPDK start-up can exceed the channelizer's 30 s default wait for the input ring.
**cells-json.** The channelizer's tolerant parser (`load_plan`) takes the first object-array named `cells` with `tag`, `C_hz`, `decim` (or `r`), `bw_hz`, and the ring from `--ring`. plan.json itself cannot be used (its cells carry `decim=1`, which the parser would read as the channelizer decimation), so the supervisor writes `chan_cells.json` (`{ring, cells:[{tag,C_hz,decim,bw_hz}]}`) next to plan.json from the CURRENT plan before every channelizer start (pass-2 changes included). Checked against the real binary: 4 cells parsed with the right centres and decim 2 [OFFLINE VERIFIED].

**launch order** (`mpci_launch.sh`, new env `CHAN_CMD`, `CHAN_RINGS`, `CHAN_WAIT_S` default 150, `CHAN_ONLY=1`): publisher -> channelizer (`chan` in `OUT/pids`, log `OUT/chan.log`) -> poll `/dev/shm/<ring>_<tag>` for every cell (exit 3 if the channelizer dies or the wait runs out) -> cells. `stop` SIGINTs all pids including `chan`. A single-cell restart (`APPEND=1`) never restarts the publisher or the channelizer [OFFLINE VERIFIED with fakes].
**pass2.** A retuned cell (new centre/rate) changes the channelizer's cell list: the supervisor SIGINTs the channelizer (it unlinks its rings), rewrites `chan_cells.json`, starts it, then restarts EVERY cell. Reason (CODE-READ): `shm_iq_ring_create` replaces the ring inode, so a running cell stays mapped to the dead old ring and ends in PRODUCER_LOST; there is no live reattach. A grid whose rate/decim has no power-of-two channelizer decimation is not applied (`pass2=decim_unsupported`). Cost: other cells lose their sync once per retune; with N cells that retune sequentially expect up to N restarts, a limit not optimised.
**watch.** First line per period: `chan state=UP|DEAD [RESTARTED|BACKOFF|GIVEUP] restarts=n overrun= discont= producer_lost= warn= err= | <last SHMIQ_CHAN_STAT>` (counts of the `SHMIQ_CHAN_*` lines in `chan.log`). A dead channelizer is restarted with the same bounded exponential backoff and `--max-restarts` as cells (old log kept as `chan.log.<ts>`), then all cells are restarted. The publisher is never restarted by `watch`. If the publisher is gone, the restarted channelizer exits after `--attach-s` and the backoff applies.

## A tool bug found and fixed (audit scanner)

`tools/mpci/static_audit.py` lost the rest of any file after a multi-line `/* ... */` comment inside a `#define` that contains an apostrophe
(the apostrophe opened a char literal), and it dropped the indentation of indented `#` lines (cleaned text shorter than the source, offsets
and line numbers drifted). In `nr_pdcch_blind_monitor_rt.c` this hid every object after line 2121: the table had 156 rows, the file has 366.
Fixed (commit 1a54c7fe39): comments inside preprocessor lines are skipped as comments, indentation kept (cleaned length == source length now
checked for all `.c` under openair1 and common). Also: block-scope converted statics (`NR_CELL_STATIC*` inside a function) are now tabled
(the A3 follow-up of the plan); this exposed 8 A3 rows, set to PER_CELL "converted by A3". The A4 row count therefore went from 400 to 606.

PER_CELL = state of one cell's receive path: configuration copies (`g_cfg`, `g_css0_cfg`), CORESET map/extent/lane tables, bank and dormant bank,
UE/RNTI persistence ring, energy floor, bootstrap table, SIB1 prior, DCI 1_1/0_1 resolvers and layout stages, length stores/states (DL, UL, per lane),
the scan queue (ring, locks, side work, counters, thread handles, args), nID/janon/disc queues and counters, USS tracker state and queue, traffic probe,
all per-cell counters and log throttles (function statics), pbwp state, dedupe, gate, slow-pass tracker. Function-local ones keep their name and are
aliased only inside their block (`#define` after the declaration, `#undef` after the block closes).

PROCESS (why):
- `dl_gpu_memory`, `dl_gpu_transfers`, `nr_dl_gpu_warmup::prepared`, `nr_dl_gw_pool_warmup::done`: hooks / one-time flags of the process-wide GPU.
- `g_btim_on`, `run_occasion_one::dbg`, `nr_syncq_enabled::e`, `joint_live_decode::warned`: mode / environment / capability flags, identical for all cells.
- `isac_segv_bt_install::alt`: sigaltstack of the process-wide SIGSEGV handler.
- `nr_pdcch_al1_mu` (extern mutex): guards AL1 union fields of bank entries; lock order bank lock -> al1 mu is the same for every cell (no cycle across cells).
- `uss_tracker` g_allowed/g_count/g_hitmask/g_vh/g_vm/g_magic/g_tables_once and `dci11 g_space`/`g_space_once`: lookup tables built once from constants (pthread_once), cell independent.
- `joint_live` `s_cache`/`s_cache_n`/`s_mu`: polar model cache keyed by shape (A, nid, L, pre); a model is a pure function of its key, shared on purpose (it can reach ~30 MB, one copy is better than N).
CONST: name/edge tables (`kSsName`, `names`, `edge`, `modules`, layout `k*` tables).

## Threads

Every thread of the PDCCH path now runs bound to its cell:
- nid_worker, slow-pass watchdog: `nr_cell_thread_create(..., -1)` (inherits the cell of the scan thread that starts them).
- janon_worker, disc_worker, uss tracker_worker, traffic-probe worker: created by `nr_core_plan_create` (no cell argument) -> the cell is passed as `arg`
  and the thread calls `nr_cell_bind` first thing. The disc worker's pool lease is `nr_pool_site_acquire(NR_POOL_DISC, nr_cell_idx(), ...)` (was literal 0).
- Scan queue consumers (`threadCreate`): `consumer_arg_t.cell`, bound at thread entry. The pool cell of the lease is now `nr_cell_idx()` of the
  consumer (3 sites: side work, spin try-acquire, job lease); it used `job.gNB_id` / literal 0. `job.gNB_id` is still carried to `proc.gNB_id`.
  At N=1 both are 0, so pool behaviour is identical. A8 should make the producer set `gNB_id` = the cell index (the plan's "align").
- Pool (tpool) candidate tasks of one occasion (`nr_pdcch_blind_cand_worker`, pushed by the scan thread): the task struct carries `cell`; the worker binds
  to it for the task and restores the previous binding. The tpool workers serve all cells and are not bound.

### Unbound-thread sites (the cell must come from the job)
1. tpool workers running `nr_pdcch_blind_cand_worker` (rt.c, `pushTpool` in the occasion body): handled via `task.cell` (above).
2. GPU host callbacks: none exist in the A4 files. `nr_pdcch_gpu_exact_fep_symbol`, `nr_pdcch_gpu_record_cpu`, the solver callbacks `solver_tda_of`/`solver_hq_of`
   and the polar/pdcch plugin calls are synchronous from the scan thread (`[CODE-READ]`). The nID GPU worker thread (`nr_pdcch_nid_gpu.c`, owner G) is
   unbound and process-wide but does not touch A4 state.
3. Callers outside the A4 files that must run on the cell's bound thread (A8 / A3): MAC thread `config_ue.c:1801` (`nr_pdcch_blind_monitor_set_tda_common`),
   `config_ue.c:2345` and `nr_passive_rrc_harvest.c:189,220` (`nr_pdcch_sib1_prior_get/set`), `nr_ue_dci_configuration.c:536,545` (`autoconf_wanted`/`autoconf_css0`);
   slot threads `nr-ue.c:710` (`nr_pdcch_blind_monitor_process`), `:1066` (`early_post`), `:1914-1917` (`nr_syncq_*`), `phy_procedures_nr_ue.c:1515`
   (`nr_dl_traffic_probe_push`); `nr-uesoftmodem.c:381` (`nr_pdcch_blind_monitor_init`, once per cell now), `:600` (`get_cfg`), `:731-737` (stats/stop, per cell).
4. Epoch listeners (`bank_epoch_listener` in the bank, `length_epoch_listener` in rt.c) use `nr_cell_idx()`: the A3 cfg-epoch authority must raise them on the cell's own thread.

## Heap objects needing pre-allocation (for A8)

Call `nr_pdcch_cell_prealloc(cell)` (new `nr_pdcch_cell.h`, defined in `nr_pdcch_blind_monitor_rt.c`; it calls the per-file functions of the other two files)

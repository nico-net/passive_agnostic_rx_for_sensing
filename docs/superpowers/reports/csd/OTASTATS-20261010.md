## How to read the numbers

- **Time base.** Receiver time only. 1 slot = 0.5 ms (mu=1). `frame.slot` stamps (sfn*20+slot, wrap 10.24 s) are unwrapped against the receiver's `abs_slot` counter (ISAC_METRICS, 20000 slots per 10 s of `t_mono_ns`) and the running PDCCH frame stamps. Convergence times are seconds after t_sync = `abs_slot` of the first ISAC_METRICS after `Initial sync successful`. Events without own frame.slot (SOLVED, bank add, sync) take the latest PHY-thread stamp (log order, a few ms to tens of ms). Wall clock unused.
- **UE / RNTI.** A UE = distinct RNTI. "DCI" = `blind PDCCH rnti_seen ... fmt=1_1` (DL C-RNTI DCI 1_1, SI-RNTI 0xffff excluded). **UL DCI 0_1 is not logged by the receiver in these runs** (rnti_seen only prints 1_0/1_1), so no UL UE count exists. `DCIRAW` was disabled. "Persistent" = >= 20 distinct DCI slots, to separate real UEs from RNTIs seen a handful of times (possible false alarms). "Solved" = `PDSCH_SOLVER rnti=... SOLVED`. "CRC-OK UE" = >= 1 `EVMGRANT crc=1 probe=0` with non-SI RNTI.
- **Decoding unit.** One `EVMGRANT` line (probe=1 solver hypotheses and SI-RNTI removed) = one decode attempt, so "% CRC-OK" is per decode attempt, not per DCI and not per TB delivered (HARQ retransmissions and multiple layout trials of the same slot count separately). It is a receiver success rate, not a gNB BLER. MCS index as logged, almost always the 256QAM table (`tbl=1`). SNR = the `snr=` field (post-equalisation estimate, dB). Nl=3 bucket means Nl>=3.
- **Dispersion.** 95% CI = Wilson on pooled counts (treats attempts as independent, so optimistic). `sd_run` = std across runs of the per-run % (runs with n>=20); this is the honest spread and is usually much larger than the CI half-width. With n=2 runs per set in J/K and A/B it is indicative only.
- **Processing.** SCANTIME/PDTIM/GPU_EXACT_FEP are cumulative counters printed periodically; the last line per run is used. SCANTIME percentiles are histogram upper bounds.
- **Caveats.** (1) The A vs B runs differ in some receiver setting that is not recorded in the logs I read (env t26l is the latest file, 14:17; J/K differ per env diff t26j -> t26k: `ISAC_PDCCH_DWELL_ADAPTIVE=1`, `ISAC_PDCCH_NO_FAKE_FOOTPRINT=1`, `ISAC_PDCCH_NID_GPU_NODROP=1` added); read A/B as labelled by the caller. (2) The cell population changes from run to run (UE counts 36..139 DCI RNTIs per run), so UE counts and convergence differences between sets of 2 runs are mostly cell load, not receiver change. (3) "Time to first DCI" mostly measures when each UE becomes active; the receiver-attributable convergence is the solve/CRC lag after the first DCI.

## T29b review: what was changed on top of the Codex WIP

- [CODE-READ] **Self-deadlock on fatal paths inside a device call (fixed).** `exit_function()`
  (AssertFatal, raw-IQ replay EOF, any driver assert) can run *inside* `nrue_ru_read()`, which
  holds the shared radio-lifetime gate. It then waited for the release thread, which needs the
  exclusive gate: deadlock until the watchdog, and the radio was **never released**. Now each
  thread counts its own gate holds (`__thread`) and `nr_shutdown_finish()`/the atexit fallback
  drop them first (they never return into the interrupted device call). New fixture case
  `fatal_in_read` (asserts no watchdog, exactly one stream stop + release).
- [CODE-READ] `nr_shutdown_finish()` now `fflush(NULL)` before `_exit()` (stdio-buffered
  log/printf output was lost on the bounded exit path); a stuck stdio lock is still bounded by
  the watchdog.
- [CODE-READ] Active (non-passive) SA UE keeps the upstream "first ^C deregisters, second ^C or
  5 s alarm stops" behaviour, but the alarm/second press now always shuts down (old `trigger_stop`
  was a no-op once `oai_exit` was set, e.g. after an RFSTALL). `--passive-rx` (and non-SA): one
  SIGINT/SIGTERM stops immediately; a fatal radio stall starts the orderly shutdown itself.
- Kept from the WIP (reviewed): itti exit gate (sem initialized before main, EINTR retry, early
  posts survive), pre-created radio-release thread + `ISAC_SHUTDOWN_TIMEOUT_S` watchdog
  (default 15, release starts at the first request, `_exit` at the deadline), RU lifetime gate,
  RFSTALL -> `nr_shutdown_request(3)` from every fatal read path and from the USRP ring producer
  (weak symbol; verified exported: `nm -D nr-uesoftmodem` shows `T nr_shutdown_request`),
  ordered joins, `_exit` after joins (no late CUDA/plugin static destructors).

## Root cause and limits of the supplied evidence

[CODE-READ, base dd3aede366; historical OTA backtrace supplied by operator]
The source-level failure chain is:

1. USRP `receive_failure` sets its own `rx_stop_requested` and returns -1.
   Ring metadata errors/overruns set `ring_err` and end the producer. These flags
   do not terminate the application or destroy its `multi_usrp` shared pointer.
2. `nrue_ru_read` sets **only** `oai_exit` on a negative read or invalid short-read
   continuation. `readFrame` does the same for an incomplete frame. The UE loop
   consequently ends; it neither posts ITTI nor invokes the cleanup tail.
3. Despite its name, `itti_wait_tasks_end` is just `sem_init(..., 0)` followed by
   one untimed `sem_wait`. It does not monitor or join the UE/ITTI tasks. The
   existing `itti_send_terminate_message` is also an empty compatibility stub.
   Setting `oai_exit` or returning from `UE_thread` cannot wake this semaphore.
4. Main's `nrue_ru_stop`, actor joins and **much later** `nrue_ru_end` are all
   unreachable. UHD's claim-renewal thread, grpc workers and DPDK pollers keep
   running. The supplied trace shows the claim-loop task, absent UE thread,
   actors/consumers, and main in `itti_sem_block`, consistent with this chain.
5. The generic `softmodem-common.c` signal handler is **not installed** by NR UE:
   `set_softmodem_sighandler()` was commented out. The installed late handler
   is `trigger_deregistration`, as the supplied main-thread stack confirms.
   Passive RX is SA-shaped, so the first signal attempts NAS deregistration and
   schedules a five-second SIGALRM. Its `trigger_stop` posts only when
   `!oai_exit`; after RFSTALL, that fallback is therefore a no-op. There is no
   useful radio/MAC owner left to carry out deregistration.
6. **The supplied trace does not establish why all subsequent SIGINT/SIGTERM
   deliveries failed.** In this exact source, once `stop_immediately` is set,
   the second `trigger_deregistration` invocation unconditionally posts. It is
   incorrect to attribute that branch to an `oai_exit` guard. The old handler
   also calls malloc/ITTI mutex code from signal context, which can deadlock if
   interrupted while those locks are owned, but the eight-frame-per-thread
   trace does not prove this happened. It contains neither signal dispositions,
   masks/pending sets, the guard value, nor a verified deployed binary hash.
   Further forensic attribution would require those observations. The new
   handler removes both the guard failure and the unsafe handler operations.
7. Before the late ITTI wait (including two seconds after starting UE workers),
   NR UE had no dedicated termination handler. Also, a post before that wait
   could target an uninitialized semaphore and then be erased by `sem_init`.

[CODE-READ] The defunct child is not capable of renewing the radio claim.
`start_background_system()` forks a command helper before radio creation;
the optional T tracer can also fork. The trace alone does not identify which
child became a zombie. The background helper PID is now retained and reaped
in normal shutdown. It is not the cause of the main semaphore wait.

[CODE-READ] Main's final `_exit(status)` follows the explicit cleanup sequence;
remaining process-owned service threads terminate with the process. It avoids
late plugin/CUDA static-destructor ordering. Fatal assertion callbacks can run
inside arbitrary worker locks: they request radio cleanup and finish the process
under the same watchdog, rather than joining themselves or racing device deletion.
The stop APIs may drain existing queues; if a worker cannot finish within the
budget, the watchdog ends the process after the independent radio release.

`SENSING: SHUTDOWN elapsed_ms=... step=... status=...` uses monotonic time from
the first request. `USRP_SHUTDOWN elapsed_ms=... step=...` is relative to driver
teardown. Watchdog logging uses a separate nonblocking stderr description so a
full log pipe or a stdio lock cannot defeat the deadline.

## Flags and deliberate shutdown changes

| Variable | Default | Meaning |
|---|---|---|
| `ISAC_SHUTDOWN_TIMEOUT_S` | 15 | Whole shutdown deadline, integer 1..300 seconds; invalid/zero values use 15. Cannot disable the deadline. Set 10 for the acceptance bound below. |
| `ISAC_RF_FAIL_AFTER_READS` | unset/off | Independent test-only fault injection: a positive integer N fails the next RU read after N admitted calls, using the production fatal-read path. No flag aliasing with CSI-RS. |

[CODE-READ] Shutdown fixes are unconditional as authorized. Signals now initiate
immediate local shutdown rather than waiting for SA deregistration. Unrelated
normal return paths retain their original success/failure code. A watchdog on
an otherwise successful exit uses failure status 1. Ordinary receive/decode
decisions are unchanged with the injection flag unset, except that incomplete
fatal reads terminate instead of propagating incomplete IQ or hanging main.

## Hard limit: process exit versus remote claim confirmation

[IMPLEMENTED, NOT VALIDATED ON X410] On an ordinary RFSTALL/actor deadlock the
radio cleanup thread can stop the stream and destroy UHD handles without main
or PHY cooperation. The fake blocked-main test verifies this ownership pattern.

**An unconditional guarantee that the X410 is never still claimed at `_exit`
cannot be made if UHD destruction itself deadlocks or the management link is
unreachable.** The implementation logs `watchdog_exit_radio_release_incomplete`
in that case and `_exit`s on schedule, stopping claim-renewal threads. A remote
claim may then persist until MPM expires its lease. It does not concurrently
reset live C++ shared pointers, falsely log successful release, send SIGKILL,
or attempt to seize/release somebody else's device claim. A hard kernel stall
or scheduler starvation also lies outside an in-process deadline guarantee.
`radio_release_complete` proves local cleanup returned; only the hardware check
below proves the remote claim is clear. Thus the literal never-claimed
requirement and real-device <=10 s cleanup remain **unverified**, not asserted.

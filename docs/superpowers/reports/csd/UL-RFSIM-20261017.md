**Bed**

In A2c the receiver found DM-RS 249 itself and latched data ID 324 after about 100 tries. So timing/TA, RIV, DM-RS, rate-match, HARQ/RV and the ID search are not the cause.

## Root causes (blind inference), receiver side
1. **MCS table never inferred.**
   - `nr_pdcch_ul_layout_lock.c:217` hard-codes `mcs_table = tp ? 3 : 0`.
   - A qam256 UL cell decodes with the wrong table, giving 0 CRC. Blind arm A3b: 574 real grants, 0 OK, tbl=0 vs truth 1.
   - Fix: sweep tables {0,1,2} (TP: {3,4}) per locked hypothesis and latch on a CRC pass.
2. **BWP look-alike.**
   - The vote picks 105@0 instead of 106@0 (tally 105@0:83, 106@0:0), so there is no lock, or a wrong CRC-lock (A3b, 111 s, crc_ok=0).
   - A configured `pdcch_blind_monitor_ul_bwp` does not seed the lock.
   - ISAC_UL_LOOKALIKE does not help: there are no edge-discriminating votes.
   - Fix: a configured/SIB1 BWP seeds the lock, plus an N/N+1 CRC-first hypothesis or an edge probe.
3. **k2 inference is minimal-k.**
   - `nr_pdcch_ul_layout_lock.c:288` `nr_ul_layout_infer_k2` returned 5 (truth 6) when the S slot has no PDCCH.
   - Fix: try k2 and k2+1 in the CRC-first trials, or use the SIB1 TDD pattern.

## Upstream OAI gNB bug (shared code, default-on fix)
4. `nr_ul_channel_estimation.c:498/729` seeded the UL DM-RS from phy_cell_id, ignoring the PDU's ul_dmrs_scrambling_id (38.211 6.4.1.1.1).
   - Effect: 0 % gNB UL CRC with a non-PCI scramblingID0. Fixed: 97.6 %.
   - Passive path unaffected: it sets both fields to the same value (nr_pusch_passive_dmrs_pdu.h:19, nr_pusch_passive_decode.c:2299). Orchestrator-checked.

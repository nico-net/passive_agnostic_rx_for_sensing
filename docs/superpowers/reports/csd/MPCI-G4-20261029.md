## What was done
1. **Per-cell workspaces** (`nr_csirs_disc_gpu.cu`, `_cluster.cuh`, `_sweep.cu`): everything that was one process-wide GPU object is now one per cell, created at the cell's prepare (before the RX fence), sized from that cell's N_RB / antennas / capacity and booked per cell in the G1 ledger: discovery stream + event, FEP workspace (cuFFT plans, buffers), batched-FFT state, accumulate and lattice scratch, the resident detector (`resident::State`, history + host scratch `all`/`groups_h` that were function statics: a data race), chunk adaptation state (`c_seg`, `c_sweep`, ...), the sweep workspace (streams, mapping, cumulative evidence bank, `stage` vector) and the per-cell mutexes. The cell is the calling thread's (`nr_gpu_memstat_host_cell`, i.e. `nr_cell_idx()` of the bound discovery worker); an unbound thread uses cell 0. Before: a second cell re-prepared the one workspace (history zeroed and rebuilt at every cell switch, cuFFT plan rebuilt for another FFT size, allocations after the fence).
2. **Single-flight discovery ticket** (`nr_gpu_budget.c/.h`, `nr_gpu_chunk.h`): `nr_gpu_disc_ticket_acquire[_bulk]/release`, recursive per thread. Every discovery GPU slice of every cell holds it: one kernel chunk with its drain (bulk, inside `nr_gpu_chunked`), or one copy / FFT / launch with its drain (short). So at most ONE discovery chunk is on the device, however many cells, and the device is idle between any two (the property that releases the RT graphs' pending body launch). Waiters: short before bulk (FEP feeds the observation ring), then cells that prefer (nID ACQUIRE; the prefer flag is now per cell: `nr_gpu_budget_discovery_prefer_cell`), then the cell with the least recent discovery GPU time (1 s half life), then arrival. The nID slice (`nr_gpu_budget_cuda.h`) takes the same ticket after the budget admission.
3. **Discovery duty budget**: bulk holds are paced when 2+ cells discovered in the last 2 s: cap on the summed bulk time = max(min(100, k*30) %, 100 - RT-busy share), k = discovering cells, 30 % = the existing per-cell discovery share of `nr_gpu_budget.c`, RT-busy = wall time with an RT user in flight (`rt_begin/rt_end`, 250 ms windows, smoothed). One cell is never paced and never waits. An RT-idle device is never throttled. First version (pct summed over cells, 30 % total) cut cell 0 to 28-31 % of its solo BATCH/WINNER counts; the "RT leaves free" form is what is shipped.
4. **nID (`nr_pdcch_nid_gpu.c`)**: state was already per cell (DBG2). Budget accounting sums over cells: the rolling window, `used_us`, owner CAS are process-wide atomics shared by all workers [CODE-READ]; the ticket now also serialises their slices. Worker core: cell k>0 no longer pins to the plan's single nID core (cell 0 unchanged); it floats over the thread's allowed set unless `ISAC_PDCCH_NID_GPU_CORE` is explicit. `nr_gpu_membudget_commit/share` for csirs and pdcch_nid are now per cell (`nr_gpu_platform.c`): the module figure is the sum of the cells' commits, each cell sizes against share / active cells (other modules and N=1 unchanged).
5. **PDCCH GPU FEP** (`nr_pdcch_gpu_fep.cu`, shadow check, default off): ONE resident context, now bound to the cell that initialised it; other cells get -1 and keep CPU LLRs.
6. **CHUNK_SLOW** counts out time spent waiting for the ticket (printed as `ticket_wait_us=` only when > 1 ms).
7. **Circuit breaker: process-wide for the time-based breaker, per cell for the "GPU off" switch** (decision). The breaker (`breaker_ready/result`, retry backoff 100 ms..3.2 s) reacts to CUDA call failures; those are device-level (sticky error, device hang, other tenant's MPS stall) and affect every cell, and N independent breakers would each hammer a sick device: process-wide is right. `nr_csirs_disc_gpu_disable()` / `g_gpu_disabled` is set by the pipeline when ONE cell's preallocation fails (its own workspace did not fit): that is a per-cell fact, and with per-cell workspaces it must not switch the other cells' GPU discovery off. Both live in A7-owned `nr_csirs_disc_backend.c` / `nr_csirs_disc.c` (not edited here): needs `NR_CELL_STATIC(volatile int, g_gpu_disabled)` + `#define g_gpu_disabled NR_CELL_REF(g_gpu_disabled)` in backend.c (disable called on the cell's bound thread, `gpu_load()` reads it on the same). One-line change for A8/A7.

## What A8 must call / know per cell
- Per active cell, on that cell's bound thread, before `nr_cell_alloc_fence()`: `nr_csirs_disc_cell_prealloc(cell, fp, n_ant)` (A7) -> `pipeline_init` -> `gpu->prepare` and `gpu->sweep_prepare` create that cell's streams and workspaces. Nothing else for the GPU side; the ticket needs no registration (the cell is the thread's).
- `nr_gpu_budget_discovery_prefer_cell(cell, on)` is called by the nID worker; the CSI-RS cell state machine (host, A7/A8) may call it too for a cell still searching (so it is served first).
- Make `g_gpu_disabled` (backend.c) per cell (see decision 7).
- Pin policy: cell k>0 nID worker floats; B1b/B5 can lease a core on top.
- Open: the footprint history (`nr_csirs_disc_fp.c`, `nr_csirs_disc_alloc_unified`) is allocated lazily at the first detect, possibly after the fence (unchanged from N=1); cell workspaces are not freed on cell release (grow-only until exit); `c_refine` over 512 units not needed (ticket wait max 0.2 s).

# ULC — PUSCH arrival timing and DM-RS discovery (U5, U6)

2026-10-08, branch `csd/ul-c`, DGX aarch64 sandbox. CPU reference only; no GPU device was available. New behavior is separately gated by `ISAC_UL_TIMING_DISC=1` and `ISAC_UL_DMRS_DISC=1`, both default off. The existing CSI-RS contract is unchanged.

## Implementation

- **[CODE-READ]** `nr_pusch_passive_monitor_rt.c:43` already derives FR1 TDD `N_TA_offset = 25600 Tc` from the live sample rate (1600 samples at 122.88 Msps) and carries the DL-tracked CFO in each UL job. The decoder now uses that DL-frame-derived advance as the signed-search origin; positive FEP offsets read earlier samples. `nr_pusch_passive_decode.c:865-951` searches the granted DM-RS on four RX and passes the selected advance to the existing PUSCH FEP/decoder window. Cold acquisition covers **nominal ±2048 samples, step 128**, then **±128 around the peak, step 16**. Tracked acquisition covers **EMA seed ±256, step 64**, then **±64, step 16**. At 122.88 Msps the cold bound is ±16.67 µs. `nr_pusch_ul_disc.c:77-110` keeps a per-RNTI signed arrival correction (EMA weight 0.25), rejects changes over 256 samples and low-coherence peaks, and invalidates on dedicated epoch or discontinuous slot history. This is an observed arrival correction, not a decoded MAC TA command.
- **[CODE-READ]** `nr_pusch_ul_disc.c:112-329` generates the receiver's Gold/port-1000 CP-OFDM pilot reference and scores de-spread adjacent-pilot coherence across all four RX. A batch API accepts whole-grant hypothesis arrays for a later GPU backend. It evaluates type 1/2, both nSCIDs, mapping A/B, additional positions 0..3, and one/two-symbol front load using the existing UL mask table and antenna-port reverse table. It requires the observed pilot-symbol set to match the hypothesized mask; a superset containing data symbols is rejected. Equivalent layouts are reported as ambiguous (`mapping_type` or `add_pos` = -1). A two-symbol front load proves maxLength 2; a one-symbol observation leaves maxLength 1 versus 2 unresolved.
- **[CODE-READ]** `nr_pusch_passive_decode.c:870-960` ranks PCI, the grant's UL ID, the RNTI's known PDSCH data and PDCCH scrambling IDs, the monitor's CORESET PDCCH DM-RS ID, and the existing DL DM-RS decision before a bounded background scan of **64 physical IDs per eligible grant** (full 16-bit space in 1024 grants). The established DL DM-RS decision is cell-level in this base, not keyed per RNTI. The selected DM-RS type, ID, nSCID, symbol mask, CDM groups and port bitmap are applied to the real PUSCH PDU after validating the raw antenna-port code point. The per-RNTI cache seeds timing and identity ranking; each later grant's symbol mask is regenerated from its own start/length and rechecked against received pilots before the decoder PDU changes. Gapped/ambiguous allocations and transform-precoded or multi-layer PUSCH remain outside this CP-OFDM rank-one oracle.
- **[ANALYTICAL]** A result is published only with at least 128 adjacent-pilot pairs and `2 × (65536 × 2 × 2 × 32) × exp(-pairs × coherence² / 4) <= 10^-6`. This is a familywise false-alarm **design target per grant under independent circular Gaussian noise**; correlated interference and wrong grants need separate calibration. Timing also requires positive coherence at least 0.35. The default-off branches leave the existing FEP/decoder path selected.

## Limits and deferred measurements

- **[CODE-READ]** The CPU reference can spend many milliseconds on an unresolved grant, especially during the 16-bit scan. It runs in the existing UL consumer; no RT-thread fallback or GPU claim is made. A full high-ID sweep needs up to 1024 same-UE eligible grants. The ±2048-sample cold timing bound and one-port rank-one pilot assumption are explicit; lack of an initial matching DM-RS prior can delay simultaneous timing/ID cold start. Reconfiguration epochs clear the 128-entry bounded per-RNTI cache; RNTI reincarnation before an epoch remains a lifecycle integration item for U4.
- **[DEFERRED]** With a UL-B grant-producing receiver and observable UL energy, replay the same raw capture with the local `pdcch_blind_monitor_dci01`, `pdcch_blind_monitor_ul_pusch` and `pdcch_blind_monitor_ul_thread` settings plus `ISAC_UL_TIMING_DISC=1 ISAC_UL_DMRS_DISC=1`; compare per-UE applied advance, residual CIR delay, ID/layout evidence, and full TB CRC. For OTA, use the orchestrator's validated X410/DPDK launcher with exactly those two flags and a single deferred UL consumer. There is no GPU device in this sandbox; the later GPU port must compare batch scores, FEP window and false-alarm behavior against this CPU reference before activation. The orchestrator can run the complete non-simulator suite under an idle-host measurement window with `flock -s -w 7200 /tmp/td_measure.lock nice -n 19 ctest --test-dir cmake_targets/ran_build/build -j4 --output-on-failure -E '^nr_td_sim_test$'`.

## What was built

Data path with a radio and several admitted cells (one process, one radio claim):

```
X410 (usrp_lib, 4 RX, capture rate R from the device's rate set) -> usrp decoupled ring (ISAC_USRP_RING_MS, existing, sized at R)
  -> iq_feed reader thread: trx_read straight into the anonymous wideband ring "nrcell" (shm_iq_ring reserve/commit: one copy, as the N=1 read)
  -> iq_chan (CPU backend, k derived threads; GPU backend = G5) -> cell rings "nrcell_<inventory id>" (anonymous, in-process registry)
  -> each cell's UE instance (cell 0 too): shm_iq consumer device on its ring (A8 RU)
```

- `radio/COMMON/iq_span.{h,c}` (new, pure): capture planner. Span = union of the cells' occupied bands (N_RB x 12 x SCS); centre = middle of the span;
  candidate rates R = r_max x 2^k (every cell rate = R / 2^j, j <= 4: halfband decimation); R must be in the device's rate set; smallest R whose flat band
  (0.8 x R, capped by the device's analog bandwidth) holds every cell wins. Cell 0 (the started cell) is always served or the plan refuses; other cells
  are added greedily in admission order. Reasons for an unserved cell: `out_of_span`, `rate_family`, `device_rate`, `channels`, `invalid`.
  `iq_span_fit()` answers "does this cell fit the running capture" (run time, no retune). The 0.8 is a property of decimating front ends (273 PRB =
  98.28 MHz is streamed at 122.88 MS/s by every radio path of this receiver), not of a host.
- `radio/COMMON/iq_feed.{h,c}` (new): reader thread over a read callback (receiver: the radio's `trx_read_func` under the shutdown gate; tests: a fake
  radio) into the wideband ring, zero copy when a whole block fits before the ring end (else staged + `shm_iq_ring_write`); timestamps follow the device
  (forward jump = gap, backward = new run); a device that repeats the previous stamp (frozen X410 stamps) is continued from the sample count
  (`IQ_FEED_TS_FROZEN` once, counted); short reads are published as they are (no restart, nothing lost); per-cell accounting from the cell ring's
  consumer table plus the channelizer's own overruns / discontinuities / lag / threads / shortfall; `MPCI_FEED` line. `iq_feed_input_mode()` is the
  pure path selector: 1 cell = direct radio path always; several cells: `shm_iq` device = A8 rings, radio = wideband, rfsim/replay = started cell only.
- `radio/COMMON/iq_chan.{h,c}`: `iq_chan_cell_pause/_resume/_paused` (no allocation; a paused entry is not computed, its ring is marked away so the
  consumer waits; resume resets that entry's history and its next write is one forward gap). Stats `n_paused`. Everything else unchanged.
- `radio/COMMON/shm_iq.c`: (a) a ring marked away before its first write (a paused-from-birth cell) is attached at once (reads wait); (b) `trx_stop_func`
  now makes a waiting read return -1 (shutdown / RX restart no longer waits for the 60 s producer-lost limit); `start` re-arms.
- `radio/USRP/usrp_lib.cpp`: `usrp_wide_plan()` right after `multi_usrp::make()`: when the receiver has a wideband plan pending (`nr_radio_wide_wanted()`,
  dlsym; never at N = 1: no query, no log) it passes the device's RX rate set (`get_rx_rates(0)`, intersected with the rates the driver's sample-rate
  table configures, so no rate is picked that would hit `exit(-1)` there), the analog bandwidth (`get_rx_bandwidth_range(0)`) and the channel count to
  `nr_radio_wide_plan()`, which writes the capture rate and centre into the config. No other driver change (see "G6 radio items").
- `executables/nr-ue-ru.{c,h}`: `nrue_ru_make_ring()` (RU 0 becomes a ring consumer; the radio's RU parameters are kept for the capture device), the
  capture device outside the RU table (`nrue_feed_config/_load/_start/_read`), stopped and ended by the shutdown coordinator after the RUs.
- `executables/nr-uesoftmodem.c` (G6 block, active only when `iq_feed_input_mode` = wideband, i.e. > 1 admitted cell and a radio): RU 0 -> ring; after
  the per-cell frame parameters: provisional plan, radio loaded on an RT thread placed like the RU start (its driver re-plans with the device's rates),
  `MPCI_SPAN` line, unserved cells logged; `plan_usrp_ring` at the capture rate; wideband ring from the host-RAM plan (half of the headroom left after the
  radio ring, `shm_iq_ring_plan_capacity` with the 1 s target / 100 ms floor; below the floor `HOST_MEM REFUSE`, exit 7), cell rings from the rest of
  that share, committed as `NR_HOST_MEM_OTHER`; served cells' entries running, unserved ones created paused (their RU attaches and waits); after the RX
  fence: memory locked, radio started, reader + channelizer threads (reader on the core plan's first pool CPU at RT-low priority, channelizer
  `iq_chan_start` on the following pool CPUs: k derived by measurement); cells' RUs then start as in A8. Run time: retire -> pause, re-admission -> resume
  when the cell still fits the capture (else `MPCI_SPAN ... unserved (no radio retune at run time)`), retune -> span verdict logged (not applied: the
  cell's UE retune is still an A8 open item); `MPCI_FEED` every 10 s and at shutdown.
- `cmake_targets/mpci_gpu.cmake` `# ---- G6 ----`: iq_span/iq_feed into `mpci_iq`, `nr-uesoftmodem` links `mpci_iq` (its ring registry is exported by
  `-rdynamic`, so the dlopen'd `shm_iq` module finds the in-process cell rings: the A8/C1 registry open item), tests.
- `tools/mpci/mpci_statics.tsv`: the 14 new statics classified PROCESS (owner G6; one capture per process); `static_audit.py --check` passes.

NO FLAGS: no env var, no option, no -D switch. Rates, centre, ring sizes, thread counts come from the cells, the device, the host-RAM plan and the core plan.

## 2. Attribution of slow decodes (> p90) 
Share of total decode time spent in bodies longer than 1/5/20 ms (new PDTIMCLS field, b, arm A, 2 runs): real 0.53/0.35/0.25 and 0.48/0.33/0.21; retry 0.32/0.12/0.04; probe 0.54/0.37/0.24. So **about one quarter of all decode time is in the ~0.3 % of decodes that exceed 20 ms**; mean 0.78-0.87 ms vs p50 0.40 ms is almost entirely tail. Without bodies > 5 ms the real mean would be ~0.5 ms.

Wall == CPU in every stage: the thread was never descheduled (no preemption, no lock/sleep, no allocation wait, no DEMOD_POOL_WAIT: 0 in all 24 runs); it was running or spin-waiting in cudaStreamSynchronize. ## 4. Fixes implemented (default-off)
* `ISAC_CSIRS_DISC_NORM_COALESCE=1` (nr_csirs_disc_gpu.cu): normalize() maps adjacent threads to adjacent RBs. Same arithmetic and same output index per thread -> bit-identical [argument, not checked by a CHECK mode].
  [M-replay] N vs A, 2 runs each: real mean 679 / 834 vs 869 / 778; p99 3305 / 9335 vs 7775 / 6515; gt20ms 10 / 19 vs 19 / 9; sum p99 2735 / 3775 vs 4315 / 5025. Within noise on the replay; the nsys effect (normalize class gone) is a single run. NOT claimed as a win; needs >= 4 runs/arm.
* `ISAC_PDSCH_GPU_CHEST_TRIM=1` (nr_pdsch_gpu_fep.cu): k_fir computes k < min(N, idx+16), zero-fills the rest. EXACT_CHEST_CHECK=1: 16000 calls, check_bad=0 (replay bNTc1, check mode makes timings invalid: mean 3.3 ms). In the same run EXACT_DEMOD_CHECK=1 reported ONE mismatch (rnti 0x7c8a, Qm 6, Nl 3, llr gpu 5 vs cpu 4) and disabled GPU demod -> unresolved whether trim, or the every-call check (other runs use check=64) exposes a pre-existing rare diff. Control run (no trim, DEMOD_CHECK=1) NOT done. Do not enable until it is.
* Counters: PDTIMCLS share_gt1/5/20ms; DEMOD_POOL_WAIT.

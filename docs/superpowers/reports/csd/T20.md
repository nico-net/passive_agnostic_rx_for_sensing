## Implementation

- `nr_pdcch_nid_stage1.h:7` isolates single-symbol scoring in `nid_best_symbol()` (host/device, explicit captured-symbol index). The Gold generator consumes words in order, and the six previous **prefix** values have constant indices. Accumulation/subtraction order, conjugated pilots, and precise division/sqrt remain unchanged; no fast math or FMA. T19's duration-combination statistic is intentionally not implemented here.
- `nr_pdcch_nid_gpu.cu:60` groups histogram atomics by equal bin within each warp. Histogram counts and median/MAD tie rules are unchanged.
- `nr_pdcch_nid_gpu.cu:107` replaces the single-thread shortlist kernel with parallel integer totals and stable `(value, lowest cell)` reductions. The host worker receives 7,168 summaries and the 16-bit hits (about **3.6 MiB**, bounded independently of window/duration). It computes the exact order-dependent FNV diagnostic and selects by descending hits, ascending cell index. The full z table stays on the GPU. CPU selection versus another device TopK implementation has **not** been benchmarked; this is the initial implementation for GB10 measurement.
- `nr_pdcch_nid_gpu.cu:155` separates prepare into parallel snapshot probes, stable active-index compaction, four independent reference/decoy builds, histogram construction, and phase-partitioned hypothesis generation. Six phases concatenate in the original order, including workspace-cap truncation.
- `nr_pdcch_nid_gpu.cu:238` uses one block per hypothesis and one lane per snapshot. The control lane sums per-snapshot scores in the original order. `NidStage2::consistency_vote()` factors out the existing per-snapshot arithmetic without changing its threshold or median rule.
- `nr_pdcch_nid_gpu.cu:261` parallelizes the winner reduction, per-snapshot reference/decoy evaluation, and evidence removal. Paired-t sums and the first 64 equivalent hypotheses retain their CPU order. Small metadata scans and the bounded tie handoff still use a control lane; no `<<<1,1>>>` launch remains.
- `nr_pdcch_nid_gpu.cu:464` enqueues the entire stage-1 sweep before one completion event. Snapshot chunks are 4/2/1 for capture durations 1/2/3. Stage-2 score tiles contain 128 hypotheses, all queued before the iteration control read. There are no `cudaStreamSynchronize` calls in `run_impl()`. Upload completion, initialization, and destruction still synchronize ownership as required.
- The worker uses a nonblocking, lowest-priority CUDA stream. Events are allocated and touched before RX, as are device workspaces. Event polling sleeps 1 ms, observes the soft budget, and drains queued work. **A complete pass is published even if contention exceeds the soft budget**; the old repeated-discard behavior cannot suppress every completed pass. This does not impose a hard shutdown/device-hang timeout.
- `nr_pdcch_nid_gpu.h:13` bumps the PDCCH plugin ABI to **2** for timing metadata. Rebuild the plugin and worker together; old plugins are rejected by the existing ABI check. `nr_csirs_disc.h` and its contract are unchanged. Default-off `ISAC_PDCCH_NID_GPU` semantics remain unchanged.
- `nr_pdcch_nid_gpu.c:94` logs `SENSING: PDCCH_NID_GPU pass k: stage1 X ms stage2 Y ms (kernels max Z ms) -> n CORESETs: ...`. Stage 1 includes the D2H/CPU selection. Kernel numbers are event intervals and include scheduling gaps/contention; nsys kernel durations are the authoritative interleaving check.

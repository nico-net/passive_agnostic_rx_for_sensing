## Task 2: the solver reading pass

### What it costs

From temporary counters, now removed, on one b OFF run [MEASURED, DGX replay, b n=1]:
- About 2980 layout hypotheses per DCI, of which about 105 are alive.
- With reopened FDRA modes, about 1240 layouts reach the parse per DCI, each taking about 110 ns. That is 137 of the 193 us loop with the counters on.
- The 256 offset keys run out on many DCIs, and the layouts past the cap mostly have keys that differ from each other.

### What was built and measured

The build was **`ISAC_DCI11_READ_MEMO`**, commit 20358510f9, reverted in 8e2eeb629f.
- For each layout, the positions of the fields its parse reads were kept.
- For each DCI, a table mapped a value key (the values read plus the options that interpret them) to the outcome of the first layout with that key: reading id, no reading, or rejected.
- **Exact by construction.** Within one DCI, equal keys give an equal accept/reject and equal compared fields.
  - Unit test `DlAdaptive.Dci11KeyDecidesExtraction`. A mutation check confirmed the test catches a missing field.
  - Mode 2 self-check: **0 mismatches** in more than 2 M layouts on b. [MEASURED, DGX replay, b n=1]
- **Gain: none.**
  - It skipped 36-41 % of parses (792 against 1238 per DCI), but the per-layout key and table cost was about 40 us per DCI.
  - x_read was not lower on b and was higher on tim (92-104 against 72-79 us). [MEASURED, DGX replay, b n=4 / tim n=3 exploratory]
  - It was removed.

### Why the cap was not removed

Grouping the layouts past the cap by the offset key would avoid their parses. But the offset key is not shown to decide the parse outcome, and the value key that does decide it barely groups those layouts. Changing which layouts back a reading is the solver-evidence change that cost TIM n_real in RNTI-CACHE. Not done.

### Existing lever re-measured

`ISAC_DCI11_PARSE_CACHE=1` is bit-exact and was measured on top of the hand-off (arm HP).
- It cuts x_read on b from 153 to 128 us (all grants) and on tim from 76 to 66 us.
- p99 is not better than H alone: b high 2952 against 2903, tim 2216 against 2242. **Not adopted.**

## Task 3: bank 1 waiting for bank 0

### Mechanism (`ISAC_PDCCH_BANK_HANDOFF=1`, default off)

On a dedicated-only slot with at least 2 banked CORESETs, the consumer posts banks 1..n-1 as **side work of the scan pool**, then runs bank 0. The pool is nr_pdcch_passive_queue.c, which already has 2 consumers pinned to their cores.
- An idle consumer of the same pool takes the side work before its next ring occasion.
- The poster joins right after bank 0, so the dwell and CORESET#0 passes still follow all banks:
  - If nobody took the work, the poster runs it itself, in the same order as without the flag.
  - Otherwise the poster waits for it.
- Concurrency is the same as the existing `ISAC_PDCCH_PAR_BANKS`: Phase 1 of different passes is independent, and Phase 2 runs under its lock. It reuses that flag's bank body (now `par_bank_run`), but has no helper thread and no extra core.
- The taker gets the poster's FEP frequency offset and a2e start stamp.
- The taker does not re-enter the bank dispatch. The poster holds that reader for the whole job; a nested enter could deadlock against a pending compaction.

Not bit-exact: with the flag, banks 0 and 1 run concurrently, so the order of their Phase-2 work can vary. The gate below checks the accept-side outcomes (n_real, crc_q) instead.

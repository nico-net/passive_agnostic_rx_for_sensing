# MPCI-LAZY — lazily started per-cell workers prepared before the fence (2026-10-29)

Branch `mpci/c-lazy` off `mpci/int-1029c` 0947bfaeb3. Labels per PROJECT_MEMORY §0.1. Host: DGX GB10 aarch64 (shared; builds and unit tests only, no replay, no radio).

## Pattern (copy of A11)
`nr_cell_parked_t` in `common/utils/nr_cell.{h,c}`: `nr_cell_parked_prepare(p, what, fn, arg, cell)` creates the worker thread through `nr_cell_thread_create` (bound to `cell`, `nr_pool_site_home_attr` so a lessee's single core is not inherited,
explicit SCHED_OTHER) and parks it on a condition variable; `nr_cell_parked_arm(p)` wakes it into the UNCHANGED worker body (0), or returns -1 when nothing is parked (failed prepare, already armed, restart after stop): the module then
runs its OLD lazy start, so a late start still works and no work is dropped. A failed prepare logs `[cK] <worker>: parked worker prepare failed: step=thread_create errno=<n> (<text>)` (stderr) and leaves the old lazy path.
The worker places itself after arming (same code as before: `sched_setaffinity`, `nr_bg_lane_enter`, pool lease), as in A11.

Follow-up commit: converted too. `nr_bgq_prepare` (nr_pdsch_gpu_demod_host.c) builds the queue and a parked worker thread (called from `nr_pdsch_passive_queue_cell_prealloc`); `nr_bgq_start` only arms it (worker sets its own affinity in `bg_main`); unprepared queues start the old way, now logging `step=pthread_create errno=`. The parked API moved to `common/utils/nr_cell_parked.c` (utils library, next to the core pool) so nr_cell.c stays pool free and no weak symbol is needed.

(superseded) NOT converted: the PDSCH `dmrsIdBg` queue (`nr_bgq_start(&g_cdmrs_q, ...)` in `cdmrs_async_on`, `nr_gpu_bgq.h`): the queue is a shared facility with its own thread creation and memory; no time left. It still starts lazily; the OTA grep below shows
whether it ever fails (`dmrsIdBg` start failure is logged by `nr_bgq_start`). Candidate for the next pass.

## Implementation and decisions

[CODE-READ] `openair1/PHY/NR_UE_TRANSPORT/nr_csirs_disc_fp.c:29` now normalizes each RE against other REs in the **same RB, symbol, and slot**, after noncoherent power summation over RX. A bounded lower-third reference tolerates dense CDM patterns; Q12 contrast clips at 2. Whole-symbol occupancy therefore cannot create contrast against an unrelated idle symbol. Sixteen-RB local screens avoid whole-carrier dilution. Legal comb components, paired-RE completion for unequal CDM port power, phase-background checks, and contiguous RB segmentation precede the unchanged legal-row mapper. Fully occupied `0xfff` masks are excluded. Coalesced complete patterns suppress contained duplicate fragments.

[CODE-READ] Extent is measured twice: energy provides a seed; after ID discovery, `nr_csirs_disc_sweep.c:291` measures row-1 sequence support across the entire captured carrier and chooses its contiguous extent. It uses the configured four-RB frequency-occupation granularity specified in [TS 38.214 §5.2.2.3.1](https://www.etsi.org/deliver/etsi_ts/138200_138299/138214/18.07.00_60/ts_138214v180700p.pdf) and [TS 38.331 CSI-FrequencyOccupation](https://www.etsi.org/deliver/etsi_ts/138300_138399/138331/18.08.00_60/ts_138331v180800p.pdf), with clipping at the capture edge. **No 52-RB width, symbol, period, offset, or PCI prior exists in this estimator.** Other rows use a neighboring-RB channel prediction to refine support. Every refined geometry is swept again over all IDs before admission. A weaker phase reuses a wider, already sequence-qualified matching geometry and must re-pass verification over that full extent; it cannot generate a cropped clone.

[CODE-READ] `nr_csirs_disc.c:116` splits multi-symbol row-1 footprints into distinct resources, permits strongly overlapping extent estimates to form legal multi-symbol row hypotheses, and preserves symbol and phase identity during winner selection. It no longer transfers a winning score/ID from a different row hypothesis. Rejected sweep-cache entries require substantial extent overlap: a rejected broad hypothesis no longer suppresses a later narrow resource merely because their bands intersect. AMBIGUOUS messages are limited to one per 20 batches; counters retain all evaluated ambiguities.

[CODE-READ] The legacy `nr_csirs_disc_detect()` remains an exact full-history decision capped at 32 outputs. The additive production `nr_csirs_disc_detect_candidates()` folds every new slot, keeps a wider candidate view, and rotates four groups of **all 13 legal periods**, including 160 and 640, across four batches. Full-ring synthetic inputs evaluate all groups. Candidate views between evaluations may be up to three batches old; the sequence sweep always uses current snapshot IQ. Per-RB sums retain 640 residues plus short-period 80/64 bases; only pooled tiles require phase-specific squares. The per-RE extent variance uses the conservative global variance. State is approximately **244.5 MiB**, versus approximately 358 MiB previously (array-size calculation, not an RSS measurement). Four CPU threads partition normalization, accumulation, and clustering.

[CODE-READ] `nr_csirs_disc_sweep.c:153` uses compact occupied-RE Gold references, cached by slot number, instead of regenerating full OAI grids for each ID and occasion. RX energies are computed once per block, not once per ID. The default public sweep still uses all occasions; the additive `max_slots` option lets production use the latest four. The CPU fallback screens expensive multiport hypotheses on one occasion and at most 24 RB before the mandatory complete sweep. This screen can defer a weak multiport resource; it is not used for row-1/row-2 TRS. GPU selection uses the same latest-occasion ordering. The CPU is authoritative, and refined winners are rechecked on it.

[CODE-READ] `nr_csirs_disc_feed.c:206` snapshots only newly committed entries into a private 640-slot ring. Per-entry locks protect copying/overwrite; **the worker calls its hook after releasing them and never holds the producer read lock during computation**. Serial stamps detect a lap during copying. Epoch reset invalidates snapshots, clears histories/caches, and cannot dispatch stale-epoch IQ. A detector overrun fails closed and the pipeline reboots from available IQ. The extra snapshot costs approximately 356 MiB at four RX/217 RB; total ring/history storage is consequently about 957 MiB, excluding scratch space. Zero lock drops do not imply zero overwrite loss when processing is too slow.

[CODE-READ] `nr_csirs_blind_rt.c:211` admits geometry, ID, period, and phase without overwriting an existing seed. Two phases require three distinct, independently scored hits **on each phase**. Adding phase two preserves already scored hits. Discovery has a 32-confirmation bank; the legacy non-discovery bank remains eight. Dynamic monitor storage accommodates both phases of discovery resources, while the manual/default-off capacity remains 16. Feature-off execution remains behind the existing gate; no receiver hook or sample transformation was added to the off path. Rebuild core and CUDA modules together because the additive sweep-config structure changed.

[CODE-READ / INFERENCE] The old CPU sweep regenerated full reference grids for every ID and every matching slot, including many dense multiport hypotheses. The old detector also repeatedly reduced the large 640-residue state. **The integrated loader did not copy the module's `normalize` callback**, so the old stateful detector actually fell back to CPU normalization even with the GPU backend selected; GPU normalization copies cannot explain that integrated run. The callback is now preserved (with the same circuit breaker) so the deferred normalization parity test can exercise it. The GPU parity fixture now obtains unified allocation through the loader hooks; `dladdr` on a guarded callback resolves to the executable, not the CUDA module. Unified allocation hooks are installed only when the module reports an available device; an installed module without a device must not break CPU ring allocation. Compact references, four-occasion production sweeps, cached RX energies, multiport screening, shared short-period sums, and scheduled clustering remove substantial work. The production detector deliberately uses CPU normalization. The orchestrator's **GPU** 3.3-second observation was not reproduced here, so this report does **not** assign a measured fraction of it to a particular GPU kernel. The added detect/hyp/sweep counters allow that attribution during G-B.

[LIMITATION] The measured CPU detector alone still exceeds the nominal 50-ms budget for 100 slots at 2000 slots/s. The worker can coalesce arrivals, but neither stable live throughput nor freedom from ring overruns is established. This is a remaining performance acceptance item, despite the functional discovery result and the removal of computation-held producer locks. The GPU timing and live throughput gates below are mandatory before claiming real-time readiness.

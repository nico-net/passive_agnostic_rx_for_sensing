## Task 2 (`918efe379b`) [CODE-READ, this commit]
- **Probes.**
  - Probes run the pass and decode only code block 0, with the whole TB's K', CRC type (CRC24B when C > 1) and E (`nr_gpu_pass_job_t.n_decode`). Their graph key is the ncb class of n_decode, i.e. 1. `nr_gpu_pass_warmup` already warms that class for every PRB class, so no keys and no GPU memory were added.
  - The body's symbol horizon reaches the demod job (`probe_last_sym`). `k_unscr` zeroes `llr[G_dem, G)` (`PassBlk.Gd`, which equals G for every non-probe), so `k_llr_stats` runs over the whole G exactly as over the body's cleared buffer.
  - A probe is never a decoded TB: tb_ok = 0, and the LLRs go to llr_out.
  - `gp_commit_decode` commits the body's probe outcome: `t_probe_seg_ok` from `seg_ok[0]`, the all-zero guard on block 0's bytes, and the segidx counters over C_dec.
  - Still gated: equivalence reruns (`t_probe_no_horizon`, `t_chest_bypass`) and probes without `ISAC_PDSCH_PROBE_C1` / solver.
- **Slot-share grants.**
  - Share grants run the pass. The pass estimates the share's widened band (`share_chest_band`, factored out of the body), and the demod reads the grant's REs.
  - A segmented grant is not widened by the share (it estimates per segment), so it is covered as is.
  - The FEP and chest caches are not read. Their contents are the same numbers.
- **Low-priority stream.** Probes launch on a low-priority twin of the instance stream when `ISAC_PDSCH_GPU_PRIO=1` (v2 only; t26gE does not set it).
- **Bug found on replay and fixed before the commit.** A one-code-block probe whose CRC passed left `llr_out` stale. The module had computed tb_ok = 1 (no LLR copy), and the host only cleared tb_ok afterwards. The CRC-fail shadow caught it: `GPUPASS MISMATCH ... probe 1 horizon -1`, in 2 of 3 smoke runs. The module now treats a probe as a CRC failure for the LLR copy. The unit test runs with `llr_out_all = 0` and pins this. The MISMATCH line now carries probe / horizon / share / G.

## Deviations
1. ON carries T1's extra flags (`ISAC_GPU_PASS_RETRY_OLD=1 ISAC_GPU_PASS_POLL_SLEEP_US=600`), as T1 did, so the tail split stays comparable.
2. Slot-share coverage reproduces the widened band instead of ignoring it. The plan's "the pass computes its own FEP / chest" would not be bit-exact: the share estimates over the group's union, and nvar and the edge filter change. The CRC-fail shadow would then flag the difference and disable the pass.
3. Probe keys reuse the existing ncb-class-1 graphs, which `nr_gpu_pass_warmup` already warms for every PRB class. Nothing new is warmed.
4. Equivalence-rerun probes and probes without PROBE_C1 / solver stay gated (diagnostics, and a path that is not in t26gE).
5. `gpugraph_ab.sh` gained `N=` and `CAPS=` (defaults unchanged) for the n=6 b batches.
6. No cmake reconfigure was needed: no new source file and no new ctest target.

# RANK2-BIG (2026-10-23): why large 2-layer PDSCH grants fail CRC

Analysis only, from existing OTA logs (`/home/nicola/NICOLA/ota_runs/ab_*`); no receiver run, no build, no radio, no gNB logs.
Host DGX GB10 aarch64. Branch `csd/rank2-diag` from `adaptive-rx-UL-DL` (e9c874c308). Script: `tests/passive_rx/rank2_diag.py` (`--selftest` runs the unittest; reuses `goal_metrics.py` tables and the DD-bias inversion).
Labels: [MEASURED, DGX OTA <run>] (all night = LOW LOAD, n=1 per run), [CODE-READ], [INFERRED]. Numbers are per run and never pooled across runs or cells.

Definitions used everywhere (so the numbers can be reproduced with `python3 rank2_diag.py RUN_DIR...`):
- real grant = EVMGRANT with `probe=0`, `rnti != 0xffff`, RNTI with >= 3 CRC-ok grants in that run ("confirmed"; it removes < 0.1 % of lines), RECOVLATE rescues credited as CRC-ok. `skip=1` lines (no-chance gate, see C1) are kept and count as failures.
- "rank-2 big" = `Nl=2`, `rb` (the number after `+`) >= 100; the >= 200 subset is reported where it differs.
- margin = true weak-layer SNR minus required SNR. True SNR = `snr_l` of the weakest layer inverted through the decision-directed (DD) noise-floor table of `goal_metrics.true_snr_db` (QPSK floor 3.9 dB, 16QAM 9.1, 64QAM 12.5); required = Shannon at the MCS spectral efficiency + 1.5 dB (`goal_metrics.required_snr_db`). `floor/unknown` = a layer within 1 dB of the DD floor, so the SNR cannot be estimated.
- Caveat [INFERRED]: the inversion is AWGN + ideal ZF; with correlated layers and channel-estimation error the true SNR is probably lower than inverted, +-1.5 dB near the floor. All margin statements inherit this.

## 0. Answer

1. Most big rank-2 failures are not receiver bugs: the gNB picks an MCS for the UE's channel, and at the passive position the weakest layer is below the SNR that MCS needs. The headline "median snr 15-16 dB, MCS 12-13 should decode" is misleading: the printed `snr` is the DD EVM SNR, and for 64QAM a DD value of 14-16 dB is a true SNR of about 3-8 dB.
2. Between 12 % and 38 % of the failures sit in a band where the receiver has real implementation loss to recover (LDPC cap of 8 iterations, weak-layer handling).
3. The aVM -> aVF jump (rank-2 big 31 % -> 75 %) is mostly a different UE population (different MCS), not proof that the pool/grant-sizing build fixed it. At equal margin the two builds decode alike, except for grants with `nsym <= 12`.
4. HARQ, deadline and drop are not material (each < 3 % of failures).

## 2. Ranked causes (share = share of that run's rank-2 big failures; ranges are across the runs of one row of the table, not pooled)

### C1. SNR below what the gNB's MCS needs at the passive position: 49-84 % (Vodafone), 77-92 % (TIM) [MEASURED]
- CRC vs margin is a clean waterfall: aVM1 0-1 % below -4 dB, 17 % at -4..0, 45 % at +0..+2, 79 % at +2..+4, 82-88 % above (hVM, aVF1 and aVF2 have the same shape; sections "Q1" of `rank2_diag.py` output). Failure classes in the table.
- By MCS, aVM1 rank-2 CRC falls from 75-86 % at MCS 5-8 to 12 % at MCS 13 and 0 % at MCS 17+ (`tbl=1`, 64QAM from MCS 11). hVM: MCS 13-16 are 0 % over 2953 grants. These are the same UE bursts at a weak-layer true SNR 5-10 dB below the requirement.
- Raw DD weak-layer `snr_l` for 64QAM rank-2: 14-16 dB gives 9 % / 3 % / 0 % / 5 % / 7 % CRC (aVM1 / aVM2 / hVM / aVF1 / aVF2); 18-20 dB gives 60-98 %. Rank-1 64QAM needs a similar DD value (14-16 dB: 32 / 19 / 81 / 41 / 17 %), i.e. no sign of a rank-2-only defect at the 64QAM level (n of rank-1 is small, 22-300).
- Population, not receiver, drives the level: per-RNTI CRC in one run spans 0 % to 90 % with the MCS the gNB gave that UE (aVM2: RNTI 0x6184, 4572 grants, MCS p50 18, 1.4 % ok; RNTI 0x9954, 2142 grants, MCS p50 12, 74.7 % ok; aVF1: RNTI 0x9d54, 6188 grants, MCS p50 9, 83 % ok). Weak-layer DD SNR is about the same in all runs (p50 13.7-15.6 dB).
- No-chance gate (3-16 % of failures, TIM up to 28 %): the receiver itself skips grants whose DM-RS SNR is more than 5 dB under the requirement (`skip=1`, CRC counted as fail). Same SNR class; see C1 fix note on the gate.
- TIM vs Vodafone (Q6): TIM failures are mostly at or under the DD floor (floor/unknown 23-56 %, plus 9-28 % gated) while Vodafone's are mostly clearly negative margin. TIM grants scheduled at MCS 12-24 with weak-layer DD SNR 13-21 dB (hTM top RNTIs: MCS p50 16/16/24/18, 0 % ok). Structure is the same as Vodafone (nsym 13-14 for big grants, PRB start 0, `tbl=1`, ports 0x3), so SNR is the primary difference. CRC at margin >= +2 is 81-90 % on every TIM run with n >= 145 (same range as Vodafone; n is small).
- hTM 1.2 % (rb>=200) vs hTN3 36 %: the margin distribution differs (hTM: 59 % of failures at margin < -2, only 18 grants at >= +2; hTN3: 218 grants at >= +2 with 89.9 % CRC). Population/UE difference between two different times; the data cannot show a code effect old main -> current main.

### C2. Edge-of-waterfall implementation loss: 12-30 % (Vodafone), 5-15 % (TIM) [MEASURED + INFERRED]
- Failures with margin between -2 and +2 dB. Part is estimator error (+-1.5 dB), part is real loss.
- Rank-2 needs about +0.8 to +2.5 dB of min-layer margin for CRC 50 % (Qm4: 0.8 / 1.4 / 1.9 / 1.5 / 1.9 for aVM1 / aVM2 / hVM / aVF1 / aVF2; Qm6: 1.8 / 1.3 / 2.5 / 1.3 / -0.1). Rank-1 CRC50 estimates are noisy (-4.7 to +5.2, small n) so a rank-2 vs rank-1 penalty is not separable with this data.
- LDPC iteration cap is 8 (OAI int8 flooding min-sum) on CPU and GPU [CODE-READ nr_pdsch_passive_decode.c:1715, :2198, :3386, :4710, :4778]; `it=` in EVMGRANT is hard-wired to -1 [CODE-READ nr_pdsch_passive_queue.c:1693], so failures hitting the cap cannot be seen in logs. Prior replay [MEASURED, DGX replay, PROJECT_MEMORY section 34]: 16 iterations gave +5 to +25 points at MCS 5-16 for CRC; that is the CRC-for-time trade the rules forbid keeping at 8 for latency's sake.

### C3. Weak-layer (second layer) loss at large layer imbalance: 27-38 % of Vodafone failures, 7-29 % of TIM failures are "decodable by a capacity-averaging model" [MEASURED, mechanism INFERRED]
- Overlay on C1/C2 (not a disjoint class): failures whose capacity-averaged margin is >= 0 although the min-layer margin is < +2: aVM1 31 %, aVM2 28 %, hVM 27 %, aVF1 38 %, aVF2 27 %; aTM1 11 %, aTM2 12 %, hTM 13 %, aTF1 29 %, aTF2 7 %, hTN3 25 %.
- At the same capacity-averaged margin the CRC collapses when the layers are unbalanced: Qm4, capacity-avg margin [2,4): gap < 2 dB 85 / 69 / 44 / 79 % vs gap >= 8 dB 0 / 6 / 4 / 0 % (hVM / aVM1 / aVF1 / aVF2; n 80-223 for gap>=8 except aVF2 25); margin [4,6): 97 / 98 / 81 / 95 % vs 42 / 56 / 35 / 23 %.
- The weak layer is always layer index 1 (second layer, port 1001): of grants with |gap| >= 8 dB, layer 1 is the weak one in 396/396 (aVM1), 1049/1049 (aVM2), 201/201 (hVM), 2577/2577 (aVF1), 1100/1100 (aVF2); TIM 175/183 (aTM1). Looks like an eigen-ordered gNB precoder (physical) [INFERRED]; if it were a DM-RS/OCC port-1001 estimation artifact the same asymmetry would appear in balanced grants, where it does not (layer 0 weaker in 63-78 % of balanced grants in 3 of 4 runs).
- CODE-READ candidates for a real receiver loss on the weak layer: `log2_maxh` is sized from the MEAN |h| and then lowered by 3 for `nl == 2` [nr_dlsch_demodulation.c:1536-1546], G and H^H y are rounded to int16 after `>> shift` [:869 nr_conjch0_mult_ch1, :882 noise_var>>3] and the mode-2 per-layer weights `w = 1/[A^-1]_ll` are rounded to int16 [:898-973]; a layer 8+ dB down has `w` of a few LSB (LLRZERO report: 17-42 % exact-zero LLRs, only -3 bits applied; l2 stays 7-8 in all gap>=8 grants, so the delta is applied but headroom was not re-sized per layer). GPU twin: `mag_per_layer` in nr_gpu_pass_graph.cu:541-542 and nr_pdsch_gpu_demod.cu:1373, :1415. Min-sum 8-bit LLR scaling (`llr_norm shift0..4` in the HARQC line) is a second place a small weak-layer LLR is flattened.
- Note: the DD `snr_l` uses a separate ZF re-equalisation, not the LLR equaliser [CODE-READ nr_dlsch_demodulation.c:1842-1843, nr_pdsch_passive_decode.c:452], so a weak-layer LLR defect is invisible in `snr_l`.

### C4. Residual failures at margin >= +2: 2-11 % (old main), 21-24 % (floatpool Vodafone), 2-8 % (TIM) [MEASURED]
- Of those residual failures, `nsym <= 12` grants are 62 % (aVM1), 48 % (aVM2), 60 % (hVM), 22 % (aVF1), 52 % (aVF2). Their failure rate at margin >= +2: 33 / 65 / 31 / 7 / 24 % versus about 5-12 % for `nsym` 13-14. Slots 0, 1, 15, 16 are the bad ones in aVM1 (64-72 % ok vs 84-96 % elsewhere).
- The floatpool arms have the lower `nsym <= 12` failure rate (7 % and 24 % vs 31-65 %); this is the only grant class where the builds differ at equal margin [MEASURED], mechanism unknown (the async recovery/TDRA S-L retry is the existing explanation, DLCRC-V-UNEXPLAINED-20261016; ISAC_PDSCH_TDRA_RETRY=1 and ISAC_PDSCH_RECOVERY_ASYNC=1 are in both env files [CODE-READ FROZEN_20261018.env, POOL_20261021.env]).
- `cdm=2` grants fail more at margin >= +2 in aVM1 (66 % vs 90 % ok) but this is the QPSK/`nsym` mix (QPSK 64 % at margin >= +2 vs 92 % for 16/64QAM; QPSK margin is the least reliable, DD floor).
- Ports 0xc (second CDM group, ports 1002/1003): 268 grants in aVM1 (rb>=100), 1 % ok, most with floor/unknown or negative margin; aTM1 316 grants, 15-24 % ok; at margin >= +4 they decode 38-94 % (aVM1/aTM1/aTF1 any-rb tables). SNR-limited, but note `try_cdm` (CDM-group retry arm) is gated to ports 0x3 only [CODE-READ nr_pdsch_passive_decode.c:4295-4296], so a wrong `cdm` count on ports 0xc has no retry. Share of failures: 1-3 %.
- Multi-user overlap (another RNTI with overlapping PRBs in the same slot, within 60 log lines): 1.2-2.0 % of rank-2 big grants (aVF1, aVM1), 8.2 % (hVM), 17.6 % (aTM1). At margin >= +2 the CRC with overlap is 57 / 81 / 94 / 92 % vs 82 / 86 / 93 / 81 % without it: no consistent penalty, not a main cause (order aVM1 / hVM / aVF1 / aTM1).

### C5. HARQ: < 3 % of failures [MEASURED]
- `rv` is 0 on 99.6-100 % of rank-2 big grants. Same-process same-NDI same-TBS retransmission candidates after a failure: aVM1 272 of 9150 failures, aVM2 126 of 8478, hVM 120 of 5730, aVF1 54 of 2755, aVF2 60 of 2674 (TIM aTM1 80 of 3476). Of those 2-38 are CRC-ok, i.e. mostly the UE did not NACK these (the UE decodes them, which is consistent with the position-SNR explanation in C1).
- HARQC counters: `retx_combined` 0/0 (hVM), 28/395 (aVM1), 1/42 (aVF1) [MEASURED]. The store combines rv-0 retransmissions only after 64 evidence events (`NR_HARQC_RV0_EVIDENCE`, nr_pdsch_passive_decode.c:1365, :1886) and refuses a TBS mismatch (nr_hq_retry.h `nr_hq_retx_rule`). Many "same NDI, other TBS" pairs (3593 in aVM1 rank-2 big) indicate missed intermediate DCIs on the same pid, not retransmissions.

### C6. Deadline / drop / stale / decoder time: <= 1 % [MEASURED]
- PDSCHQ at run end: aVM1 stale 441 of 84700 queued, full 0; aVF1 stale 84 of 55849; hVM 2; aTM1 706 of 357859. `lag` p99 31-35 slots, `tot` p99 7.6-17.9 ms, but CRC at margin >= +2 is flat over `tot` bins (aVM1: 87 / 82 / 80 / 81 % for 1-2 / 2-3 / 3-5 / >=5 ms; aVF1 95 / 94 / 92 / 92 / 91 % for 1-1.5 / 1.5-2 / 2-3 / 3-5 / >=5 ms). Failures have higher `dec_us` (aVM1 p50 3210 vs 2039 us) because they are the large, low-margin TBs, and decode is run to completion regardless. Brief question 2: late/dropped/stale grants were not a driver, so the core pool + grant sizing could not have fixed big-grant CRC through that route.
- The skip gate of C1 is the only mechanism in the receiver that gives up on a decode (see C1).

### Not supported by the data
- "Failures are retransmissions whose first transmission was missed" (C5, < 3 %).
- Specific DM-RS config (ports 0x3 vs other, 2 CDM groups, extra DM-RS): at equal margin ports 0x3 / cdm=1 / cdm=2 decode alike (aVF1 margin >= +2: 93 / 93 %), see C4 for ports 0xc.
- Rank-2 vs rank-1 receiver penalty at the same MCS and SNR: the CRC-vs-margin curves overlap within noise for margin >= +4 (rank-1 >= +6: 94-98 %; rank-2 >= +6: 82-98 %).
- Partial code-block failure vs whole-TB failure (Q5): not observable. `ldpc_seg_fail`/`ldpc_tb_fail` in ISAC_METRICS are run-global (all grants), `ldpc_tb_fail` is always 0, and EVMGRANT has only `cb=` (code-block count). CRC falls with `cb` (hVM: 68 % at 4-5 CB, 0 % above 30 CB) only because `cb` grows with MCS and PRB count.

## 4. Experiments that would confirm each cause

- C1 (SNR-limited): offline replay of the stored captures (`raw_pci415_12s_b`, `raw_pci923_tim_12s_tile3`) with noise injection into a high-margin rank-2 segment to get the true CRC-vs-SNR curve per MCS (fixes the DD-inversion uncertainty and gives the exact rank-2 implementation loss); or a float-ZF/ML genie receiver on the same failing grants. If those fail too, C1 is confirmed; if the genie decodes, the loss is in the fixed-point/GPU chain (C2/C3).
- C2: replay A/B on rank-2 big grants only, `ISAC_LDPC_ITERS` 8 vs 12 vs 16 vs 24, metric CRC for margin -2..+4 and `it` histogram (needs `it=` logged). Expected from C2: gain concentrated in the edge band.
- C3: replay A/B of (a) `ISAC_L2MAXH_DELTA_NL2` -3 vs -5/-6, (b) float lane for G and `w`, (c) `ISAC_RX_ML_2L`; stratify by |gap| >= 8 dB. Diagnostic: `ISAC_MMSE2_DIAG=1` with CPU demod on the gap >= 8 grants to read weak-layer zero-LLR share and `w` in LSB. Pass criterion: CRC at gap >= 8 and capacity-avg margin [2,4) rises from 1-13 % toward the 65-88 % of gap < 2.
- C4: OTA or replay A/B `ISAC_PDSCH_SIGNAL_GEOM_RETRY=1`, or pre-first-pass S/L learning; report CRC of `nsym <= 12` at margin >= +2 per slot. For the build comparison (population confound): interleave old main and floatpool back-to-back on the same cell A/B/A/B and compare CRC at margin >= +2 and the `nsym <= 12` failure rate, not the raw CRC.
- C5: no experiment needed; log `retx_cand` per run (script prints it) and confirm < 3 %.
- C6: already confirmed flat in `tot`; a deadline/queue A/B is not worth running.

## 5. Log gaps found

- `it=-1`, `eq=-1`, `occ=-1` in EVMGRANT (queue.c:1693): no iteration count, no per-decoder tag.
- EVMGRANT logs only the first pass; rescued grants are credited only via RECOVLATE (no time). `dmrs_snr=a,b,c,d,comb` is per RX branch, not per layer; `zabs=0` on the GPU pass; `ldpc_tb_fail` always 0.
- `frame.slot` repeats every 10.24 s, so (rnti, frame.slot) is not a unique key over a 15 min run (goal_metrics.py and RECOVLATE joining share this).

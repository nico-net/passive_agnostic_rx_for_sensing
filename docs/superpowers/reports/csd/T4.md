# T4 — U4 CSI-RS scramblingID / slot-offset sweep

Host: DGX aarch64, worktree `rr-csd-c`, branch `csd/t4`. No radio, replay, or GPU timing was run.

## Implementation

- `openair1/PHY/NR_UE_TRANSPORT/nr_csirs_disc_sweep.c:147`: gated CPU entry calls
  `nr_generate_csi_rs()` for each ID/delta/lattice slot, with `(meta.slot + delta) % slots_per_frame`.
  The reference is CRB-aligned, restricted to the hypothesis extent, generated separately for every port.
  Occupied REs follow dense symbol/subcarrier order; coherent block magnitude/energy normalization matches
  `nr_csirs_blind_correlate_blocks_shift`, including partial final blocks. Port and antenna scores are
  averaged non-coherently, then averaged over valid lattice slots. Invalid entries and off-lattice slots
  never contribute. Zero-energy input returns zero.
- `nr_csirs_disc_sweep.c:27,54,98`: input validation, OAI-derived compact RE descriptors, deterministic
  ascending-ID/delta tie handling, and runner-up selection after maximizing deltas **within each ID**.
  The CUDA module calls these host services through the executable's exported symbols.
- `nr_csirs_disc_gpu_sweep.cu:40,198`: device word-wise Gold recurrence, CSI-RS initializer
  `(2^10 * (14*slot+l+1) * (2*id+1) + id) mod 2^31`, per-port CDM signs and absolute-RB sequence indices.
  One CUDA block per hypothesis/ID/delta/lattice-slot; warp lanes score independent coherent blocks.
  References use unit QPSK, equivalent to OAI's exact +/-8192 samples at amplitude 16384.
  Explicit host/device copies work with ordinary or managed input rings; workspace allocations are reused
  across hypotheses in a batch. CUDA errors return -1 for fallback.
- `openair1/PHY/CODING/CMakeLists.txt:126`: separate `nr_csirs_disc_gpu_sweep` MODULE under
  `ENABLE_LDPC_CUDA`, exporting `nr_csirs_disc_gpu_sweep_entry` with the `.sweep` signature.
  Does not define or replace T2's ops table or footprint module. The self-contained block links cudart,
  builds the comparison test, and retains the CPU host services in `nr-uesoftmodem` for dlopen resolution.
- `CMakeLists.txt:993,2820`: includes the CPU reference in `PHY_NR_UE` and registers the standalone test.
- `nr_csirs_disc.h`: additive only: `<stddef.h>` for its existing `size_t`, exported U4 module entry,
  and API return/default/normalization documentation. No existing field or semantic changed.
- `tests/nr_csirs_disc_sweep_test.cc`, `tests/nr_csirs_disc_sweep_fixture.c`: independent small synthetic
  builder using the real OAI generator, four independently phased RX branches and per-port channel phases,
  10 dB AWGN, deterministic random ID/extent, no dependency on T2's generator. C bridge avoids OAI C VLA
  declarations in C++/CUDA headers.

The CPU handles an existing OAI generator edge case locally: for density 0 (even half-density) and an
odd exclusive RB end, its modulation-length calculation truncates the last even RB. Passing one more
RB to the generator computes that Gold symbol; the extra odd RB is unoccupied, so the mapped/scored
extent is unchanged, including at RB 274. The common PHY generator and frozen snapshot remain untouched.

## Performance estimate and limits

[ESTIMATED, NOT MEASURED, GB10] For the requested 64 x 1024 x 1 x 8 x 651 x 4 workload, there are
1.365 billion received/reference pairs, roughly 16.4 GFLOP for correlation and energy, plus Gold generation
and block normalization. Assuming sustained 0.5–1 TFLOP/s for this kernel gives 16–33 ms of arithmetic;
allowing 5–15 ms for packing, allocations, launches, copies and reductions yields roughly **21–48 ms**.
The under-50-ms target is plausible but **not validated**. This estimate assumes cache reuse of each
hypothesis's compact input and excludes first CUDA context initialization. Workspace grows only when
needed within a batch; CUDA allocation/context overhead and low utilization while generating Gold words are risks to the estimate. Multi-port rows
add per-port work and are not represented by the single-port 651-RE budget fixture.

The CPU is a reference/fallback, not a real-time exhaustive search at 64 hypotheses. The caller must hold
ring contents stable during the sweep and initialize OAI modulation tables (normal PHY startup does so).
A null cfg selects `{0,1024,1,32}`; invalid explicit cfg returns -1. Both public entries are inert unless
`ISAC_CSIRS_DISC=1`. The returned runner-up is zero for a single-ID range. No U1/T2/T5 runtime integration
or OTA detection is claimed in this task. The orchestrator must connect this entry to the merged `.sweep`
ops and retain the host services when fusing the CUDA modules.

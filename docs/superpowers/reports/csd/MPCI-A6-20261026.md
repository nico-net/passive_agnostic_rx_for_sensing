## 2. Decision: optional-work CPU share (nr_pusch_passive_queue.c `g_opt_win_*`, `opt_share_ns_per_s`) = PER_CELL window, process-constant total

`[CODE-READ]` The window (`g_opt_win_start_ns`, `g_opt_win_used_ns`) caps the optional UL work (UCI explore, rescue, provisional trial bookings: `nr_pusch_passive_optional_share_left/charge`) at
`1 s / online cpus` of CPU per wall second (a full second when `ISAC_PUSCH_CORES` dedicates cores).
The core pool (`common/utils/nr_core_pool.h`) serves cells with EQUAL weights (decayed token-time usage per cell, work conserving, strict class priority inside).
- A PROCESS window would be one bucket for all cells: a busy cell would exhaust it and starve another cell's optional work while the pool still grants both cells equal tokens, and a cell's N = 1 result would depend on its neighbours. That contradicts the per-cell fair share.
- PER_CELL window with the SAME per-cell budget would multiply the optional load by N.
- Chosen: PER_CELL window; the per-cell share is `(1 s / online cpus) / nr_cell_count()` when no dedicated list is set (the process total stays the single-cell value, each cell has the pool's equal share); with `ISAC_PUSCH_CORES` (existing variable, unchanged meaning) the share stays a full second per cell.
  `share` itself (a host constant) is PROCESS; the division is applied at the use. N = 1: `nr_cell_count() == 1`, nothing divides, same value as before. `[HYPOTHESIS]` if the pool later gets weighted cells, the divisor becomes the cell's weight fraction (B1 owns that).

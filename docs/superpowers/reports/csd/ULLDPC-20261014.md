## 2. Part 1: UL LDPC on the GPU (`ISAC_UL_GPU_LDPC=1`)

- `nr_pdsch_gpu_ldpc.cu`: the DL kernels (bit-exact port of OAI's min-sum, CRC stop rule on snapshots) behind a **UL pool of its own**
  (`nr_pusch_gpu_ldpc_init/run/stats`): 2 contexts so the 8 DL LDPC contexts are never taken or waited on; pinned buffers allocated and
  **written at warm-up** (no GPU first touch), device pointers cached; low-priority stream; duty cap `ISAC_UL_GPU_LDPC_PCT` (default 15 %
  of each 100 ms); a start-up self-test decode proves the stream can run the cluster launch (else it falls back to a plain lowest-priority
  stream); a **hard deadline** `ISAC_UL_GPU_LDPC_DEADLINE_US` (default 4000): the kernel writes only the context's own pinned buffers, so a
  late call is abandoned (context stays reserved until its stream drains, `reclaimed` counter) and the CPU decoder runs: a GPU stall costs the
  UL at most the deadline.
- `nr_pdsch_gpu_ldpc_host.c`: the DL host code (rate dematching on the CPU, one launch per TB with all its code blocks, first snapshot with
  passing CRC, syndrome-0 fallback) made instance based (DL and UL have their own counters, own CHECK and disable state); the passive PUSCH
  receiver installs the wrapper on its **private copy** of the coding interface (`nr_pusch_passive_decode.c`), so the DL decoder is untouched.
  CPU fallback, all counted: HARQ-combined buffer (`d` not cleared), `K % 8 != 0` (Z not a multiple of 4; the kernel packs bytes), busy,
  over cap, RT in flight, deadline, error. `ISAC_UL_GPU_LDPC_MIN_BITS=N` keeps TBs below N bits on the CPU (default 0).
  `ISAC_UL_GPU_LDPC_CHECK=n` (default 64): every n-th TB is also decoded on the CPU and compared bytewise + per-CB success; a mismatch
  switches the UL GPU decoder off.
- **Equivalence** `[OFFLINE VERIFIED, DGX unit test]`: `test_nr_pusch_gpu_ldpc` (the DL test run through the UL pool, `./test_nr_pdsch_gpu_ldpc 2 ul`):
  1635 snapshots and 264 stop-rule cases, 0 mismatches. `[MEASURED, DGX replay b + tim]`: CHECK=1 (every TB, real captured LLRs) 1418 TBs, 0 bad;
  CHECK=64 over the 12 L-arm runs 1715 compared TBs, 0 bad; 0 `UL_GPU_LDPC MISMATCH` lines in any log.
- **Speed** `[MEASURED]`: GPU call mean 0.2 ms (max 1.5 ms) per TB in replay (CHECK=1 run); unit bench on an idle GPU, BG1 Z384: 1 CB
  141 us GPU vs 134 us CPU (big core), 4 CBs 143 us vs 450 us. So the GPU LDPC removes CPU work from the little cores 0,1 and wins on multi-CB TBs;
  it gives **no latency win** for the typical 1-CB UL grant. Shape refusals (K % 8 != 0) were 0.7-13.5 % of the TBs per Lr run; 5740 TBs in the busiest tim run, none lost to cap, busy or deadline.
- **UCI reservation search bound** (`ISAC_UL_UCI_BUDGET=N` trials, `ISAC_UL_UCI_BUDGET_US=T`, default 0 = old behaviour; counters
  `uci[... cut= skip_restore=]`): LDPC trials per 12 s run `[MEASURED]` b R/F 13.3-23.2 k -> L arms 160-240; tim R/F 9.3-26.4 k -> L arms 8-960
  (tim Ld runs 1 and 3 had only ~40 grants). A call that ran no trial skips the restoring re-decode. Rescues stay 0-1 per run in every arm
  (so the search found nothing to lose in replay); learned footprints are tried first, then the smallest swept ones.
  The effect on p99 is **not separable** from the GPU LDPC in these runs (Ld and Lr carry both flags).

## 3. Part 2: the UL stalls

Instrumentation (`ISAC_UL_STALL_DIAG=1`, `nr_pusch_gpu_diag.h`): per UL GPU call (FEP and LDPC) the host launch time, the in-stream
`cudaEvent` time (stream reaches the call -> end), the remainder (wake lateness) and the calling thread's CPU time / involuntary switches
(`RUSAGE_THREAD`); one `ULSTALL` line per call > 2 ms. Plus `UTIM ... fep_gpu_call_tot`.

**Finding** `[MEASURED, DGX replay tim, first run, n=25 FEP stalls]`: of a stalled FEP call (median 88 ms, max 903 ms) the in-stream GPU time is
98-100 % (median 88.3 ms), launch 25 us, wake 46 us, thread CPU 3.5 ms, involuntary switches in 5 of 25 calls. **It is not consumer
preemption, not the poll sleep, not a page migration. The kernel waits in the GPU.** Attribution run `[MEASURED, DGX replay tim, n=1 each]`
with `ISAC_CSIRS_DISC=0`: FEP calls 8387, late (> 2 ms) 1, max 9.4 ms, ULSTALL 3 lines with gpu_us 60-139 (wake 4.9 ms = host); LDPC deadline
0, max 0.55 ms. With discovery on, the same arm has 14-73 late calls and a 57-455 ms max. The UL FEP/LDPC streams sit in the **discovery SM
partition** (`ISAC_GPU_DISC_SMS=8`), together with CSI-RS discovery's multi-ms to 400 ms kernels; stream priority orders only pending blocks
(`ISAC_UL_GPU_PRIO=1`, greatest priority inside the partition, was tried: arm Ld still stalls).

**Fix** `ISAC_UL_GPU_PART=rt` (default `disc` = old): the UL streams are created in the **real-time partition at the least stream priority**
(DL streams outrank them; a running UL block is never preempted, the blocks are short). A dedicated UL partition split from the RT SMs
(`ISAC_GPU_UL_SMS`) was tried and **dropped**: the driver refuses the second split (rc 915).

## 4. Merging csd/fattails and the single UL core plan

Merged csd/fattails (84d5d6622d; one conflict in `p99_replay.sh`, took fattails' own-receiver check) and csd/ulbwp. Needed: yes, see DL above.
The two plans conflict only on UL priority: FATTAILS put the PUSCH consumer on core 0 at SCHED_OTHER; ULQ ran 2 consumers FIFO 30 on cores 0,1 and a
snapshot thread at FIFO 31 on core 0. A FIFO UL thread on any core starves that core's `kworker`, and a page migration (`lru_add_drain_all`) waits for
the kworker of **every** core, so a busy RT UL thread on cores 0/1 stalls the DL too (FATTAILS: kworker/0 waited 950 ms with FIFO PUSCH on core 0).

**Final plan** (env: `ISAC_PUSCH_CONSUMERS=2 ISAC_PUSCH_CORES=0,1 ISAC_PUSCH_PRIO=0 ISAC_UL_SNAP_CORE=0 ISAC_UL_SNAP_PRIO=0`; confirmed in the logs:
`passivePusch0/1` affinity 0/1 priority 0, `passivePuschCap` affinity 0 priority 0). Without `ISAC_UL_SNAP_PRIO=0` the snapshot thread would be FIFO 1 (PUSCH prio + 1).

## 5. Part 3: the UL BWP lock

`ISAC_UL_LOCK_SIGN=1` (needs `ISAC_UL_LAYOUT_LOCK=1`; `=2` is shadow mode: the table is kept and logged, the old/LLR rule still decides and one `SIGN_SHADOW would lock`
line is logged). `nr_pdcch_ul_layout_lock.c`:

- A probe (one grant scored under every hypothesis, up to 192) is a **detection for every hypothesis with DM-RS MRC SNR >= 6 dB**, not only the argmax. Probes with a
  control hit (wrong-slot DM-RS >= 6 dB) or more than 6 detecting hypotheses (wide-band energy) are skipped. For each pair the counters `only[a][b]` (a detects, b - which
  has PRBs for this grant - does not) are kept.
- Rule: hypothesis a leads when, against **every rival that was ever detected**, `P(X >= A | n = A + B, 1/2) <= 0.02` with `A = a-only + prior(a)`, `B = b-only + prior(b)`,
  `A >= 6` (`>= 5` for the DL BWP / SIB1 UL BWP, which counts one discordant probe) and >= 2 RNTIs. A rival that is never discordant but equally often detected (a
  twin) blocks the lock; the prior cannot break it. A vote floor of 6 for non-prior leaders is built in.
- Why it addresses the look-alike: 216@1 for a true 217@0 grant reads exactly the next L PRBs (the same RIV bits decoded with N-1 give start s+L). A neighbouring UE's
  same-PCI DM-RS can win the argmax there, but `b-only` needs the true UE's own DM-RS to be absent while `a-only` grows with every grant the true UE sends. The test is
  therefore only as strong as `P(true UE detected) > P(neighbour present and detected)`: in a fully packed slot the discordant split approaches 50/50 and the rule
  correctly refuses to lock.
- Tests `[OFFLINE VERIFIED, DGX unit]`: `UlLayoutLock.SignRuleOnSyntheticTallies` (truth vs look-alike, look-alike leading in raw detections, coin flip, 6:0 / 5:0 / prior
  thresholds, single RNTI, never-discordant twin with/without prior, 60:3 contamination) and `SignRuleLocksTheTruthNextToAnAdjacentLookAlike` (end to end through
  `on_dci` / `probe_plan` / `probe_feed` with a shifted-neighbour world: locks 216@1, the generator's truth; the old rule locks it too in this world, so the test does **not** show the
  old rule failing - that is the OTA observation of ULBWP-20261014, not reproduced here).
- Shadow table in the replay logs `[MEASURED, DGX replay]`: no run reached a sign lock. tim (without `FIT_READ`/`PREFIX_ENT`, so the width-13 hypothesis family is present): the old rule
  locks the false **107@2** in 3 of 3 L-arm runs (6-10 votes); the sign table has 107@2 det 7-16 with 107@5 at `6>15` (rival-only 6, leader-only 15, p = 0.039 > 0.02) and no
  `SIGN_SHADOW` line: the sign rule does not make that false lock. b: 1-2 detections per hypothesis in 12 s, no lock either way. 12 s captures are too short to decide a lock.
- **UL SNR / CRC** `[MEASURED, replay]`: no replay locked the correct layout (b never locks; tim locks the false 107@2), so there is no SNR per correctly locked RNTI. DM-RS SNR of the
  trial footprints (3638 b / 6569 tim decodes, Lr arms): b p10/p50/p90/max -16.0/-9.2/0.0/0.0 dB (top RNTIs 0x5186 -10.1, 0xa07a -8.5), tim -18.2/-8.3/-1.1/+8.1 dB (>= 6 dB in 0.27 %; top
  RNTIs 0x4e32 -10.0, 0x5098 -3.8). UL CRC-OK per run (3 runs each): b R 0/0/0, F 0/0/0, Ld 1/0/0, Lr 0/0/0; tim R 2/0/0, F 0/0/0, Ld 0/0/0, Lr 0/0/1; the passes are 63-209-bit CRC16 TBs (mcs 0-20) at snr -16..-2 dB with
  `data_id` (31, 45) not the PCI: false-pass signature `[INFERENCE]`. **No real UL CRC-OK was found.**

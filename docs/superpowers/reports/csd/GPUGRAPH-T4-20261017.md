## Task 4: held instance plus data-driven entry (12de9de49b)
- **Instance hold:** `nr_pdsch_passive_decode` holds the pass instance that its first pass takes until the call returns (`nr_gpu_graph_call_begin/end`, nesting-safe).
  - This covers consumer calls and the RECOVERY_ASYNC worker's arm chain.
  - Acquisition follows the probe-reserve rule unchanged.
  - `nr_gpu_pass_dl_try` is now acquire / launch / release; the release runs only when the instance is not held.
- **Entry rule (a deviation from the plan's arm-bit rule):** on the held instance, C is skipped only when every C input equals that of the last C on the instance.
  - C inputs: the FEP block, chest rows, the pilot contents, the segment tables, and the DIRECT rxdataF redirect.
  - So a CDM or pilot change always re-enters at C (Review Focus 1, by construction).
  - The IQ ring is identified by its pointers and offset, which assumes its samples do not change within one call.
- **T4-1 fix:** the PassBlk, geometry and scrambling H2D moved out of C to the head of every split launch (`h2d_params`). D and L therefore never read a previous body's parameters.
- **Chest post moved from C to the head of D.** Its nvar divisor is number_symbols, so the S-toggle arms can enter at D. The post only writes ResBlk.post, so re-running it is idempotent.
- **`call_dirty`:** a body that runs the stage path invalidates the held estimate, because the stage path may rewrite rxdataF, which D reads in place on DIRECT.
- **Tests [OFFLINE VERIFIED, DGX GB10, DIRECT + DISCRETE]:**
  - GpuGraphRetry.EntryFollowsChangedInput: 4 grant shapes x 7 bodies per call:
    - the first body enters at C;
    - a probe of the same grant enters at D;
    - an unseen key mid-call falls back and the hold is kept;
    - an rv 2 body enters at D;
    - pilots changed in place enter at C;
    - the same inputs again enter at D;
    - after a dirty mark the body enters at C;
    - after call_end the instance is released.

    Every body equals the stage path from scratch.
  - **Mutation check:** with the D-head H2D removed, the test FAILS under DISCRETE on the rv-2 body. It catches the stale-parameter bug.
  - test_nr_gpu_pass 45/45 DIRECT, 45/45 DISCRETE (full binary).
  - ctest gpu|pdsch 32/32.
  - The ctest discrete variant's filter does not include `GpuGraph*`. Adding it needs a cmake re-run (orchestrator).

## Deviations
1. **Entry by C-input comparison, not by arm bits.** `nr_gpu_graph_arm_entry` and `dl_try2(entry)` are not implemented. The comparison is stricter: CDM can never get a stale estimate.
2. **No L entry.** The RV arm is off in t26gE. An RV change enters at D and is still exact (tested).
3. **The chest post moved from C to D** (spec 10.3 lists it in C). This lets the S-toggle arms enter at D.
4. **NR_GPU_PASS_RING kept at 4** (memory; busy did not rise).
5. **CONT_FAIL host LLR copy kept.** Its consumers are the shadow-fail hash, SELFCHECK and gpu_record. Its cost is inside post_us p99 <= 64 us.
6. **MidCallFallbackEqualsStagePath not written as a separate test.** It is covered inside EntryFollowsChangedInput: an unseen key mid-call, then a D body equal to the stage path, and the dirty path.
7. **Step A commit was rebuilt and tested on its own (44/44 DIRECT and DISCRETE)** before Task 4 was layered on top.

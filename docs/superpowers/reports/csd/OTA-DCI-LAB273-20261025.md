## Root causes fixed (commits)

1. `c9e8858e4b` **PCI-nID USS discovery.**
   - Root cause: the dedicated CORESET#1 is 270 RB, non-interleaved, duration 1 and has no `pdcch-DMRS-ScramblingID`, so n_ID = PCI and n_RNTI = 0 (TS 38.211 7.3.2.3).
   - The anonymous (RNTI, length) search ran only for nID != PCI. Once one RNTI was known, every new geometry got a per-RNTI sweep with 0 hits in 385k feeds.
   - The n_RNTI rotation also descrambled with other UEs' C-RNTIs.
   - Fix: the anonymous search runs for every UE on PCI-nID USS geometries, and exact-owner tasks use only {0, own C-RNTI}.

   The same commit fixes four more things:
   - **USS hash fit.** It froze at M_L = 1. Now the table rotates and refits, and 1 occasion in 16 is audited at all positions.
   - **Re-sync CFO.** `UE_synch()` used to retune to the residual instead of radio offset + residual, losing a −13.9 kHz correction and every later decode. Fixed.
   - **BWP switches** between same-length entries now need TB-CRC evidence.
   - **Launcher:** the td_measure lock is taken before the gNB starts.
2. `5432bc95a1` **CORESET-independent DCI sizes.**
   - A UE's DCI 1_1/0_1 size does not depend on the CORESET carrying it, so a known RNTI is now decoded at the length the cell (DL) or that RNTI (UL) locked on air. Without this the true CORESET was rejected for "no fresh CRC evidence".
   - **Shadow BWP entries:** an entry with a cell-locked length and no TB-CRC is not a separate BWP. This took BWP_CHANGE epochs from 39163 per run to 0.
3. `8cc6623346` merge of `sens6/dgpu-q4` 1664119420. `60178049cd` sets `ota_lab273.s6.env` to auto per-path mode.
4. `e18da8416a` **GPU demod self-check no longer disables the graph pass.**
   - In auto mode a ±1 LLR rounding mismatch of the bit-exact old-path GPU demod cleared `g_on`. That froze GPUPASS (shared `refuse()`) at 3098 launches instead of ~68k, the pass_dl trial could not finish, and every grant fell to the old path: PDSCH CRC 0.1 %.
   - Now only the old-path demod stops; the pass keeps its own shadow checks.
5. `4ec6fa9fbc` `groundtruth.py` `match_clock()`.
   - `match()` keeps one slot offset per run and breaks at every RX recovery: the 02:11 run scored 0.62 / 0.71 instead of 0.80 / 0.9995.
   - `match_clock()` reports per-RNTI DL/UL recall/precision and PDSCH CRC.
6. `287e525f92`, `48b39256fa`: EVIDENCE RANK solver experiment, **reverted** in `76a8b89392` (see open item 1).

Other host finding: NIC IRQs must stay on CPU 0. Spreading them over 0-2 broke the X410 stream within 5 s (20 ring restarts).

## Open

### 1. Blind DM-RS/TDRA layout solve converges stochastically

The solve came at 3 %, 5 %, 51 %, 52 %, 66 %, 78 % or 93 % of a 5-min run, or never.

**Cause** (measured, 03:53 run, `PDSCH_SOLVER probe` lines joined to SCHED):
- Of 100634 probes before the solve, only 270 tested the true physical hypothesis (S = 1, add_pos = 2, table qam256, layout 41), and only 56 of those at the true rank 4.
- The planner spreads probes uniformly, least-tried first, over ~60 readings × 48 (S, add_pos, table) variants.
- A true-hypothesis probe passes 9 % of the time, against 28 % for a full decode of the same grants. This is partly because S = 0, L = 13 gives the same TBS and data-symbol count with the PDCCH symbol mixed in.
- The solve needs 1–2 CRC24 passes.

**Tried (EVIDENCE RANK: probe share ∝ 1/rank of its measured SNR), reverted:**

| ranking | rfsim | OTA |
|---|---|---|
| data EVM | slowed: 3.5–9.3k probes, CRC 84–94 %; EVM favours a wrong denser Qm | 2k probes (n = 1) |
| DM-RS comb SNR + 3.09σ Welch test | neutral: 1.8k, 96.6 % | 22k / 29k probes (vs 45–100k) |
| DM-RS + same-Qm EVM | neutral: 2.0k, 96.21 % | variant ranks on the scan thread cost 25–55 % scan drops; an unconfirmed solve |

**Next:**
- Keep the DM-RS ranking (rfsim-neutral, 2–4× on air).
- Move all ranking work off the PDCCH scan thread (plan asynchronously or cache the ranks per RNTI).
- Treat S/L hypotheses that are equal in TBS as one physical class and resolve them by the PDCCH-symbol EVM.
- A/B on air with ≥ 5 runs per arm.

### 2. Big grants not demodulated (`nsym=0`)

Not budget or deadline drops. They are the TAIL-FIX no-chance gate (DM-RS comb SNR more than 5 dB below what the MCS needs).

| allocation width | DM-RS comb SNR (median) | data SNR (median) | gated |
|---|---|---|---|
| > 128 RB | 8.5 dB | 5.4 dB | 1194 of 1248 |
| 1–4 RB | 33.7 dB | 23.5 dB | — |

- Ungated big grants pass 9/854.
- Per-branch noise variance is 7–17 dB higher on wide grants at the same DM-RS power.
- Routing to the GPU would not help: the graph pass has the same in-graph gate.
- The degradation with allocation width is a receiver-side estimation/impairment issue to find (candidates: timing ramp across the band, port leakage under frequency selectivity).
- There are too few narrow grants away from RB 0–3 to separate position from width.

# T23 — automatic passive receiver core planner

Host: DGX Spark `spark-74c3`, aarch64. No receiver, replay, OTA, or GPU runtime was executed.

## Implementation

[CODE-READ] `common/utils/nr_core_plan.h` and `common/utils/nr_core_plan.c:102` (solver),
`:185` (detector), `:242` (activation), `:289`/`:301` (pthread integration) implement a dependency-free Linux detector and a pure,
bounded placement solver. It reads online CPUs, the process's allowed affinity, isolated/nohz_full lists,
IRQ default hexadecimal mask, package/cluster/core/sibling topology, capacity (frequency fallback), and
UHD `[use_dpdk=1] dpdk_corelist`. It conservatively reserves the union of `/etc/uhd/uhd.conf`,
`$HOME/.uhd/uhd.conf`, `/root/.uhd/uhd.conf`, and `UHD_CONFIG_FILE`, when the device arguments enable DPDK.
Unreadable/missing DPDK assignments fail preflight rather than guessing. DPDK also reserves SMT siblings.
Capacity is grouped in 10% bands: this host reports slightly different capacities within the same core class.

[CODE-READ] `executables/nr-uesoftmodem.c:167` plans after configuration parsing and before receiver worker
creation. The default is enabled for `--passive-rx`, independently of CSI-RS discovery; the explicit T23
requirement takes precedence over the general CSD brief's discovery-only gate. `ISAC_CORE_PLAN=0` leaves
the legacy scheduling path in place. Non-passive operation does not activate the planner.

[CODE-READ] Role counts include RX antenna dependent default thread-pool size (2–8), ring enable,
DL/UL/SYNC actors, scan/PDSCH/PUSCH queues, USS tracking, GPU FEP, CSI-RS, nID, and housekeeping.
Unset actor counts scale to available physical CPUs (one DL and one UL on the 20/12/8-core fixtures).
Explicit actor counts and numbered command-line/config/environment affinities are reserved first.
The planner fills individual consumer/actor assignments, so automatic placement does not require contiguous
core numbers. Explicit conflicts involving RT or DPDK, unavailable CPUs, invalid lists, excessive pool
counts, and insufficient physical CPUs produce a descriptive startup error; overrides are never silently moved.
A negative config core is the existing “unspecified” sentinel. Environment core values must name a valid CPU.

[CODE-READ] `common/utils/system.c:245` applies affinity in pthread attributes **before entry**, including
without CAP_SYS_NICE. Reader/ring/control/actors retain their RT priorities when permitted. Planned
non-RT workers use SCHED_OTHER, including the generic pool: on an oversubscribed host FIFO workers at
different priorities would otherwise starve one another. The main thread's inherited mask and already-created logging/configuration helpers exclude RT
and DPDK physical cores. Raw pthread helpers (PBCH scan, legacy ID sweep, CB0, exports/capture, PRACH/SRS,
USS and CSI-RS) use the same pre-entry affinity wrapper. The nID worker consumes its existing environment
hook; **no `nr_pdcch_nid_*` file was changed**. No CSI-RS contract or semantics were changed.

[CODE-READ] `radio/USRP/usrp_lib.cpp:1110` starts the planned ring with pre-entry affinity and assigns one
UHD control endpoint per reserved control CPU (`:910`). If UHD creates more endpoints than reserved, stream startup
fails rather than stacking busy-pollers. `ISAC_UHD_CTRL_THREADS=N` reserves additional automatic control
CPUs for multi-endpoint devices; the default is one, matching the supplied X410 evidence. Explicit
`ISAC_UHD_CTRL_CORES` lists reserve their full membership. The plan is logged once, with individual
forced-sharing warnings. This is scheduling protection, not a bandwidth or throughput guarantee.

[ANALYTICAL] The supplied hand layout omits dedicated DL/UL/SYNC cores. Adding them while retaining
all four pool workers requires two non-RT shares even on DGX. This equivalent automatic layout preserves
the safety properties of the hand layout and makes the previously unassigned actors explicit; reproducing
every old number while adding three exclusive actors is impossible on 17 non-DPDK cores. Removing an
optional worker frees its CPU automatically. The smaller host shares only non-RT roles, with warnings.
These are placement checks, not sens6 measurements or evidence that 4 × 122.88 Msps is sustainable there.

## Limits and deferred measurements

[IMPLEMENTED, NOT VALIDATED] OTA scheduling/throughput and GPU runtime. No placement can guarantee
absence of stream overflows on an arbitrarily slow host or with insufficient memory bandwidth. An
impossible exclusive RT allocation fails before radio startup; CPU IDs beyond the fixed Linux cpu_set_t
limit (1023) also fail safely. Process affinity restrictions are respected, including taskset/cgroup
restrictions; the planner does not widen them or change kernel isolation, IRQ routing, or DPDK configuration.
No CPU hotplug or runtime affinity replan is performed. The passive planner currently supports one RU;
multi-RU configurations fail preflight rather than reusing one reader/ring assignment. A device that
requires the legacy software-decimation spin pool (FPGA without hardware DDC) is rejected after rate
negotiation and before streaming: that additional busy-poller topology cannot be known from host
configuration. Use a DDC FPGA image; the explicit legacy opt-out remains available. Radio initialization
errors in planned mode propagate to a normal failed startup instead of the old assertion/abort.
 GPU roles are reserved from requested features
even if the GPU loader later falls back to CPU. IRQ defaults do not prove the effective affinity of every IRQ.

the CPU-only build used for this task does not produce CUDA modules. Run from the repository root using the new `tests/passive_rx/dgx/ue.passive.ota.autocores.cfg` (no core
fields). UHD's existing DPDK configuration remains the source of its lcores. The command has feature flags

- Fix [CODE]: the scan thread only copies the 3 DM-RS REs per RB of antenna 0 for both CORESET symbols. The FFT of the extra symbol is now antenna 0 only, into a thread-local buffer. The copy goes into a 16-entry ring; when the ring is full the observation is dropped, and the tracker's evidence is relative, so drops only slow it down. The existing nid_solver worker (SCHED_OTHER, nice 10, background lane) runs the unchanged correlation, `nr_pbwp_coreset_observe` / hypothesis and the "BWP CORESET found" log (`pbwp_corr_run`). - Core pool (csd/int16-corepool, read only, not used) [CODE]: no two pool threads would share a core, so passivePdsch0 would no longer be pre-empted on core 7. But the pool only moves the cost. The heavy work would stay inside the SCAN-class lease, which has the highest priority. Decodes would then wait for a token instead of being pre-empted, and the pool also needs ISAC_POOL_CORES (an env flag). The fix here is therefore (a). If the pool is adopted later, it must guarantee all of the following:
  1. Exclusivity covers every thread pinned to a pool core, the RT receive thread and the non-pool helpers included. No thread outside the pool may run on a pool core; nid_solver and the background lane stay off the pool cores.
  2. The DECODE class gets a bounded lease wait while SCAN holds tokens: the reserve must hold at least one token that SCAN cannot take, or DECODE must age into it.
  3. Discovery and solver work never runs under a SCAN lease.
  4. It works with no env setting (a default core list), or it is not part of the product.

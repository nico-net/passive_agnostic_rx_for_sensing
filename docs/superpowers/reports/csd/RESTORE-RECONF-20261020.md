Pure rules: nr_passive_reconf_rules.{c,h}; state machine in nr_passive_ue_ctx.c (non-RT writer thread). Primary evidence is DCI / HARQ / RAR / silence; RRC and Msg4 evidence only confirm or refine.

3. RRC processing delay (TS 38.331 12: 10 ms setup/resume/reestablishment, 16 ms reconfiguration): anchored to the inferred reconfiguration moment, i.e. a trusted dedicated parameter changing under traffic (DCI size, TD winner, layout ...). Window [slot - delay, slot]: the other dedicated parameters of that UE are re-verified (HINT) and the per-RNTI DCI-length SUSPECT threshold drops from 200 to 16 misses for 100 ms (accelerated re-lock). An RRC message (CCCH in a PDSCH, or a large SRB1 SDU) anchors the same window when seen; at its end the epoch authority is told (`nr_cfg_epoch_note_rnti_reopened`).
4. BWP switch delay (TS 38.133 8.6.2, TS 38.213 12): a BWP-indicator DCI naming another resolved entry records the window [+type1, +type2] slots (type is a UE capability, TS 38.306, invisible); the BWP epoch and `NR_UEP_BWP` are raised when the upper bound elapses, not at the DCI.
5. RRC_INACTIVE / IDLE: silence horizon from DCI (10 s -> IDLE, or INACTIVE for a UE with a resume identity; 60 s -> GONE). Linking across incarnations only with evidence (Msg4 identity: S-TMSI part 1 or resume I-RNTI via TS 38.331 UL-CCCH RRCSetupRequest/RRCResumeRequest bits -> param `RESUME_OF`); random identities never link; without evidence a returning value is a new incarnation.

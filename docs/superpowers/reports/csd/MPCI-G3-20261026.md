## 3. What A8 must call
Per further cell, on that cell's bound thread, before the RX fence and after cell 0's warm-up: `nr_gpu_pass_warmup(ue)` (registers the cell with the module: HARQ slab, quota floor, UL enable), `nr_gpu_pass_ul_prewarm(ctx)` for its UL contexts, `nr_pusch_gpu_fep_init(...)` for its UL FEP pool. Cell exit: `nr_gpu_pass_cell_retire(cell)` (module symbol; slab kept).
HARQ slab is a planned cost (admission counts `nr_gpu_cell_bytes` kind harq): it is booked as a dynamic PASS grant when the elastic headroom has room and allocated either way; the real refusal is the allocation.

## 4. Open items / limits
1. **Geometry (main limit).** The captured FEP kernels carry n_rb_dl, first_carrier_offset, CP lengths and the time-shift table by value (`nr_pdsch_gpu_fep.cu`), and `nr_pdsch_gpu_fep_init` refuses a different cfg, so a cell whose FEP geometry differs from cell 0's runs the CPU path (correct, not accelerated). Lifting it: pass n_rb_dl/fco through the per-pass parameter block and make the legacy `exact_fep2`/chest paths cell-aware. [CODE-READ]
2. nbRx and delay table are process-wide (same fallback).
3. No usage-decayed fair share above the floor.
4. UL FEP tables are duplicated per cell (tens of KB), booked as shared in the ledger.
5. Remaining unbound GPU threads: LDPC `gpu_worker` (`nrLDPC_coding_cuda_decoder.c:350`) and CUDA `host_done` (`ldpc_cb0.cu:980`): [CODE-READ] the LDPC plugin has no `nr_cell` use and touches only per-slot job state and process counters, so nothing to carry; `bg_main` (`nr_pdsch_gpu_demod_host.c`) uses the job-carried cell (A5).

# NL2SPEED 2026-10-12 -- why ISAC_L2MAXH_DELTA_NL2=-3 slowed demod 7x, and the fix

## Root cause [MEASURED, DGX OTA 2026-10-12 20:15-20:26, TIM, logs ab_TmL1_1_201805 / ab_TmL2_1_202331 vs ab_TmA_1_201522 / ab_TmB_1_202048]
- Not a CPU fallback for nl>=2, not retries. In both t26zL runs the GPU demod CHECK (every 64th grant) fired once:
  `GPU_EXACT_DEMOD MISMATCH ... Qm 2 Nl 4: llr[132] gpu 792 cpu 1142 -- GPU demodulation disabled` (L1, after ~1000 calls) and
  `Nl 4 ... llr[7] gpu 526 cpu 2047` (L2, after ~14000 calls). Mismatch disables the GPU demod for the rest of the run, so demod
  ran on CPU: mean 1096/1048 us (cpu 1002) vs 155/153 us, p50 455/445 us vs 85 us, p99 13.3/12.8 ms vs 1.3/1.2 ms (PDTIM/PDTIMPCT).
  t26z arms: check_bad=0, refused[]=all 0.
- The flag added the delta for every nl>=2 (CPU `nr_dlsch_demodulation.c`, GPU `nr_pdsch_gpu_demod_host.c`). At Nl 3/4 (mode 2 double
  Gauss-Jordan, ISAC_PDSCH_GPU_EXACT_DEMOD_NL34=1) a 8x finer shift makes the near-singular 4x4 solve sensitive to last-bit/pivot-tie
  differences; the GPU port is not bit-exact there ([HYPOTHESIS] pivot tie, as documented for GPUALLOC; the mismatching RE was not isolated).
  Side observation: the t26zL runs also had 5-8 discovered CORESETs vs 1-2 and PDCCH_NID_GPU kernel overruns up to 38-52 ms
  [MEASURED, same logs]; run-to-run discovery variance, secondary to the disabled GPU demod.

## Fix [IMPLEMENTED, commit on csd/nl2-speed]
`ISAC_L2MAXH_DELTA_NL2` now applies to nl == 2 only (CPU and GPU, `nl == 2 ? s_l2d2 : 0`). Nl 3/4 are untouched, so they stay on the
proven bit-exact path; the 2-layer CRC gain (the only one measured) is kept. Default off, no new flag. Costs: Nl 3/4 get no delta
(never measured to benefit).

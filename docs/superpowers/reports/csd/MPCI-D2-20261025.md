## What was done

1. **Line attribution (F5 = prefix).** `[CODE-READ]` + `[OFFLINE VERIFIED unit]`
   - Seam addition in `common/utils/nr_cell.{h,c}`: `nr_cell_count()` (default 1, relaxed load) and `nr_cell_set_count(n)` (fatal outside 1..NR_CELL_MAX). Verbatim text is in the plan's Task log.
   - `common/utils/nr_cprintf.h` (header only): `nr_cell_tag_lines()` (in-place tagging, bounds-safe, trailing newline not tagged), `nr_cprintf(...)`, `nr_cfprintf(FILE*, ...)`. At count <= 1 they call `vfprintf` directly (same bytes). At count > 1 the whole call is formatted, tagged on every line and written under `flockfile`.
   - `common/utils/LOG/log.c`: one hunk in `log_output_memory`, before the colour end sequence. The tag goes at the very start of the record (before the colour start), every line of a multi-line record is tagged.
   - `common/utils/LOG/CMakeLists.txt`: `nr_cell.c` is now part of the `LOG` library (log.c needs the TLS index and the count). Other targets must link LOG and not compile `nr_cell.c` again.
   - Threads bound to no cell (radio threads, GPU callback / CUDA event threads) read cell 0 and are tagged `[c0]` (documented in the header and the Task log). The dashboard handles radio lines by grammar, so the wrong `[c0]` does not matter there; per-cell job lines printed from callbacks must name the cell explicitly (A3-A7).
   - No printf site in a decode file was converted (A3-A7 use the shim).
2. **Metrics JSON.** `nr_passive_metrics_emit` inserts `"cell":<k>` as first key only when `nr_cell_count() > 1`. Adding `"cell":0` at N=1 would change the bytes of every record (ISAC_METRICS log line and metrics file), so N=1 equivalence wins; the parser takes "no key" as cell 0. The metrics are still process-global statics until A3-A8 make them per cell; the key reports the emitting thread's cell.
3. **Parsers** (`rxparse.py`, `monitor.py`, `monitor.html`; minimal changes):
   - `rxparse.split_cell()` strips the tag (also after a harness timestamp and after colour leftovers `ESC[0m` / `[0m`); no tag = cell 0.
   - `RunState` is the router: cell 0 is the object itself, `children[k]` hold cells >= 1. `feed_line` routes by tag; `feed_metrics` by the `cell` key; `feed_obs` by PCI owner. `snapshot_for(pci)` returns the snapshot of the state owning that PCI, with `cells` = union (each with `cell_idx`) and `sel`. Single cell: identical to `snapshot()`.
   - Receiver-wide line types (`CHPOW`, `RFSTALL`, `RFCENSUS`, `RFTSDISC`, `RFCHAN`, `CMDLINE:`) are recognised by grammar whatever the prefix, fed once to the router and mirrored into every cell state (also into cells that appear later: a bounded replay buffer). One `RFSTALL` is one stall in each cell page, not two.
   - P99AGE (inventory row 11) ported: regex, `_h_p99age`, `timing.p99age`, table on the Performance page (format string checked against `nr_pdsch_passive_queue.c:2667`). Row 11 H5 (process attribution) was checked on main: `10e0a0b18c` is in the tree and the dashboard is spawned by the receiver; no change needed.
   - `monitor.html`: the "all cells (receiver-wide)" mark (port of 1040882805) now appears on counter cards only for logs WITHOUT cell prefixes (`meta.attributed` false); the radio cards (per-antenna power, radio channels) carry the mark whenever more than one cell is shown. "Converged RNTIs (solver)" per cell was already in the tree (filters by PCI).
   - `monitor.py`: `state_payload` / compare / summary use `snapshot_for(cell)`; `meta.attributed`, `meta.cell_idx`. The `?cell=` parameter is the PCI key as before.
   - Known limit: two cells with the same PCI get the union key `PCI@c<k>`; the HTML grant lookup for such a collision uses the union key (no collision test case; not expected on real cells).
4. **Scorers (no flags, rework after the operator "NO FLAGS" rule).** New `tests/passive_rx/cellsel.py` (`prepare(lines, cell)` for programmatic use, `multi_cells`, `log_cells`). `goal_metrics.py`, `dgx/score_rx.py`, `dgx/score_rx_solver.py` and the ported `tests/passive_rx/mpci/mpci_runsum.py` have NO `--cell` option and read no env var for it; behaviour is automatic:
   - log without tags: output byte-identical to the pre-D2 scripts (golden files);
   - tags of one cell only: tags stripped, same as that cell's unprefixed log;
   - tags of several cells: every cell is scored separately, one complete independent block per cell. Text: header `== cell <k>` before each block. JSON: `{"run"|"arm": ..., "cells": {"0": {...}, "1": {...}}}`. Never a merged number. Gate mode: `== cell <k>` plus one verdict line per cell, exit status = worst cell.
   - untagged lines of a multi-cell log belong to no cell and are dropped. `cellsel.prepare(lines, None)` on a mixed log still raises SystemExit(2) (programmatic safety), `prepare(lines, k)` selects a cell.
   - mpci_runsum: ported from `ref/mpci-old` (`--arms` mode kept), per-cell blocks under `== cell <k>`.
   - No CLI option or env var was added anywhere in D2 (checked on the diff against the base: no getenv/environ/add_argument/new flag). The `?cell=` HTTP query of the dashboard and ISAC_PDTIM_CLASS mentions are pre-existing.

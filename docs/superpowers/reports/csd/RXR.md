## Implementation

- [CODE-READ] `radio/USRP/usrp_lib.cpp` gates producer recovery on `ISAC_RX_RECOVER=1` (default off). Overflow and other UHD metadata errors, receive exceptions, startup timeouts, missing timestamps, and ring overruns enter the same bounded stop/drain/restart path. `ISAC_RX_RECOVER_MAX` defaults to 20; 20 ms of valid samples resets the failed-start count. A recovered four-channel X410 stream uses a timed START based on `get_time_now()+0.02 s`; both the control read and stream command are inside the retry catch. The accepted command time bounds the new epoch's first timestamp if UHD reports an old frozen stream-start timestamp. The producer retains a monotonic logical write index, publishes a new epoch on the first valid packet, and abandons unread samples at the boundary. The reader skips that boundary, rejects a slot if a fault overtakes conversion, checks availability without unsigned underflow, and leaves the existing exit-3 shutdown in place only after the retry limit. Index/retry accounting is in `radio/USRP/usrp_ring_recovery.h`.
- [CODE-READ] `executables/nr-ue.c`, `openair1/PHY/NR_UE_TRANSPORT/nr_initial_sync.c`, and `openair1/PHY/NR_UE_TRANSPORT/pss_nr.c` detect either a hardware timestamp gap or a driver epoch change, drop the current slot, clear timing, and run a PSS/SSS search around the previously decoded PSS sample position on the learned PCI and SSB. The expected PSS is projected modulo the serving cell's 20 ms SSB period, then passed as a 10 ms frame number plus position within that frame to the scanner (whose PSS window is frame-local). Fast search correlates PSS on the strongest branch in a quarter-symbol window while keeping all configured branches for SSS/PBCH; a miss tries a two-symbol window, the other frame, and a coarse survey before ordinary full-capture search. While the sync actor searches, the main receive thread repeatedly reads and discards two-frame windows, draining the ring. The soft configuration epoch invalidates in-flight IQ consumers while retaining learned dedicated state; legacy behavior remains under the flag-off path. Successful reacquisition logs `RX_RECOVER epoch=.. gap_samples=.. resync_ms=..`.
- [CODE-READ] `radio/USRP/usrp_ring_view.h:10` and `usrp_lib.cpp:2146` gate the direct read on `ISAC_USRP_RING_ZEROCOPY=1` (default off). The reader shifts sc16 samples directly from a circular ring window into PHY `rxdata`, including the wrap, without the intermediate ring-to-temporary-buffer copy. The format-shift write into `rxdata` remains necessary. `ISAC_USRP_RING_TRAFFIC_METRICS=1` appends cumulative `usrp_ring_copy_bytes` and `usrp_ring_direct_bytes` to `ISAC_METRICS` (`openair1/PHY/NR_UE_TRANSPORT/nr_passive_metrics_json.c:182`); take deltas between metric timestamps to get bytes/s. Flag-off JSON remains unchanged.
- [CODE-READ] `ISAC_USRP_RING_PKTS` already permits 1–64 packets per `recv()` and defaults to 8. The supplied OTA benchmark with one packet had zero drops; no larger default is justified by that evidence.
- [CODE-READ] The raw-IQ device already had `ISAC_RAW_IQ_GAP_AT_S` and `ISAC_RAW_IQ_GAP_S` test-only injection. RXR uses it without changing the replay device.
- [CODE-READ] The CSI-RS discovery contract (`nr_csirs_disc.h`) was not changed.

## UHD behavior and limits

- [CODE-READ + UHD documentation] RFNoC continuous-stream overflow recovery is initiated within UHD's RX streamer before the application receives overflow metadata. The public `recv()` documentation says the metadata error may arrive only after valid buffered samples are returned. No documented RX streamer option disables the internal radio restart/control operation. The application therefore catches the resulting exception and retries the stream; checking metadata cannot prevent an exception that UHD raises first. See [RFNoC radio overrun handling](https://files.ettus.com/manual/classuhd_1_1rfnoc_1_1radio__control.html) and [RX streamer error handling](https://files.ettus.com/manual/classuhd_1_1rx__streamer.html).
- [OTA, orchestrator] The direct ring read completed one 120 s X410 run with the dedicated DL chain; the stream had no fault in that run. Its traffic counters were not captured, so the GB/s reduction remains calculated rather than measured OTA. The corrected timed restart, timestamp rebase, and fast resync have been verified only by source inspection, unit tests, and raw-IQ replay; they still need a faulting X410 run. After 20 consecutive failed attempts, exit 3 remains intentional.

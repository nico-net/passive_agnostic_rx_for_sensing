# MPCI G3b: the GPU decode pass serves cells of different FEP geometry (2026-10-26)

Branch `mpci/g-g3b` from `mpci-main` @ 86a3f902e2, DGX GB10 aarch64 (shared). Labels: [OFFLINE VERIFIED, DGX GB10 aarch64 unit] = unit test run here, serial, `CUDA_MPS_PIPE_DIRECTORY=/tmp/nicola_nomps`; [CODE-READ]; [HYPOTHESIS]. No receiver run, replay, bench or timing.

## 1. Design
Geometry = (n_rb_dl, first carrier offset, CP lengths, time-shift table, nbRx). N, symbol count, offset divisor and delay table must equal cell 0's (same family); nbRx must be <= cell 0's (rings, demod staging and instance buffers are sized by cell 0).

## 2. Tests [OFFLINE VERIFIED, DGX GB10 aarch64 unit]
`test_nr_gpu_pass_geo`: 4/4 on the DIRECT model and 4/4 with `NR_GPU_PASS_DISCRETE=1`.
- FepEqualsCpu: GPU FEP of 217/4RX, 162/4RX, 106/3RX (15 kHz CP), 51/2RX, 51/4RX with another CP (own time-shift table), 273/1RX equals the OAI CPU FEP (DFT + `apply_nr_rotation_symbol_RX`) bit for bit on all rows (0 of 1512); equal geometry returns the same id; 5 RX, another FFT size, 0 PRB refused.
- CellsOfOtherGeometry: cells 217/4RX and 51/2RX (plus a third cell of the 217 geometry): pass result equals the stage path of that geometry (TB bytes, CRC, nvar, seg_ok, rxdataF) and the transmitted payload; every run alone and interleaved with the other cells is bit-identical (TB, final LLRs, rxdataF); all graph hits, no new class for the twin cell, unregistered cell and wrong-antenna job return 1.
- BudgetExhaustedFallsBack: with all headroom taken the 106/3RX geometry is refused (-2), nothing registered, cell jobs return 1; with headroom back it registers and decodes; PASS dyn bytes = measured graph bytes (+ the cell HARQ slab).
- SplitModeSharesTheLdpcGraph: split mode, 133/4RX adds 29 keys, 133/2RX only 12 (L graphs shared); both decode like the stage path.
Regression: see section 4.

## 3. Memory cost per extra geometry [Bench-like, DGX GB10, shared host, cudaMemGetInfo deltas: logic evidence only]
FULL graph mode, 16 default classes: 217 PRB/4 RX about 56-63 MB; 6 classes of 51 PRB/2 RX about 23 MB; 106/3RX 9 classes about 22-28 MB; split mode 133/4RX about 36-42 MB, 133/2RX about 19-25 MB. Plus 16 KB time-shift table when the CP differs. Each cell still has its own 99 MiB HARQ slab (G3). Cost scales with the PRB classes and layers warmed, not tuned.

## 5. What A8 must call per cell
Nothing new: `nr_gpu_pass_warmup(ue)` on the cell's bound thread, pre-fence, after cell 0's (it now registers the geometry itself, serialised by a mutex), then `nr_gpu_pass_ul_prewarm`, `nr_pusch_gpu_fep_init` as in G3. Cell exit: `nr_gpu_pass_cell_retire(cell)` (geometry and graphs stay for same-geometry cells).

## 6. Open items
1. UL pass with another geometry: keyed and warmed the same way, compiles and existing UL tests pass, but there is no UL two-geometry functional test [CODE-READ only]. UL graphs capture the UL FEP pool of the registering thread's cell.
2. nbRx larger than cell 0's, other FFT size or delay table: still CPU path (rings/demod staging sized by cell 0).
3. Admission has no model of the geometry's graph bytes (`nr_gpu_cell.h` has no kind); it is measured and reserved at registration.
4. Solo reference is in-process (alone vs interleaved, stage path, CPU FEP, payload); a separate process with the geometry as cell 0 was not run (would need an env/CLI seam).
5. Estimate depends on cudaMemGetInfo deltas; if nothing is measured the geometry's own bound is off (process cap not applied).

## Implementation

[CODE-READ] `openair1/SCHED_NR_UE/phy_procedures_nr_ue.c:2418` replaces the old 14-symbol FEP/ring copy with `nr_csirs_disc_td_push()` and the due-only confirmation entry. The existing SIB1 TDD query skips full UL slots only when both the pattern and its reference numerology are known. Unknown/mismatched numerology feeds every slot; flexible/mixed slots remain eligible. Previously computed CSI-RS/PDSCH symbols are reused by confirmation.

[CODE-READ] `openair1/PHY/NR_UE_TRANSPORT/nr_csirs_disc_td.c:125` copies each antenna's contiguous CP-bearing span from the first FFT window through the last. Its offsets match `nr_slot_fep`: slot timestamp, per-symbol ordinary/long CP selection including unsynchronized CP behavior, and the `nb_prefix_samples / ofdm_offset_divisor` early start. The original absolute offsets are retained for CFO phase. The actor snapshots common CFO (including the thread-local override), the compensation flag, and symbol rotations; it performs no FFT, rotation, allocation, GPU call, file write, or blocking lock acquisition. `nr_slot_fep` does not apply the separate per-branch CFO table, so this feed does not introduce that `nr_slot_fep_ant` behavior either.

[CODE-READ] The host staging pool is preallocated and touched at startup, with best-effort transparent huge pages. It is ordinary host memory, so GPU migration of FFT buffers cannot block the actor. Queue entry pointers are exchanged with 100 private worker entries under a short mutex; the actor uses `trylock` and counts collisions/full-queue drops. The worker holds no producer mutex during CP removal, CFO compensation, FFT, rotation, FD publication, dumping, or detection. Epoch reset invalidates queued and in-flight TD data before clearing the FD ring. A changed FFT/grid/CP/numerology configuration fails closed with counted drops until discovery is restarted; ordinary same-geometry epoch resets are supported.

[CODE-READ] `nr_csirs_disc_td.c:176` packs CP-free FFT windows and uses the existing OAI `nr_fo_compensation` when enabled. `nr_csirs_disc_gpu.cu:152` adds a batched unitary cuFFT primitive to the existing `csirs_disc_gpu` module. Input/output and FFT work buffers use unified memory when that backend is available. Plans/workspace persist between compatible batches. The worker uses OAI `dft` on CPU when the module/device is absent, CPU is selected, or the guarded GPU call fails. Both backends then use the same OAI `apply_nr_rotation_symbol_RX` and unchanged U1 CRB extraction. The GPU handles FFTs; CP packing, CFO and Q15 post-rotation execute on the worker CPU. The added ops member preserves existing API semantics; core/modules must be rebuilt together.

[CODE-READ] `nr_csirs_disc_feed.c:309` drains the current backlog in chunks of at most 100 slots, then invokes the detector once. It consumes at most the FD ring capacity per pass, so it cannot overwrite unprocessed FD entries within a coalesced pass. The timed worker wait avoids a producer wake mutex and bounds an otherwise lost wake to 5 ms. The existing `nr_csirs_disc_ring_push()` remains available for direct frequency-domain fixtures and dumps. Live optional FD dumping now runs on the worker.

[CODE-READ] `nr_csirs_blind_rt.c:510,889` adds `nr_csirs_blind_rt_slot_fep()`. Candidate admission and due scoring use the same lock, eliminating a gap between selecting needed symbols and scoring a newly admitted candidate. Live confirmation tries the lock and counts a skipped call if busy. Each actually scored candidate uses the authoritative CSI-RS mapping to FEP only its symbols, once per actor slot, across all antennas. Confirmed rechecks use the same mechanism. The legacy row-5 ZP path now reuses discovery's second symbol instead of performing another antenna-0 FFT. The frequency-domain harness continues to call `nr_csirs_blind_rt_slot()` directly.

[CODE-READ] Feature-off retains the existing gate, legacy confirmation locking/FEP and metric JSON schema. No shared PHY transform implementation or receiver sample buffer is changed. ## Backlog and memory bounds

[ANALYTICAL] Default `ISAC_CSIRS_DISC_TD_RING=1024` stores **512 ms** of arrivals at 2000 slots/s while the worker is occupied; 100 additional slots are private to the in-flight FFT chunk. The FD history remains 640 slots. A coalesced detector pass receives at most 640 new slots. Drops are finite-memory backpressure, never a wait on the actor. The bound assumes the queue initially has space: available stall coverage is `(1024 - pending) / 2000` seconds. No finite ring guarantees lossless operation when long-term service is slower than arrivals.

[ANALYTICAL] For a coalesced batch of B slots, sustained service requires `FFT/packing/rotation/copy(B) + detector/sweep(B) < B / 2000` seconds. A fixed 150-ms detector cost alone requires B>300; at B=640, it leaves <170 ms for everything else. Detector cost need not remain fixed as B increases. This implementation coalesces, but **2000 slots/s has not been established**. `CSIRS_DISC FEP` logs expose slots, total worker FEP/publication time, packing+CFO+FFT time, GPU/CPU chunk counts, pending slots, feed drops, TD overflows and confirmation lock drops. Existing `csirs_disc_feed_drops` also includes TD losses.

[ANALYTICAL] At four RX/217 RB/4096 FFT with mu=1, the TD pool is approximately 1138 MiB; its two packed FFT buffers total 175 MiB. Existing two FD rings plus detector state are approximately 957 MiB. CPU storage is therefore roughly 2.22 GiB plus other scratch; CUDA adds approximately 175 MiB FFT work plus cuFFT plan/workspace. These are allocation calculations, not measured RSS.

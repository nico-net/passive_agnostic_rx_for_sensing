# GPUFUSE — PDSCH per-grant decode time: GPU demod launches, 3/4-layer EVM, the per-run stall (2026-10-11)

Branch `csd/gpu-fuse` (worktree `rr-csd-gfu`, base `csd/otatest` 3c68c65006 = GPUSHARE). Host: DGX Spark GB10 (sm_121,
48 SMs, CUDA 13.0). Builds, tests, benches and replays only through `heavy.sh`; no radio, OTA, capture or UHD tool; solver
scheduling not touched. Replays: private copy of `tests/passive_rx/timacq_replay.sh`, **SPEED=1**, env
`rr-orchestration/ota/t26r.env` (single line; already has `ISAC_PDTIM_PCT=1`, `ISAC_PDSCH_GPU_EXACT_LDPC=1`,
`ISAC_GPU_DISC_SMS=8`, `ISAC_GPU_RT_ISOLATE=1`, DEMOD/CHEST CHECK=64), binaries frozen per arm (copied build dirs).
Commits: 4199ad784b, 245b20988a, c7f4b83e21.

## Verdict

* **Goal (per-grant decode mean < 0.5 ms): not met; means down 10-50 %.** `[MEASURED, DGX GB10 replay]` (table 1.1)
  - b (Vodafone): sum of PDTIM stage means 653-797 (A) -> 588-627 (F2) / 592-687 us (F3); p50 435-455 -> 355-375 us,
    p99 4.0-6.0 -> 2.6-3.7 ms; second-half means 466-630 us.
  - TIM 12 s: **1425-1773 -> 574-966 us** (demod stage 668-726 -> 143-235 us); p99 6.2-12 ms -> 3.5-6.8 ms.
  - capture 8 (1,200-2,200 decodes per run, one slow window sets the run mean): 969-1974 -> 772-1348 us; second halves
    430-852 us.
  - Left on b (F3): fep 103-133, chest 142-161, demod 144-253, ldpc 163-173 us; p50 of the sum 355-375 us. The gap
    to 0.5 ms is tails (p90 0.7-0.8 ms, p99 2.6-3.7 ms) and a remaining 40-560 ms stall in about half the runs.
* **What the "large TIM grants" really were.** `[MEASURED, TIM replay, ISAC_PDSCH_GPU_EXACT_DEMOD_SHAPES=1]` 20 % of
  TIM grants are **4-layer QPSK on <= 52 RB** (+2 % 3-layer QPSK): demod 1,479 us each, of which the GPU was 162 us.
  The other ~1.3 ms was the host copy of nr_rx_pdsch()'s EVM block (`evm_symbol`, a 4x4 complex double solve per RE)
  plus a 3.6 MB device->host copy of the extraction buffers, because the GPU EVM existed only for Nl <= 2. Fixed by
  the GPU EVM for 3/4 layers (`ISAC_PDSCH_GPU_EXACT_DEMOD_EVM_NL34=1`). The genuinely large grants (2-layer 16/64QAM on
  > 200 RB) take ~200 us on an idle GPU and 570 us (was 693 us) mean in the replay.
* **Launch overhead: two causes, both fixed.** (1) Every demod kernel took the whole 32 KB job struct by value
  (incl. the evm[] outputs): ~32 KB of parameters per launch, ~16 launches per grant. Now a ~1 KB `__grid_constant__`
  prefix. (2) 8-11 launches on the critical stream -> 4-5 (gather, level+decision, mask, [alignment], tail). Idle-GPU
  bench (4 RX, EVM on): 51-RB 1-layer QPSK 66 -> 43 us, 273-RB 1-layer 64QAM 85 -> 71 us, 273-RB 2-layer 64QAM
  208 -> 193-199 us. `[MEASURED, DGX GB10, private bench of nr_pdsch_gpu_demod_run, idle GPU]`
* **The "one 30-200 ms stall per run": one source found and fixed, one left.** `[MEASURED, nsys replay b]` the first
  launch of the CSI-RS discovery kernel `resident::segment` (~21 KB local memory per thread) made the driver grow the
  device's local-memory reservation to ~2 GB: `cudaLaunchKernel` blocked 218 ms and **no kernel started on the GPU**
  in that window (PDSCH included; GPU_EXACT_DEMOD max = 219 ms in the same run). `ISAC_GPU_LMEM_PRERESERVE=1` moves
  the growth to start-up; the nsys trace with it shows no launch > 2 ms. **Still open:** 40-560 ms demod maxima in
  3 of 6 F3 runs (table 1.1 `max`); not attributed (no osrt trace of a run with one). Candidates `[HYPOTHESIS]`:
  403 `cudaMalloc` + 64 `cudaHostAlloc` (up to 23 ms each) issued at run time by the discovery side after PDSCH starts
  (driver-lock contention), and the demod context pool (8 contexts; 5 consumers x (1 active + 1 EVM-deferred) can
  exhaust it, `acquire()` then spins).
* **Bit-exactness: unchanged.** `[MEASURED, replay]` DEMOD_CHECK=1 (every grant, CPU vs GPU: LLRs, comp, mags,
  dl_valid_re, log2_maxh, branch; EVM accumulator incl. exact kappa sums): TIM 10,000/10,000 (commit 1) and
  8,003/8,003 (commit 2), b 18,000/18,000, check_bad 0, evm_far 0 (max rel. EVM difference 2.5e-5 < 1e-4 tolerance,
  incl. 3/4-layer grants). Every timing run (CHECK=64): check_bad 0, evm_far 0, GPU LDPC check_bad 0.
  `[OFFLINE VERIFIED, DGX GB10]` LLR checksums of 15 synthetic grant shapes (Nl 1-4, QPSK-256QAM, ALIGN 1/2, 2/4 RX)
  equal to the base library; test_nr_pdsch_gpu_demod total=0; test_nr_pdsch_gpu_ldpc mismatches=0;
  test_nr_gpu_green ok=1; test_nr_csirs_disc_fp 45/45 (with ISAC_GPU_LMEM_PRERESERVE=1); test_nr_csirs_disc_sweep
  ran to completion (its pass line was not captured). Full ctest not run. sens6 gate clean.

### 1.3 Idle-GPU cost of the remaining demod work (`[MEASURED, DGX GB10, private bench, ISAC_PDSCH_GPU_EXACT_DEMOD_PROF=1]`)

* 2-layer 64QAM 273 RB: the QAM-FIX FP64 MMSE is ~100 us of ~200 us (the GB10 runs FP64 at ~1/64 rate; the CPU
  arithmetic is double with libgcc's `__divdc3`, so no exact FP32 or integer replacement exists for it).
* 4-layer QPSK 51 RB (stock fixed-point MMSE, `k_tail<5>`): 122 us; ~10k SASS instructions per RE (int16 saturating
  cofactor arithmetic) on 8.7k threads -> instruction-throughput bound. Compile-time determinant masks removed the
  local-memory spill but not the cost. Output-buffer placement (host vs device memory) makes no difference.

## 2. Changes

* **4199ad784b perf(gpu-demod)**: kernels take the job prefix up to `evm[]` as a `__grid_constant__` parameter
  (`JobK`); EVM partial-sum layout for 4 layers (`nr_gpu_evm_sym_t` err_l/qr/qi/qd/qx[4]; header change, host and
  module rebuilt together); `k_evm1<T, NLM>`; `ISAC_PDSCH_GPU_EXACT_DEMOD_EVM_NL34=1` (default off) = GPU EVM for
  Nl = 3, 4; `ISAC_PDSCH_GPU_EXACT_DEMOD_SHAPES=1` (default off, diagnostic) = per (Nl, Qm, RB class) wall/GPU line
  `GPU_EXACT_DEMOD_SHAPES` next to `GPU_EXACT_DEMOD calls=`.
* **245b20988a perf(gpu-demod)**: `k_level` + decision (last block), `k_align` (terms+sums+rotation per 2 chunks),
  `k_tail<MM>` (compensation + MMSE + kappa + LLR per RE; kappa via block sums + 64-bit atomics, integer-exact), stock
  MMSE determinant with compile-time masks. These replace the previous kernels whenever `ISAC_PDSCH_GPU_EXACT_DEMOD=1`
  (no separate flag: same outputs bit for bit, verified above); the path itself stays default off.
* **c7f4b83e21 fix(gpu)**: `ISAC_GPU_LMEM_PRERESERVE=1` (default off) in `nr_csirs_disc_gpu_ops()`: sets
  `cudaLimitStackSize` to the largest local frame of `resident::segment` / `resident::finish` (86 KB) at start-up.
  Log: `[GPU] ISAC_GPU_LMEM_PRERESERVE=1: per-thread local memory 1024 -> 86080 bytes (no error)`.
* Not done: CUDA-graph capture of FEP -> chest -> demod -> LDPC (the stages are separate host calls with CPU work in
  between: geometry, rate dematching; per grant 1 + 3 + 4-5 + graph launches remain); chest / FEP kernels unchanged.
* TLS: no new `__thread` data. Files: `nr_pdsch_gpu_demod.{cu,h}`, `nr_pdsch_gpu_demod_host.c`, `nr_csirs_disc_gpu.cu`.

## 3. What remains to reach < 0.5 ms (not done)

1. **The remaining long stalls** (40-560 ms demod maxima in half the runs): an nsys `-t cuda,osrt` run that contains
   one, then the runtime `cudaMalloc` / `cudaHostAlloc` of the discovery path (403 + 64 calls after PDSCH start on b)
   and the demod context pool (raise `CTX` 8 -> 16 or release the EVM-deferred context earlier).
2. **Chest tails**: single `k_fir` launches of 1,232-1,488 rows (one block per row over all 4,096 subcarriers) last
   up to 66 ms under contention [nsys b]; bound the per-row work to the row's REs + FIR tail (outputs beyond
   `12 nb_rb + 14` are always zero) and split very large jobs.
3. **4-layer stock MMSE** (`k_tail<5>`, 122 us idle for 51 RB) and the FP64 4-layer EVM solve: the main per-grant GPU
   cost left on TIM.
4. Launch count across stages (FEP 1, chest 3, demod 4-5, LDPC 1 graph): one graph per grant shape would need the
   CPU steps between stages moved or overlapped.

## 5. Risks

* `ISAC_GPU_LMEM_PRERESERVE=1` reserves 86 KB x the GPU's resident-thread capacity (~8 GB of the 128 GB unified
  memory) for the whole run — the same amount the first `finish` launch would otherwise reserve at run time.
* GPU EVM for 3/4 layers is a float/double re-implementation of a diagnostic (EVMGRANT / SNR gate input), equal to the
  CPU block to < 1e-4 relative (CHECK), not bit for bit — the same contract as the existing Nl <= 2 GPU EVM.
* 4-layer grants now put FP64 EVM work on the GPU's second stream (SM contention with other consumers).

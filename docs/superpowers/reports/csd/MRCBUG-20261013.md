# MRCBUG (2026-10-13): why the receiver with the higher post-equalisation SNR decodes worse -- the DD-SNR of a FAILED MRC decode is a modulation floor, not an SNR

Host DGX GB10 aarch64, worktree `rr-csd-mrc` (branch `csd/mrc-bug` from `csd/otatest` 2a04ca8145). Build `build_t26` (CUDA, x86-free
cmake config of this worktree); every build, test and replay through `heavy.sh`, one at a time. ENVFILE `ota/t26b.env`. No OTA, no
capture, no UHD in this task. Cells never pooled: **Vodafone PCI 415** (OTA logs `ab_H0{a,b,c}_1_08*` = t26b and `ab_H1{a,b,c}_1_08*` =
t26h, 2026-10-13 08:17-08:50, 150 s each; replays `raw_pci415_12s_b` = "b", `raw_pci415_12s_20261008` = "old") and **TIM PCI 923**
(replay `raw_pci923_tim_12s_tile3` = "tim"). "snr" = EVMGRANT `snr` (decision-directed, float ZF over the combined branches).
Data and scripts: `docs/superpowers/reports/csd/mrcbug_data/` (`ota_H0_H1_analysis.txt`, `dd_floor_and_bound.txt`, `h0*.py`, `cmp.py`).

## 0. Verdict

1. **The bug is in the SNR used to compare the receivers, not in the MRC arithmetic.** The decision-directed SNR has a
   modulation-dependent FLOOR: a stream that is pure noise reads 3.9 dB (QPSK), 9.1 dB (16QAM), 12.5 dB (64QAM) after the RMS
   normalisation and nearest-point decision the estimator uses (`[COMPUTED]` Monte Carlo, `dd_floor_and_bound.py`). The 4-branch MRC
   output of a grant that FAILS is noise-like and reads that floor; the single-branch output of a failing grant is structured
   (interference, phase drift) and reads well below it. `[OTA VERIFIED, Vodafone PCI 415, H0+H1, 6 runs]` failed comb=3 grants
   report an `snr` **1.8 dB (16QAM) / 2.5 dB (64QAM) ABOVE the ideal MRC of their own per-branch LS SNRs** (67 % / 77 % of them more
   than 1 dB above that physical bound); failed comb=1 grants sit at the bound (QPSK, 16QAM) or 5 dB below it (64QAM). Passing
   grants of both receivers sit 2-4 dB below the bound (§2).
2. Consequences. (a) `ISAC_RX_MRC_PER_RNTI_SNR=1` (t26h) fed every full decode, pass or fail, into the per-receiver SNR EMA: each
   failed grant handed the MRC receiver +4..+8 dB against the single branch, so it was picked where the single branch decoded better
   -- the t26h collapse (1-layer MCS 10-16 at `snr` >= 10: 82 -> 51 %). (b) Every "CRC at SNR >= 10 dB" statistic that includes
   failed grants is biased against comb=3: its failing 64QAM grants read 12-16 dB and fill the 10-16 dB bins. That is the paradox
   of the task ("higher SNR, decodes worse"): at equal REPORTED snr the comb=3 bin holds more garbage. The within-RNTI HIGHMCS table
   (MRC higher snr AND higher CRC) is the passing-grant regime, where both estimators are honest (§2.3, genie).
3. **Fix** `ISAC_RX_MRC_PER_RNTI_SNR=2` (default off): only CRC-OK decodes feed the per-receiver EMA; a receiver without 3 passing
   samples falls back to the CRC rule. Unit test `PdschSolver.ReceiverPickIgnoresTheSnrOfFailedDecodes` `[OFFLINE VERIFIED]`.
   Replay pick-share / CRC in §5 (populations differ run to run; the OTA A/B in §6 is the gate).
4. **Secondary, real, a tail effect: the MRC fixed-point headroom.** The output shift charges `log2(live branches)` = 2 bits for a
   4-branch sum whatever the branch imbalance; with one dominant branch the sum is 1.3-2.5x, so 1-2 int16 bits are lost against the
   single-branch receiver on the same grant (`[MEASURED replay b, EVMGRANT zabs=]` mean |z| per dimension: single branch median
   143-196 LSB, MRC 73-89 LSB, MRC p10 32 LSB) and the per-branch floor of `|h_a|^2 >> shift` biases the QAM thresholds low. Shown
   noise-free in `DlschFixedPoint.ImbalancedMrcNeedsTheEnergyShift` (|H| 120-240: 7-8 % wrong 64QAM LLR signs under the count rule,
   0 % under the energy rule) `[OFFLINE VERIFIED]`. Fix `ISAC_RX_MRC_SHIFT_SUM=1` (default off), CPU and GPU, `GPU_EXACT_DEMOD
   check_ok=8000 check_bad=0` `[MEASURED replay b]`. Replay CRC within noise (§4); the genie zero-LLR share of CRC-OK MRC TBs drops
   (old: 8.6/7.8/4.9 % -> 2.7/0.5/0.1 % by SNR bin).
5. Not the bug (checked): the MRC weights ignore per-branch noise `[CODE-READ]` but the float DD estimator uses the SAME weights, so
   that loss is reported honestly; ALIGN=2 overfits one phase per 48 REs (noise-power bias ~1/48) `[INFERRED]`; the fixed-point LLR
   path agrees with the float decisions on passing TBs (HIGHMCS §4, 0.0-0.2 %) and the genie bit-error rate of CRC-OK TBs at equal
   `snr` is the same for both receivers (§2.3); GPU demod is bit-exact (`check_bad=0` in every run, §4).

## 2. The mechanism: a decision-directed floor that the MRC output reaches and the single branch does not

### 2.1 The floor [COMPUTED, Monte Carlo of the estimator's own rule: RMS-normalise, nearest constellation point, EVM]
Pure complex Gaussian noise reads: QPSK 3.9 dB, 16QAM 9.1 dB, 64QAM 12.5 dB, 256QAM 14.4 dB. True SNR -> DD `snr`: 16QAM 0 -> 9.6,
6 -> 10.8, 12 -> 13.0, 18 -> 18.1; 64QAM 0 -> 13.3, 6 -> 15.2, 12 -> 17.1, 18 -> 19.1 (the +2..3 dB optimism HIGHMCS §4 measured at
10-14 dB is this curve). Below ~15 dB true SNR a 64QAM `snr` carries almost no information.

### 2.2 Failed grants sit ABOVE the physical bound on the MRC receiver only [OTA VERIFIED, H0+H1 pooled, Nl=1]
Bound = ideal MRC of the four per-branch LS SNRs (`br_snr`, comb=3) or the best branch's LS SNR (comb=1). `snr` minus bound:

| Qm | receiver | CRC | n | mean | p50 | p90 | share > bound + 1 dB |
|---|---|---|---|---|---|---|---|
| 2 | comb=1 | ok / fail | 2633 / 1283 | -2.7 / -0.1 | -2.1 / 0.3 | -0.1 / 1.8 | 1.7 % / 23.6 % |
| 2 | comb=3 | ok / fail | 4456 / 2098 | -2.0 / -0.1 | -1.8 / 0.2 | 0.0 / 2.5 | 2.3 % / 34.8 % |
| 4 | comb=1 | ok / fail | 631 / 1267 | -4.6 / -0.2 | -4.4 / 0.2 | -1.7 / 1.7 | 0.0 % / 19.6 % |
| 4 | comb=3 | ok / fail | 1291 / 2229 | -2.2 / **+1.8** | -2.1 / **+2.0** | -0.2 / +4.7 | 2.4 % / **66.6 %** |
| 6 | comb=1 | ok / fail | 305 / 278 | -4.4 / -4.8 | -3.9 / -5.0 | -1.9 / -1.0 | 0.3 % / 1.4 % |
| 6 | comb=3 | ok / fail | 553 / 376 | -1.9 / **+2.5** | -2.3 / **+2.8** | +1.1 / +5.6 | 10.3 % / **77.1 %** |

Failed comb=3 grants: 16QAM mean best branch 2.2 dB, ideal MRC 6.3 dB, reported `snr` 8.1 dB; 64QAM 7.7 / 12.0 / **14.5 dB** (the 64QAM
floor with a little signal). Failed comb=1 64QAM grants read 8.0 dB (p50) at a best-branch LS SNR 5 dB higher: their output is
structured, not Gaussian, and the DD rule reads it LOW. 64-83 % of the failed comb=3 QPSK/16QAM grants have >= 2 branches below
0 dB SNR (0 % of the passing ones): the equal-noise MRC sum of those branches is what makes the output noise-like `[INFERRED]`.
CRC-fail `snr` medians by Qm: comb=1 1.2 / 4.4 / 8.0 dB, comb=3 3.8 / 7.8 / 14.8 dB (floors 3.9 / 9.1 / 12.5).

### 2.3 Passing grants are honest on both receivers [MEASURED, DGX replay b, t26b + ISAC_RX_MRC_PER_RNTI_AB=1 (round robin), RM genie]
Genie LLR-sign error of CRC-OK TBs by `snr` bin 6-10 / 10-13 / 13-16 / 16-19 dB: comb=1 2.37 / 1.00 / 0.12 / -- %, comb=3 2.21 /
0.91 / 0.24 / 0.03 % (n 82-107 / 43-77 / 16-44 / 20). Same curve: when a decode passes, `snr` means the same thing on both receivers.
kappa (|z| / QAM threshold) is 0.99-1.00 for both above 13 dB; below 10 dB it is 1.15 (comb=1) vs 2.06 (comb=3): the MRC output of
failing QAM grants is noise with no amplitude structure (kappa > 1.3 grants pass 0 of 88 on OTA, all bins).

## 3. Why the SNR pick collapsed (t26h) [ORCH + OTA VERIFIED]
`comb_pick()` with `ISAC_RX_MRC_PER_RNTI_SNR=1` takes the receiver with the higher EMA of `snr` over ALL full decodes of the RNTI.
On an RNTI whose QAM grants fail on both receivers the comb=3 samples read 8-15 dB and the comb=1 samples 1-8 dB (§2.2), so the EMA
gap is +4..+8 dB for comb=3 regardless of which receiver passes more. H1 moved the comb=3 share from 52 to 77 % and the MCS 10-16 CRC
at "snr >= 10" from 82 to 51 %; the comb=3 grants H1 added are the ones reading the floor (comb=3 kappa > 1.1: 48 % of QAM grants in
H0, 0.8 % of them pass).

## 4. The secondary defect: MRC headroom from the branch COUNT [CODE-READ, OFFLINE VERIFIED, MEASURED replay]
`nr_rx_pdsch()` (and `nrd_decide()` on the GPU) size the int16 output shift as `(log2|h|^2_max >> 1) + 1 + log2(contributing)` with
`contributing` = number of live branches (those within 12 dB of the strongest in |h|^2, chest noise included). On air 4 of 4 branches
are live on 97 % of the MRC grants while the branch SNRs sit up to 15-20 dB apart, so the output is shifted for a 4x coherent sum that
is 1.3-2.5x. `ISAC_RX_MRC_SHIFT_SUM=1` replaces the count with round(sum_live |h_a|^2 / max |h_a|^2) (`nr_mrc_shift_branches()`,
`nr_mrc_weights.h`; same integer arithmetic in `nrd_decide()`): balanced branches unchanged, one dominant branch = the single-branch shift.
- `[OFFLINE VERIFIED]` `test_dlsch_fixed_point`, 4 branches, one 10 dB above the others, exact H, no noise, 64QAM, 273 PRB:
  |H| 120: count rule 8.19 % wrong LLR signs, energy rule 0.000 %; |H| 240: 7.17 % vs 0.000 %; |H| 60: 21.0 % (kappa 1.48) vs 6.96 %;
  |H| >= 480: both exact. Balanced branches: identical shift and LLRs. `test_nr_pdsch_gpu_demod`: 0 model mismatches.
- `[MEASURED, DGX replay b, CHECK=1]` `GPU_EXACT_DEMOD calls=8000 check_ok=8000 check_bad=0`, 0 MISMATCH lines with the flag on.
- `[MEASURED, DGX replay b, CPU demod, EVMGRANT zabs=, n 1590]` int16 output level: single branch |z| median 143-196 LSB (p10 68-73),
  MRC 73-89 (p10 32-33). The unit test's failing regime is |z| <= ~15 LSB, so on these captures the defect bites only the low tail;
  quantisation is not the main loss at these levels (the LDPC input sees mean |LLR| 200-700, LLRDIAG).
- `[MEASURED, DGX replay, EVMGRANT l2=]` the shift moves by -1 bit on most MRC grants (b: comb=3 mode 10-11 -> 9-10 with comb=1 at 9;
  tim: 10/12 -> 9/11 with comb=1 at 8/10). 20-30 % of the Nl=1 grants sit at l2 <= 9 (|h| <= 256), the region the unit test shows losing.
- `[MEASURED, DGX replay, AB round robin, 1 run/arm, CRC at snr >= 10]` CRC within run noise: b comb=3 MCS 5-9 81.7 (60) -> 75.3 % (81),
  tim comb=3 MCS 10-16 30.8 (107) -> 29.5 % (95), old comb=3 MCS 10-16 83.3 (6) -> 100 % (6). Genie zero-LLR share of CRC-OK comb=3 TBs,
  old, bins 10-13 / 13-16 / 16-19 dB: 8.6 / 7.8 / 4.9 % -> 2.7 / 0.5 / 0.1 % (b: 0.8 / 0.2 -> 0.8 / 0.2, no change). A resolution gain,
  not a CRC gain at these n. Keep default off; candidate for the OTA A/B below.

## 8. Open
- The DD estimator itself: a floor-free SNR needs a non-decision-directed estimate (e.g. the LS branch bound `br_snr`, which is also
  decision-directed but reads the FIT of y to h s and does not saturate upward). Not changed here; `br_snr`-based pick not tried.
- Why the single-branch failing output is structured while the MRC one is noise-like is inferred (equal-noise sum over sub-0 dB branches),
  not measured per RE.
- Mean |LLR| at the LDPC input is 440-740 (OTA LLRDIAG) against an int8 rail of 127 in the CPU segment path: a known, separate item
  (`ISAC_LLR_SCALE`, opt-in, not in t26b); not measured here.
- Replay CRC of the headroom fix at n >= 1000 per bucket; 12-dB mask vs noise-weighted MRC (`ISAC_RX_MRC_PER_RNTI=2` receivers 4/5) on air.

# MPCI A10 — cell identity at sync (2026-10-29)

Branch `mpci/c-a10` off `mpci-main` 51c8f013ab. Host for everything below: DGX GB10 (aarch64), shared with another user; builds and unit tests only, no replay, no radio.
Problem and evidence: `DL-HEALTH-20261029.md` section 4 and problem 2 (`[MEASURED, DGX+X410 34B2AF1, 2026-10-28]`: 2 of 24 cell starts locked a co-channel PCI, sw28_P1 c0 415 -> 380, mp28m_Q1 c1 403 -> 27, and decoded nothing).

## What changed

1. **Descriptor PCI registry** (`radio/COMMON/ru_park.{h,c}`): `ru_cell_want_pci_set(cell, pci)` / `ru_cell_want_pci(cell)` (-1 = unknown, the default for every cell and for a receiver without inventory), and a per-(cell, kind) log rate limiter `ru_cell_sync_note_due`. Lock-free atomics, no allocation. Three new statics, classified PROCESS in `tools/mpci/mpci_statics.tsv` (`--write` then `--check`: rc 0; UNCLASSIFIED stays 54, all G1, none new).
2. **Writers** (`executables/nr-uesoftmodem.c`): the descriptor's own `pci` is stored in `mpci_cell_prealloc` (every cell, before its slot thread's first search), in `mpci_cell_start` on a reactivation (live re-add, A12) and in `mpci_cell_retune` — each BEFORE the tuning is posted, so the re-acquisition that follows already pins it.
3. **Reader** (`executables/nr-ue.c`, `UE_synch`, the single entry of every search: initial, RX_RECOVER fast/coarse/full fallback, SFO-rebase re-acquisition, live re-add, scan confirm): when the registry holds a PCI for `UE->Mod_id`, `UE->target_Nid_cell` is set to it. That is the existing pin (PSS N_ID_2 in `pss_search_time_nr`, SSS N_ID_1 in `rx_sss_nr` in passive mode). `apply_live_tune` still resets the target to -1, and `UE_synch` re-pins right after. With no descriptor PCI nothing is touched (N = 1 without inventory: byte-identical path).
4. **Defensive gate + log** (`UE_synch`): a lock whose `Nid_cell` differs from the wanted PCI is rejected (`cell_detected = false`, scanning continues); this cannot happen while the pin holds, it is a guard. A search that finds nothing logs once per 10 s window and cell. A lock logs every time (rare event).
5. **Pinned search made robust against a stronger co-channel cell** (`pss_nr.c`, `nr_initial_sync.c`): a first version of the unit test showed that pinning alone is NOT enough when the wanted cell is ~10 dB weaker. The pinned PSS search takes the global correlation maximum of the wanted N_ID_2, and the leakage peak of the stronger cell's SSB (other N_ID_2) can exceed the wanted cell's own peak; the SSS stage then accepts the garbage position (one pinned N_ID_1 trivially beats "the second best", `rel_ok`), the PBCH CRC fails, and every later capture repeats the same wrong peak. Now a PSS search pinned to one N_ID_2 over the full capture (stock int16 path, stride 4, and the decimated passive path) also reports the next two peaks, at least one SSB apart, in the unused result slots; `nr_search_ssb_common` evaluates the candidates (refactored into `ssb_try_candidate`) and keeps the one with the best pinned SSS metric (the frequency-domain symbols and compensation are redone for the winner). A blind search (target -1) is unchanged: first accepted candidate returns, as before. N = 1 differs only in pinned FULL searches (RX_RECOVER full fallback, MAC-driven resync): best of at most 3 peaks by SSS metric instead of the first; windowed/coarse recovery searches are unchanged.
6. **Test** `test_nr_sync_pin` (`openair1/PHY/NR_UE_TRANSPORT/tests/nr_sync_pin_check.c`, in ctest): production `nr_search_ssb_common` on a synthetic capture (2048-FFT, 106 PRB, mu 1) with two co-channel SSBs of distinct PCIs at distinct timings and an independent TS 38.211 transmitter, the wanted one 9.8 dB weaker, for both the stock and the decimated PSS path, for the two observed pairs (strong 380 / wanted 415, strong 27 / wanted 403).

No flag, env var, CLI option, `-D` switch or test seam was added (the test calls the production function with a plain struct). Nothing is PCI-specific; the only value used is the descriptor's own.

## Limits `[CODE-READ]` / `[HYPOTHESIS]`

- Pin = N_ID_2 + N_ID_1 + the SSB frequency position the tune already sets. The descriptor's `ssb_index` (beam) is NOT enforced: a cell has several beams and the receiver follows the one it syncs to; enforcing the descriptor's beam could lock out a valid beam. The wrong-lock cases (idx 1 instead of 4 / 3) had the wrong PCI, which the pin removes.
- Two co-channel cells with the SAME N_ID_2 are separated by the SSS pin only if the wanted cell's PSS peak is the global maximum (or one of the next two): same-N_ID_2 neighbours (e.g. 415 vs 100) share one correlation profile. Not tested synthetically.
- If the wanted SSB is not on air or not decodable in a capture, the cell now stays unsynchronised and keeps scanning (it used to lock the neighbour). `SCAN_PBCH_FAIL ... pci=` lines continue to be printed per failed scan; the `MPCI_SYNC ... not found` line is limited to 1 per 10 s and cell.

- Live re-add (A12): after `MPCI_LIFE cell=k ... back in the inventory` the next `MPCI_SYNC cell=k ... locked` must carry the re-added descriptor's PCI.
- N = 1 / no cells.json: no `MPCI_SYNC` line at all.
Also compare `SYNC_SCAN ms=` and sync latency against the baseline: a pinned search evaluates up to 3 candidates (cheap SSS on one N_ID_1).

# DECQUEUE -- PDSCH decode-queue isolation (2026-10-10/11, branch csd/dec-queue)

Goal: PDSCH per-grant decode (sum of fep+chest+demod+ldpc stage means, and p50) < 0.5 ms without CRC regression.
Labels: [MEASURED OTA] = DGX OTA 2026-10-10 23:1x Vodafone PCI 415; [MEASURED replay GB10] = offline replay on this DGX (heavy.sh, HEAVY_CPUS=0-14); [CODE-READ].

## Findings
1. [MEASURED OTA] t26q (t26p_ul + DMRS_ID_SCAN=16 + UL_LOCK_SIB1_FIRST + UL_LOCK_CRC_FIRST) vs t26p_ul: fep 288/140, chest 222/170, demod 636/532, ldpc 532/341 us. [CODE-READ] cause candidates, all confirmed in the OTA run.log (ab_Vq1_1_231143):
   - the PUSCH consumer thread is created unpinned at FIFO 50 ("passivePusch0: affinity ffffffff, priority 50"), above the PDSCH consumers (FIFO 40, cores 7,8,9,3,4): it can preempt any of them. UL_PUSCH_SOLVER cpu_us_per_probe = 6049 us.
   - the DM-RS ID full scan (~65 ms, 16/s allowed) runs INLINE on a PDSCH consumer (dmrs_scan_job): up to one decode core fully busy.
   - 25-37 % of bodies are retry bodies. OTA: 5803 DECODETDRA chains in 15772 decodes; 2446 rescued (all by arm 2 = start-symbol toggle), 3350 failed after 3-7 extra bodies PLUS a final re-decode of the plain reading whose only purpose was restoring `*out`. PDTIM calls (31600) = 2 x decoded grants.
   - FEP slot share: SLOTSHARE fep hit/miss = 4385/13656 (24 % hit; cache is per consumer thread), chest hit 1.4 %. [MEASURED replay GB10] Sharing across consumers needs a ~0.9 MB copy per hit (~ the FEP cost itself), so it is NOT implemented.
   - 86 % of solver-era decodes are probes (PDSCH_SOLVER probes=6015 of 7000 grants, probe_ok=71) even with 28/31 candidates solved; probes are for the unsolved RNTIs, not for solved ones.
2. PDTIM means are per BODY, not per grant. Removing cheap retry bodies (FEP cache hit) RAISES the per-body mean; judge arms by CRC-OK and by bodies/grant too.

## Changes (all default off; flag-off path unchanged except the always-on `out_plain` struct copy in passive_decode_retry)
| flag | effect |
|---|---|
| ISAC_PUSCH_CORES=<list>, ISAC_PUSCH_PRIO=<n> | pin the PUSCH consumers, set their priority (0 = SCHED_OTHER; default 50) |
| ISAC_PDSCH_DMRS_SCAN_ASYNC=1, ISAC_DMRS_SCAN_CORE=<c> | DM-RS ID scan + pool votes run on one SCHED_OTHER worker thread on a copy of the DM-RS symbol (4-deep ring, full ring drops the job) |
| ISAC_PDSCH_RETRY_PREDICT=1 | per-RNTI streak (nr_pdsch_retry_pred.h): after 2 rescues by the S-toggle arm, that arm runs first; a miss resets the streak |
| ISAC_PDSCH_RETRY_NORESTORE=1 | no final re-decode of the plain reading after all arms failed; `*out` is restored from a copy taken after the first body |
| ISAC_PDTIM_PCT=1 | extra PDTIMPCT log line with per-stage p50/p99 (16 us buckets) |
Tests: test_nr_pdsch_retry_pred (2), test_nr_core_plan EnvList.Nth (nr_env_list_nth) pass. Scripts: tests/passive_rx/dtq_arm.sh (arm A=t26q, B=A+isolation, C=B+retry flags), dtq_sum.py, timul_replay.sh.

## What remains for < 0.5 ms
Isolation recovers at most the t26q-vs-t26p_ul gap (OTA 1678 -> ~1200 us); the t26p_ul base (fep 140 + chest 170 + demod 532 + ldpc 341) is itself 2.4x the target. Needs: GPU/CUDA stages (dtg worktree: ISAC_PDSCH_GPU exact FEP/chest/demod, currently GPU=0 in t26q), cutting bodies per grant (2.0-2.9 now), cross-consumer FEP/chest reuse without copies (same-slot grants on one consumer), and a steady-state replay (>= 60 s capture or solver-state preload) to measure it. OTA test of arm B (flags on t26q + ISAC_PUSCH_CORES=6 or 17, ISAC_PUSCH_PRIO=30, ISAC_PDSCH_DMRS_SCAN_ASYNC=1 ISAC_DMRS_SCAN_CORE=2 or 18) is the next step.

# USSHASH-20261014 -- cost of the `pdcchUssHash` thread

Branch `csd/usshash` (from `csd/scan2` fed40c4904), DGX GB10, `build_t26`. Labels per PROJECT_MEMORY 0.1. Replay = `scan2_arm.sh` -> `p99_replay.sh`, env `ota/t26bPQ.env`, SPEED=1,
one replay at a time under heavy.lock, n=6 per arm interleaved, captures never merged. R = `ISAC_SCANCOST=2 ISAC_LOG_ASYNC=1`, flags off. X = R + `ISAC_PDCCH_USS_FAST=1 ISAC_PDCCH_USS_TRACK_BACKOFF=4`. Not OTA.

## 1. Profile: the premise was different `[CODE READ]`
`pdcchUssHash` (`nr_pdcch_uss_tracker.c`) does NOT decode known UEs. It is the *discovery tracker*: for each geometry (CORESET) it keeps 64 strongest-candidate observations and, at
8/16/32/64 and then every 256 observations, scores ALL 65535 RNTIs x 3 hash ids x <=64 samples x 7 M hypotheses (TS 38.213 Y_p,k position vs observed CCE), integer/float only: no FEP, LLR or polar,
no samples touched. The cost was a 64-bit `%65537`, a `% N`, a float division and an sqrt in the innermost loop, repeated every 256 observations per geometry. So the FEP-reuse / per-RNTI
AL / RNTI-merge / TDD-skip levers of the brief do not apply to this thread (the per-RNTI USS-hash decode filter is `ussh_allows` in the monitor, a different, already gated path).
Profile by inspection plus per-thread CPU ticks (cpu.txt).

## 2. Change (default off)
- `ISAC_PDCCH_USS_FAST=1`: `score_compute_fast`, same ranking: modulo via 2^16 = -1 (mod 65537) fold + reciprocal multiply (exact, N<=135), per-sample weight tables (w*vh, w*vm), hit test = one byte of a (N,delta) mask. Only float rounding differs.
- `ISAC_PDCCH_USS_TRACK_BACKOFF=k`: a geometry that has a stable RNTI is rescored every 256*k observations instead of 256 (first rounds 8..64 unchanged; a new RNTI is still found at the next due round).
- `nr_pdcch_uss_tracker_score_test` hook + gtest `UssTrackerFast.MatchesReferenceAndFindsPlantedRnti` (in test_nr_pdcch_blind_monitor): ref vs fast top-4 RNTIs and hit counts identical, scores within 1e-3. Passes.
- Full ctest on build_t26: only the known failures (dft_test, test_nr_modulation, qam64, qam256, test_nr_td_grantwork).

## 5. Core placement `[CODE + ENV READ]`
starttest.sh prefixes `ISAC_PDCCH_USS_CORE=7`, then the env file's `ISAC_PDCCH_USS_CORE=12` comes later in the same `env` call: **12 wins** (the replay line shows both). Core 12 also hosts
`ISAC_CSIRS_DISC_DETECT_CORES=12,13,14` (and 13 = nID GPU core); core 7 is a PDSCH core. The thread is SCHED_OTHER, so it time-shares with those. With FAST the load is small enough that placement matters little; no move made.

## 7. Risks
Replay only (load ~half of air), n=6; b CRC noise hides small effects. Backoff delays discovery of a NEW RNTI on an already settled geometry by up to 3 extra rounds (~1024 observations); first rounds unchanged, FAST alone is
ranking-identical so FAST=1 BACKOFF=1 is the zero-risk subset. Not done (not applicable to this thread): FEP reuse, per-RNTI AL restriction, RNTI merging, TDD slot skip.

## Findings that shaped the design [READ FROM CODE]
- The async recovery lane already existed and is on in the frozen config (ISAC_PDSCH_RECOVERY_ASYNC=1, nr_pdsch_recovery.c, `t_recov_mode == 1`): a failed first pass of a dedicated DCI 1_1 grant returns, EVMGRANT is logged at first-verdict time, and the arms run on pdschRecov from an IQ snapshot. The held feedback (solver token, crc_note, bwp, layout, Technique D, data-id, xoverhead) is delivered once by `recov_feedback`. In gTZ1, bodies p99 = 1 (RESULT.md), so the tail is the first body of failing grants, not inline arms. The gate therefore carries most of the benefit.
- What was missing: the worker did not yield to first-pass work, a full lane dropped the NEWEST job, and UL_RETRY ran before the UL verdict.

## Changes
1. Yield: `nr_recov_yield.h` (one rule, tested). The worker waits (poll 100 us, max 2 ms) while `nr_pdsch_passive_first_pass_waiting()` (DL real ring backlog or UL real queue pending) is true, before each job and before each arm; then it gives the remaining arms up (counted `yielded` / `g_ry_yields`). No new thread: pdschRecov is the existing worker.
2. Drop-oldest: `nr_pdsch_recovery_acquire` on a full lane evicts the oldest queued job (never the running one), delivers its FAIL feedback and done hook once, counts `dropped_old`. Busy lock still drops the newest (`dropped_full`, never waits).
3. UL: the UL_RETRY alternates now run after the verdict (UL_E2E / UL_PUSCH_CRC at first-decode time), on the same consumer, re-checking `nr_pusch_passive_rescue_allowed()` before each alternate; the IQ capture is released after them. A rescue logs `UL_RETRY ... late tot_us=` (no second UL_PUSCH_CRC line) and applies the withheld updates (g_crc_ok, ticket CRC-OK feedback, ids confirm, discovery and FDRA feedback).
4. No-chance gate, shared helper `nr_snr_gate.h` (T64/T256/TLOW, exact goal_metrics.py formula, threshold required - 5 dB, NaN for reserved MCS, tbl>2 reads T64).
   - DL: in `passive_decode_body_core` right after the chest's dmrs_snr fill, test `dmrs_snr.comb_db`. Skip: no demod/LDPC, status CRC_FAIL, `out->skip=1`, EVMGRANT `skip=1` (else `skip=0`), e2e stamped as normal; `passive_decode_retry_impl` returns at once (no predicted arm, no async hand-off).
   - UL: in `nr_pusch_passive_decode` before the HARQ acquire / LDPC / UCI search, on `ul_dmrs_snr_db`; UL_PUSCH_CRC `skip=`; no UL_RETRY.
   - Exempt: probes (t_probe_first_seg, probe_last_sym, no_horizon, UL layout probe/trial, solver probe), non-dedicated RNTI classes (SI/P/RA), UL transform precoding, grants without estimate (-99). rv != 0 is exempt when combining is on (`harq_combine_on()` for DL, `ul_harq_combine_on()` for UL); both states work.
   - Not covered: the GPU graph pass (frozen default) estimates inside its graph, so a gate between chest and demod needs a hook in nr_gpu_pass_graph.cu (off limits). The gate acts on the CPU/exact-GPU body path (graph fallback, retries, need_cpu). Follow-up on csd/int16-fixad: after the C sub-graph (split mode) test `nr_snr_no_chance()` and skip D and L.

## What each retry arm feeds, and how it is preserved
| arm / action | feeds | preserved by |
|---|---|---|
| TDRA S toggle (arm 2), predicted-first | `nr_retry_pred_hit/miss`, g_ry_try/ok gate | predicted body is still the first decode inline (only for RNTIs with a proven toggle; skipped on a gate skip); the worker runs the same counters |
| CSI-RS rate match, CSI population, DM-RS CDM, wide MRC | `out->config_recovered`, g_ry_try/ok, DECODETDRA log | run on the worker, same code |
| rescue (any arm) | solver token CRC-OK, `nr_pdsch_passive_crc_note`, bwp_crc_result, dci11_layout_feedback, Technique D sweep, data-id feed, xoverhead/qm observe, RRC harvest, MAC TA, replay, RECOVLATE tot_us | `recov_run` / `recov_feedback` (unchanged); RECOVLATE stays creditable in goal_metrics.py |
| no rescue / evicted / yielded / expired / epoch change | the same feedbacks with the FAIL outcome, exactly once | `feedback()` guard, eviction path, yield path, tests |
| UL_RETRY rescue | g_crc_ok, ul ticket confirm, ul ids, discovery/FDRA feedback | late block in nr_pusch_passive_queue.c |
| gate skip | same learning as any CRC fail (solver, layout, ids failed) | normal failure path; no retry feedback is owed |

Arms never feed DL HARQ soft state (all are disabled with `harq_combine_on()`); UL HARQ is stored by the first decode as before (the alternates ran after it before too).

# ULBWP-20261014: why the blind UL BWP lock fails on Vodafone PCI 415 (3680.01 MHz, 217 PRB)

Host: DGX Spark (aarch64). Read-only analysis of OTA run logs (`~/NICOLA/ota_runs/ab_*`), no build, no replay (receivers were running, OTA window open). Code read: `openair1/PHY/NR_UE_TRANSPORT/nr_pdcch_ul_layout_lock.c` (vote/lock rule), `nr_pusch_passive_decode.c` (probe). Labels: [MEASURED, DGX OTA, log] unless stated; no capture replay done [NOT MEASURED].

## Verdict

Not SNR-limited and not a hypothesis-space or DM-RS bug. The lock fails because the **vote evidence is statistically thin** (4 informative votes in 150 s against the 6 needed), made thinner by probe starvation and by a UE population that produced few informative strong grants. Mix, dominated by **thin evidence / vote yield**; the UL SNR is adequate wherever there is a grant. The true layout is 217@0 and the receiver already ranks it first in this run.

## Evidence

1. **The true layout is in the hypothesis set and wins** [MEASURED, T0a `ab_T0a_1_091016`]: among probes with best >= 6 dB and >= 2 dB over the second hypothesis (informative, non-degenerate), 217@0 has 4 votes, every other hypothesis has 1 (215@1, 212@3/4/5, 189@0, 178@39, 135@4). The same count in other runs of the same cell: S4c 12 vs 1; VY2 103 vs 7; H0b 172 vs 7 (216@1). Plurality is always 217@0 (= the DL BWP).
2. **SNR is not the limit** [MEASURED]: T0a probe lines show best DM-RS MRC SNR of 6-20 dB on 59 of 7606 probes (0.8 %); 12 informative. Strongest examples 19.9, 17.6, 17.6, 16.0, 15.9, 15.1 dB. Control (wrong-slot DM-RS) >= 6 dB on 3 probes (0.04 %), mean ctl -4.8 dB. The weak contrast the task quotes (best 0.7-2.2 vs ctl) is the typical probe (mean best +1.7 dB = max over 192 noise-only hypotheses), i.e. grants of UEs with no detectable PUSCH; it says nothing about the grants that do carry a signal. UL_PUSCH_CRC snr_db unusable (always 0.0).
3. **Same cell, same flags, same morning, it locks** [MEASURED]: 217@0 locks in S4a, S4b, S4c, T0b, T2c (14/6/10/16/6 votes) and in 2026-10-12 VY2, Vz1, Vz2, Vy2, S0a, S1a, S1b, S0c, S1c. T0a/T1a/T1b/T0c/T1c do not lock in 150 s. Informative-probe yield per fed probe: T0a 0.16 %, S4c 0.43 %, VY2 1.7 %, H0b 3.8 %. So T0a is a low-yield window (about 3x below S4c), not a broken pipeline.
4. **Starvation is real but not the discriminator** [MEASURED]: T0a fed 7452 of 38140 booked probes (20 %); core_fraction 0.179. But locked runs are similar: T0b fed 453/6237, core_fraction 0.152; VY2 fed 9948/30879, 0.199. PUSCHQ T0a: queued 45292, decoded 251, dropped full 16338 stale 20377. With 5x feed T0a would have ~20 217@0 votes (extrapolation [INFERENCE]), i.e. a lock in ~45 s, so full feed would very likely have fixed this run, but the lock outcome across runs is dominated by the yield, not by the feed fraction.
5. **Most strong detections cannot vote** [MEASURED]: of 59 strong T0a probes, 47 have best == second == third (degenerate: 180@x/179@x-1/178@x-2, identical PRBs, `tied=39`). They are the L=1-type grants of the strongest UEs; by design they vote for nobody. Only 12 are informative.
6. **Lock rule is fragile in both directions** [MEASURED]: LOCK_MIN 6 votes, ratio 2, 2 RNTIs. With ~6 votes the early sample decides: many runs lock "216@1:6" with 217@0 at 0-3 (T2a, T2b, M*, L2, K3, SV1 ...), H0b locked 216@1 at 6 votes/53 s and, after a reset, accumulated 217@0:177 vs 216@1:32 in the same run (no relock by the end). 216@1 is the structural look-alike: for a true 217@0 grant of L PRB, hypothesis 216@1 reads the next L PRB, which in a packed high-load slot is another UE's PUSCH carrying the same PCI-scrambled DM-RS. The collision guard only covers neighbours that are themselves pending probes. [INFERENCE from the geometry and the 216@1 : 217@0 ratio of 0.2-0.5 in data-rich runs]. This also explains why capture b (10-08) locked 216@1 [replay, ULLAYOUT.md] while 217@0 dominates every OTA run with >100 votes: the 216@1 locks are a thin-evidence artefact [INFERENCE; the true UL BWP of that capture was not independently verified].
7. hyps=192 (ISAC_UL_LOCK_BWP_ALL=1) vs 63: no extra false votes (ctl_votes 3 of 19), so the larger set is not what blocks the lock; it only costs a little max-of-N noise.

## Root cause

Lock needs >= 6 non-degenerate, non-colliding >= 6 dB votes, but (a) 80 % of probes are dropped before scoring (full/stale queue on a shared RR core), (b) 80 % of the strong detections are degenerate and vote for nobody, and (c) the T0a UE mix gave only 0.16 % informative yield. The decision rule is a hard count, so 4 correct votes against 1 are discarded; the same weak rule false-locks 216@1 elsewhere.

## Proposed fix (not implemented: no build/replay possible during the OTA window; general, no cell constants)

1. Replace the hard count by a likelihood/sequential test on the existing per-hypothesis tally (an SPRT path already exists behind `nr_ul_layout_sprt_enabled`; the votes are binomial with a measurable noise rate from ctl_votes). Lock on log-likelihood ratio of leader vs runner-up, so 4:1 with ctl 0.04 % locks while 6:2 early flukes do not.
2. Book only informative probes: skip grants whose testable ranges coincide for the top-K hypotheses (twins), and prefer fresh DCIs, so the 20 % that fits the worker is not wasted on probes that cannot vote.
3. Give the UL consumer its own core (ISAC_PUSCH_CORES not shared with the PDCCH scan, or priority above it) during the layout-search phase only.
4. Use the DL BWP (217@0) and SIB1 UL size as an explicit prior in the test (cheap: it is already hypothesis 1 in the data), but never as a forced answer.

## OTA test to confirm

Two 150-300 s arms on the same cell at the same hour: A = t26bC as is; B = same with the UL consumer on a dedicated core (fed fraction >= 80 %). Prediction if starvation matters: time to 6 votes for 217@0 drops roughly in proportion to the fed fraction and T0a-like windows lock. Prediction if yield matters (this report): B still shows an informative yield 0.2-0.5 % and the lock time varies run to run by 3x regardless of feed. Log per-run: fed/booked, informative strong probes per hypothesis (this report's awk on ULLAYOUT_PROBE lines), and the final tally.

## Not checked

DMRS-estimator internals (delay search, TA, freq-offset sign) were not audited; evidence (up to 20 dB hits on the right hypothesis, ctl at noise) says they work. No replay with the SPRT path; no per-UE SNR from the gNB noise table (unavailable).

### Residual issue (not fixed)
216@1 (and 216@0) are structural look-alikes of 217@0 (shift by L PRB, same-scrambling DM-RS of neighbouring UEs): in packed slots the winner-take-all vote lets the neighbour's stronger DM-RS vote for the wrong hypothesis. Proposed next step: replace the vote by a per-hypothesis hit-rate with a pairwise sign test (a-only vs b-only detections), which a neighbour cannot fake because b-only requires the true UE to be undetected. Env line for the next OTA: add `ISAC_UL_LOCK_LLR=1` (and optionally `ISAC_PUSCH_SEARCH_PRIO=60`, which the C arm showed only changes timing).

# TIMMCS0 (2026-10-12): TIM MCS-0 CRC 46-55 % at SNR >= 10 dB -- status: root cause NOT established, one real defect found, diagnostics added

Host DGX GB10, worktree rr-csd-tm0 (csd/tim-mcs0 from ebb50d1dea). All builds/tests/replays via heavy.sh; no OTA, no captures.

## Findings
- [MEASURED, DGX OTA 2026-10-11, ab_Tt3_1_105947, MCS 0 probe=0 SNR>=10, n=1552] pass/fail is a coin flip with NO dependence on any
  logged field: Nl 1 (543/1078 pass) / Nl 2 (220/472), nsym 13 vs 11, comb 1 vs 3, cdm, ports, snr, snr_cpe, rho, kappa all ~50/50.
  => not RE mapping / DM-RS power / CSI-RS rate matching (those depend on nsym/cdm/ports/position and would not be uniform). A random
  per-grant bit is the signature of a DCI field read from a wrong position (NDI toggles per new TB) -> rv.
- [MEASURED, replay DGX raw_pci923_tim_12s_tile3, ENVFILE t26v, 0.25x, ISAC_RV_RETRY=1] SENSING: RVRESCUE (new log): 9 MCS-0 grants of
  RNTI 0x5264 had DCI rv=1 (ndi=0) but decode only with rv=0 -> a real misread of rv by the solved layout (SOLVEDLAYOUT new log: this
  cell's RNTIs solved to layouts 861/903/905 with MCS offsets 16/18/18: layouts 2 bits apart all read MCS 0 on zero bits, so the CRC-proven
  layout of an RNTI whose passes were MCS 0 need not be the true one, and its rv bits sit on other fields).
- BUT the replay does not reproduce the OTA rate: MCS 0-4 >= 10 dB passes 328/379 (86 %) base, 323/379 with ISAC_RV_RETRY=1 (+0), rescue
  only 9 grants (one RNTI). Mixed with ISAC_PDSCH_READING_RV=1: 158/183 (86 %, fewer decodes in total: 322 vs 551, replay variance not
  separable at n=1). tim_4s_1010_1853 yields no decodes in any arm (t4 tiny). So rv misread explains <= 3 % of MCS-0 failures in
  these replays; whether it explains the OTA 50 % is [HYPOTHESIS] (OTA logs of 10-11 carry no rv/ndi).

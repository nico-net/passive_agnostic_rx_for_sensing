## 3. Change: SOLVERTDDEND (`a2a40f8b68`)

- The monitor reads the slot's last DL symbol from the broadcast TDD pattern. This is `nr_passive_acq_tdd_pdsch_last_symbols`, the same source the TDA-field rows use; it is false or unknown without SIB1. The value goes to the solver through `nr_pdsch_solver_set_slot_last()`, per scan-consumer thread, set for every grant.
- Trigger: a solved RNTI whose decode allocation (S + L - 1) ends after that symbol.
- Effect: the slot phase is searched from its first grant, with the DL end first for each start symbol and then the usual end-symbol rotation. The old path waited for `SOLVER_PHASE_FAIL = 8` failures and `full_ok >= 20`.
- Flexible symbols are not excluded, and the full decode itself is unchanged.
- Without TDD knowledge the old rule applies unchanged.
- **The rfsim phy-test bed has no SIB1** (`tdd_unknown` in every TRAFFIC line, `tdd[sib1=0]`), so this rule is inactive in both rfsim beds. r273_b confirms it: "failed 8 of 8", unchanged. **Live effect on an SA cell with SIB1 TDD: `[IMPLEMENTED, NOT VALIDATED]`.**
- Unit test `PdschSolverPhase.TddEndSearchesTheSpecialSlotFromItsFirstGrant` `[OFFLINE VERIFIED, sens6 x86]`: 2 failed special-slot full decodes with the TDD end versus 18 without; first special-slot pass at grant 27 versus 187; full slots unaffected.

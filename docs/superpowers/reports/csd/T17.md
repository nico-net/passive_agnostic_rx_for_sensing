## Implementation [CODE-READ]

- `openair1/PHY/NR_UE_TRANSPORT/nr_pdcch_nid_gpu.h:36`: bounded record/generation hand-off, C module ABI, capture configuration.
  T15 integration point is **`nr_pdcch_nid_gpu_records(out, capacity, &generation)`**:
  `-1` means no new generation (or consumer lock busy), otherwise the returned number of records,
  including zero. Fields are `nid, sym, dur, grid_rb, groups, L, R, shift, ties`.
  Each consumer owns its generation cursor. It must not reuse an old list after a zero-count update.
- `openair1/PHY/NR_UE_TRANSPORT/nr_pdcch_nid_gpu.c:40`: three pinned staging batches, nonblocking producer try-lock/drop,
  one explicit `SCHED_OTHER` worker pinned to one allowed core. Upload completion releases staging
  before analysis; the worker never holds the capture mutex during a CUDA call. Allocation, dlopen,
  thread creation and CUDA kernel warm-up precede RX. Stop joins the worker before freeing resources.
- `openair1/PHY/NR_UE_TRANSPORT/nr_pdcch_nid_gpu.cu:186`: explicit CUDA device allocations for the rolling history and scratch;
  only new IQ and slot/symbol metadata are uploaded. Stage 1 sweeps all 65,536 IDs for each captured
  start symbol, makes the 4096-bin median/MAD decisions, accumulates hits, and selects the Poisson
  shortlist on the GPU. Stage 2, including duration, phase/extent, all legal L/R/shifts, AL census,
  consistency gating, paired decoys, ties and residual subtraction, executes on the GPU.
  Metadata/result/control transfers also use buffers pinned at init, avoiding pageable-memory
  staging in the processing path. Only bounded results and two control integers cross back to the CPU. No managed-memory bulk
  arrays or CPU-side sweep. The stream uses the lowest available priority.
- `openair1/PHY/NR_UE_TRANSPORT/nr_pdcch_nid_algorithm.h:307`: fixed-workspace port of the frozen CPU stage-2 algorithm.
  The CPU test instantiation uses the same port, compared against a **separate copy** of the original
  `idsweep_offline.c` in `tests/nr_pdcch_nid_reference.c`; the frozen tree itself is unchanged.
  Histogram hull quantiles replace sorting the same integer positions; counting values below 1/2
  implements the original upper-median consistency gate. Stable score/index selection preserves
  the original glibc qsort tie order and first-64 tie cap. CUDA FMA contraction is disabled.
  Stage-1 six-entry rings hold **prefix sums**, preserving CPU addition/subtraction order rather
  than using the frozen GPU tool's differently rounded sliding accumulation.
- `openair1/PHY/NR_UE_TRANSPORT/nr_pdcch_coreset_map.c:409`: keeps carrier/CSS0/TDD gates, one window per tenth DL slot, and symbol
  rotation. With GPU enabled, forwards capture to staging and never starts the snapshot-file worker.
  GPU duration defaults to 3 so a single run can rank durations 1..3; legacy duration still defaults
  to 1. As in the original capture, starts whose full window would cross the slot boundary are skipped.
- `openair1/PHY/NR_UE_TRANSPORT/nr_pdcch_blind_monitor.c:973`: small adapter reuses the existing record parser/validation via an
  in-memory stream, leaving downstream bank/dwell logic for T15. Off retains the original file
  path and polling. Existing `DISC_MAX` limits remain this branch's downstream consumer limit.
- `executables/nr-uesoftmodem.c:474`: startup adjacent to `nr_dl_gpu_warmup`, shutdown after producers

## Controls and bounds [CODE-READ]

| Variable | Default | Bounds / effect |
|---|---:|---|
| `ISAC_PDCCH_NID_GPU` | off | Only exact `1` enables; failure disables capture, no CPU sweep fallback |
| `ISAC_PDCCH_NID_GPU_CORE` | last allowed core | Must be in process affinity; one core, policy SCHED_OTHER |
| `ISAC_PDCCH_NID_GPU_EVERY` | 2 | 1..1000 new consumed batches between passes |
| `ISAC_PDCCH_NID_GPU_WINDOW` | 10 | 1..20 batches; first pass waits for a full window |
| `ISAC_COREMAP_IDSWEEP_DUR` | 3 on GPU, 1 off | 1..3, same clamping as legacy capture |
| `ISAC_PDCCH_NID_GPU_BUDGET_MS` | 5000 | 100..60000; abort incomplete pass, retain previous published generation |

A batch is 336 windows. Capture is the existing single receive-branch capture, even with four RF
receive branches; it does not add an antenna summation absent from the reference. Max started
bandwidth is 275 RB and max complete CRB index is 275. Negative Point A is supported within this
CRB bound; non-RB-aligned Point A is analysed but cannot publish records, as in the frozen tool.
Changes in capture geometry/PCI flush device history, publish an empty generation, and restart
the cadence; partial staging batches restart on changes.

The processing budget is checked between 16-snapshot stage-1 tiles and 1024-hypothesis stage-2
tiles. It is a cooperative deadline, not GPU preemption or a proven hard latency bound. The
bounded serial GPU preparation/finalization kernels also require device measurement. A timeout
never publishes partial results. CUDA errors stop capture. No processing-path CUDA allocation,
registration, or free exists; the T13 module-local allocation fence is sealed after workspace pre-touch, kernel, event,
and transfer warm-up.

At 275 RB, duration 3, window 10, pinned IQ staging is 39,916,800 bytes. Device IQ history is
133,056,000 bytes. Prefix/decoy workspace is about 178 MB, plus about 59 MB of hypotheses and
about 20 MB of stage-1 arrays. IQ is uploaded once per new batch; repeated passes read device
history. These are allocation-size calculations, **not measured coherent-memory traffic**.

Logs: `SENSING: PDCCH_NID_GPU pass k: stage1 ... ms stage2 ... ms -> n CORESETs: ...`.
No discovery snapshot files or `/tmp/coresets_discovered.txt` are written by the new path.

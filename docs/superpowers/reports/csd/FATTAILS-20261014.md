### Findings so far
- `[MEASURED, DGX OTA 2026-10-14 T2a, offline read]` whole-decode time (EVMGRANT `dec_us`, incl. recovery bodies) is the real fat
  tail: p50 1.1 ms, p99 115 ms, max 959 ms; 305 grants > 100 ms (72.5 s total). PDTIMSLOW: chest bodies 26-36 ms CPU-bound = inline
  chest CHECK; demod bodies wall >> CPU (5-70 ms CPU, up to 612 ms wall) = inline demod CHECK + GPU waits.
- `[MEASURED, DGX replay b, ref binary rr-csd-b build_t26 c3ceb2f472]` reproduces it: real-body p99 4.5 ms / max 98 ms, dec_us p99
  49 ms / max 287 ms.
- `[MEASURED, DGX replay b, perf sched + bpftrace]` **root cause of the 20-900 ms device-wide stalls**: GPU first-touch of
  unpopulated pageable host buffers -> UVM ATS fault -> `uvm_migrate_pageable` -> `migrate_vma_setup` -> `lru_add_drain_all`,
  which waits for the `mm_percpu_wq` kworker of every core; `kworker/6` (core 6 = scan consumer FIFO 50 + PUSCH FIFO 30) waited
  up to 916 ms. All PDSCH consumers then poll (20 us sleeps, wall >> cpu, outside the stage timers, mostly in
  `nr_pdsch_gpu_demod_evm_wait`). In the inline-check arm 388/398 migrations hit the inline CHECK's `calloc`'d GPU output buffers;
  in the async arm ~470 migrations remain, attributed (frame-pointer stacks, uncertain) to allocations near
  `nr_pdsch_gpu_demod_grant` -> hypothesis: the demod `geo_y`/`geo_h` buffers (hence item 3).
- `[MEASURED, DGX replay b, n=1]` async checks: real-body p99 4.5 -> 2.0 ms, max 98 -> 7 ms; whole-decode p99 31 -> 14 ms but
  max still 218 ms (stalls remain, item 3 targets them); check_bad 0, 0 MISMATCH.

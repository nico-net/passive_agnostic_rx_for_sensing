# MPCI-B1 core pool: per-cell fair share (pool part), 2026-10-25

Branch `mpci/c-b1` (from `mpci-main` @ 9b2d7c3f6e). Plan: `2026-10-23-mpci-main-plan.md` B.4 changes 1, 2, 3, 5 (change 4 = call sites and B1b are NOT done).

## What changed
Files: `common/utils/nr_core_pool.{c,h}`, `common/utils/tests/test_nr_core_pool.cpp`, `common/utils/tests/bench_nr_core_pool.cpp`. No CMake edit (both targets already registered in `common/utils/tests/CMakeLists.txt`). No env var, no CLI option, no flag (operator rule NO FLAGS).

1. Inside a class the waiting cell with the lowest decayed token-time usage U_c is granted (`NR_POOL_USAGE_HALFLIFE_NS` = 50 ms, equal weights; U_c integrates the cell's held leases of all classes). Ties (< 1 us) go to the old round-robin; inside a cell oldest deadline as before. Work conserving (only waiting cells compete, an idle cell costs nothing).
2. Active cell = lease or waiter, or an event within `NR_POOL_ACTIVE_WINDOW_NS` (100 ms). DL cap per cell `max(1, N-1-(A-1))`, global DL sum <= N-1 and the global UL rule (UL waiting caps DL at N-2) unchanged. A cell that already holds a DL token leaves one for every other cell waiting for its first one, and a cell with no DL token is never held back, so every active cell reaches a DL token within one release (no deadlock possible: a zero-DL waiter is always reserve-free). Scan reserve stays shared and is granted by rule 1. Everything derives from N.
3. `nr_pool_cfg_default_n(n)`: DISC/HOUSE promotion off for n < `NR_POOL_PROMO_MIN_TOKENS` (6), cites FLOAT-LANE-POOL-20261021 section 3. `nr_pool_create(..., NULL)` uses it; an explicit cfg is used as given (the existing aging tests pass explicit cfgs with 1-2 tokens, and the bench).
5. Stats: `nr_pool_stats_t` gains `leases_cell/waited_cell/wait_max_ns_cell/hold_ns_cell/wait_hist_cell`. CORE_POOL line grammar, appended after `house[...]`, only when some cell != 0 has leased, then one block per cell that has leased (cell order):
   ` cell<c>[n=<leases> waited=<waited> hold_ms=<token-time ms> wait_us p50<=<us> p99<=<us> max=<us>]`
   With cell 0 alone the line is byte-identical to before (pinned by the golden test).

API changes (additive): `nr_pool_cfg_default_n(int)`, `nr_pool_set_clock_for_test(fn)` (function hook, NULL in production; while set waiters skip the timed age wake-up), new stats fields. Call-site buffer note: `nr_pdcch_passive_queue.c` formats the line into `char pl[900]`; with >= 3 cells the line (about 550 + 110 per cell bytes) can be truncated: enlarge to >= 1600 when call sites are converted (not in B1 scope).

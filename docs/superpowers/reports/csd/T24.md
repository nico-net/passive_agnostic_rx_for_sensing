## Implementation

[CODE-READ]

- `openair1/PHY/TOOLS/nr_gpu_budget.{h,c}`: one arbiter inside the T18
  `libnr_gpu_platform.so`, shared by the core and all participating `RTLD_LOCAL`
  modules. A single atomic owner word excludes discovery from pending RT work.
  RT performs one admission attempt and falls back immediately when discovery
  owns the GPU; it never locks or sleeps on discovery. Discovery workers sleep
  between attempts. A 1001-bucket rolling second reserves **5000 us before every
  submission**, charges completed CUDA-event time rounded upward, and also paces
  submissions without accumulated idle-time credits. No new affinity policy.
- `nr_gpu_budget_cuda.h`: events allocated before T18's RX fence; each discovery
  kernel/transfer completes before another is admitted. An observed >5 ms slice
  or RT timeout closes subsequent discovery admission. Initialization/warmup is
  outside the runtime budget. CUDA polling uses the same C deadline loop as the
  injected-clock tests.
- `nr_pdcch_nid_gpu.cu`: stage 1 uses one snapshot and 4096 IDs per sweep launch.
  Stage 2 scores eight hypotheses over 32 snapshots per launch, preserving the
  original snapshot addition order and consistency votes across chunks. Other
  kernels have individual admission/completion boundaries. Uploads, result
  copies and history clears are charged in at most 1 MiB pieces. Existing kernel
  event counters still work; stage elapsed times now include budget yields.
- `nr_csirs_disc_gpu.cu`, `nr_csirs_disc_gpu_cluster.cuh`: production FEP and
  incremental accumulation use one slot per chunk; FFT, kernels, history clears
  and transfers have individual admission boundaries. `nr_csirs_disc_gpu_sweep.cu`
  tiles sweep work into 32 candidates × one snapshot, bounds gather submissions,
  and retains refinement sums across one-slot refinement chunks.
- `nr_pdcch_nid_gpu.c`: publication or acquisition timeout enters MAINTAIN;
  verified-bank feedback pauses uploads and passes until periodic recheck.
  Feedback includes generation and epoch. Stale bank entries, unexplained outside
  occupancy, changed capture geometry and receiver epoch changes resume work;
  queued old-epoch snapshots and results from an obsolete in-flight epoch are
  discarded. The monitor checks exact symbol/geometry/nID with a new verified-only
  bank predicate. Existing bank-query semantics are retained.
- nID module ABI is **4**: an additive capture-configuration epoch invalidates
  device incremental history. Rebuild the worker and module together. The
  `nr_csirs_disc.h` contract is **unchanged**.
- PDSCH FEP/LLR/readback and PDCCH GPU FEP use bounded stream queries and existing
  negative-return CPU fallback paths. A timed-out module remains disabled with
  its private staging/device buffers retained, so a late DMA cannot write a CPU
  fallback result. Polar likewise retains its internal host buffers on timeout;
  a transient admission refusal remains retryable. The polar shim uses try-lock
  admission instead of waiting behind another decoder.
- `nr_pdsch_passive_queue.c:261`: with budgeting enabled, bypass the stack-owned
  request queue's unbounded condition wait using one nonblocking direct-execution
  gate and a compound deadline. This avoids abandoning a stack request while a
  worker can still access it. The flag-off dedicated-worker path remains.
  No thread creation, scheduling or affinity code was changed.
- `nr_passive_metrics*.{h,c}` and the existing summary timer add
  `gpu_budget_used_pct`, `discovery_yields`, `rt_gpu_wait_max_us`,
  `rt_gpu_fallbacks`, and `discovery_overruns`, with one existing ISAC_METRICS
  emission opportunity per 10 s when budgeting is enabled. Percent is the
  lifetime measured GPU-time/wall-time average; counters/maxima are cumulative.
  Wait maximum conservatively includes staging/submission time. Refusals and
  deadline fallbacks are counted, rather than every unrelated CPU-only decode.

## Limits

[IMPLEMENTED, NOT VALIDATED] CUDA has no host-enforceable kernel preemption time.
The 5 ms submission target is implemented through small chunks plus an event-based
fail-closed guard; **it is not a measured device bound**. A first overlong chunk
can exceed 5 ms before its completion is observed. RT takes CPU fallback while
that discovery work is in flight. Driver API latency, host scheduling, foreign
processes, and CPU fallback execution time are outside the polling-loop bound;
this patch therefore does **not** establish an unconditional zero-RFSTALL theorem.
The 250 us default must be assessed against actual slot slack and decode cost.
The legacy LDPC/CB0 decoder's independent timeout policy is unchanged.

A CUDA error or deadline timeout conservatively stops new discovery admission
for the process lifetime; timed-out RT modules retain buffers and require a
receiver restart to re-enable. This protects ownership at the cost of GPU
availability. Discovery stop/join still drains an already submitted CUDA slice;
a permanently hung driver cannot be canceled safely in process. Existing CPU
fallback and ring-drop policies remain responsible for overload.

Legacy standalone bulk CSI-RS diagnostic APIs are event-accounted but do not
have the production pipeline's one-slot workload bounds. GB10 validation must
cover all deployed rows/geometries, including single-thread refinement kernels,
and compare numerical output with the untiled path before enabling OTA use.

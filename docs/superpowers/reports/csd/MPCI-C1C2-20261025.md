# MPCI C1/C2 — IQ ring with in-process backing, CPU channelizer with backend interface (2026-10-25)

Branch `mpci/c-c1c2` (from `mpci-main` @ 9b2d7c3f6e). Host for every number: DGX GB10 aarch64, shared with other sessions, `nice -n 19`, no receiver, no GPU, no radio.

## What was done
- C1 `radio/COMMON/shm_iq_ring.{c,h}`: ring with two backings behind one API, `shm_iq_ring_create(backing, name, n_rx, capacity, rate, centre, n_consumers)`. ANON = private `mmap(MAP_ANONYMOUS)` plus an in-process name registry (views are reference counted, the memory outlives the producer handle); POSIX_SHM = old `/dev/shm` ring for tools. Header v3 adds a consumer table (cursor, overruns, dropped per consumer; ring total). v1/v2 rings still attach.
- `shm_iq_ring_plan_capacity(budget, rate, n_rx, n_rings, target_ms, floor_ms)`: pure; largest power of two within `ceil_pow2(rate x target)` that fits the budget, 0 below the floor. Budget comes from the caller (a share of `nr_host_membudget`); nothing hardcoded.
- `shm_iq.c` consumer device: ring found by name (in-process registry first, then `/dev/shm`), name = `sdr_addrs` of the device config, constants for timeouts. Registers in the consumer table, accounts overruns. H3 passband (`num_rb_dl x 12 x SCS`, SCS from `nr_scs_for_raster`, at least 30 kHz) via `iq_ddc_cell_passband()`. Heartbeat unsigned-wrap fix (old fa4e444678: load heartbeat first, clamp at 0) kept and re-tested.
- C2 `iq_ddc.{c,h}` ported; NEON quantiser only on `__aarch64__`, portable C otherwise (the old code had no x86 SIMD; the halfband loops use GCC vector extensions that compile to SSE/AVX). `iq_ddc_set_force_scalar()` is a function seam for the NEON-vs-portable test, not a flag.
- C2 `iq_chan.{c,h}`: one channelizer thread (or `iq_chan_step()` from the caller), block loop over all entries, entries added/removed/retuned live at block boundaries, overrun/discontinuity skip + history reset, ring-epoch follow, zero-shift decim-1 entry = memcpy from the input block, narrow rings sized from a budget. Backend struct `iq_chan_backend_t`, CPU backend, registry, selection hook, `iq_chan_cpu_bench()`.
- NO FLAGS (coordinator rule 2026-10-25): no env var, no CLI option, no -D switch in C1/C2. The old publisher wrapper `shm_iq_pub.c` (env-driven, M4 dwell/subset) and its tests are NOT ported: the in-process receiver publishes its wideband ring directly, and the wrapper needs a hook in `common_lib.c` (see Hook). The soak/bench modes of the test binary take command-line options (test tool only, not product code).

Verbatim in `radio/COMMON/shm_iq_ring.h` and `radio/COMMON/iq_chan.h` (summarised in the final message).

## STOP C2 extra: 60 s, two cells, anonymous ring, two consumer threads
`test_iq_chan --soak 60 --rate R` (generated input, nice -n 19, two cells A: 106 PRB, B: 51 PRB, 4 RX, ONE channelizer thread, two consumers each comparing every block with an independent `iq_ddc`):
- [Bench, DGX GB10 aarch64, shared host, n=1 per rate] 122.88 MS/s x4, cells decim 2+4: 76919/76919 blocks bit-exact on both streams, 0 mismatches, 0 gaps, timestamps continuous, 0 overruns/discontinuities. Producer paced at 84.0 MS/s (0.68x real time; the test paces at 60 % of the measured free-run capacity so that the consumers' oracles do not starve it); thread busy 85.6 %.
- [Bench, same, n=1] 245.76 MS/s x4, decim 4+8: 72162/72162 blocks bit-exact, 0 gaps, 0 overruns. Paced at 78.8 MS/s (0.32x real time), thread busy 74.7 %.
- STOP verdict: continuity and bit-exactness over 60 s MET. Real time is NOT reached at 245.76 MS/s x4 on one CPU thread (see below); the pace is stated, not extrapolated.

Sustained free-running rate of the CPU backend on ONE thread, 4 RX, `test_iq_chan --bench --reps 3 --secs 3`, [Bench, DGX GB10 aarch64, shared host, n=3]:

| input | cells (decim) | rate per channel | real-time factor |
|---|---|---|---|
| 122.88 MS/s | 1 (2) | 309-315 MS/s | 2.546x (mean of 3) |
| 122.88 MS/s | 2 (2+4) | 142-145 MS/s | 1.166x |
| 245.76 MS/s | 1 (4) | 277 MS/s | 1.128x |
| 245.76 MS/s | 2 (4+8) | 133-134 MS/s | 0.543x |

So one CPU thread keeps up in real time with two cells at 122.88 MS/s x4 (1.17x, thin margin on a shared host) but not at 245.76 MS/s x4 (0.54x); there the GPU backend (G5) or several channelizer threads are needed. The admission input is `iq_chan_cpu_bench()` / `iq_chan_backend_cpu.capacity()`. Contrast with the old MPCIFIX numbers (4.49x mixer-only, 1.49x for 245.76->122.88): different loads, not compared.

## Hook needed in common_lib (NOT done)
`radio/COMMON/common_lib.c` would need nothing for the consumer device: it is loaded by name like `raw_iq` (`device = { name = "shm_iq"; }`), `device_init` is exported. To find an in-process anonymous ring the device module must share the executable's registry: the receiver executable must export `shm_iq_ring_*` (link `mpci_iq` with `ENABLE_EXPORTS`), otherwise the module's own copy of the registry is empty and it falls back to `/dev/shm` (POSIX rings only). The in-process receiver (D1) should instead call `shm_iq_ring_view()` directly. The old `shm_iq_pub_maybe_wrap` call in `openair0_device_load()` is not needed in the in-process design and was not ported.

## 2. Model

**Host RAM (reuses `nr_host_membudget.h`).** `B = calc(avail)`; the process-wide bytes already held (`host_shared_bytes`: USRP ring reservation, pinned mirrors) come off first; the per-cell fixed arenas (PDSCH queue) next; what is left is split among the served cells by `weight`. Inside a cell's share the receiver's own start-up sequence is replayed with `nr_host_membudget_fit_pct` / `fit`: snapshot holders (10 %, floor 2), CSI-RS ring (30 %, floor 160), time-domain pool (60 %, floor 256), GrantWork pool last (60 % of what is left, floor `consumers*8`). With one cell the share is `B - shared`, so every line is the live code on the live state.
**GPU (reuses `nr_gpu_membudget.h`, `nr_csirs_disc_mem.h`).** `B = calc(free_at_probe)`. Process-wide modules (LDPC pool, CB0, TD CB0, pass instances) at `min(need, share)`; per cell: HARQ store (99 MiB), the discovery ring detector state, and ring slots in [160, 640] sized by `nr_gpu_membudget_fit` from the cell's slice of the csirs pool; one shared PDCCH nID context sized for the widest served grid. The graph module's share above its floor is lent to the per-cell modules when more than one cell is served (one cell: today's weights exactly). SHARED/unified: the GPU bytes planned come off the host budget and hard limit (as `nr_host_membudget_set_unified` does).
**Cores / channelizer / max.** `max_cells` (the core layout's `nr_cl_max_cells`, an int input), `NR_CELL_MAX` 16, and a channelizer budget in output MS/s summed over the cells that need a frequency shift (a cell at the window centre needs none; `chan_budget_msps < 0` = unlimited).
**Policy.** The primary cell (first non-LOST, normally cell 0) is always served and follows today's rules unchanged: a module below its floor is off, and only the hard limit (`avail - 512 MiB`, minus unified GPU bytes) refuses: `plan->refuse = 1`, nothing served (the existing `HOST_MEM REFUSE`, exit 7). The other cells are admitted in order MAINTAIN, ACQUIRE, NEW (inventory order inside a class), LOST never. A cell is served iff with it added: count < `NR_CELL_MAX`, count < core limit, channelizer budget holds, every GPU ring that existed keeps its floor and the GPU total plus the graph floor fits, every host module that was ready stays ready and the newcomer's modules reach their floors, and committed host bytes stay under the hard limit. Reason order on the first failing check: `max, cores, channelizer, gpu_mem, ram`. A refused cell never changes the others (test). The process is never refused because of cell k > 0.
**16 GB floor.** Replaced by the `nr_host_membudget` reserve rules: `0.8 * avail - 1.5 GiB` for sizing and `avail - 0.5 GiB` hard. Justification: the 16 GB floor came from `mpci_auto.py` as a rule of thumb on the 128 GB DGX (a host constant); on sens6 (9-15 GB) it would refuse every cell and on a cloud host it is meaningless. The budget rules are derived from the probe (MemAvailable, cgroup headroom), were measured to avoid swap and the OOM killer on sens6 at 273 PRB [MEASURED, sens6 rfsim, HOSTMEM-273-20261024 section 4], and are already what the single-cell receiver enforces.

## 3. Results

Tests `[OFFLINE VERIFIED, DGX GB10 aarch64 unit]`: `test_nr_cell_admit` 17/17, `test_admit_model_py` 4/4 (C and Python outputs identical on 18 fixtures, about 100 lines). An ASAN+UBSAN build of the CLI on the fixtures is clean.
**N = 1 equivalence.** `OneCellHostEqualsMembudgetReplay` replays the real stateful `nr_host_membudget` API (commit queue, `size` snapshot/csirs/td, `share` + `fit` for the GrantWork pool) under `NR_HOST_MEM_BUDGET_MB` for 8 available sizes x 4 grids (51/106/217/273) x 2 antenna counts x with/without shared bytes (128 cases): sizes, committed total, budget, hard limit and the refuse decision are equal; the test requires >= 40 non-refused comparisons and >= 20 shrunk ones. `OneCellGpuEqualsMembudget` compares the ring slots with `nr_csirs_disc_mem_capacity(share_of(calc(free)))` for 5 free sizes x 3 grids. ## 5. Differences from the plan text and open items

- Plan expectation "two 217-PRB cells -> one `unserved gpu_mem`" on sens6 holds in the model (1 served); two 273 likewise; 3 cells of 51 PRB already hit `gpu_mem` (detector state per cell is large). All `[CODE-READ]`.
- The old process-per-cell RAM data point (13 GB RSS per 217-PRB cell, MPCI-DASH-REVIEW O5) is not used: in the model a 217-PRB cell holds 14 GB only because the GrantWork pool takes the whole unified budget at full size (16 GiB per cell at 4 RX); the pool is scalable (floor 64 MiB), so the DGX limit is cores, not RAM. G1 must report the real RSS of a second cell.
- Not modelled: the per-cell IQ ring of the channelizer output, UL IQ retention, the live GrantWork re-probe, GPU `pass` scaling when its share is below the need at several cells (counted at need), the wideband ring (host_shared input).
- Cell index 0 stays the primary only while it is not LOST; D1 must pass the cell that the process was started on first.
- Next: D1 calls `nr_cell_admit_plan` once before the RX fence and logs `nr_admit_plan_format`; G1 replaces every `[HYP]` row; B2's `nr_cl_max_cells` fills `max_cells`.

[CODE-READ] `nr_csirs_disc_td.c` exchanges pointers to owned staging entries under the short producer mutex. The CP-bearing sample pool uses managed memory when CUDA is available. A chunk calls `gpu_ops.fep` once, with capture-time CFO, original symbol offsets, and symbol rotations. CPU fallback retains the T8 OAI transforms and logs once that it is not real-time.

[CODE-READ] `nr_csirs_disc_gpu.cu:fep_host` performs CP-window selection, CFO compensation, batched unitary cuFFT, symbol rotation, time-shift rotation, and wrapped CRB extraction on the GPU. CFO reproduces the `get_sin_cos` Q14 lookup and **128-sample quantized recurrence**, including its accumulated rounding, with `samples_per_subframe` and the original `offset[l]` phase origin. It does not substitute a floating-point sinusoid. CFO sample multiplication wraps; recurrence rotation saturates. The host passes the compiled rotation mode so ARM RDM's separate product rounding is distinguished from the ARM rounded-multiply and SSE truncating paths. Time-shift multiplication preserves OAI's saturating SIMD multiply and signed-16 conjugation. Odd-RB rotation ranges are retained. The existing standalone FFT callback remains available with its original semantics.

[CODE-READ] The cuFFT plan uses a persistent 100-slot batch, padding the unused tail of shorter chunks with zeros, avoiding plan churn as backlog sizes change. Scratch allocations persist. Final extraction writes **directly to the FD ring**, without a host per-symbol sample loop or CRB copy. `nr_csirs_disc_ring_write_begin/end` serialize reset/readers and publish metadata only after device completion. Failed writes invalidate overwritten entries before the CPU retries; they are never published as valid GPU output. In GPU mode, epoch reset may wait for the in-flight device call; the TD producer does not use the commit/ring locks.

[CODE-READ] `nr_csirs_disc_feed.c:disc_worker_main` detects once after the entire drain, which remains bounded by the 640-slot FD capacity. Live TD mode processes the single-writer FD ring directly; the pipeline mutex already serializes detection and epoch reset. It removes the second 100-slot snapshot copy. Direct FD producers and offline fixtures retain the existing snapshot API.

[CODE-READ] `nr_csirs_disc_fp.c` now selects the GPU **in the production incremental path**. Additive callbacks perform tiled lower-third Q12 normalization, integer sufficient-statistic accumulation, pooled period reduction, significance screening, and the alternative-phase/background test. Managed history is retained between calls; ordinary host input rings use an explicit device copy. GPU lattice screening preserves the first-tile duplicate policy and tile/component order. The old public `normalize` output layout is unchanged. A device accumulation failure discards possibly partial history and reconstructs the available snapshot on CPU; the loader observes its circuit-breaker backoff. Older, unavailable IQ cannot be reconstructed after that reset.

[CODE-READ] The host still performs contiguous RB segmentation and bounded candidate merging: at most 275 RB, eight segments per density, a 2048-entry candidate heap per period group, and the existing four-group schedule over all 13 periods. Hypothesis construction/cache stay on CPU (128 views, 256 hypotheses/cache entries); production sweeps remain bounded to 32 hypotheses and the latest four occasions. Sequence extent refinement stays CPU. **The expensive full-1024-ID refined recheck now uses the GPU sweep too**, with CPU fallback on error. There is no PCI, bandwidth-extent, symbol, or period prior. Device tests must establish that these remaining host stages fit the latency budget.

[CODE-READ] `CSIRS_DISC BATCH` reports detection/hypothesis/sweep times and cumulative `gpu_detect`, `cpu_detect`, `gpu_lattice`, `cpu_lattice` counts. These identify actual callback use, separately from the sweep backend. The throughput and forced-GPU dump tests fail on CPU detector/lattice fallback, rather than accepting a successful CPU result as GPU evidence.

## Confirmation contention

[CODE-READ] T8's `confirm_drops` counts **entire live confirmation invocations skipped by a failed candidate-bank trylock**, including slots on which no candidate might have been due. It is not a full confirmation-output queue. A skipped due call loses independent evidence and can delay confirmation by a period.

[CODE-READ] The live call now retains its actor-owned IQ buffers and waits for the bank lock, then performs the due-only FEP/scoring. Worker admission/query critical sections contain bounded metadata work, never discovery FEP, detection, or an ID sweep. Startup configures priority inheritance for this mutex where supported, before worker/DL actors start, to avoid low-priority admission priority inversion. `confirm_wait_max_us` is logged alongside the retained drop counter. **This trades skipped evidence for serialization latency**; zero drops does not prove absence of harmful waits. The deferred live gate must inspect this maximum and RF health. Feature-off retains its original mutex initialization and execution.

[OFFLINE VERIFIED, DGX aarch64] The contention regression holds the bank lock while another thread invokes a due slot, releases it, and verifies both required row-5 symbols were processed with no increment in `confirm_drops`. It also retains due-only and already-transformed-symbol reuse assertions. It does not claim a measured 2000-slot/s live confirmation budget.

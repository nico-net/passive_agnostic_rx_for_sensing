# Fix A + Fix D: one GPU submission per grant, isolated pools (2026-10-19)

Branch csd/int16-fixad (from freeze-20261018). Host: DGX GB10 (sm_121, unified memory). All timings below are BENCH numbers
(unit microbenchmark, synthetic grants, no receiver running, run through heavy.sh at nice 19), not on-air. No replay, no OTA was run.
Evidence label for correctness claims: [unit test, DGX GB10]. sm_89 (RTX 4060 Ti) builds (CMake arch list 89;121) but was not run.

## 1. What changed

**Pools and streams (requirement 3).** `NR_GPU_PASS_RING` = 4 DL + 2 UL + 1 probe/overflow = 7 instances. Each instance owns its streams, graph
executables, FEP staging slot, demod and LDPC context (all indexed by instance), so a DL and a UL submission never wait for an instance or stream of
the other pool. DL real grants take a DL instance at once; if the 4 are busy they take the probe-pool instance (overflow, counted `ovf_takes`);
probes are admitted only while at least two DL instances are free and no real grant waits, so the overflow instance is normally idle. A running
probe is never preempted: a grant that finds the overflow instance on a probe waits for that probe at most 400 us (condvar, counted `ovf_waits`),
then the old path takes it (counted busy, logged once). No real grant ever waits for another real grant. Design comment: top of nr_gpu_pass_graph.cu.
- **GPU access:** the real-time SMs (40 of 48) are split into two green contexts: DL 32 SMs, UL + probes 8 SMs (nr_gpu_green.h; GPUs with < 32
  real-time SMs keep one context and rely on stream priority: DL highest, UL/probe lowest). Discovery keeps its own 8 SMs. UL passes no longer
  register as RT users of the discovery budget (they never hold off a CSI-RS slice).

**Completion (requirement 4).** No sleep-poll loop and no whole-pass spin. The thread sleeps once to 60 us before the EMA-predicted end of the class
(timer slack 1 us), spins to 100 us after it (unseen class: 500 us), and only then blocks on a blocking-sync event. Measured wake latency (GPU end to
host running), p50/p99: blocking event alone 174-262 / 400-550 us (this host, nice-19 thread); sleep+spin 3-4 / 4-10 us (78 us once). The blocking
wait is therefore the outlier fallback, not the normal path. Core time per grant drops from the full GPU span (old: spin up to 600 us then 20 us naps)
to about 160 us.

**In-graph no-chance gate (coordinator addendum).** nr_snr_gate.h taken unmodified from 09090d31de. DL: a kernel after the chest post computes the
DM-RS comb SNR (same definition as nr_pdsch_dmrs_snr.h: per-RX SNR from the smoothed estimate and the chest residual, MRC sum) and sets a CUDA
conditional-node handle; the demod+LLR sub-graph D and the LDPC+CRC sub-graph L are IF bodies, so nothing runs when the grant is below required - 5 dB
and the device writes skip=1. UL: the same on the PUSCH graph with the nr_ulsch_dmrs_snr_db definition. Exempt: probes, SI/P/RA grants, rv != 0,
transform-precoded UL. Host: crc=0 skip=1 in EVMGRANT / UL_PUSCH_CRC, no arm, no retry. Conditional nodes in a green-context graph need the green
context's CUcontext (driver entry points via cudaGetDriverEntryPointByVersion; prototype in the session notes).

**UL pass (requirement 2).** The existing Task 7 graph (FEP -> chest -> MMSE -> LLR -> descramble -> dematch -> LDPC -> CRC, one launch) is sound and
bit-exact against the CPU reference over 200 slots (Qm 2/4/6/8, TA, keep, SNR down to -18 dB); it is now the UL path, not an opt-in.

**Removed from the hot path (requirements 5, 6).** ISAC_UL_GPU_PASS, ISAC_GPU_PASS_POLL_SLEEP_US, ISAC_PDSCH_GPU_GRAPH_PROBE_RESERVE,
ISAC_GPU_PASS_CHECK, ISAC_UL_GPU_PASS_CHECK, ISAC_PDSCH_GPU_GRAPH_MB, ISAC_GPU_RT_PARTS, the RETRY_OLD env read. Shadow decodes of the old path are off
(`check = 0`); the comparison lives in the unit tests. Fallback reasons are logged (first occurrence per gate / busy / unseen) and counted in the census.

Reading: "old" is the former completion wait (spin 600 us then 20 us naps) on the same graphs; with idle cores it also wakes in 3-20 us, so the wall times
agree. What the new wait changes is core time (about 160 us per grant instead of the whole span) and removal of the 20 us-nap quantization. The
"stage path" (separate FEP/chest/demod/LDPC submissions with host steps in the test harness) takes 5.3-8.6 ms DL and 5.5-6.8 ms UL in the harness:
a harness figure, not the on-air old path (0.59-0.89 ms DL). DL C=16 and UL probe shapes were not in the picked grid (no grid shape gave 16 CBs).
Host time per grant that remains: prep 2.4-5 us + launch calls 13-19 us (DL: marker, H2D of the parameter blocks (no-op on unified memory), 3 graph
launches, done event; UL: one graph launch) = about 18 us DL, 14 us UL, plus the wait. On the discrete sm_89 model the H2D of parameter blocks
before the first sub-graph is real (one host copy burst, before the launch, no host sync between sub-graphs).

**Interference (DL real alone vs with 2 UL passes + 1 DL probe looping on other threads; UL real alone vs 2 DL + probe):**
| | submit->GPU start p50/p99 | GPU span p50/p99 | wall p50/p99 |
|---|---|---|---|
| DL alone | 2.0 / 3.3 | 477 / 549 | 483 / 556 |
| DL + UL + probe load | 4.3 / 468 | 532 / 1052 | 552 / 1448 |
| UL alone | 5.1 / 6.2 | 376 / 382 | 384 / 391 |
| UL + DL load | 6.4 / 19 | 415 / 567 | 428 / 688 |

The pools remove queuing: submit->GPU start p50 stays at 2-6 us under load and no submission ever waited for an instance. They do NOT make the
columns equal: GPU span grows 11 % (p50) under load with the SM partition (34 % without it, measured before the split: 486 -> 653 us), and the
p99 tails grow (host threads of the bench are descheduled on this nice-19, loaded host; the 468 us gstart p99 is host noise between marker and
launch, not a GPU queue). The remaining p50 cost is the shared memory system (unified memory, L2). DL alone is unchanged by taking 8 SMs away
(485 vs 486 us); UL alone is 33 % slower on 8 SMs (376 vs 283 us). The unit test asserts only the submit->start p50 (within 25 us or 25 %).

VRAM (GB10 estimate): instances 168 MB for 7 (24 MB each); graph executables 0.55 MB each; the full unit-test warm set (5 DL-shape executables per
class: 4 real + overflow) is 1477 MB against 1008 MB with 4; the default cap is now 2048 MB (was 1024). Real-grant capacity stays 4, plus the overflow.

## 4. NOT done
- **Single submission per grant for DL** is not reached. The DL pass is still the C / D / L sub-graph chain launched back to back on one stream (3
  graph launches, no host step between; about 15 us of host time). A parent graph per (C, D, L) combination would multiply the graph memory (the reason
  for the split); chaining by device-side tail launch needs relocatable device code (a CMake change, forbidden here). UL is one launch.
- The blocking-sync wake is 170-260 us on this host; no futex/host-callback variant was measured (same driver wake path expected).
- No on-air or replay validation of: UL pass as default (hypothesis-cache gate unchanged), the SM split, the in-graph gate, overflow instances.
- The old path is still present for shapes the pass cannot do (PTRS, HARQ arms, unseen class, > 32 segments, need_cpu) and for the UL/DL stage paths
  used by tests; it is no longer selectable by env switches. Fallbacks are logged and counted.
- Retry arms and recovery untouched. PDCCH untouched. sm_89 not run. The UL stage-path streams (old UL FEP / LDPC pool) stay in the DL context.
- Merge notes: nr_pdsch_passive_queue.c EVMGRANT format/args and the UL_PUSCH_CRC / result `skip` lines overlap 09090d31de textually (identical
  intent); nr_pdsch_dmrs_snr.h and nr_snr_gate.h are byte-identical copies of the csd/int16-dmrssnr and csd/int16-tail files.

# T18 — GPU platform and SHARED memory backend

Host: DGX aarch64, sandbox without a GPU device. Branch `csd/t18`, base `40001ec2e0`.
This task explicitly applies to existing GPU paths independently of `ISAC_CSIRS_DISC`;
the discovery feature gate and CSI-RS contract are unchanged.

## Platform and policy

[IMPLEMENTED, NOT VALIDATED ON DEVICE] `openair1/PHY/TOOLS/nr_gpu_platform.{h,c}`
is a core shared library, not a CUDA module. Both CPU builds and dlopen modules use
one instance (including LDPC's DEEPBIND loader). It links only pthread/dl; no CUDA
headers or libraries are required to compile it. CUDA runtime functions are resolved
with dlopen/dlsym; versioned runtime sonames are tried when the unversioned name is
absent. Device name uses `cuDeviceGetName` from the dynamically loaded driver, avoiding
a version-dependent `cudaDeviceProp` ABI. Remaining capabilities use scalar runtime APIs.
`CUDA_VISIBLE_DEVICES` controls the process's visible device; the current runtime device
is probed. This phase assumes one selected device per receiver process.

The idempotent probe runs at `nr_dl_gpu_warmup`, or earlier if LDPC is loaded first.
The core logger routes its capability line to LOG_I and warnings to LOG_W; standalone
module tests use stderr. Exactly one `SENSING: GPU_PLATFORM` capability line records name,
CC, integrated, pageableMemoryAccess, pageableMemoryAccessUsesHostPageTables,
canMapHostMemory, concurrentManagedAccess, hostNativeAtomicSupported, total/free bytes,
selected model and managed opt-in. Attribute-query failure is treated as unsupported.

Capability decision table (synthetic inputs, not new hardware measurements):

| Device | Integrated | Pageable access | Host page tables | auto |
|---|---:|---:|---:|---|
| Integrated/coherent (GB10 class) | 1 | any | any | SHARED |
| Discrete with hardware-coherent pageable access | 0 | 1 | 1 | SHARED |
| Discrete PCIe, including software HMM | 0 | 0 or 1 | 0 | DISCRETE → CPU |
| No device/runtime | — | — | — | unavailable → CPU |

`ISAC_GPU_MEMORY_MODEL=auto|shared|discrete` overrides selection; invalid values fail
closed. Explicit shared is an operator override; mapped-host support and UVA are still
required. Auto checks **both** pageable access and host page tables to avoid mistaking
HMM for hardware coherence, following the [NVIDIA memory capability distinction](https://docs.nvidia.com/cuda/cuda-programming-guide/02-basics/understanding-memory.html).
DISCRETE is deliberately unavailable in phase 1, including on sens6 sm_89, with one
platform warning. LDPC keeps its existing CPU implementation loaded; other migrated
modules return NULL/error through their existing CPU fallback contracts.

## API and memory mapping

| API/kind | SHARED phase 1 | DISCRETE phase 2 |
|---|---|---|
| `nr_gpu_alloc(DEVICE, bytes)` | cudaMalloc; device scratch/working sets | planned cudaMalloc |
| `nr_gpu_alloc(STAGING, bytes)` | portable pinned mapped host memory | planned pinned host staging plus device view |
| `nr_gpu_alloc(SHARED_RW, bytes)` | portable pinned mapped host memory | planned host/device pair and explicit ownership transfers |
| `nr_gpu_device_ptr(base)` | tracked GPU address for exact allocation/registration base | planned device view; add offsets after obtaining base |
| `nr_gpu_copy_async(dst, src, bytes, stream)` | cudaMemcpyAsync, cudaMemcpyDefault | explicit H2D/D2H/D2D through same API |
| `nr_gpu_sync(stream)` | stream synchronization; NULL = default; sync_all waits device | same contract |
| `nr_gpu_register_host(ptr, bytes)` | portable mapped registration of OAI-owned memory | planned registered staging |
| `nr_gpu_free` / `nr_gpu_unregister_host` | tracked ownership selects matching CUDA release | planned release both views |

`ISAC_GPU_SHARED_MANAGED=1` changes only SHARED_RW to cudaMallocManaged; requires
concurrentManagedAccess. Default never uses managed memory in migrated modules.
Kernel callers must use the device view for shared/registered buffers, not assume
pointer equality; CPU consumers synchronize before reading/reusing outputs. CUDA
modules use the typed `nr_gpu_allocate` adapter in `nr_gpu_cuda.h`; errors retain their
CUDA-compatible status and existing fallback handling. Symbol copies and deliberate
invalid-direction CUDA fault injection remain CUDA operations, not allocation policy.

The core seals the allocator immediately before `nrue_init_openair0`, after T13 and
discovery preparation. A mutex serializes the fence with outstanding allocations.
Late allocation/registration/free is rejected before CUDA, counted and logged once;
existing buffers remain resident until process exit. Copies and synchronization remain
available. Existing T13 local stream/event/graph fences remain and consult the common
fence. LDPC pool graphs already warmed are replayed; new graph keys use direct launches
after the fence. Late legacy LDPC thread contexts fall back to its CPU decoder.

The existing device working sets and staging copies are preserved. Mapped allocation
is not permission to repeatedly read CPU memory from kernels. In particular CB0 retains
its bounded explicit-copy working path on GB10; its legacy test-only unified mode uses
the platform's device-view lookup. This preserves T13's host-memory bandwidth budget.

## Migrated modules and build

[IMPLEMENTED, NOT VALIDATED ON DEVICE]

- `ldpc_cuda`: TB pool, legacy single-CB path, CB0 entry; CPU plugin fallback remains
  available on model/architecture/allocation rejection.
- `td_cb0_gpu`: staging, GPU de-matching scratch and copies.
- `pdsch_gpu`: FEP/cuFFT, channel estimation/MMSE/LLR allocations and transfers.
- `pdcch_gpu`: existing FEP/LLR backend allocations and transfers (not T17's nID search).
- `polar_gpu` / static `polar_sc_cuda`: parameter storage, staging, batch scratch and copies.

`cmake_targets/nr_gpu_arch.cmake` validates numeric architecture lists against nvcc's
supported GPU list at configure time. Both `LDPC_CUDA_ARCH` and
`CMAKE_CUDA_ARCHITECTURES` accept lists; default `89;121`. An explicit LDPC list controls
receiver modules; an independently supplied CMake list is also validated. Each requested
numeric architecture gets a cubin, and the highest gets generic PTX for forward JIT.
Explicit `-real`/`-virtual` entries are accepted; highest PTX is always added.
Architecture-specific a/f variants are rejected because their forward-compatibility
contract differs. Older toolkits that cannot build 121 must select a supported list
(e.g. 89) or upgrade, rather than silently dropping an architecture.

Every CUDA module records `nr_gpu_built_archs`. Migrated module initialization checks
the probed CC against its cubins (same major, device minor >= binary minor) or generic
PTX (device CC >= PTX CC). Mismatch logs module, built list and device and returns the
CPU fallback. Runtime JIT/driver errors still use existing module error handling.
All modules use the shared CUDA runtime. Shipping binaries now also requires
`libnr_gpu_platform.so` next to the executable/modules (`$ORIGIN` build RPATH on the receiver/modules supports relocation).

## T16/T17 merge recipe — deliberately untouched source files

[PARTIAL] No `nr_csirs_disc*` or `nr_pdcch_coreset_map*` source/header was edited. The
CSI-RS module build targets receive architecture metadata, but their entry points,
allocations and loader gating are **not migrated** here. T17's new nID GPU code is
also outside this worktree. The global guarantee applies to the migrated modules;
complete receiver-wide DISCRETE rejection and allocation fencing require these merges.
No existing CSI-RS contract semantics were changed.

1. Link new CUDA targets to `nr_gpu_platform`, add `nr_gpu_module.c` once per module,
   and apply `NR_GPU_MODULE_ARCHS`, `NR_GPU_BUILT_ARCHS`, `NR_GPU_MODULE_NAME` and
   `CUDA_RUNTIME_LIBRARY Shared` as the existing target loop does.
2. Include `PHY/TOOLS/nr_gpu_cuda.h` in CUDA code. In the exported module getter/init,
   return NULL/error unless `nr_gpu_module_ready()` succeeds. Do this before any CUDA
   stream creation, kernel launch or raw allocation; preserve the CPU fallback.
3. Replace ring/history allocation hooks with `nr_gpu_alloc(NR_GPU_SHARED_RW, bytes)`
   and `nr_gpu_free`. Use DEVICE for kernel-only sums, Q12 history/workspace, FFT and
   sweep scratch; STAGING for CPU-written descriptors/packed batches. Shared allocation
   itself does not justify CPU copies or whole-history GPU reads on every batch.
4. Replace host registration and pointer assumptions with `nr_gpu_register_host` and
   `nr_gpu_device_ptr`; obtain the device base then apply offsets. Use the transfer API
   and synchronize before publishing ring metadata or allowing CPU access.
5. Reserve maximum bounded geometry/capacity, streams and kernel/cuFFT state during
   warm-up, before the core RX seal. On oversize/growth requests return an error for
   CPU fallback; never free/reallocate ring, history or sweep scratch on the live path.
   Stop using cudaMallocManaged unless the explicit shared-managed opt-in is selected.
6. Retain T16/T17 parity tests and add denied-growth/discrete/arch-mismatch tests at their
   loader boundaries. Verify one capability log and zero late-allocation counters.

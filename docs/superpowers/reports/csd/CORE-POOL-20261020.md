# CORE-POOL-20261020: one shared core pool with priority admission

Branch csd/int16-corepool, rebased on adaptive-rx-UL-DL 3f0d9217fa. Labels: [Build/ctest/Unit test/Bench, cloud x86] (4-core, no GPU), [CODE-READ, cloud x86],
[NOT YET RUN] (anything on the DGX or on air). No OTA, no replay and no DGX run was done from the cloud host; nothing here is a DGX number.

## 1. What changed
- common/utils/nr_core_pool.{h,c}: N exclusive core tokens. A consumer thread leases one token per job (pins itself to that core), releases it
  and returns to the home lane (the float lane, never a pool core). Always on, no env flag.
- Core list = the existing site map: union of ISAC_PDSCH_CORES and ISAC_PUSCH_CORES (built-in defaults; PDSCH default is now 6,7,8,9,3,4) minus
  the RT receive core, ring core and UHD control cores, minus cores outside the allowed set. Default result: 6 cores (6,7,8,9,3,4) instead of 11 role
  cores (scan 6,7; PDSCH 7,3,4,0,1; PUSCH 8,9; UL snapshot 8). cfg `scan_thread` core is ignored by the pool.
- Users: scan consumers (SCAN), PDSCH consumers and PUSCH consumers + the UL snapshot copy + PUSCH layout probes (DECODE|UL), PDSCH recovery (RETRY). Class DISC has no caller in the code yet:
  ulBgDisc is NOT leased (nr_pusch_ul_bgdisc.c: one run holds a core 113-287 ms and is not chunked) [CODE-READ, cloud x86]. They run SCHED_OTHER (no FIFO/RR); the pool is the only protection.
- Queues keep their stacks and thread-local state. Only the pin and the right to run change, so no job code moved.

## 2. Guarantees and how each is enforced
(a) Nobody else on a pool core: nr_pool_enforce() strips pool cores from every non-member task at start-up and about once a second (scan consumer
loop); members (any thread that has leased) are exempt. threadCreate()/nr_core_plan_create() turn an explicit pool core into "home lane". The pool never
contains the RT/ring/UHD cores. Unleased members sit on the home mask, so a wake lands off the pool (fixes the brief old-core wake).
(b) Decode never waits for scans: leases are capped so a token is always left: scan+low <= N-1 (the last token is the decode reserve, scans cannot take
it), decode+low <= N-1 (scan reserve), low <= N-2. Waiters past their age (RETRY 4 ms, DISC 20 ms, HOUSE 100 ms) are promoted and may use any free token.
(c) Discovery/solver never under a scan lease: they lease class DISC on their own threads; a request of another class under a held lease is counted
in CORE_POOL stats `nested` (must read 0 on air). Discovery threads other than ulBgDisc stay in the float lane for now (follow-up: lease DISC).
(d) No env needed: the list comes from built-in defaults; on a host smaller than the site map the allowed non-RT cores minus one are used.

## 3. Open items, state after the audit
- GPU waits [CODE-READ, cloud x86; corrects the first version]: the token is HELD across GPU waits. nr_gpu_poll_relax gives it away only inside an explicit
  per-thread give scope (nr_pool_site_gpu_give_begin/end) and NO call site opens one: every poll site holds a lock/GPU context or has a deadline fallback, and
  giving there deadlocks or changes which jobs fall back to CPU. Open: wait_done (nr_gpu_pass_graph.cu), budget-off NrGpuRtScope::wait (budget code, GPU agent),
  UL LDPC/FEP naps.
- Slot-spread: idle consumers = min(idle threads, free tokens). Spin hand-off: a spin try-acquires and naps 20 us if none is free.
- Deadlock audit [CODE-READ, cloud x86], fixed in 29b0667: scan side_finish now parks/unparks (waits for another scan consumer that needs a SCAN token; deadlock at
  small N); site pool falls back when < 3 site cores survive; the lease no longer spans slot-gate / k0 producer waits (the probe loop still does). Tokens are
  acquired with no queue lock held and released before cond waits. UL snapshot: a lease per memcpy.
- nested now counts scan-side discovery/solver steps run inline under the SCAN lease (autodiscover, discovered step/poll, DCI length sweeps, UL layout/discovery
  grants, DM-RS scan filter, PDSCH solver, blind CSI-RS): expect nested > 0 on air until that work moves to a DISC thread (pending user decision).
- Home mask excludes RT/ring/UHD; children of a lessee start on home; release on stop; enforce tick also from the PDSCH/PUSCH loops.
- Remaining minors: promoted waiters may take the reserve token (M6); N=2 UL/DL cap asymmetry (M7); member table is tid-based; nfree read is racy (benign).
- Not audited: GPU budget code.

## 5. Proposed core map
Pool 6,7,8,9,3,4 (6). Main slot thread 5 (ISAC_UE_RT_CORE). Float lane 10-14 for GPU worker, CSI-RS disc, detect, USS, nID, janon, dmrsScan (unchanged for
now). UHD ctrl 15, ring 16, DPDK 17-19. Freed: 0, 1, 2. Receiver cores 16 -> 13 now; 11 once the float lane is shrunk to 2-3 cores by moving discovery
onto DISC leases (follow-up, not done).
To run the pool build, unset ISAC_PDSCH_CORES / ISAC_PUSCH_CORES / ISAC_UL_SNAP_CORE in the env file (otherwise the site list from the file defines the pool).

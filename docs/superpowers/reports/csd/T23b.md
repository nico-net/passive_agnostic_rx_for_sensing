# T23b — DGX dedicated core planner startup fix

Host: DGX Spark `spark-74c3`, aarch64 CPU build. No receiver, replay, OTA, or GPU runtime was run.

## Cause and change

[CODE-READ] `common/utils/nr_core_plan.c:115` reserved all numbered affinities before placing automatic RT roles, then required every automatic RT role to use an entirely unused physical CPU. The dedicated layout pins UE 5, UHD control 15, scan 6, USS 7, PDSCH 2–4, pool 8,9,0,1, GPU FEP 10, CSI-RS 11, and nID 13. With the ring enabled and pinned to 16, only 12 and 14 remain for DL, UL, and SYNC. The old solver rejected SYNC, although the actors may share a CPU under the legacy scheduler. All 20 online CPUs are separate physical cores in the fixture; this is an exclusivity policy error, not a logical-versus-physical count error.

[CODE-READ] `ISAC_USRP_RING_CORE=16` by itself does not enable the ring: `ISAC_USRP_RING_MS` must be positive. The listed environment without `ISAC_USRP_RING_MS` has three free cores (12,14,16) and does not reproduce the old solver failure in the fixture. The supplied OTA error therefore requires an additional reservation or topology detail beyond the listed environment. The ring-on variant reproduces the exact `sync[0]` failure. `ISAC_CSIRS_DISC_DETECT_CORES` has no runtime reader in this tree; T16 discovery uses the single `ISAC_CSIRS_DISC_CORE` worker, so 12–14 are not additional reservations.

[CODE-READ] `common/utils/nr_core_plan.c:129` now uses exclusive physical cores first. If pins exhaust them, automatic roles share an allowed non-DPDK physical core, preferring another waiting RT actor over a non-RT worker or the reader/UHD control busy pollers. Explicit pins remain untouched, including explicit RT collisions, and every shared role receives a warning (`:293`). Invalid, offline, out-of-cpuset, and DPDK pins still fail. If RT roles cover every available core, inherited helper affinity remains valid rather than causing a second false abort. No GPU budget, PDCCH decoder, or CSI-RS contract code changed.

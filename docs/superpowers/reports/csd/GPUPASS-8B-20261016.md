# GPUPASS Task 8b: stamps, pass poll threshold, retry bodies (2026-10-16)

Build: csd/gpupass ad6eec2b22 + stats script, build_t26, DGX GB10 aarch64, shared host (heavy.lock). Env t26f.env, p99_replay.sh defaults, ISAC_E2E_TRACE=1. Arms interleaved (gpupass_ab.sh, ARMS env), n=6 per arm per capture, captures never pooled. Label: [MEASURED, DGX replay <cap>, SPEED=1, n=6]. Aggregator: tests/passive_rx/gpupass_8b_stats.py (SINCE=<epoch> to skip Task 8 logs).
Arms: OFF = t26f. ONR = ISAC_GPU_PASS=1 ISAC_UL_GPU_PASS=1 ISAC_PDSCH_RECOVERY_ASYNC=1 ISAC_SSB_FEP_GPU=1. ONRP = ONR + ISAC_GPU_PASS_POLL_SLEEP_US=600. ONRX = ONRP + ISAC_GPU_PASS_RETRY_OLD=1.

## What was added (all default off)
1. Stamps: entry of nr_gpu_pass_{dl,ul}_run (clock read only after the pass-active check), before launch, graph done, after commit; histograms prep / launch-to-done / post in the GPUPASS and GPUPASS_UL census lines (power-of-two upper bounds, us).
2. ISAC_GPU_PASS_POLL_SLEEP_US (nr_gpu_poll.h, nr_gpu_poll_relax_pass): spin threshold of the pass's graph wait only; unset = ISAC_GPU_POLL_SLEEP_US (today). Same safety: after N us it nanosleeps 20 us per poll (RT-starvation fix intact); N=0 would be a pure spin, do not use.
3. ISAC_GPU_PASS_RETRY_OLD=1: every body after the first of a call, and every body of the ASYNC recovery worker, skips the pass (new gate retry=) and runs today's exact-GPU path (the pass's bit-exact reference), so retry results are unchanged by construction. Unit test GpuPassRetry.OnlyRetryBodiesGoOld. The shadow check stays on first bodies; retries need none (they are the reference). The full stage reuse (device-resident FEP/chest across bodies) was NOT built: it needs a no-FEP graph variant per class (+~3 GB graph memory) and an instance held across bodies, i.e. well over 3 h. Not done: skipping the pass up front for grants predicted to fail (needs per-RNTI state; follow-up).

## Code reading (item 3) [CODE READ]
Each retry arm (S toggle, CSI, CDM, wide MRC) is a full passive_decode_body: it re-enters the pass gate and re-runs FEP+chest+demod+LDPC (FEP is identical across arms, chest differs). That explains launches > grants.

## nomem gate (coordinator question) [MEASURED + CODE READ]
The gate (`!t_gpp && !nr_gpu_allocations_allowed()`) counts bodies on a thread whose per-thread job/LLR buffers were not allocated before the RX fence. With ASYNC on, these are the recovery worker threads (nr_pdsch_passive_queue.c worker, started after the fence, never prewarmed). nomem == retry count with RETRY_OLD: b ONR/ONRP nomem 1.6-5.1k per run, tim ~1.0k per run; ONRX nomem 0 and retry= 0.9-5.3k (same bodies, now counted as retry and sent to the old path on purpose). So no pool runs out; a worker body simply cannot use the pass. RETRY_OLD removes the symptom. Prewarming the worker is possible but pointless (a retry body in the pass is slower, see below).

## Reading
- The big, robust effect is ASYNC recovery (+ SSB FEP on GPU): b whole p50 1125 -> 616 (-45 %), whole >5 ms 1.5 % -> 0.1 %, tim >96 PRB p99 23.6 -> 7.7 ms. Not caused by the pass.
- Poll threshold 600 (ONRP vs ONR): b whole p50 -8 %, first<=96 p50 -6 %, p99 -19 %; tim whole p50 -3 %, first p50 -3 %, but one tim ONRP run had 0.96 % calls > 5 ms. Gain 20-40 us, i.e. the 20 us nanosleep wake-up, as hypothesised, but small and within run spread except on b. Not conclusive; keep opt-in.
- RETRY_OLD (ONRX vs ONRP): b whole p50 568 -> 564, first<=96 536 -> 528; tim identical to within 1 us on first, p99 2567 -> 2208. Effect on the median is within noise; the ONRX launches drop is only because worker bodies stop using the pass (that is the nomem fix). It does remove the nomem gate and keeps CRC-OK parity (b full runs 45.4 vs 45.5, tim 65.2 vs 64.4).
- vs OFF the pass arms still do not beat the first-body time (<=96 PRB first p50 528-616 vs OFF 560-576): the launch-to-done floor (256-512 us bucket) is the graph itself, not host prep or wake-up. Further gain needs GPU-side stage timing (nsys) or CBPAR for >96 PRB.

## Recommended OTA recipe (provisional)
t26f + ISAC_GPU_PASS=1 ISAC_UL_GPU_PASS=1 ISAC_PDSCH_RECOVERY_ASYNC=1 ISAC_SSB_FEP_GPU=1 ISAC_GPU_PASS_POLL_SLEEP_US=600 ISAC_GPU_PASS_RETRY_OLD=1 (= ONRX). Evidence: replay n=6 per capture, no CRC-OK loss on full runs, 0 mismatches, calls >5 ms 0.02-0.26 % (OFF 0.04-1.84 %). Honest ranking: the benefit comes from ASYNC + SSB_FEP; the pass itself is neutral on first-body latency; POLL 600 and RETRY_OLD are small and low risk. If an OTA arm must be reduced to the proven part: t26f + ASYNC + SSB_FEP_GPU (+ pass off), which was not measured here as a separate arm (ONR contains the pass). Needs an OTA CRC check at daytime load for ASYNC (2-4 % lost handoffs, Task 8).

## Concerns
- No pass-off ASYNC+SSB arm was run, so the pass's own contribution inside ONR is not isolated (OFF vs ONR confounds it).
- Poll 600 effect is near run spread; a tim ONRP run had 0.96 % >5 ms (outlier, unexplained).
- b grant counts vary 2x between runs of one arm (late acquisition), limiting CRC-OK precision to ~3 pp.
- Full stage reuse and up-front skip of predicted-failing grants not implemented.
- ctest: only the known failures (dft_test, test_nr_modulation, test_nr_pusch_ra0_qam64/256, test_nr_td_grantwork); test_nr_gpu_pass 33/33 in DIRECT and ISAC_GPU_FORCE_DISCRETE=1.

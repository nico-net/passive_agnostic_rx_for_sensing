## 2. Root cause `[CODE-READ + MEASURED]`

- `[CODE-READ]` `nr_dlsch_mmse()` (`nr_dlsch_demodulation.c`):
  - Modes 0-2 build G from `nr_conjch0_mult_ch1(..., shift)`, i.e. int16 conj(h_r) h_c >> log2_maxh summed over the antennas.
  - The right-hand side is `rxdataF_comp` = H^H y >> log2_maxh, also int16.
  - For nl > 1, log2_maxh = log2(max median |h|^2)/2 + log2(nbRx/2), so G_ll lands at ~2|h| LSB for 4 RX.
  - With |h| ~ 20 LSB (TIM; Vodafone's level is ~10x higher), the strong layer's G_ll is ~40-50 LSB and the weak eigenvalue
    (-20..-24 dB) is below 1 LSB. Mode 0 (adjugate / determinant) and mode 2 (double Gauss-Jordan on the **already rounded**
    G and b) cannot recover what the rounding removed.
- `[MEASURED, DGX replay tim_R2, ISAC_PDSCH_LLR_DUMP vs python on the same grants]`:
  - Rank-3/4 QPSK LLRs (mode 0) have |llr| p50/p90/p99 = 1/1/1, with 14-54 % exact zeros.
  - The non-zero signs agree with the decodable float solution on 41-52 % (random).
  - Rank-1/2 LLRs on the same capture: p50 2-14, 0-45 % zeros, 81-90 % agreement.
- `[OFFLINE VERIFIED]` Python emulation of mode 2 at TIM's level (channel scaled to the receiver's units, ratio from chest
  nvar), on the 20 MCS-0 grants:

  | arm | decoded |
  |---|---|
  | G and b rounded to int16 | 0/20 |
  | same with a 2^6 output gain | 0/20 |
  | log2_maxh - 4 | 2/20 |
  | **exact G and b** | **19/20** |

- `[OFFLINE VERIFIED, test_nr_llr_norm MmseExact.Rank3LowLevelIllConditioned]` Synthetic 4x3 channel, |h| ~ 20 LSB, layer 2
  9 dB weak, correlated columns, noise-free int16 y: exact solve 0 sign errors of 12000; int16-rounded G 645 of 12000.
- Why TIM and not Vodafone: chest `nvar_db` 15-19 (TIM) vs 36-40 (Vodafone), i.e. a ~20 dB lower absolute level in int16
  units at the same gain 38 (cell power, distance). The same code with ~10x larger |h| keeps 3-4 more bits in G. Vodafone
  rank 3/4 is not immune either: b rank-3 QPSK gains 9 -> 30 and rank-4 1 -> 16 with mode 3 (§5).

## 3. What was excluded `[MEASURED, offline python on raw dumps tim_R1 (rank 3/4) and tim_R2 (all ranks)]`

in dB. Each cell is nSCID 0 | nSCID 1.

What this shows:
- Port 1002 sits in CDM group 1 with the FD-OCC + sign and the same sequence (nSCID 0, id 88). The Rel-16
  `dmrs-Downlink` flip of nSCID for λ=1 gives no coherent power, and neither does nSCID 1.
- 1003 is absent at rank 3 and present at rank 4.
- On single grants port 1002 is 4-9 dB below 1000/1001. That matches CDMDIAG's raw group-1/group-0 energy of -9..-12 dB
  (group 0 carries two ports).
- No maxLength-2 DM-RS: symbol 3 is data (power profile flat, no coherent DM-RS), and sym2 ± sym3 combining shows no TD-OCC
  structure.
- With the decoded port set the float receiver decodes (§1). With port 1003 in place of 1002, or the OCC sign flipped, it
  decodes 0/30.

**DCI.** SOLVEDLAYOUT has a 4-bit antenna field (table 7.3.1.2.2-1, type 1 maxLength 1, value 9 = ports 0-2, 2 CDM groups).
The DM-RS energy per port confirms exactly that row. dmrs-SequenceInitialization 0 is confirmed by the nSCID column.

**PRG.** The mean |h_{n+1}-h_n|^2 / mean |h|^2 of adjacent pair estimates is the same at PRG-2/4/8 boundaries as inside a
PRB:
- port 1000: 0.131-0.138 vs 0.130;
- port 1002: 0.099-0.108 vs 0.130.

There is no per-PRG precoder change inside these 16-48-PRB allocations, and frequency interpolation across them is safe.

**Layer mapping, codeword, scrambling, rate matching.** Rank 3/4 is one codeword. The float chain uses the standard layer
mapping (d(i·Nl+l)), c_init = rnti·2^15 + 923, G = 11·12·nrb·2·Nl and the TS 38.214 TBS (1480 for 16 PRB / 3 layers / MCS 0,
the receiver's own). It decodes. The receiver with mode 3 decodes exactly the same grants as the float model: 11/11 of 40 on
replay tim_R4, bit for bit the same pass/fail string.

## 4. The fix: mode 3, `ISAC_PDSCH_MMSE_EXACT_NL34` (commits e8ec900500, d1cdb8974c)

| flag | effect |
|---|---|
| `ISAC_PDSCH_MMSE_EXACT_NL34=1` | mode 3 for every Qm at Nl 3-4 (default off) |
| `ISAC_PDSCH_MMSE_EXACT_NL34=2` | also Nl 2 |
| `ISAC_PDSCH_MMSE_MODE=3` / `ISAC_PDSCH_MMSE_AB=3` | the same mode globally / as a paired A/B arm |
| `ISAC_PDSCH_MMSE_EXACT_NVAR_DB` | s2 for Nl == nbRx: chest nvar x 10^(dB/10), default 21 |
| `ISAC_PDSCH_MMSE_EXACT_CAL=1` | diagnostic MMSE3CAL line: residual / nvar ratio and mode-3 CPU time per symbol call |
| `ISAC_PDSCH_RAW_DUMP=<path>` (+ `_MINNL`, default 3; `_MAX`) | diagnostic: FEP'd allocation (14 symbols x nbRx, c16) + 32-int header incl. DCI words, once per rnti+slot |

How mode 3 works:
- **Inputs:** G and H^H y in double, directly from the int16 extracted estimates and samples. They are scaled by 2^-shift
  so the units stay those of mode 2.
- **Noise variance:** for nbRx > nl, the decision-free residual ||y - H x_zf||^2 / (nbRx - nl), per data symbol, from every
  4th RE. For nbRx == nl (rank 4 on 4 RX) no noise-only dimension exists, so s2 = chest nvar x 10^(21/10). MMSE3CAL
  measured the residual at +19.2 / +21.0 dB over nvar on TIM (sd 3), +16.1 dB on b (with nl=2) and +6.7 dB on b's rank-3
  grants. 21 dB errs high, the safe side per §1, but the ratio is population-dependent: `[KNOWN ISSUE]`.
- **Solve:** unbiased MMSE, z_l = x_l / [A^-1]_ll, A = G + s2 I. That is w_l x_unbiased with w_l = mu_l / [A^-1]_ll, the
  per-layer SINR weight. Per-layer QAM thresholds w_l n1/n2/n3, as mode 2.
- **Output gain:** continuous, so that the strongest layer's mean G_ll lands at 2^10 LSB, independent of the receive level
  and of `ISAC_L2MAXH_DELTA*`. A first version used 2^(10-shift); with the NL2 delta of -3 that saturated 2-layer 16QAM
  (paired b/tim nl=2 16QAM 29-38 % vs 61-70 %). Fixed before these results.
- **Solver:** Cholesky (A = L L^H) in the pure header `nr_mmse_exact.h`. It matches the earlier Gauss-Jordan version to
  1.4e-14 at 0.086 / 0.137 us per RE (3 / 4 layers, GB10, `timrank34_data/bench_solver.c`; Gauss-Jordan 0.130 / 0.225).
- **GPU:** `nr_pdsch_gpu_demod_host.c refuse()` returns RF_NL for mode 3, so such grants run the CPU `nr_rx_pdsch()`; the
  GPU CHECK never compares them.
- **Flags off:** paths unchanged. The only reachable difference is `ISAC_PDSCH_MMSE_MODE=3`, which used to clamp to 0 and is
  set in no env.

Tests:
- `[OFFLINE VERIFIED]` `test_nr_llr_norm`: 7/7, including `MmseExact.Rank3LowLevelIllConditioned` and
  `MmseExact.ResidualAndUnbiasedScale`.
- ctest `-R 'pdsch|dlsch|llr|solver|mmse'`: 20/20 pass (build_t26, before the otatest merge).
- `test_nr_llr_norm` re-run 7/7 after the merge.

## 6. Cost `[MEASURED, shared host, replay]`

- MMSE3CAL CPU time of the mode-3 block: **59 us per data-symbol call** on TIM (83379 calls) and 128 us on b (6563 calls,
  larger allocations). That is ~0.65 ms per 16-PRB rank-3/4 grant.
- The rest of the demod increase comes from the whole `nr_rx_pdsch()` of those grants running on the CPU: the GPU refuses
  mode 3, and failed grants also pay the recovery arms.
- PDTIM demod mean: TIM 280 -> 1527-1584 us, tim4 125 -> 1172 us, b 144 -> 272-280 us, old 117 -> 142 us. Mostly a
  population effect on TIM, where rank-3/4 grants went from ~1 % to ~40 % of calls.
- chest and LDPC means are unchanged within noise.
- `[INFERRED]` A GPU port of mode 3 is the cure. The existing nl 3/4 per-RE kernel in `nr_pdsch_gpu_demod.cu` is the
  template; the per-symbol reductions (s2, gain) need a fixed summation order for CHECK bit-exactness. Not done here.

## 1. Verdict

1. **UL length sweep: 118 -> 19 us/pass (b), 61 -> 9 us (tim); `ulwait` 26 -> 1.4 us (b).** Bit-exact bookkeeping, empty CCEs are not decoded.
2. **UL 0_1 tasks gated by the USS hash**, self-correcting: decode stage b 59 -> 42 us, tim 20.6 -> 16.1 us.
3. **Learned TDD slot filter** works (skips only zero-evidence UL slots, 7 % of b passes in a 12 s replay); gain is small in replay, needs OTA time.
4. **New finding, biggest tail cause: the 70-430 ms scan-pass maxima are blocking `write(2)` of log lines under the Phase-2 lock.**
   `ISAC_LOG_ASYNC=1` removes them: max pass b 18 ms (median of run maxima 6.5 ms) vs R 126 ms (median 11.4 ms).
5. **GPU polar: rejected.** `nr_polar_sc_cuda_test` was never failing, it was "Not Run" (target not part of `ninja tests`); fixed. In the live
   scan the GPU path is slower and creates 180-920 ms maxima (section 5).
6. Occasion p99 b 3.34 -> 2.38 ms, tim 3.25 -> 2.60 ms (SPEED=1) and 3.2 -> 1.9 / 2.9 -> 1.9 ms (half speed): better, **not << 3.4 ms, not sub-slot.**
   Remaining cost: TIM's anonymous DL length sweep, 49 % of scan-thread cycles (section 6).

## 5. GPU polar (item 3)

- `nr_polar_sc_cuda_test`: the code was fine (bit-exact, 0 mismatches over ~25 (length, AL) cases x 950 vectors, `VEC-PATH` 776 items equal). ctest said "Not Run" because the executable is not a dependency
  of the `tests` meta-target (`ninja ... tests` never built it). Fixed (`add_dependencies(tests nr_polar_sc_cuda_test)`); ctest #222 passes. `[OFFLINE VERIFIED, DGX build_t26]`
- Standalone benchmark (same test, not quick) `[MEASURED, DGX]`: CPU 1.8 us per AL2 decode (one core). GPU batch of 1 / 8 / 32 / 128 items: 319 / 261 / 284 / 326 us total (kernel 230-285 us floor: the SC tree is a
  ~1000-op serial chain, one warp per item); 512 items 432 us (0.84 us/decode); one 520-decode occasion 503 us vs 924 us on one CPU core (1.8x).
- Live scan, `NR_GPU_POLAR=1` (the existing `sweep_gpu_prefill` path, which batches the full candidate x length grid per sweep) `[MEASURED, DGX air-like replay, n=2]`: with `ISAC_GPU_BUDGET=1` (OTA env) the budget
  logic refuses almost every call (1 GPUTIME line per run) and results equal CPU. With `ISAC_GPU_BUDGET=0` the GPU is used (3000-4000 calls, ~400 items each, 650-1160 us mean per call: kernel 355-700, D2H 90-475 on the shared
  GPU): **R+GPU / N+GPU vs R / N: scan loss 3.4-6.5 % (was 0.0), occasion max 180-920 ms (was 8-12), ulsweep 148-215 us (R 138; N 19), dlsweep 268 us (tim, R 182), pass 343-651 us (R 386-404),
  tim p50 1233-1565 us (R 1081).** Reason: after the screen a pass needs ~50-100 decodes (~0.2 ms of CPU) while one GPU round trip costs 0.65-1.2 ms plus contention with PDSCH on the shared GPU, and the
  scan thread waits for it. Verdict: not adopted, no further GPU work on the polar scan; the batch only wins for >= 500 items per call, which the screened scan never has.

## 9. Risks

- UL sweep screen can drop weak-SNR sweep hits (b audit: ~30 % of the hits of those runs); effect = later UL length lock, not a lost accepted DCI. Lower `ISAC_SCAN2_UL_Z` (e.g. 1.64) buys recall for cycles.
- UL USS gate: before a violating position is audited (1 slot in 16) the first such UL DCIs of a UE are not decoded; after the fit widens they are. A cell whose 0_1 uses a different search space disables the gate for that geometry after the first violation.
- TDD learner: a slot with rare PDCCH is only protected structurally (guard/special rule) and by verification (1 in 8 passes, hashed); a pattern change is found within about 8 frames per slot. Replay length (12 s) cannot validate it on air.
- `ISAC_LOG_ASYNC`: log lines are lost if the process dies hard (exit via signal handler drains; `_exit`/SEGV do not) and when the 16 MiB ring fills (counted and printed at exit).
- Evidence is replay only (n = 8-12 per arm, load ~half of air); b discovery bimodality widens every b interval. No OTA run, nothing on hardware.

## 2. PCI 4 (and 614): why the dedicated CORESET was never found, and the sibling carrier

Findings [MEASURED]:
- 508, 4 and 614 have identical MIB fields (k_ssb=2, coreset0=11, ss0=4, dmrs_typeA=1; OTA logs ab_U508a, ab_U4a, ab_B4a, ab_Apci508 and replay) and SSB timings within 10 samples @7.68 MS/s (fastscan dt 0/10): sectors of one site on one carrier. CORESET#0 and the SIB1 PDSCH therefore overlap in time and frequency.
- PCI 4's PDCCH identity is confirmed (n_id=4 by RNTI 0xffff) but SIB1 never decodes: OTA EVMGRANT SI-RNTI snr 1.3 dB, 0/35 crc (U4a), 0/3 (B4a), 0/1 (P4) against 508: snr 2.9, 1364/5154 (B508a). 614 in the replay: 325 SI-RNTI DCIs, PDSCHQ crc_ok 0/292. 508 decodes (114/425 = 26.8 % on the same capture, replay r508). So PCI 4/614 have no SIB1 -> no SCC -> `carrier=unchecked` -> `nr_pdcch_coreset_map_idsweep_want()` returns -1 (needs carrier_verified != 0) -> no GPU nID sweep at all (t26b_pci4 replay on c3610: no sweep line; BLINDPIPE's Point-A sweep: `undecided lit=0`, 1536 symbols).
- The nID = PCI Point-A sweep finds nothing because the nID = PCI hypothesis was the only one tested; the real dedicated PDCCH uses another nID or does not exist (below).

Fix `ISAC_SIB1_SIBLING=1` (default off; `nr_passive_acq_state.c`, hook in `nr-ue.c` right after the MIB/pbch_locked note) [CODE-READ + OFFLINE VERIFIED test_nr_passive_acq_state 16/16 incl. new `SiblingCarrier...`]:
- a cell that decodes its own SIB1 with servingCellConfigCommon stores {N_RB, mu, offsetToPointA, offsetToCarrier, k_ssb} in `/tmp/passive_rx/sib1_sibling_<absolute SSB kHz>.bin`;
- a cell on the same absolute SSB frequency with the same MIB k_ssb and no verdict yet adopts it as a carrier HYPOTHESIS (log `ACQ carrier SIBLING hypothesis`); its own SIB1 replaces it; a different k_ssb is refused (other CRB grid); flag off = no file, no hook effect (byte-identical behaviour).
- General: nothing cell-specific; it is the co-sited-sector fact, and a wrong hypothesis cannot create a CORESET (every dwell is verified by TB-CRC RNTI recurrence).
Replay effect [MEASURED, replay live_auto_0942/c3610 x8, -C 3590190000 --ssb 517, FO -4842, t26b_pci4 + ISAC_SIB1_SIBLING=1, 1 run]: PCI 4: `SIBLING hypothesis -> 162 PRB offsetToPointA 32` (verdict MISMATCH as for 508: 162 inside a 217 grid), 13 GPU nID passes, 16 candidate CORESETs, dwells started (2054 dwell runs, 0 accepts). PCI 614: same adoption, 92 GPU passes, only SI/RA RNTIs. Without the flag the same run has no sweep line [MEASURED p4b].
Verdict [MEASURED / INFERRED]: the candidates (nid 33538 `ties=6`, 26722 `ties=48`, same values in every run on this capture) are the CORESETALL noise class; no RNTI recurrence (RNTIs seen on 4: 0x1d x20, 0xffff x17, 0x63 x8, two singletons) -> no dedicated CORESET is observable in this second. 508 itself on the same capture with its own SIB1: 40 GPU passes (t26z, DUR 1), 0 candidates, RNTIs only 0xffff x489 + RA-RNTI 0x1d (a PRACH was seen, so a UE existed, but Msg4 is not in the second). "No CORESET found" and "no UE traffic" remain indistinguishable on the 508/4/614 captures that exist; the hypothesis "4 shares 508's geometry and is found with a full nID sweep" is now TESTABLE (the sweep runs) but not CONFIRMED.
Open (not solved): the SIB1 of 4 and 614 is interference-limited (SINR ~1.3 dB, 0 % crc). The lever is soft combining of the SIB1/SI repetitions (8 per 160 ms) and an interference-aware (IRC/successive) demod of CORESET#0 overlap; it sits in the PDSCH demod/queue files excluded for this task: [NOT RUN].

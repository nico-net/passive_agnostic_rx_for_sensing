# TIMRM (2026-10-12): TIM MCS-0 "50 % CRC" root cause found and fixed behind ISAC_PDSCH_REP_FIELDS=1

Host DGX GB10 aarch64, worktree rr-csd-rmx (csd/tim-rm from csd/otatest f72ee5c0a2), build_gpu (CUDA). All builds/replays via heavy.sh, ENVFILE t26z.env,
0.25x, no OTA/capture/UHD. TIM (PCI 923) and Vodafone (PCI 415) numbers are never pooled.

## Root cause [MEASURED, replay DGX raw_pci923_tim_12s_tile3; CODE-READ]
Not TBS, rate matching, CSI-RS, DM-RS power or PT-RS. The failing MCS-0 grants are exactly those whose parsed rv != 0:
- [MEASURED, DGX OTA logs 2026-10-12, ab_NT1_1_152707 / ab_Tz1_1_135834, SNR >= 10, probe=0] MCS 0 with rv 0: 450/451 and 153/162 pass; MCS 0 with rv 1/2: 0 of ~450 and 0/40 pass. MCS 1-4 are always rv 0.
- [MEASURED, replay] new log RMDCI (raw DCI bits next to the parsed fields) on 366 grants: every MCS-0 failure with parsed "ndi 0, rv 1" (98 of 98) has bit 23 = 1, bits 24-25 = 0.
  Read with the layout whose MCS sits at bit 18 (the layout the RNTI's MCS > 0 passes prove) that is NDI = 1, rv = 0: a NEW transport block sent at rv 0.
  The solver's merged "reading" however carried the fields of whichever layout parsed first: the layout with MCS at bit 16 reads the same MCS 0, same allocation, same ports,
  but takes (bit 22, bit 23) = (MCS LSB side, NDI) as the rv -> rv 1 whenever NDI = 1. NDI toggles per new TB, hence the coin flip, independent of every logged field.
- [MEASURED, replay] bit-level genie (new, ISAC_PDSCH_RM_GENIE=2: re-decode a failed grant over all TBS x rv): 49 of 49 hits that were found were rv 0 with the SAME TBS (no hit at any other rv); the rescued TBs are not copies of earlier TBs (52/53 not identical to any earlier decoded TB), i.e. new data, not retransmissions.
- Rate matching / TBS are sound: [MEASURED] re-encoding CRC-passing 1-layer TBs and comparing with the LLR signs (RMMAP) gives 0.0-0.3 % bit errors, flat over the codeword (no slip, no tail error).
This is the mechanism TIMMCS0 hypothesised and implemented as ISAC_PDSCH_READING_RV; that flag did not show it because the replays it used had few NDI = 1 MCS-0 grants, and it hurts elsewhere (below).

## Fix (default off): ISAC_PDSCH_REP_FIELDS=1
nr_pdcch_blind_monitor_rt.c, solver path: after readings are built, the group containing the RNTI's representative layout takes NDI / rv / HARQ pid from the representative's own parse.
Readings, ids and refinement probes are unchanged. General (no cell constant): applies to any layouts that collide on the MCS field.
Unit test [OFFLINE VERIFIED, DGX] Dci11Reading.TimRealMcs0PayloadNdiReadAsRv (real 47-bit TIM payload, both layouts, 217 PRB): pass, with the TIMMCS0 test. The RT-path change itself is covered by the replay matrix only.

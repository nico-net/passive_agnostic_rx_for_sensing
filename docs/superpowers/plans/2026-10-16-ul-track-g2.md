# UL track (G2 + G3 for UL): probe/real log split, BWP look-alike lock, data-ID search on GPU, HARQ combining — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the passive receiver decode real UL grants: CRC >= 80 % on SNR-qualified grants of UEs whose IDs are found, latency p99 <= 500 us for them, UL queue drops < 1 %, with the compute-heavy parts (data-ID search, HARQ combining) written directly on the GPU.

**Architecture:** C4 first (every UL measurement depends on separating probes from real grants), then C1 (the BWP look-alike lock misplaces every real grant), then a health measurement, then C2 (IQ retention per UE + a background 1024-candidate data-scrambling-ID search on the GPU, CPU sweep as reference), then C3 (HARQ soft combining on the GPU). C1 and C4 are CPU control/logging and may be done on a cloud x86 session (rfsim); C2 and C3 are DGX-only (GPU).

**Tech Stack:** C/CUDA (OAI fork), existing GPU LDPC UL pool (`ul_exec`, nr_pdsch_gpu_ldpc.cu:848), Python stdlib analysis (`goal_metrics.py`, `health_grid.py`), replays and rfsim.

**Spec:** `docs/superpowers/specs/2026-10-16-target-gpu-pipeline.md` (section 1.2 UL timeline, items C1-C4 of section 6, interfaces `nr_gpu_pusch_*`, `nr_gpu_iqstore_put`, `nr_gpu_dataid_search_*` of section 5). Evidence: `docs/superpowers/reports/csd/ULCAUSE-20261016.md`, `SCORECARD-BASELINE-20261016.md` (UL rows), `GPU-INVENTORY-20261016.md` (2c).

## Review Focus
1. A probe line must never count as a real UL grant in CRC, latency or drop statistics. Pinned by `test_ul_probe_lines_excluded` (Task 1).
2. A BWP look-alike pair (sizes differing by one RB with the start shifted by one, e.g. 216@1 vs 217@0) must not lock on evidence that cannot tell them apart; with no discriminating evidence the DL-BWP prior wins. Pinned by `test_lookalike_without_edge_evidence_prefers_prior` (Task 2).
3. The data-ID search must stay off the latency path: it is a background job, chunked so no launch exceeds the X of the stall plan (provisional 200 us). Pinned by the chunk-size assertion in Task 4's unit test.
4. A wrong data ID that passes CRC by chance (CRC-16/24 false alarm) must not lock: lock only after a second CRC pass on a different grant of the same RNTI. Pinned by `test_id_lock_needs_two_independent_passes` (Task 4).
5. HARQ buffers must be cleared on an NDI toggle; combining a new TB with old LLRs must never happen. Pinned by `test_ndi_toggle_clears_buffer` (Task 5).

### Task 4 (C2): UL IQ retention + 1024 data-ID search on the GPU — sub-plan first

This task is multi-week. Step 1 writes `docs/superpowers/plans/<date>-ul-dataid-gpu.md` with the writing-plans skill and gets the orchestrator's review before coding. Binding contract:
- Retention: per RNTI keep the IQ slice (UL PRBs x 14 symbols x 4 RX) of the last N strong grants (DM-RS SNR >= 10 dB) in the existing snapshot pool memory (`nr_pusch_passive_queue.c` snapshot pool, PUSCHQ2 `snap[pool=...]`), DIRECT mapped / DISCRETE device ring through `nr_gpu_buf_alloc`.
- Search: `nr_gpu_dataid_search_submit/collect` (spec section 5): for one retained slice, all 1024 data-scrambling IDs (0..1023) x the DM-RS-ID set: descramble the stored LLRs (LLRs computed once per slice by the existing UL GPU FEP/equaliser), LDPC decode + CRC on the GPU through the UL pool (`ul_exec`), BG class at lowest priority, chunked so no launch exceeds X (stall plan; provisional 200 us); CPU `nr_scrambling_id_sweep` (nr_pusch_passive_ul_ids.c:217-259) is the bit-exact reference for one ID.
- Lock: an ID locks for an RNTI only after CRC passes on two different grants of that RNTI (false-alarm guard); locked IDs go to the per-UE table the real-time UL decode reads.
- Acceptance: on a retained V slice, GPU hit set == CPU brute-force hit set (CPU run offline once, may take minutes); search of 1024 IDs completes in <= 1 s wall on the DGX in BG class without raising DL tot p99 in a replay A/B; UL CRC on real grants of locked UEs >= 80 % when SNR-qualified.

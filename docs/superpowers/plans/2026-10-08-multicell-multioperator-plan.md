# Multi-PCI and multi-operator sensing: ordered work plan

2026-10-08. **Plan only; no implementation or radio run in this worktree.** Target acceptance is G12 two co-channel PCIs, G13 two simultaneous carriers, then G14 at least two simultaneous operators with two calibrated RX antennas per carrier for AoA. The sequence starts with cheap evidence tests, but production integration waits until the single-cell T26c PDCCH/PDSCH efficiency work, RXR recovery/direct-ring validation, and G10/G11 tracking foundation have passed their own gates. Use the [design](../specs/2026-10-08-multicell-multioperator-design.md) and `PROJECT_MEMORY.md` §§12,14,17–20. Every result names host, capture/cell, RF profile, antennas, commit and evidence label; replay is never called OTA real time.

## Integration order and branch boundaries

The experiments in WP0–WP2 are read-only or isolated diagnostics and may start now. Production packages WP3–WP10 begin **after** the single-cell efficiency changes (T26b/T26c GPU PDCCH FEP, batched PDSCH, known-RNTI scan, queue admission), their live-rate OTA gate, and RXR's timed recovery have landed on the integration base. G10/G11 persistence/epoch behavior must be established before G12–G14 acceptance. Rebase once at that point; do not edit T26c's `nr_pdcch_blind_monitor_rt.c`, `nr_pdsch_passive_queue.c`, GPU FEP modules, or the DL/UL branches' solver/UL implementation while those branches are active. Use new context/adapter files and narrow API additions in WP3–WP5; move state owner by owner after those merges. DL and UL owners review the matching context-key and job-tag changes; merge DL and UL first, then this series, one package at a time. Preserve the `nr_csirs_disc.h` contract unless separately approved by its owner.

All new runtime behavior gets its own `ISAC_MCELL_*` flags, default off; the unflagged one-cell path must remain behaviorally identical. Stage only explicit paths, run the frozen sens6 diff gate before each commit, commit on the implementation branch, never push from this plan. Builds/ctest use the shared measurement lock, `nice -n 19`, `-j8`/`-j4`; benchmark, rfsim and GPU throughput use the exclusive lock on an idle host. The orchestrator owns replay and X410 OTA execution. No gNB config/log is receiver input.

## Acceptance detail and stop rules

For WP0, the second PCI question is resolved by **independent** PSS/SSS/PBCH evidence plus timing and cell-specific RS/CRC on the nID-10163 grants. If the capture has no second PBCH lock, write “inconclusive” and use the two-cell synthetic/recorded fixture; do not promote an nID to a cell. WP1 stops before receiver changes if the X410 cannot hold the two RF centres with valid phase calibration or if GB10 drops samples at the chosen rate. WP2 stops before multi-cell implementation if real-time single-cell p99 and queue lag remain beyond the admission budget. The user minimum is met only when G12, G13 and G14 all pass in the same integrated receiver with two operators **simultaneously** and two calibrated antennas per carrier.

Use the existing G12–G14 definitions in `PROJECT_MEMORY.md:1620-1622`; the added sensing criterion here makes the gate stricter for this project. The predeclared G12 tolerance must specify each metric and SIR before testing (suggest initial candidate: PBCH success and PDCCH/PDSCH CRC within 10% relative of same-profile, isolated-cell baselines where sample sizes support that comparison; AoA error/availability must be specified from calibration data). G13's “no added sample loss” is assessed against WP1's RF-only 2+2 baseline and against separate two-RX decoder baselines. G14's 30–60 minute OTA run reports exact two-operator overlap in sample time, not summed dwell time. False cell/UE assignments and unlabelled observation gaps fail all three gates.

## Review artifacts per package

Each implementation package lands with a small report in `docs/superpowers/reports/csd/`: source anchors, exact flags/defaults, commit/build identity, tests with evidence labels, sample-time performance and memory counters, limitations, and deferred OTA commands. Reviewers receive the two-cell replay traces and a per-cell comparison table. Do not combine DGX replay, rfsim and OTA percentages, different captures or different antenna profiles into one headline number. The operator runs radio tests under the exclusive lock; builds finish first, no receiver is killed with SIGKILL, and `ISAC_RX_BRANCH_FO` stays unset.
